# 真实播放器 GET 限速观测工具

## #36 本地正文放行实验

`-body-manifest <JSON> -listen 127.0.0.1:80 -body-control <JSON>` 启用独立 HTTP 夹具，完全绕开正式缓存引擎。manifest 是 `{song,file,md5}` 数组；启动逐文件重新计算 MD5，不修改视频。只对列出的歌曲提供 `/Api/Songs/play?id=...`，其余歌曲返回 404。标准库 `ServeContent` 保留单 Range、后缀 Range、HEAD、条件请求与 Content-Length 语义；多 Range 与产品一样不支持。

控制文件为 `{"limitBytes":-1}`（不限量）或非负累计额度；只控制 User-Agent 以 `NSPlayer/` 开始的 GET 视频正文，所有此类并发请求共用额度。解析器 GET 不受限，仍独立计数；这只能回答 WMF 数据路径的供数上界，不能断言解析器数据对起播无贡献。基线须先核实实际 UA。上调额度继续放行，额度用尽时连接保持打开，不伪造 EOF；降低额度不能收回已交付字节。每次写出最多 16 KiB，记录实际返回字节数、文件偏移和 Flush 结果。这里的成功 Write 是服务端接受的正文量，不能严格证明游戏已经消费；Flush 失败、取消及重复区间需分别保留。

默认额外监听 `127.0.0.1:443`，仅将加密 TCP 原样转发到 `api.udon.dance:443`，不解密 TLS；`-body-https ''` 可关闭。启动前停止产品网关，保留控制台用于正常条款/hosts 流程。与 SOCKS 模式共用 `-stop-file` 和 `-duration`，不能同时使用两种模式。

独立样本前按下文取得停止、清空正式队列及关闭预览的反馈，再重启夹具重置累计额度。`Cache-Control: no-store` 不能证明客户端没有旧媒体缓存，必须核对真实 GET；正式和预览由实际操作标记，不能只靠 UA/Range 推断。长暂停导致超时或新 GET 时保留为实验干扰，再用短暂停对照。`body-summary.mjs <日志>` 输出白名单请求和正文区间摘要；`writeBytes` 保留各响应的实际 Write 字节（含错误文本），视频区间及歌曲累计量仅包含 GET 200/206。原始逐次写入轨迹与游戏日志留在忽略目录，公开前按统一时间原点脱敏。

当前夹具在首次等待正文额度前 Flush 响应头，零额度和共享额度已耗尽的新 GET 也可立即收到状态与 Content-Length。LIVE-20261019-01 的历史二进制尚无此修复；历史请求/测量保持原样，影响评估见[本轮报告](../../docs/live-acceptance-20261019-01.md)。针对性回归：`node --test experiments/live-get-probe/body-summary.test.mjs`，以及下文 Go 测试中的响应头先行、正文暂停/恢复检查；Windows 命令使用 `scripts/with-test-temp.ps1` 包装。

## 上游 SOCKS 限速实验

合计限速模式支持 `-rate-file <JSON>`，内容为 `{"bytesPerSecond":125000}`。改为 0 会唤醒原连接上等待的转发块、恢复不限速，不关闭游戏请求或重启网关；适合观察带宽恢复后的真实自动重试。控制文件应原子替换，错误内容使夹具停止并记录错误。此选项不与每连接模式混用；正文放行模式也不使用它。

仅供集中实机验收。独立、只监听 loopback 的 SOCKS5 中继，使用产品的 DoH 回源解析，不修改生产缓存引擎。仅接受 TCP CONNECT 到 443。默认所有资源连接的上游到网关字节共用一个节流器；使用 `-per-connection` 后，每条上游 TCP 连接各有一个节流器，多连接的吞吐可以叠加。`api.udon.dance` 和 `x.kiva.moe` 的元数据连接豁免。TLS 不解密、不更换证书；计数包括 TLS 开销，不能当成纯视频正文吞吐。

默认监听 `127.0.0.1:19081`。`-bytes-per-second 0` 不限速；例如 `1048576` 为合计 1 MiB/s。每连接 1 Mbps 使用 `-per-connection -bytes-per-second 125000`，0.5 Mbps 使用 `62500`，这里 Mbps 为十进制。连接可能复用多个 HTTP Range，限速不是按请求重置。使用 16 KiB 最大转发块，不积攒空闲突发额度；已取消的排队块可能留下小量未使用额度。`-stop-file <path>` 文件出现时关闭监听和本轮连接；`-duration` 默认 45 分钟，作为遗忘清理的兜底。每秒日志保留连接数、累计受限/豁免字节及各连接的匿名 ID/累计字节。短采样窗口可能跨过转发块边界，应报告量化误差，不把单个瞬时样本当成精确带宽上限。

每档启动独立中继，控制台设置 `upstreamMode=proxy`、`proxyBackend=external-socks5`、`socks5Address=127.0.0.1:19081`，避免直接回源绕过上限。先关闭预缓存并使用新的隔离缓存；不修改日常存储。游戏接入及条款确认由正常控制台流程完成。已有播放器缓存不能通过清空服务器目录排除，必须依据实际 GET 范围和接收字节判断样本。

采集产品 `request_started/request_finished`、下载开始/完成/取消及真实游戏事件。关注同一内容最后一个 GET 结束到下一 GET 到来的空窗，并与完整下载时刻比较；单条 Range 或客户端取消不能直接证明所有 GET 均已结束。基线和各限速档的普通播放、主动 Seek/切歌分别记录。人工音画反馈与 HTTP 结果分开。

每个独立样本前，须取得用户明确的停止播放、清空队列反馈，再重启网关、更换隔离缓存。仅观察到 GET 暂时结束不足以证明游戏已经停止：旧歌可能自动重连，取消后的下载也可能继续占用合计带宽。确认样本窗口中只有目标资源下载；有旧歌进入时保留干扰记录，不将该段当成单首限速样本。拖动、刷新和切节点各自建立前置状态，不把连续混合操作当成独立对照。

必须单独记录正式与预览模式。正式播放先入队，有人工操作间隔且不能拖进度；预览可立即播放，默认从非零位置开始且可以拖动。两者可同时播放，因此清空正式队列不等于关闭预览，重叠 GET 不一定来自同一个播放器。正式场景先关闭所有预览；Seek 归入预览场景。无法回忆的历史模式标为未知，不能据非零 Range 推断用户主动 Seek 或播放器自动重连。

`observe.mjs` 输出实时白名单摘要。`summarize.mjs` 为本批次生成详细脱敏轨迹，默认保存到忽略目录中的 `sanitized-full`；`review-evidence.mjs` 生成 Git 中的精简证据及清单。进行中状态、未测项和未发布的完整轨迹必须如实保留，最终收尾后再更新。

开发校准：`go test -tags=no_easytier ./experiments/live-get-probe -count=3`。四路合计 512 KiB 在 512 KiB/s 下不得短于 1 秒；中继字节一致、取消关闭与连接计数归零分别检查。它们不代表真实游戏通过。

每连接限速另检查三条独立连接各自的字节额度可以同时完成，不因共享配额延长到三倍时间。本工具改动不改变产品运行行为，无需新增实机台账项；实际游戏场景归入原 LA-020/037/040，记录工具源码差异、EXE 哈希和限速范围。

原始日志、二进制、hosts 备份和隔离存储仅放入忽略的 `artifacts/acceptance-evidence/<batch>/`。实机结果、脱敏摘要、manifest、索引和台账按仓库验收机制一起交付。
