# 下载并发与播放优先

本页是当前运行规则与参数。核心创新、分层理由、期限公式和完整算例见[以期望完成时间驱动的全局块调度](block-scheduler-design.md)；实现过程和自动结果见[开发记录](block-scheduler-validation.md)。

后续架构设计及待决问题统一见 canonical 文档[下载需求与资源管理设计](download-resource-design.md)。固定 M 下载启动窗口已实现；后续新增 `need-by + 30 秒` 的下载延续截止，并且不保留块下载暂停／恢复；停止后复用仍保留的完整块，未完成块重新下载。下载延续截止和暂停恢复尚待迁移，本页区分当前运行行为。

## 当前实现（全局块调度，2026-10-16）

需求层将 GET 请求区间、实际读取等待、队首、普通队列和补齐转换成独立的块需求，先按来源过滤、再汇总每块属性；调度器只认识内容块、完成期限、有效租约和实际读取阻塞。旧 P0～P4、每视频固定 worker 和固定三块读取窗口已移除。

固定提前量落地前，当前 T 实现的维护见下方 [T 的定位与维护约束](#t-的定位与维护约束)；后续目标以 canonical 文档为准。

| 约束 | 当前行为 |
| --- | --- |
| 内容及执行 | 1 MiB 固定块；MD5、大小与块号共同标识，资源会话保证实体/选路一致性；同块只执行一次 |
| 全局并发 | 16 路软上限：普通需求受当前开放额度及软上限约束，Blocking 缺块立即执行，可突破 16 路；首请求、重试、重定向和顺序 200 回退统一由块调度管理，底层 HTTP 只跟踪生命周期 |
| 启动节奏 | 普通额度从 1 路开始，有可启动积压且额度已满时，每 250 ms 最多新增一路；已有额度立即复用，无可启动积压即停止增路，active 归零且无可启动工作时收缩至 1。Blocking 不等窗口、缓增或额度；所有执行计入 active 直到收尾结束 |
| 启动窗口 | 普通有限期限块在 ReadyBy ≤ now + M 时可启动，再检查 active < open；M 默认 500 秒，设置范围 120～86400 秒。实际耗时观测不参与准入或排序 |
| 暂停保留 | 最多 32 个检查点，文件长度合计最多 512 MiB（含空洞）；超限淘汰最早暂停者；已有读者引用释放后才删除，淘汰后的新需求重新下载 |
| 需求展开 | GET 只提交与实际请求区间相交的未完成块，队列和独立补齐可覆盖整文件；不设每视频候选数或并发上限。首次响应头前只执行一个初始化块，冷 Range 从请求涉及的块开始；实际 Read 等待另行贡献 Blocking，不附带固定预读窗口；未接入的库资源不展开 |
| 元数据 | 最多 32 个资源会话、4,096 个已注册块；核心最多 32,768 份需求，产品按块提交一份摘要；需求管理层每块最多 128 份活跃来源与交接记录。MaxLocalValidations 限制本地验证并发（CLI 保留 `-max-downloads`），不决定视频网络席位 |
| 交接 | GET 取消/关闭后最多 2 秒；队首消失后最多 20 秒；普通队列删除直接撤销。Blocking 撤销，ReadyBy 在原期限与来源退出时刻的较晚者上分别延后 2/5 秒，协调器处理延迟和无关事件都不延长交接 |

“可启动积压”包括已进入启动窗口的有限期限任务，以及具有有效独立补齐需求、允许提前执行的任务；这里的“可启动”指满足窗口或提前准入条件，仍可能等待普通额度。两类积压都能驱动缓增，不能仅因没有已入窗任务就停止增路。

Blocking 只在 Read 确实等待缺失内容时成立，GET 到达或刚结束的读取都不自动取得此标记。多读者独立撤销，不同 Blocking 块均立即放行；同等非阻塞期限按不透明 Owner 公平分配；普通块优先比较最早有限 ReadyBy。每份需求保留自身租约，过期或关闭句柄不能被迟到更新复活。来源仍有效才续 30 秒租约，资源协调器每 10 秒确认存活；交接租约不续期。 核心任务没有任何有效需求时立即停止执行，并只保留 30 秒供新需求重接；提交后从未添加需求的任务同样计时。到期自动退休并通知协调器，执行器完成收尾后回收任务容量，无需调用方再次 Close；显式 Close 和引擎关闭不等待保留期。新有效需求撤销本次回收计时，重复 Submit、无效更新或暂停收尾不延长无需求保留期。这是任务元数据的兜底，不生成交接或延长下载权限。

同块存在有效 GET 时，交接不参与调度属性竞争，但仍按自己的固定租约存活；独立的队首/普通队列期限照常参与。过滤后 Blocking 取实际等待的或、ReadyBy 取最早有限值；Opportunistic 独立保留有效无期限来源的普通提前准入能力，不能因同块有限期限而消失，也不绕过额度/缓增。任何有效来源都能维持块存活。管理层按每份租约最早到期时间重新汇总，交给核心的最晚 LeaseUntil 仅是最终存活上限，不能代替各来源独立到期。

正常交付完成、服务端失败、读取推进/Seek、块完成和关闭引擎不创建 GET 交接；客户端取消保留未消费部分交接。队首与普通队列互换时原地更新来源和时间。队列连续存在时保留来源标识，删除后重加或重置产生新标识，旧地址解析结果不能复活已撤销来源。队列变化、GET 增减及元数据更新统一重算受影响的队列期限，相同快照不顺延；移除时冻结该成员最后的身份、期限基准和移除时刻，避免合并通知丢失中间升降。GET 请求退出时同样冻结退出时刻，重复关闭不改写；2 秒/20 秒交接均从各自来源退出时刻计算，处理前已过期就直接过滤。交接只保留计算后的时间和非阻塞属性，原始来源与原因仅写入转换日志，不进入交接的运行时数据模型；交接不再产生交接。

GET 按请求刚到达的时刻和 Range 起始字节估算播放位置：总大小优先读 media.byte_size，直接资源 URL 尚未入库时使用已验证的同源 s；时长取同 MD5 的歌曲清单 end（秒），不减 start。资源直链没有歌曲 ID 时，取关联清单中最早的有效 end。只有与 GET 请求区间相交的块才取得该 GET 的播放期限，块期限为到达时刻加上“块起点减 Range 起点”对应的播放时间；起点位于块内时，该相交块取到达时刻，之前的整块不创建 GET 需求。后续读取和下载进度不移动这个时间基准。有限 Range 的结束字节限制需求范围，但不表示整部媒体播放结束，队列预计开播时间仍按剩余媒体时长计算。

HTTP 与下载协调器共用一个 GET 来源，按实际响应接受的字节逐块撤销已消费部分；Reader/Seek 不推进交付，短写明确失败，来源身份及原播放时钟持续到请求结束。请求区间按块向外对齐，下载一个相交块的完整内容以保持原有校验和共享；不会因此激活相邻的整块。区间完成后仍有 GET 读者时，会话保留已下载数据供响应消费，不以“没有缺块任务”取消读者，也不自动生成整文件补齐需求。独立队列/批量来源仍可补齐其他块，只有全文件完成并通过校验才发布正式缓存。共享会话初始化期间保持同一个在途初始化请求，新 GET 接入不另开探测；上游忽略 Range 返回 200 时保留原顺序整文件回退。

单 Range 支持明确起点、开放末尾及后缀形式；无效/多 Range 和 HEAD 不形成播放时钟。If-Range 的 ETag 或日期不匹配而回退整文件时，估算起点为 0；日期条件复用已验证本地文件及本地校验额度，与 ServeContent 的时间比较一致。冷流没有修改时间，日期条件按整文件估算。

大小和时长都有时按需计算整文件平均总码率；只缺一项用 2 Mbps 推导，二者都缺时用 45 MiB、210 秒（派生码率约 1.8 Mbps）。无效/非正时长视为缺失，估计值不写回数据库。所有比例只作调度近似，不声称已知变码率、索引位置或播放器缓冲。VRC 日志不参与媒体参数估算。

每个 GET 的预计结束时刻为“到达时刻 + 时长 × (1 − Range 起点 / 总大小)”。队列首项的开始时刻取当前所有有效 GET 的最早预计结束时刻，之后逐首累加前项时长；每首的块期限再加其字节起点对应的播放时间。没有 GET 记录时从队列首次到达时刻开始；最后一个 GET 传输退出时保留已算出的队列起点，不把传输结束当成播放结束，也不保留历史 GET 集合或延长下载需求租约。后续 GET 可重新建立起点，批量下载和 HEAD 不参与。未知歌曲占位按典型时长累加；相同顺序的重复快照可更新新到的清单/大小，但不会重置时间基准。队列 URL 解析补齐大小后立即细化对应块期限，过时解析不更新已移除成员。Debug 的 playback_timing 和 queue_playback_timing 记录估算输入及结果，便于联合 LA-041 对照真实开播。

按多路下载不会互相争抢带宽的假设，对已入窗或允许提前执行的普通候选，以及 Blocking 块，额度判断为 `need.Blocking || active < open`。Blocking 块立即启动，已经在途则继续共享；所有执行都计入 active，直到正文关闭和收尾完成才扣减。普通排队块按 ReadyBy 选择，Blocking 存在本身不禁止普通补位；例如 open=4、4 路普通加 2 路 Blocking 时 active=6，降到 4 仍等待，降到 3 才补入 1 路可启动普通块。无可启动积压时停止增长；在途请求自然完成。Blocking 出现、消失、身份变化或普通期限临近都不暂停在途任务。

删除原 200 ms 竞争让位、小尾部暂停保护与 500 ms 恢复冷却。只有需求撤销后该块已无有效需求、租约到期、任务/引擎关闭等生命周期事件才正常取消并清理；仍有其他独立需求则继续。取消后的分块前缀和检查点沿用已有恢复规则：仅块执行暂停时，新 GET 可以接入尚未退出的资源会话，在旧响应清理完成后恢复；整个会话已决定退出时，新 GET 等待清理后重新接入。顺序 200 无安全分段续传，执行上下文一旦取消就停止接入新 GET，即使协调器或执行器还在收尾；新 GET 等待旧会话清理完成后重新下载。

文件仍由资源层管理：完整块和部分前缀保存在受管临时文件，暂停元数据只在当前引擎内并受上述保留上限约束；恢复沿已验证终点、强 ETag 和原候选进度，不重访已失败通道。首次响应头尚未收到时的调度暂停也在当前资源会话内保留候选游标和已验证重定向地址，恢复使用新执行上下文；有效响应交给首块后释放会话中的这份引用。所有响应仍校验状态、Content-Range、长度及编码，弱/缺失 ETag 依赖最终 MD5。收到全部声明字节但未通过 EOF/超长检查的块不会提前发布。GET 的全部所需字节被响应写入层接受即完成，完整 200 和 206 均不等尾字节校验或发布。完整视频持久化仍独立校验，后续失败不追溯修改已完成的 GET；手动准备仍等待校验发布。完整分块文件收尾的大小与 MD5 校验和缓存命中验证共用 MaxLocalValidations 本地额度，校验通过后归还额度并发布；关闭等待执行/读者清理，异常残留由下次启动处理。

普通有限期限块始终按 ReadyBy 排序，堆首到达 ReadyBy − M 时进入启动窗口；M 改变只移动边界，不保存逐块预计启动时刻。ReadyBy < now 时 started 日志记 overdue，已删除基于 T 的 start_urgent。已经在途的块不参加启动窗口判断。无期限补齐仍使用独立普通索引，已入窗的有限期限候选优先，二者共享软上限和缓增。

M 默认 500 秒，设置「提前准备时间 M（秒）」接受 120～86400 的整数；配置字段 prepareAheadSeconds 经引擎 Config.PrepareAhead 传至调度器。0 使用默认值，较小非零值直接拒绝，不迁移旧配置。保存并重启应用后生效，不抬高软上限或跳过 250 ms 缓增。

动态 T 均值及衰减已删除。sample 事件仅报告成功完整标准块的实际准入至可读耗时，测速保留完成块数和最近实际 BlockTimeMS，不参与调度。连接、响应头、正文、成功重试及写入计入实际耗时，排队和可读后的清理不计入；尾块、部分续传及顺序 200 不作为标准块观测。

下一次控制唤醒仅取堆首未来入窗时刻、下一次允许增路、租约和孤儿回收等生命周期时刻；已入窗但额度已满的块等待完成/缓增事件，不把过去的入窗时间设为零延迟定时器。需求更新只调整相关索引堆；完成和来源变化都会重新判断，不周期性扫描/排序所有工作。每次已准入块执行（含重试）或顺序整文件回退、缓存校验及最终发布分别有有限超时；首次及块间窗口等待不消耗执行预算。响应头超时和传输错误处理保持独立；只有完成后才能感知变慢，固定 M 也不能保证大批同期限块都准时完成。

排队不分配分块缓冲，实际执行各自取得缓冲；复用池最多留 16 份，Blocking 超限执行按需额外分配、归还时不扩大复用池；无有效需求的块释放任务元数据。Debug 的 block_schedule 记录 active/open、block_time_ms、prepare_ahead_ms、放行时的过期状态、准入工作字节 work_bytes、采样和额度变化，不再输出 target/supply。block_demand 记录汇总来源/交接覆盖，block_demand_handoff 记录转换前的来源及原因。

API、清单、测速和空闲连接不属于这里的 16 路视频下载软上限。队列与批量任务的上层两个解析/下载调用者仍用于限制来源准备；资源一旦接入就按块竞争，不再占独立的视频网络席位。活动文件和仍被旧读者引用的文件不计入“暂停检查点”上限，该上限不是整个临时目录的磁盘配额。调度不提供总带宽整形或游戏帧时间保证。旧对照结果保留于历史开发文档，不能直接证明新策略的效果；本次自动验证和替代测试映射见[开发记录](block-scheduler-validation.md)，实机范围为 LA-040 并联动 LA-008/018/037/038/039。

## 2026-09-26 历史评估

以下保留当时的实现、建议和环境限制；“尚未实现 Range”“没有播放抢占”及 race 工具缺失不代表当前状态。

Auto 下的下载补齐、队列预缓存先查询 node=cf，失败后查询 node=nya；固定模式仅选择查询参数。资源来源以 API 的实际返回域名集合为准，不与 CF/HKG 名称绑定。同内容候选可用于失败回退，相同 URL 不重复尝试。通过快速存在性检查命中的 MD5 文件直接复用，缺失内容按 MD5 去重。已有共享下载继续当前传输，避免重复下载。

### 当时的并发与限制

| 层级 | 当前行为 | 扩大并发所需修改 |
| --- | --- | --- |
| 下载补齐 | `batch.go` 固定两个 worker | 将 worker 数连接到后台并发设置 |
| 队列预缓存 | `queue.go` 同时处理最多两首，只准备设定的预缓存范围 | 同步调整 active 上限和结果通道容量；保留队列顺序及失效取消 |
| 下载引擎 | `cache.go` 后台额度为 `max(1, min(2, MaxDownloads-1))`，默认总额度三份 | 显式配置后台额度并保证总额度至少多一份，不能仅提高 MaxDownloads |
| 同一资源 | 共用下载、校验和发布，多个请求不重复占用名额 | 保留共享任务的额度归属 |
| 取消任务 | 取消等待者；已开始的共享下载继续占后台额度 | 不能在调用者取消时提前归还额度 |

两首后台下载和一个冷缓存播放可以同时占用三个名额。预留的是任务名额，不是带宽；当前没有带宽限速或播放抢占。队列预缓存和下载补齐互斥，但只读扫描可同时运行，扫描仍会竞争网络请求和磁盘校验资源。

### 当时的可行方向

优先考虑可配置的跨歌曲并发：保留默认两首，先在下载补齐试验三至四首，同时保留一个播放名额。队列预缓存范围已可设为 1～100 个位置（默认 3），并发数仍为两首。扩大并发需要覆盖调度器和引擎，而不是只修改 HTTP 连接池。

单视频 Range 分段并发需要额外设计：检测真实 Range 支持、验证每段 Content-Range 与长度、约束分段总连接数、协调失败及取消、合并后全文件 MD5 校验。现有 spool 按连续写入字节数向播放器开放数据，不能直接改为乱序写入；需先跟踪连续可读区间。两线路元数据不一致时不能拼接内容。其复杂度明显高于跨歌曲并发，本次未实现。
