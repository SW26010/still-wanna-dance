# 待验证清单

当前功能范围见[范围说明](scope.md)。本清单区分当前 StepStash 构建的验收缺口和原版 d309146c 的黑盒调查；原版待测不表示 StepStash 尚未实现相应功能。

## 当前构建需补的验收

- [ ] 使用当前构建完成 CF/HKG 冷缓存、热缓存、Auto 选路及完整视频校验的联合游戏验收。
- [ ] 在 HTTP 播放 API 接入后验证实际播放器解析、播放、切歌、恢复进度及多人中途加入。
- [ ] 验证播放地址解析失败时的本地降级体验，并确认后续下载失败不会误报为成功播放。
- [ ] 复核在线队列、容量淘汰后重新入队、下载补齐及实际保留数量。
- [ ] 在交互式 Windows 桌面复核便携包、托盘、重复启动、退出/重启及 hosts 提权接入与移除。
- [ ] 补充长时间运行、磁盘满、只读目录和异常断电的实机验证。
- [ ] 完成核心请求内容和必要响应字段的逐项原版对照，记录有意保留的协议差异。

自动化已覆盖 Range/HEAD、校验、并发、客户端中断、重启后的缓存复用、版本隔离和容量策略；具体覆盖与运行命令见[服务手册](service.md#验证范围)和[开发环境](development.md)。上述待验收项目不否定已有自动化结果，也不能仅凭自动化勾选为实机通过。

## 历史实机结果

2026-09-25 的[早期服务验收](acceptance.md)验证了 CF/HKG 完整冷下载、原版旧库复用与回读、游戏切歌及公开房非 owner 中途加入。随后 [c69e844 联合验收](release-acceptance-20260925.md)覆盖了队列、统计、容量、托盘及 hosts 操作。这些是指定构建和样本的结果；当前统一存储不再提供旧库兼容，历史通过项不作为当前版本的兼容承诺。

## 原版黑盒调查遗留问题

以下编号沿用原调查清单，均针对原版，详见[原版测试结果](test-results.md)。若继续调查，应先验证隔离上游和故障注入确实生效。

| 编号 | 待明确的问题 | 已有证据与缺口 |
| --- | --- | --- |
| Q01 | e/s 与元数据是否严格校验 | 需补错误校验和、长度、截断及缺失元数据的矩阵 |
| Q02 | 同 ID 内容更新如何失效 | 已见 CF/HKG 样本共享文件，完整跨版本矩阵未确认 |
| Q03 | 同曲并发如何协调 | 需确认完整请求、不同 Range 与客户端中断时的回源和发布规则 |
| Q04 | 下载或进程中断如何恢复 | 需区分续传、重下和残留清理 |
| Q05 | 上游错误如何传播 | 需补错误码、截断、超长和校验不符的可控故障测试 |
