# LIVE-20261113-09 手动刷新状态对照与加载窗口复现

公开事件时间均以本批次 T=0 归一化；负值表示基准之前，换算不提高原日志的时间精度，绝对时刻映射仅留本地。

## 结论

本批次连续采集三个目标样本，用户均为好友控制房间的非 owner、无预览。没有改变产品或 WD 实现。

1. **10182 刚卡顿、尚未黑屏时刷新**：按钮与重载回调同秒发生，新请求从零转到当前进度；旧请求未立即结束，与新请求重叠。恢复带宽后用户确认追上好友。
2. **9898 黑屏但 WD 已再次起播时刷新**：也立即触发重载，未复现点击无回调；其状态不是最早样本的加载窗口，不能据此说最早一次是偶发。
3. **11577 自动重试加载中、尚未再次起播时刷新**：只有按钮日志，没有重载回调；下一次重试仍延续约 30 秒周期。复现了 [LIVE-20261113-07](live-acceptance-20261113-07.md) 的关键外部现象。

现在可记为“在观察到的自动重试加载窗口内可复现”，不是“仅一次偶发现象”。这不证明内部是哪条状态判断，也不证明所有加载中的刷新都必然被忽略。恢复供数后用户确认三个目标样本均正常并跟上进度；不证明逐帧同步。owner 回零失败仍按 [LIVE-20261113-05](live-acceptance-20261113-05.md) 保留。

### 10182：刚卡顿刷新

- GET 5 为 `bytes=33546240-40981543`，交付 1,056,768 字节后在 T+108.972 秒记录 `206 / expired`。
- GET 6 在 T+187.811 秒请求 `bytes=34603008-40981543`。用户确认刚卡顿、尚未黑屏；T+193 秒按钮与 `OnUSharpVideoReload` 同秒。

### 9898：黑屏，但自动重试已再次起播

- GET 27 的 206 只交付 8 KiB 后过期；GET 28 为 `bytes=38961152-130223213`，30 秒后 `504 / expired`。随后 WD 报错、自动重试。

- 原 GET 31 与新 GET 34 在 T+875.338 秒均为 `504 / failed`，不是自身 `expired`；两种结果分开保留，不混算 need-by 截止。恢复带宽后，GET 37 从 `bytes=51625984-130223213` 完成交付，用户确认追上。
- 这一段证明“黑屏外观”不足以确定加载状态，没有证明最早点击无回调是偶发。
