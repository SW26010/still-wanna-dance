## 已打开页面时的故障导航修复

- 修复前，`TestFaultOpeningKeepsConnectedWebUI` 在真实 `/api/lifecycle` 连接存续期间发布故障，稳定捕获首页打开调用，失败为 `fault reopened the home page while WebUI was connected`。原因是故障消费入口直接打开根 URL，没有检查已有页面；前端路由未主动跳转。
- 正常 Console 和启动失败受限界面均复用现有生命周期连接判断是否已有页面，不增加在线状态或轮询；连接期间消费自动打开请求，关闭最后一个页面后新故障仍可打开。托盘和已有实例的显式激活继续使用原入口。
- 定向回归覆盖连接期间不打开、关页后新故障可打开，以及关闭中断时保留故障、无法打开时的兜底和生命周期／管理错误处理。
- `SWD_FAULT_NAVIGATION_BROWSER_EVIDENCE` 启用的 `TestFaultOpeningNavigationBrowser` 连接真实 Console 与 Edge，占用原子写入槽制造实际设置保存失败，确认设置页、日志级别草稿、保存重试及原错误反馈保留；另开说明页面后触发另一管理接口错误，两页地址和原草稿仍保留，浏览器打开器调用为零。测试使用替身记录打开调用，不接管日常浏览器。截图和结果位于忽略目录 `artifacts/fault-navigation-20261104/`。
- 首轮浏览器检查错误地按 `alert` 角色寻找现有错误条，因组件实际使用 `group` 而失败；改为在设置面板内匹配真实失败响应的文案后通过。此失败属于测试定位，与产品导航修复无关，未改变组件或错误文案。
- 最终故障中心、桌面和程序入口 Go 整包测试通过，Console 的生命周期、受限界面、管理错误及设置校验定向回归通过；受影响包的 `go vet`、脚本语法及差异检查通过，纯 Go Windows EXE 构建成功。测试仍未启动游戏或修改 hosts；没有重新验证默认浏览器的窗口复用策略。

## 触发语义收敛

本节替代前序实现将大部分管理失败响应直接视为故障的规则；现行策略仍以[配置生命周期](../settings-lifecycle.md)为准。保留已有响应状态、文案、配置及重试周期，只整理通知准入和故障来源。

- 修复前的三项回归均先观察到失败：无效曲库查询请求打开界面；成功取消连通性检测清除了测速操作的故障；零预算和预算不足触发批量任务故障。原始失败分别为 `invalid query requested the WebUI`、`connectivity cancellation cleared a calibration fault` 和 `successful or budget-limited batch requested the WebUI`。
- 管理读取及独立处理函数按显式保留的原始错误上报，不从响应码或正文判断严重程度；操作错误继续由共用分发入口记录。共用 `requestRejection` 标记覆盖输入／字段校验、忙碌、过期状态及确认要求，与取消统一判定为既非新增故障、也非恢复；合并错误仍含运行故障时不抑制。响应正文只保留原有展示与脱敏用途。
- 操作来源由分发处明确指定，测速、连通性检测、SOCKS5 及取消分别记录；成功重试只清除对应来源。设置、加速及导入仍沿用各自既有业务来源与界面错误展示，异步任务故障仍由最终结果清除。
- 批量预算停止保留原任务结果，不触发通知、不清除旧任务故障；实际任务失败及记录写入失败继续通知。真实文件故障注入覆盖预算停止同时无法保存任务记录的情况。
- `ServeHTTP` 回归覆盖 15 类无效输入及设置拒绝，另覆盖加速忙碌、预期拒绝与取消合并、预期拒绝与真实故障合并。数据库读取故障即使沿用 HTTP 400 也继续通知；无效查询不清除旧故障；VRCX 的脱敏响应和原错误链回归保留。
- Console、程序入口、故障中心与桌面整包测试通过，Console 本轮耗时约 173 秒。真实 Console + Edge 再次验证设置写入故障及日志目录读取故障，确认两页地址、草稿及错误反馈保留，打开器调用为零、页面异常为零。证据及 Go 回归输出在忽略目录 `artifacts/fault-navigation-20261104/refined/`；打开器仍为测试替身，不代表默认浏览器窗口复用策略已验证。
- 最终保留导入原有业务来源后，补跑导入、VRCX、操作恢复、预算及拒绝分类回归通过（约 19 秒）；受影响包 `go vet`、脚本语法和差异检查通过，最终纯 Go Windows EXE 构建成功。未新增后台轮询或可配置阈值，未启动游戏、修改 hosts、提交或推送。

### 导入结束通知的分类丢失修复

- 后续复核发现：`runImport` 的空资源拒绝在 `launchImport` 结束时经 `status.Error` → `errors.New` 丢失分类，之前直接调用 worker 的用例未覆盖这段异步收尾。真实 `startImport` → 完成通知回归在修复前失败为 `empty catalog rejection requested the WebUI`；同一转换也丢失真实文件错误的原因链，缺失来源目录的回归无法再通过 `errors.Is(..., os.ErrNotExist)`。
- 收尾通知优先传递 worker 原始错误；仅在 worker 未返回错误、但逐文件结果仍有失败时，沿用原状态文案生成通知。界面结果、源文件和恢复方式不变。
- 新回归覆盖空资源时不通知、不清除旧导入故障，以及真实文件故障继续通知并保留原因；清理回归补验逐文件失败仍通知、成功重试后清除故障。
- 导入全组及相关拒绝分类／管理故障定向测试通过（约 15 秒），Console `go vet`、差异检查和更新后的 Windows EXE 构建通过；结果位于 `artifacts/fault-navigation-20261104/refined/import-classification-regression.log`。复用前序界面验证，本次没有前端变更。
