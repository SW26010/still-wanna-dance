# Udon 上游故障窗口与 Wi-Fi 绑定采样

2026-10-29 晚。在故障持续期间采集默认路由和指定 Wi-Fi 的独立样本，并对照真实产品组件的协议回退。**指定 Wi-Fi 下仍存在明显的 HTTPS 连接及握手失败；HTTP 双栈可以交付合法资源。** 同时捕捉到 HTTPS 短暂恢复和收到 206 后正文超时，不能把整个窗口解释为 HTTPS 恒定不可用。

本轮只新增观测记录和脱敏证据，没有修改产品源码、日常 EXE、配置或 hosts，也没有启动游戏。采样期间工作区另有回退顺序修改，本轮将其冻结成独立探针进行一次实网对照，不代表该修改已完成全部回归或部署。现行契约仍以[上游通道](../upstream-channels.md)为准。

## 网卡绑定与采样范围

核实 Wi-Fi 已连接后，再将 Node 请求的源地址、DNS 查询及 Go 产品组件的 DoH 和目标 TCP 连接一起绑定到该接口。Node 记录并核对实际 socket 本地地址；`Find-NetRoute` 使用绑定源地址查询后返回 Wi-Fi。Wi-Fi 和原默认接口的 `WeakHostSend` 均关闭。没有修改系统默认路由。

初次绑定误选了 Wi-Fi 的 ULA IPv6 地址。该批 IPv6 超时不能证明公网 IPv6 不通，混合地址族的产品对照也不能用于后续结论。原始失败单独保留，主统计排除整个初始绑定批次。修正后使用 Wi-Fi 的公网 IPv6，HTTP 双栈均成功；此前关于 Wi-Fi IPv6 HTTP 不通的临时判断撤回。

以下时间以初始窗口的共同零点记为 T+秒，与摘要及附件轨迹一致，可核对批次重叠；不公开绝对起点。

| 批次 | 相对时间 | 用途 |
| --- | --- | --- |
| 默认路由独立采样 | T+0.000–320.252 秒 | 原网络条件的基线，最多两并发 |
| 默认路由产品组件 | T+93.213–347.950 秒 | 三轮完整曲库与播放、资源路径 |
| 修正后的 Wi-Fi 独立采样 | T+512.756–692.774 秒 | 新连接，轮换三个 IPv4 和三个 IPv6；每个资源片段 256 KiB |
| 修正后的 Wi-Fi 旧策略组件 | T+524.889–790.099 秒 | 三轮，保留普通连接复用、候选池和 30 秒操作期限 |
| Wi-Fi 候选修改快照 | T+631.590–702.904 秒 | 一轮，同网卡、同样的组件探针 |

默认路由的控制域名曾由系统 DNS 返回 `198.18.0.0/15` 内的合成地址；这不能当作指定 Wi-Fi 的公网直连控制。Wi-Fi 修正批次的控制域名返回正常公开地址。两条路径的统计分开保存。

## 指定 Wi-Fi 的独立请求

主统计来自 [wifi-matrix.jsonl](../evidence/wifi-ip-selection-20261029/README.md)。每个请求正常校验证书，最长 12 秒；最后一轮还受三分钟总截止限制。播放地址必须返回 302，资源必须返回正确 Content-Range、完整 262,144 bytes，且读取没有错误。没有保存响应正文或签名资源 URL。

| 请求 | IPv4 完整成功 | IPv6 完整成功 | 结果 |
| --- | ---: | ---: | --- |
| Udon 播放 API HTTPS | 0/4 | 0/4 | 5 次 TCP 建连阶段超时、3 次 TLS 阶段超时 |
| Udon 播放 API HTTP | 4/4 | 4/4 | 0.584–1.803 秒，合法 302 |
| Udon 视频 HTTPS | 0/3 | 0/3 | 4 次 TCP 建连阶段超时、2 次 TLS 阶段超时 |
| Udon 视频 HTTP | 3/3 | 3/3 | 1.849–3.437 秒，合法 206；六段正文 SHA256 相同 |
| Cloudflare 控制请求 HTTPS | 1/1 | 0/1 | IPv4 3.161 秒完成；IPv6 TLS 阶段超时 |

这组新连接样本中，Udon HTTPS 为 0/14，HTTP 为 14/14。没有出现可据以判断限流的 429，也没有上游 5xx；HTTPS 失败发生在取得业务状态之前。控制请求说明 IPv4 HTTPS 并非全部不可用，但不足以定位到本地出口、中间网络、Cloudflare 或源站中的哪一段。256 KiB 请求耗时不是链路总带宽测量。

## 产品组件与完整正文

探针复用 `upstreamnet.Resolver`、`upstreamrequest.Pool`、`upstreamrequest.Fetch` 和 `playbacksource.Resolver`。曲库完整读取并校验歌曲 ID；资源是共享 Fetch 的 256 KiB Range 读取，不代表完整下载调度器或游戏播放验收。各批次最多一个产品操作在执行；独立小片段探针和候选快照存在时间重叠，因此不能把耗时差直接当作严格性能收益。

所有完整曲库响应均为 2,885,371 bytes、10,470 首、版本 `20261028232411`，SHA256 为 `f7253636e98bc181ae7e6e357c810bebd1ece0b251f152b379ad568e92399454`。

| 条件 | 旧策略曲库路径 | 显式 HTTP 曲库对照 |
| --- | --- | --- |
| 默认路由三轮 | 0/3；三次均在 30 秒截止 | 3/3；11.654、14.091、4.817 秒 |
| 指定 Wi-Fi 三轮 | 1/3；失败 20.836 秒、HTTPS 成功 23.978 秒、失败 30 秒 | 3/3；19.109、15.579、21.370 秒 |

Wi-Fi 第三轮给出了明确的时间分配证据：五次 HTTPS 失败后，HTTP 返回 200 并交付了 813,599 bytes，但只剩约五秒，最终被总期限截断。随后同一曲库的显式 HTTP 对照完整成功。这个样本证明“HTTP 已能交付，但回退太晚导致完整读取失败”确实出现在实网，不需要凭收到 200 就假定操作成功。

Wi-Fi 第一轮另有 `channel is not ready`，不能把它计作服务器状态错误。默认路由第一轮资源探针取得空候选且没有发出请求，也单独保留，不计作资源请求失败。候选就绪和 DNS 生命周期的具体根因，本轮没有定位。

## 捕捉到的恢复与正文失败

[旧策略 Wi-Fi 时间线](../evidence/wifi-ip-selection-20261029/README.md)保留以下互相限制的观察：

- T+634 秒，曲库 HTTPS 在约 1.269 秒收到响应头，并于 T+657 秒完整读完；随后复用该 HTTPS 连接的播放地址请求只用 0.448 秒成功。
- T+668 秒，另一资源 HTTPS 请求返回 206，但到单次十秒期限只读到 123,146 bytes，发生正文超时；最终由 HTTP 完整交付 256 KiB。
- 其余两轮播放地址需先经过多个 HTTPS 失败，最终 HTTP 成功，总耗时分别为 25.414、25.401 秒；资源路径总耗时约 27–29 秒。

Node 的新连接样本和 Go 的连接复用、不同客户端栈分别统计。Go 的短暂成功不抹掉同时段其他候选的失败，Node 的 0/14 也不能外推为整个窗口所有 HTTPS 均失败。

## 当前修改快照的一轮对照

T+613.197 秒将采样期间出现的 `attempts.go` 修改复制到独立文件，通过 Go overlay 冻结。文件 SHA256 为 `049f8d5461d30714315d365e4309d4f263e272677adfbab2a59905fac9e9040a`。旧探针均在该快照之前编译，仍保留五次 HTTPS 后才作 HTTP 回退的游标行为；候选快照改为当前路径 HTTPS 传输失败后立即尝试该路径 HTTP。两者都保留共同候选上限和证书校验。

[候选时间线](../evidence/wifi-ip-selection-20261029/README.md)显示：

| 操作 | 候选快照结果 |
| --- | --- |
| 完整曲库 | 第一次 HTTPS 约 4.957 秒失败，随即 HTTP；25.912 秒内完整成功 |
| 显式 HTTP 曲库对照 | 28.571 秒完整成功，说明这段正文吞吐本身也较慢 |
| 播放地址 | HTTPS 失败后 HTTP 成功，总耗时 5.593 秒 |
| 256 KiB 资源 | HTTP 回退完整成功，总耗时 11.236 秒 |

这证明候选顺序确实执行，并在该坏网样本下成功完成业务读取。只有一轮且与旧探针部分重叠，不证明稳定提速比例或长期成功率。旧策略在 HTTPS 短暂恢复时也有 0.448 秒成功，不能省略这个对照。

## 证据与复跑

[汇总](../evidence/upstream-window-20261029/summary.json)含分组统计及操作结果，[清单](../evidence/upstream-window-20261029/manifest.json)包含脱敏文件和实际探针构建的 SHA256。失败、初始 ULA 选错、主动停止和修正后批次分别保留。私有原始资料单独保留；完整脱敏轨迹和源码快照见[附件说明](../evidence/wifi-ip-selection-20261029/README.md)，不包含私人源地址、资源 URL 或二进制。

复跑时先重新读取网卡当前地址和 DNS，IPv6 必须选公网地址，不能直接沿用旧绑定配置；核对源地址路由和实际 socket 地址。原始脚本 `window-sampler.mjs` 记录分阶段时间，`product-window.go` 记录真实组件的每次尝试及正文进度；`summarize.mjs` 生成脱敏证据并校验本机地址和签名参数未泄露。默认路由与 Wi-Fi、旧构建与候选快照始终分开统计。故障窗口恢复后，本报告保留的失败时序可用于构造受控回归，不以此要求重新启动游戏。
