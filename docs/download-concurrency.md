# 下载并发与播放优先

本页是当前运行规则与参数。核心创新、分层理由、期限公式和完整算例见[以期望完成时间驱动的全局块调度](block-scheduler-design.md)；实现过程和自动结果见[开发记录](validation/block-scheduler-validation.md)。

现行架构规则、接口及验证边界统一见 canonical 文档[下载需求与资源管理设计](download-resource-design.md)。固定 M、完整块复用及停止后建立新任务已实现，不保留暂停／恢复。下载延续截止 `need-by + 30 秒` 已由调度器执行，来源集合只结束范围和自身时钟已过期的 GET，原子承接未来未交付范围；协调器保留其余合法执行，同块旧清理完成后才可重新准入。

2026-11-13 的时钟分离、GET 截止职责及统一交接已落实，设计来源为 `d4152f81`，现行规则与验证入口统一维护在 canonical 文档。

## 当前实现（全局块调度）

需求层将 GET 请求区间、队首、普通队列和补齐转换成独立的块需求，先按来源过滤、再汇总每块属性；本地读取等待直接登记到调度器，由调度器独立维护 Blocking；调度器只认识内容块、完成期限、有效租约和实际读取阻塞。旧 P0～P4、每视频固定 worker 和固定三块读取窗口已移除。

使用需求、本地保护、固定窗口、下载截止及块存储已接入；跨模块规则以 canonical 文档为准。

| 约束 | 当前行为 |
| --- | --- |
| 内容及执行 | 默认 1 MiB，块大小在引擎创建时固定；引擎 `Config.BlockSize` 可传入其他尺寸，用户设置尚未开放。MD5、大小与块号在该引擎内共同标识，资源会话保证实体/选路一致性；同块只执行一次 |
| 全局并发 | 默认 16 路软上限，设置范围 1～64：普通需求受当前开放额度及软上限约束，Blocking 缺块立即执行，可突破所设上限；首请求、重试和重定向统一由块调度管理，底层 HTTP 只跟踪生命周期 |
| 启动节奏 | 默认每 250 ms 最多新增一路，设置范围 0～2000 ms。正间隔时普通额度从 1 路开始，有可启动积压且额度已满才增长；无积压停止增路，active 归零且无可启动工作时收缩至 1。0 关闭缓增，按需直接使用软上限额度。已有额度立即复用；Blocking 不等窗口、缓增或额度；所有执行计入 active 直到收尾结束 |
| 启动窗口 | 普通有限期限块在 ReadyBy ≤ now + M 时可启动，再检查 active < open；M 默认 500 秒，建议 200～2000 秒，设置范围 100～16000 秒。实际耗时观测不参与准入或排序 |
| 块保留 | 完整块由引擎持有，可跨会话复用；不保存半块前缀，不设检查点数量/字节上限。发布或失效时释放注册表引用，旧读取引用释放后删除；退出清理全部块，不跨运行恢复。仅在「不保留」时，失去保护后逐块回收；「限制为」（包括已用满）和「不限制」时保留运行期块 |
| 使用需求容量 | 按资源与块号去重，最多 4096 块；非 GET 新增唯一块后的总数不超过 2867，共享及不扩张更新不受此门槛阻挡。完整 GET 范围无法准入时返回 503。已下载但仍被需要的块继续计数；消费、来源结束及固定交接到期释放，队列准备完成不释放；正式视频 HIT、成功发布或 Range 返回 TEMP 后仍由资源使用协调在回收、重新入窗时按当前需求补回缺块 |
| 需求展开 | GET 声明与请求区间相交的全部使用块，队列和独立补齐可覆盖整文件；协调器只为其中缺失块派生下载任务，不设每视频候选数或并发上限。冷 Range 从请求涉及的块开始，所有缺块直接参与全局调度，不等待首响应头；实际 Read 等待另行贡献 Blocking，不附带固定预读窗口；未接入的库资源不展开 |
| 元数据 | 无独立资源会话数量门槛；调度器最多 4,096 个已注册下载块；核心最多 32,768 份需求，产品按块提交一份摘要；来源共享不另按每块 128 份贡献拒绝，使用容量按唯一块统计。MaxLocalValidations 只限制整文件合并、校验与发布，普通打开和属性检查不占名额，不决定视频网络席位 |
| 交接 | 客户端关闭 GET 或队首消失后 E+2 秒；GET 因块截止退出承接未交付且原 N>E 的范围至 E+15 秒；普通队列删除直接撤销。交接不接触 Blocking；读取等待在本地 Read 结束/取消时独立撤销。保留原 ReadyBy，关闭普通启动资格；合法在途 Run 继续，不能仅凭交接启动或重建执行，协调器处理延迟和无关事件都不延长交接 |

“可启动积压”包括已进入启动窗口的有限期限任务，以及具有有效独立补齐需求、允许提前执行的任务；这里的“可启动”指满足窗口或提前准入条件，仍可能等待普通额度。两类积压都能驱动缓增，不能仅因没有已入窗任务就停止增路。

Blocking 只在 Read 确实等待缺失内容时成立，GET 到达或刚结束的读取都不自动取得此标记。多读者独立撤销，不同 Blocking 块均立即放行；有限期限相同的非阻塞候选按不透明 Owner 公平分配；已入窗有限候选按最早 ReadyBy 优先，无期限／提前执行候选按来源顺序集中准备。每份需求保留自身租约，过期或关闭句柄不能被迟到更新复活。来源仍有效才续 30 秒租约，资源协调器每 10 秒确认存活；交接租约不续期。 核心任务失去最后有效普通需求及读取等待时立即进入结束状态，拒绝新需求和迟到更新；响应与写入清理完成后通知协调器并释放任务容量，不保留 30 秒重接期。Schedule 原子登记任务及普通需求，或接入此前登记的读取等待；新需求等待旧任务释放后按当前摘要建立新任务，不复活旧句柄。

所有闭准入贡献统一保留自己的使用及租约，不改变独立开放来源的下载时钟，无需 GET 覆盖特判。需求集合过滤后取最早有限 ReadyBy；调度器独立维护实际等待的 Blocking 和最早 WaitSince，不改写来源 ReadyBy，也不从等待时刻制造有限截止；Opportunistic 独立保留有效无期限来源的普通提前准入能力，不能因同块有限期限而消失，也不绕过额度/缓增。任何有效使用来源都能维持其使用引用；下载执行仍受有限 need-by 的截止约束。管理层按每份租约最早到期时间重新汇总，交给核心的最晚 LeaseUntil 仅是最终存活上限，不能代替各来源独立到期。

正常交付完成、其他服务端失败、读取推进/Seek、块完成和引擎关闭不生成交接。客户端关闭承接全部未交付范围，队首退出承接仍持有范围，两者不筛 N>E；截止退出 GET 才筛 N>E。队列连续成员保持来源身份，重排原地更新；删除、重置不复活旧身份。退出 E 和原时钟在创建时冻结，重复通知、处理延迟和新 GET 都不延长有效期。交接持有完整选中使用范围（含本地可读块）并继续计入现有唯一块容量，下载完成后不占 active；运行时仅保留范围、原时钟及固定到期。来源和原因只写转换日志，交接不再产生交接。

GET 按请求刚到达的时刻和 Range 起始字节估算播放位置：总大小优先读 media.byte_size，直接资源 URL 尚未入库时使用已验证的同源 s；时长取同 MD5 的歌曲清单 end（秒），不减 start。资源直链没有歌曲 ID 时，取关联清单中最早的有效 end。只有与 GET 请求区间相交的块才取得该 GET 的播放期限，块期限为到达时刻加上“块起点减 Range 起点”对应的播放时间；起点位于块内时，该相交块取到达时刻，之前的整块不创建 GET 需求。后续读取和下载进度不移动这个时间基准。有限 Range 的结束字节限制需求范围，但不表示整部媒体播放结束，队列预计开播时间仍按剩余媒体时长计算。

HTTP 与下载协调器共用一个 GET 来源，按实际响应接受的字节逐块撤销已消费部分；Reader/Seek 不推进交付，短写明确失败，来源身份及原播放时钟持续到请求结束。请求区间按块向外对齐，下载一个相交块的完整内容以保持原有校验和共享；不会因此激活相邻的整块。区间完成后仍有 GET 读者时，会话按本地保护与回收规则保留已下载数据供响应消费，不以“没有缺块任务”取消读者，也不自动生成整文件补齐需求。独立队列/批量来源仍可补齐其他块，只有全文件完成并通过校验才发布正式视频。上游默认支持 Range；忽略 Range 返回 200 时关闭响应、记录警告并进行已有的有界候选切换，不再顺序整文件回退，见 [canonical 边界](download-resource-design.md#7-不保留块下载暂停与恢复)。

单 Range 支持明确起点、开放末尾及后缀形式；无效/多 Range 和 HEAD 不形成播放时钟。If-Range 的 ETag 或日期不匹配而回退整文件时，估算起点为 0；日期条件复用响应使用的已验证本地文件句柄，与 ServeContent 的时间比较一致。冷流没有修改时间，日期条件按整文件估算。

大小和时长都有时按需计算整文件平均总码率；只缺一项用 2 Mbps 推导，二者都缺时用 45 MiB、210 秒（派生码率约 1.8 Mbps）。无效/非正时长视为缺失，估计值不写回数据库。所有比例只作调度近似，不声称已知变码率、索引位置或播放器缓冲。VRC 日志不参与媒体参数估算。

每个 GET 的预计结束时刻为“到达时刻 + 时长 × (1 − Range 起点 / 总大小)”。队列首项的开始时刻取当前所有有效 GET 的最早预计结束时刻，之后逐首累加前项时长；每首的块期限再加其字节起点对应的播放时间。没有有效 GET 时按 [canonical 队列预计使用时间](download-resource-design.md#队列预计使用时间) 保留未来估算，将已落后的起点推进到当前时间；来源层复用使用需求计时器按 10 秒节奏维护有限期限并通知下载与本地保护，不依赖新快照或下载执行。滚动阶段按块距队首的相对时间分别判断下载、保护资格，等待任务及已完成资源不会在刷新间隙自动入窗或重取。最后一个 GET 传输退出不等于播放结束，后续 GET 可重新建立起点，批量下载和 HEAD 不参与。未知歌曲占位按典型时长累加；相同顺序的重复快照可更新新到的清单/大小，本身不重置时间基准。队列 URL 解析补齐大小后立即细化对应块期限，过时解析不更新已移除成员。Debug 的 playback_timing 和 queue_playback_timing 记录估算输入及结果，便于联合 LA-041 对照真实开播。

按多路下载不会互相争抢带宽的假设，对已入窗或允许提前执行的普通候选，以及 Blocking 块，额度判断为 `need.Blocking || active < open`。Blocking 块立即启动，已经在途则继续共享；所有执行都计入 active，直到正文关闭和收尾完成才扣减。普通排队块先选择已入窗有限期限候选，再选择无期限／提前执行候选，Blocking 存在本身不禁止普通补位；例如 open=4、4 路普通加 2 路 Blocking 时 active=6，降到 4 仍等待，降到 3 才补入 1 路可启动普通块。无可启动积压时停止增长；在途请求自然完成。Blocking 出现、消失、身份变化或普通期限临近都不暂停在途任务。

删除原 200 ms 竞争让位、小尾部暂停保护与 500 ms 恢复冷却。只有需求撤销后该块已无有效需求、租约到期、任务/引擎关闭等生命周期事件才正常取消并清理；仍有其他独立需求则继续。取消后仅保留本地完整块，未完成块从起点重新下载。已移除暂停任务、恢复结果及首次响应头前的游标，每次新执行重新选择候选；有限 need-by+30 秒到期也立即结束旧任务，Blocking 或其他来源不能保留过期执行，清理完成后才释放额度。块截止反馈只使剩余范围包含该块且自身 N+30 秒已到的 GET 明确失败，其来源以 download_deadline 原因撤销；需求管理原子承接原 N>E 的未来未交付范围至 E+15 秒。协调器移除过期块执行并重算，其他合法在途块保持同一执行，共享本身不构成 GET 失败条件。自身也错过截止的队列准备撤销整视频使用范围；同成员重复快照/重试不能重新注册，队列预计开始时刻或媒体时间估算改变后才可再次准备。较晚队列和无期限手动需求保留，清理后重新整合并执行统一窗口与容量判断。已过期交接仍保持原使用/保护期限，但不再贡献下载时刻。新 GET 可以共享现有合法执行；只有整个资源确已决定退出时才等待会话清理。

本地资源注册表独立持有完整块及实体信息，新会话使用调用方当前地址；Range 重试复用块文件，执行中半块只在复用缓冲中存在。Range 在正文长度、EOF、Content-Range、编码及强 ETag 检查通过后提交。每块普通写入并关闭后才可读，不强制 Sync；GET 跨块读取使用独立偏移和短期文件引用。全部所需字节交付即完成，不等整视频校验或发布。完整块收齐后先按持久化保留集合准入，再取得固定快照、按顺序合并并计算 MD5，校验通过再 Sync、关闭和重命名；整个合并发布占用一个 MaxLocalValidations 槽位。旧读者仍可读取原块文件，最后引用释放后删除；下次启动只清理异常残留，不恢复资源。准入与回收复用资源评分及全部同分规则，并发候选按完整大小预留、同资源由共享会话只计一次；较高分候选可取消较低分预留，发布前再核对保护和保留集合，发布后转正式库存，放弃释放。资源（含收藏）预算为零、视频超预算或优先级不足时不合并/校验/发布（收藏优先与全部屏蔽规则见 canonical 第 8 项）；GET 仍可读取完整块，队列返回 TEMP 表示临时可读，手动补齐返回未取得保留资格并按预算停止，不触发换源。激进回收开启时，临时块失去保护后逐块回收，必要块 I/O 引用释放后删除；固定仅在「不保留」时开启。合并快照前已正常回收的缺块返回未保留，不触发存储故障。

普通有限期限块始终按 ReadyBy 排序，堆首到达 ReadyBy − M 时进入启动窗口；M 改变只移动边界，不保存逐块预计启动时刻。ReadyBy < now 时 started 日志记 overdue，已删除基于 T 的 start_urgent。已经在途的块不参加启动窗口判断。无期限补齐仍使用独立普通索引，按 OpportunisticOrder 升序选择，同一正号按任务登记次序选择；0 保留给未编号调用，在该索引中排在正号之前并保持原排序。顺序只聚合有效且开放的提前执行来源，独立于同块有限期限。编号分配、重试及重启边界以 [canonical 手动下载规则](download-resource-design.md#无明确期限的手动下载) 为准。已入窗的有限期限候选优先，二者共享软上限和缓增。

M 默认 500 秒，建议 200～2000 秒；设置「提前准备时间 M（秒）」接受 100～16000 的整数，建议上限不限制输入；配置字段 prepareAheadSeconds 经引擎 Config.PrepareAhead 传至调度器。0 使用默认值，范围外的非零值直接拒绝，不迁移旧配置。保存并重启应用后生效，不改变所设软上限或增长间隔。

设置页「高级下载设置」提供「下载并发上限（软）」`downloadConcurrencySoftLimit`（整数 1～64，默认 16）及「并发增长间隔（毫秒）」`downloadGrowIntervalMS`（整数 0～2000，默认 250）。配置缺失或 null 使用默认值，明确的 0 ms 保留为关闭缓增；越界或非整数拒绝保存。两项经引擎 Config.DownloadConcurrencySoftLimit / DownloadGrowInterval 传入同一个调度器，保存只更新已保存快照，重启应用后生效。为减小 CPU 占用，强烈不建议增加并发数或减小增长间隔；建议保留默认值。并发上限不是带宽限速，也不保证游戏帧时间。

动态 T 均值及衰减已删除。sample 事件仅报告成功完整标准块的实际准入至可读耗时，测速保留完成块数和最近实际 BlockTimeMS，不参与调度。连接、响应头、正文、成功重试及写入计入实际耗时，排队和可读后的清理不计入；尾块不作为标准块观测。

下一次控制唤醒仅取堆首未来入窗时刻、下一次允许增路、下载截止和租约等生命周期时刻；已入窗但额度已满的块等待完成/缓增事件，不把过去的入窗时间设为零延迟定时器。需求更新只调整相关索引堆；完成和来源变化都会重新判断，不周期性扫描/排序所有工作。每次实际 HTTP 尝试的总时限为 DownloadTimeout（默认 10 分钟），候选回退重新计时，正文不按候选数平分，也不让所有重试共用一轮执行超时；响应头等待另为剩余候选保留父级／任务期限，收到响应头即停止该预算，见 [canonical 超时规则](download-resource-design.md#单次尝试超时与下载延续截止)。本地视频校验及最终发布各自保留独立超时。首次及块间窗口等待不消耗尝试预算，父级取消和更早的任务截止仍可结束所有尝试。响应头超时和传输错误处理保持独立；只有完成后才能感知变慢，固定 M 也不能保证大批同期限块都准时完成。

排队不分配分块缓冲，实际执行各自取得缓冲；复用池最多保留所设软上限数量的缓冲，Blocking 超限执行按需额外分配、归还时不扩大复用池；无有效需求的块释放任务元数据。启动日志记录所设软上限和增长间隔。Debug 的 block_schedule 分别记录来源 ready_by 与实际 wait_since，以及 active/open、block_time_ms、prepare_ahead_ms、放行时的过期状态、准入工作字节 work_bytes、采样和额度变化，不再输出 target/supply。block_demand 只记录普通使用摘要，不再输出 blocking；实际 Blocking 由 block_schedule 记录，block_demand_handoff 按来源退出记录完整块范围、原来源、原因、真实退出时刻、首块原期限及固定到期。

API、清单、测速和空闲连接不属于这里的视频下载软上限；隔离测速保留 16 路 / 250 ms 基准，不随下载设置改变。队列与批量补齐按现有顺序逐项解析并登记，成功占用唯一块使用需求容量后即继续下一项，完成结果独立收集；容量不足时只保留一个已解析待接入项，等待来源释放通知，不重复解析或并发解析整批。已移除两个歌曲调用者、32 个资源会话及队列位置数量限制；完整队列按块容量登记需求，实际下载时机由 M 控制，全局网络执行和本地验证额度各自保持原职责。临时块和合并副本不计入正式库存容量；块保留不是磁盘硬配额。调度不提供总带宽整形或游戏帧时间保证。旧对照结果保留于历史开发文档，不能直接证明新策略的效果；本次自动验证和替代测试映射见[开发记录](validation/block-scheduler-validation.md)，剩余游戏范围与旧编号分流统一见[现行台账](live-acceptance-backlog.md)。
