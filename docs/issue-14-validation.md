## 节点导入与快照

`internal/proxyengine/mihomo/import.go` 复用固定版本上游转换器，调用前限制 URI 协议/参数并隔离已知会输出原始 URI 的错误路径。仅提取 YAML proxies；支持 URI/Base64，不加载完整运行配置。端口、地址、默认参数归一化，展示名和 TCP 无关 UDP 标志不影响身份。重复节点跳过；不支持/无效项逐条固定诊断，不返回输入、名称、地址或凭据。VLESS 的 TLS client-fingerprint 属于明确传入上游的连接参数。

`internal/console/proxy_nodes.go` 使用当前用户 DPAPI 保护整份版本化节点文档，嵌入 config 的同一次原子写入；预览是有限内存草稿，设置及向导最后保存才提交。快照参与 Settings 比较及向导 HMAC 版本校验。失败写入不发布，解密失败保留密文；API 导入预算与普通设置接口分开。

自动验证覆盖三种输入的一致性、重复/部分失败、字段拒绝、输入预算、私密结果、鉴权、草稿过期和冲突、关键参数身份变化、向导版本、保存/重启/同用户搬迁、损坏密文和失败原子替换。真实跨用户/机器不以这些测试替代。

## 桌面运行时

策略规范为 `direct/proxy/auto`，旧 `socks5` 值读取后归一化为 `proxy`；`proxyBackend` 独立为 `external-socks5/mihomo`，缺省兼容外部 SOCKS5。底层 `socks5/host/stable-v1-*` 历史键仍表示固定代理出口，不因 UI 命名改变。

`network_mihomo.go` 对生效快照按 HMAC 身份排序，最多创建 5 个 Node，备用仅保留配置和历史身份。当前持久状态只有吞吐/冷却，没有可比较的资源首响应样本，因此启动采用稳定暂定集合，不声称全局 Top 5。K 仅为启动策略参数；正常业务和测速只暴露活跃集合。没有推荐时业务直接使用同一固定候选，不先等测速。强制代理下空库或无法解密均明确失败；auto 允许直连。密钥异常保留坏文件，使用新随机临时身份并禁止据此删除旧历史。

候选池先退役，随后关闭自有 Mihomo Node；启动失败也清理已创建对象。游戏 HTTPS relay 单独使用 `c.dns.DialContext`，应用 HTTPS 回源仍可代理。可确认的固定出口写入已有 ResourceSource.APIChannelID。

本地独立回环服务验证 Console → Mihomo → Pool 的 SS、VLESS TLS、AnyTLS、Hysteria2 冷启动 HTTP 请求及正文；无公网代理、游戏或第三方互操作覆盖。另验证 K 与保存总数分离、K 变化身份不变、临时身份不继承、退役拒绝新流、强制代理无节点不直连、auto 直连、游戏 relay 与应用 API 拨号分离，以及已保存备用/读取失败/已删除节点的历史清理差异。原设置测试的 `socks5` 期望改为规范策略 `proxy`。

## 设置与首次引导

两处复用同一网络字段组：使用策略与后端分开，Mihomo 支持文件读取或粘贴文本，检查后显示条目序号、受支持协议与固定诊断。用户核对部分成功结果后通过原保存/最终应用流程替换整份节点库。没有有效节点时无草稿 ID、不可清空旧库；仅选择 Mihomo 而没有节点时保存/向导校验提示导入。

浏览器只在当前内存持有原始输入，有效导入后清空文本及文件选择；保存仅发送不透明草稿 ID，不在浏览器持久存储节点。过期/跨标签冲突由服务端拒绝；丢弃或离开时迟到响应不能恢复过期草稿。已保存、已加载、活跃数量与不可解密/临时身份提示独立显示。Monitor 卡片显示代理通道短身份而不是把所有协议标作 SOCKS5。
