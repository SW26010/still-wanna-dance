# Wi-Fi 单路 IP 优选：本窗口有明显收益

2026-10-29 晚至 10-30 凌晨，Asia/Shanghai。**对本机 Wi-Fi、`play.udon.dance` 的同一个 1 MiB 视频块，扩大候选范围后，单路 IP 优选获得了可重复的收益。** HTTP 冻结候选相对三个 DNS 地址的配对中位速度为 **3.46–3.86 倍**，六轮方向全部一致，失败未增加。HTTPS 冻结候选完整交付 12/12，三个 DNS 对照为 0/18；这是可用性改善，不能计算有效吞吐倍率。

全部预定测量已经完成。仓库保存脱敏报告和精简统计，完整轨迹与源码快照另存附件。本轮未接入产品、修改 hosts、路由或日常配置，也未开展游戏验收。

最低的单轮 HTTP 比值仍为 2.56 倍。两个候选均满足采样前设置的工程判据：至少五个完整配对、至少五次更快、配对中位比至少 1.25，且失败不增加。这不是统计显著性或跨网络稳定性声明。

HTTPS 的 18 次 DNS 失败中，16 次取得 206 后未在 30 秒内读完，另两次未取得有效响应。不能把收到 206 当作成功，也不能把这些未完成请求赋零速后计算“无限倍提升”。三个 DNS 地址在较早的串行确认阶段曾各自 3/3 成功，说明可用性随时间变化，不能宣称它们永久不可用。两个额外候选在后续六轮中仍各自 6/6 完成。

所有成功的留出响应均为 HIT。DNS HTTP 响应后缀为 SEA；额外候选出现 SJC/LAX，同一个 IP 也可能更换后缀。这些是观测特征，不足以定位故障责任或把 IP 等同于固定物理节点。

## 同 IP 的 HTTP / HTTPS 对照

六轮留出中，三个相同 DNS 地址的 HTTP 合计 18/18 完成，HTTPS 为 0/18，支持当时的可用性改善；没有双方完整样本，不能给出吞吐倍率。两种协议共同选中的额外地址只有 `104.21.64.1`：HTTP 中位速度 0.766 MiB/s，HTTPS 0.712 MiB/s，按同轮配对的中位速度比为 **1.068（约 +6.8%）**，HTTP 六次中五次更快，双方均 6/6 完成。未达到本批 25% 的工程收益幅度门槛。

因此，坏路径上的协议差别很明显，但优选到这个共同的好 IP 后，HTTP 的额外吞吐优势较小。不能把 HTTP 第一候选的 0.803 与 HTTPS 第一候选的 0.631 直接比较成协议收益，因为两者 IP 不同。这些是协议、端口及路径共同变化的实测，也未隔离纯 TLS 成本。配对仅使用相同 IP、相同块和相同轮号；协议次序按轮交替，仍不是同时测量。

[协议配对复算](../evidence/wifi-ip-selection-20261029/protocol-comparison.json)保留每轮耗时和比值；[离线复核工具](../../experiments/upstream-wifi/README.md)从完整脱敏记录重新计算。

## 候选、样本和选择过程

历史名单来自三个各 104 地址的池：原程序固定名单、按地址空间随机抽样、按 15 个 IPv4 前缀分层抽样。再纳入各范围首地址和历史 pilot，去重为 326 地址，加本轮三个 DNS 地址，共 **329 个不同 IPv4**。完整名单和固定顺序见[计划](../evidence/wifi-ip-selection-20261029/plan.json)。这覆盖了历史尝试过的 15 个范围，不是扫描每个网段内的全部地址。

固定样本为歌曲 42、偏移 **8,388,608**、长度 **1,048,576 bytes**，即 `bytes=8388608-9437183`。块 SHA256：

```text
3004a6effabbfc907339499cc8ae5be5b1ce2f1cd59b5c9ff30ad0e11ca24af7
```

HTTP 和 HTTPS 均请求同一个块，但独立筛选、评分和比较。采样时代码检查真实远端、206、Content-Range、长度、identity、强 ETag 和块 SHA256；HTTPS 保持域名和正常证书校验。所有连接及 DNS 使用 Wi-Fi 源地址和接口绑定，socket 选项回读、实际本地地址和远端均有私有证据，失败不回退其它网卡。

1. **全池初筛：**同时测四个不同 IP，每个 IP 单请求、单连接；每 IP 交替执行 HTTP/HTTPS，每请求最多 30 秒，每 12 个候选插入 DNS 对照。共 658 个非中断初筛结果，HTTP 104/329 完整成功，HTTPS 93/329 完整成功。
2. **串行确认：**每种协议取完整成功初筛前 12 名，再加入全部 DNS。HTTP 去重后 14 地址、HTTPS 15 地址，各执行三轮串行确认。排名只使用这三轮，初筛的并发速度不混入评分。
3. **漏选审计：**每协议按预定顺序复查 12 个初筛失败地址，各有一个随后成功，速度分别为 0.086 和 0.121 MiB/s。初筛失败不代表永久不可用；其余未复查失败地址保持未知，不补造成成功或已证实无收益。
4. **冻结与留出：**只有三次串行确认均成功者可入选，每种协议固定两个最快额外 IP，再加入三个 DNS 地址，轮换和反转顺序，完成六轮串行验证。冻结发生在全部 60 个留出请求开始之前。

四路初筛存在共享链路竞争，只承担挑选候选的作用。串行确认和留出消除了本探针内部的并发竞争，未控制其它应用流量。六轮“留出”指这些结果未参与选择，不代表六个统计独立网络环境。DNS 地址是实验固定对照，不声称它们就是普通产品请求实际会选中的地址。

## 覆盖、失败和中断

| 阶段 | HTTP 成功 / 非中断请求 | HTTPS 成功 / 非中断请求 |
| --- | ---: | ---: |
| 329 地址全池初筛 | 104/329 | 93/329 |
| 穿插 DNS 对照 | 27/28 | 1/28 |
| 三轮串行确认 | 34/42 | 41/45 |
| 初筛失败地址审计 | 1/12 | 1/12 |
| 六轮留出 | 30/30 | 12/30 |

另有两次 HTTP 恢复前验证，均完整成功。全部共 **894 条原始记录、887 条非中断逻辑记录**，七条中断记录原样保留；总应用读取正文 **389,014,717 bytes，约 370.99 MiB**，低于 1 GiB 上限。这不是网卡总流量。全池开始到最终结束约 72.6 分钟，其中两次暂停累计约 13.9 分钟；最终六轮留出约 11.3 分钟。筛选成本已经记录，本轮没有测算生产选点策略的摊销收益。

第一次暂停来自探针错误地把 `108.162.192.1` 的 HTTP 403 当作资源整体失效。停机前 DNS 和另一候选仍能完整读取同块。修正后将单 IP 401/403 保留为候选失败，在同一 URL/ETag/哈希的 DNS 验证成功后继续，原 403 没有删除或重跑。第二次暂停用于迁移运行目录，也先验证同块再接续。两次合计七个在途样本被打断，补测与原中断记录都保留。

初筛跨三个程序版本，原始源码、二进制和停机快照均保留。**全部串行确认及六轮留出使用同一个 r2 构建**，SHA256 为 `915c345b8828423ddedb3b979aa12e1a1e81e3a2f9c14c103303291e31b22602`。

## 结论边界与证据

本轮支持“在当时的 Wi-Fi 路径上，针对这个资源块，从更大的候选池中选择额外 IP 可以明显改善单路交付”。不能外推到完整视频、多路调度、其它视频块、冷缓存 MISS、IPv6、其它线路或长期时段；也未测试这些地址接入产品后的选点开销、回退或播放体验。所有结论来自本地实测，没有修改日常程序来固定这些 IP。
