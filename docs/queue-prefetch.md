# 日志队列预缓存

控制台「房间队列预缓存」读取 VRChat 新增日志，按队列顺序准备前 N 个位置（默认 3）中具有有效曲库 ID 的歌曲。作为本地 CDN 的子项随服务启停；设置中的「随 CDN 启用房间队列预缓存」（`queuePrefetchEnabled`）默认开启，旧配置缺少该字段时也默认开启，可关闭。实际游戏读取本地缓存仍需 hosts 接入。设置中的 `logDir` 默认是当前 Windows 用户的 `AppData/LocalLow/VRChat/VRChat`。旧配置自动补上默认值。

设置中的「队列预缓存数量」（`queuePrefetchCount`）可设为 1～100，默认 3；旧配置缺少该字段或设为 0 时使用默认值。数量按队列位置计算，非曲库条目也占位置。按现有设置保存规则，停止 CDN 和批量任务后保存，下次启动 CDN 生效；并发下载仍最多两首。

## 日志检测与频率

参考 dancing-log 本地检出 `c3fa28fa3b68879cb43513bc2cb53f1cc03fa1cc` 的 [vrc_log_watcher.py](https://github.com/SW26010/dancing-log/blob/c3fa28fa3b68879cb43513bc2cb53f1cc03fa1cc/dancing_log/vrc_log_watcher.py) 与 [vrc_log_parser.py](https://github.com/SW26010/dancing-log/blob/c3fa28fa3b68879cb43513bc2cb53f1cc03fa1cc/dancing_log/vrc_log_parser.py)。调查时 GitHub 返回 404，实际参考源码来自本机已有仓库。独立用 Go 标准库实现，没有引入 Python 运行依赖。

- dancing-log 默认轮询 0.25 秒。StepStash 每 **3 秒**检查当前日志并从字节偏移读取增量，每 **15 秒**扫描新日志文件；没有新增内容时不解析、不请求歌曲 API。
- 初次启动从现有最新文件末尾开始，等待新的队列同步。不会重放旧会话；在点歌前开启最稳妥。新会话文件从头读取，按 VRChat 文件名中的会话时间选取，旧文件 mtime 改变不会倒退。
- 保留尚未写完的行，完整换行后再解码，支持 UTF-8 跨次写入。单次最多读取 4 MiB，单行最多 1 MiB。截断、替换、读取失败、异常队列行会清空待处理队列。
- 处理 `OnPreSerialization: queue info serialized:` 和 `OnDeserialization: syncedQueuedInfoJson =` 两类 JSON 数组。忽略当前视频 userData 和预览事件；不读取玩家姓名到业务状态，不持久化完整日志。
- 离房、进入新房间、应用正常退出或文件切换时清空待处理队列；日志 5 分钟无新增时也清空，等待新的同步。
- 当前文件新增日志通常在 0～3 秒内被读取，新日志发现通常在 0～15 秒内。游戏本身的日志缓冲、磁盘和系统调度会增加延迟，这不是严格实时保证。

## 下载调度

同一次读取中的快照先合并为最终队列，再通知后台协调器，最多同时准备两首。每首开始前重新检查最新顺序；解析视频地址后也再检查一次，避免接口慢时把已删歌曲提交下载。

使用设置中的回源线路（默认 Auto：主动下载 CF 优先，失败后回退 HKG；同校验和与大小才允许在同次传输中替换）、大小/MD5 校验和 `Prefetch` 共享下载机制；详见[统一回源选路](console.md#统一回源选路)。歌曲持续处于设定的预缓存范围时，已经准备成功的歌曲不因重复同步而重新请求；离开设定的预缓存范围后清除完成标记，重新进入时再次解析地址并检查缓存，缺失则补下。完整队列中的已有缓存持续受保护，不受热度影响，也不会因移出设定的预缓存范围而失去保护；预算不足时可暂时超限，普通离队（包括空队列快照）后保留 30 秒交接保护，避免播放请求稍晚到达时预缓存已被淘汰；重复快照和 HEAD/探测请求不会延长或提前结束期限。到期主动触发回收，停止监听、换房、日志失效及退出立即清除交接保护，活动播放请求仍由独立引用保护。仅凭队列快照无法区分删歌与开始播放，因此普通删歌和清空也有此宽限期；这不保证整首播放期间始终留盘。失败最早 60 秒后重试，且歌曲必须仍在前 N 个位置（默认 3）。原始日志存在 `songId=-1` 条目，保留位置但不请求曲库。与全曲库下载补齐互斥，补齐期间临时暂停，结束后仅在 CDN 仍运行且此功能启用时恢复；只读扫描可同时运行。队列预缓存和下载补齐各支持最多 2 首并发，下载引擎统一限制后台任务最多占用 2 个名额（默认总共 3 个），为播放保留 1 个名额。取消任务后，已开始的共享下载仍占用后台额度，直到真正结束；新任务等待额度，不会挤占播放预留名额。删歌、切房或歌曲移出设定的预缓存范围时，立即取消该歌曲的地址解析与额度等待；已开始的共享下载继续执行，直到完成、失败或程序退出，失效任务不计入队列失败或重试。尚未实现带宽限速或抢占。

停止、删歌、切房只清除尚未提交的任务，已开始的共享视频下载继续执行，直到完成、失败或程序退出，以免打断游戏。退出控制台会关闭缓存引擎并取消全部下载。预缓存没有独立启停操作；随 CDN 启用的偏好持久保存。日志目录不可读时显示预缓存错误，不阻止 CDN 启动。

失败状态按歌曲 ID 保存并按当前队列顺序显示，其他歌曲成功不会掩盖仍待重试的失败。歌曲删除、队列清空、换房或停止监听时清理对应错误；重试成功只清除该歌曲的错误。已被移出队列的下载即使稍后失败，也不会恢复过期提示。

## 离线回放与验证

独立命令只读日志并输出统计，没有缓存或网络调用：

```powershell
go run ./cmd/stepstash-replay -logs '<log-collector-directory>\logs\source-vrc-logs'
```
