# 配置与运行生命周期

配置可以在服务或任务运行时保存。保存只校验、写入配置文件并更新已保存快照；当前 Console 的配置、网络连接、共享本地资源引擎、监测策略、扫描与任务保持不变。

所有设置统一在应用重新启动后生效，包括没有任务运行时保存的设置。单独停止、启动播放网关或任务不会应用待生效配置。

「激进的缓存回收策略」保存为显式枚举 aggressiveCacheReclamation=auto/on/off，初始为 auto。自动只在视频保留选项为「不保留」时开启，「限制为」及「不限制」时关闭；使用有效预算判断，不受界面记住的预算输入值或当前剩余额度影响。手动开启/关闭不随预算变化，选回自动后恢复跟随。该选项仅在本地视频的存储设置编辑，使用引导沿用已保存策略，恢复本页默认也不改动它；状态快照保留策略本身，实际行为由当前运行配置计算。仅切换策略也参与待重启，引导核对仅展示此前已保存、尚未生效的策略差异。配置格式为 5，不迁移旧格式。

「高级下载设置」中的下载并发软上限与增长间隔也遵循此规则。配置字段 `downloadSoftLimit` 与 `downloadGrowIntervalMS` 缺失或 null 时分别使用 16 和 250，明确保存的 0 ms 表示关闭缓增；范围与执行语义见[下载并发](download-concurrency.md)。

「本地存储」中的本地延续保护时长也在应用重新启动后生效。`localProtectionGraceSeconds` 缺失或 null 时默认 300，接受 0～10000 的整数；显式 0 表示不延续保护。引导保留该设置，并在最终核对中显示此前保存但尚未生效的更改；保护资格、起算点和回收边界见[本地保护](download-resource-design.md#本地保护)。

状态接口中的 `settings` 是已保存配置，`activeSettings` 是当前运行配置，`restartRequired` 是两者规范化后的差异。两份配置均不返回代理密码；密码差异仍参与待重启判断。保存请求省略密码时保留最近保存的密码，显式空串清除密码。

设置表单展示已保存配置；运行信息、本地视频列表与监测展示当前配置。保存失败不会更新已保存快照；把配置改回当前值会清除待重启提示。

播放网关和队列预加载通过各自的启动、停止操作独立运行。共享本地资源引擎由 Console 持有，懒创建后保留到应用退出，不随任一消费者关闭。队列的 `desired` 表示用户开启意图，`running` 表示当前任务是否运行；下载补齐只暂停实际运行，不修改意图。暂停期间关闭队列会阻止后续恢复；播放网关故障也不会关闭队列。

引擎记录的首个本地存储故障通过状态接口 `storageError` 展示；无故障时省略该字段。控制台公共错误栏持续显示原因、停止新下载的影响及修复后退出并重新打开应用的步骤，已保存的本地视频仍可读取。修复目录、成功读取本地视频、启停播放网关或队列都不会清除此错误；新应用实例创建新引擎后重新判断。此字段直接读取引擎，不额外持久化，也不改变表示配置差异的 `restartRequired`。

设置中的「控制台启动」集中提供「运行控制台时自动启用播放网关」（`autoStartCDN`）和「运行控制台时自动启用房间队列预加载」（`autoStartQueue`）。两项独立，默认都启用，只控制控制台程序启动行为，手动启停不改写它们；重新打开网页或激活已有实例不会触发。保存后下次启动应用生效，仍需有效的条款确认记录，不自动修改 hosts。

首次启动尚未确认条款时，自动启用延后到引导最后「确认并应用」成功。仅同意条款、浏览或校验引导不会启动网关和队列；无需重启时，在配置及可选导入应用成功、完成回执写入后，按当前两项设置补执行一次。需要重启时，旧进程不启动，由新进程按已保存设置自动启用。应用失败不补执行；启动失败沿用各自的错误提示和手动重试入口，不影响另一项。补执行后，重复提交、回执恢复或重新进入引导不会重试启动，也不会重新开启已手动停止的服务。

受支持配置中，两项各自缺失或为 null 时默认启用；明确保存的 true/false 保留，包括旧配置中的关闭选择。队列不从 `autoStartCDN` 或已废弃的 `queuePrefetchEnabled` 推导，保存仍使用现有两个字段，不增加重复开关。

待应用配置会显示「立即重启并应用」。有尚未保存的表单更改时按钮禁用。重启请求使用现有 Host、Origin 和会话令牌校验；先返回响应，再由程序入口停止服务与任务。`run()` 返回并完成全部延迟清理（包括配置锁、桌面单实例锁及日志文件）后，`main()` 才启动替代进程。

重启保留绝对配置路径、实际控制台端口及托盘模式，避免重复打开浏览器。页面等待新实例的会话令牌出现后刷新；响应丢失不会重复发送重启请求。60 秒内未确认新实例时显示手动恢复提示。批量任务不自动续跑；播放网关和队列按保存的自动启动配置启动，仍受使用条款限制。退出和重启同时到达时，首次被接受的操作决定结果。

引导最终核对复用后端完整配置校验，用规范化配置（含不向浏览器公开的凭据）比较是否需要重启，并核对首次同意后的待执行启动意图。校验只返回重启／执行启动设置两个事实，不保存设置或启动服务。摘要据此展示本地服务、队列和游戏连接的具体影响；无法核对时不允许确认。正式应用仍重新校验。无需重启的重新引导保留已手动关闭的服务；需要重启时按启动设置执行。完成反馈读取实际状态，不能将配置应用成功等同于服务启动或播放成功。

「退出时恢复游戏直连」（`restoreHostsOnExit`）默认开启，缺失或 null 采用默认值，明确关闭则保留。保存及引导保留/核对遵循同一 saved/active 契约；本次退出或重启按旧进程的当前设置执行，新进程再应用已保存值。默认恢复后，重启完成需点击「开始加速」重新接入；只自动启用网关不重新写入 hosts。权限助手和失败边界统一见[hosts 契约](console.md#hosts)。
