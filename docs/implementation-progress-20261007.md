## 已实现

- Monitor 按操作、入口、节点、资源域名及通道模式过滤候选，再按既有推荐和滞回排序。业务直接执行被测 transport，最多尝试四个候选；没有有效观测时使用一次配置通道。播放解析按剩余时限为备用节点留预算，不再竞速。清单仅匹配实际消费入口。
- 下载层已移除歌曲 API 查询、地址 LRU、临时 Range 测速和独立健康排名。资源请求按当前完整地址的域名使用 Monitor 通道，同地址最多四次通道尝试；重定向继续验证域名、MD5 和大小，并为目标域名重新获取合格通道。
- 现有 SQLite 增加歌曲 URL 记录，每个歌曲/API/node 保留一条完整地址。保存查询开始时间、观测完成时间、MD5 和大小；较早发起的结果不能覆盖较新的查询结果。失败标记带观测版本条件，不能误伤同 URL 的新观测。可复用窗口为 24 小时；这不是对签名有效期的保证。console 的成功 API 查询落库，已有清单映射保持不变。
- 即时播放与队列复用 `loadSong`：保护并立即使用本地资源；缺失时启动一次服务器生命周期内的查询，同时尝试持久化地址；地址失败则标记该观测失效并等待已有查询。播放已经开始输出后不切换内容。队列仅等待共享任务完成，取消等待不会取消下载；补齐继续使用独立的按目标 MD5 调度及预算检查。
- 播放传输统计与 GET 需求评分分开保存：成功完成、有歌曲 ID 且返回正文的即时 GET 按歌曲 30 秒去重；队列、HEAD、失败、中断不计数。这是服务端传输证据，不宣称客户端已经起播。新首正文时延包含 API 查询和数据等待；历史响应头样本保留但不与新样本混合，界面取消不同起点的延迟降幅比例。
- 同版本清单冲突仍拒绝写入，并输出新增/移除/MD5 变化数量、最多八个示例歌曲 ID、接受和候选摘要。映射相同时明确提示元数据或规范化表示差异，不猜测历史冲突原因。
- 共享下载支持 1 MiB 区块和真实完成区间。同 MD5 的大小不一致时拒绝共享。每任务最多两个请求（全局上限为 `2*MaxDownloads`），一个后台填洞，另一个服务读取需求；重叠区块需求合并。已有读取器使用独立偏移。
- 206 响应校验 Content-Range、大小、编码和实际长度，短读最多两次尝试；存在强 ETag 时使用 If-Match 并核对返回 ETag。初次 Range 被忽略且返回合法全文时降级顺序下载并记录 `range_unavailable`；分段途中忽略 Range 会终止任务。
- 覆盖所有区块后按文件顺序校验 MD5，再沿用 Windows 安全的复制、同步和发布流程。尾部读取不等待文件前缀；无 Range 的整文件 HTTP 响应仍在验证发布完成后交付最后一个字节。已输出的局部字节不代表已通过完整 MD5 校验。
