# 功能范围与验证边界

本文描述当前源码实现的功能；运行结果按构建版本记录。旧版测试通过不代表当前构建已完成相同的实机验收。使用方法见[WebUI 与桌面程序](console.md)和[命令行服务](service.md)。

## 目标

为 Windows 上的 VRChat WannaDance 提供本地视频存储、本地未命中边下边播和后台预加载。以可观察的播放协议为依据独立实现，不要求恢复原版源码或复现原版错误行为。

## 已实现的范围

| 功能 | 行为与入口 |
| --- | --- |
| HTTP 本地视频存储 | 有效 API 响应动态确定的资源域名、GET/HEAD、单段 Range、条件请求；本地未命中共享下载，校验大小和 MD5 后发布 |
| HTTP 播放 API | 已有关联且本地文件可用时直接读取，后台检查地址；缺失时解析并回源，向播放器直接返回视频 |
| HTTPS 透传 | 桌面程序同时监听 80/443；HTTPS 保持原站加密连接，不读取本地视频或填充视频块缓存。独立命令行入口不监听 443 |
| 回源连接 | HTTPS 优先，传输失败时允许[有界 HTTP 回退](upstream-channels.md#业务请求的协议策略)；内置 DoH 不降级，HTTPS 验证原域名证书；桌面程序支持在 API 返回域名集合中测速优选 |
| 桌面程序 | 本地网页、Windows 托盘、单实例、设置持久化、可选启动时启用播放网关、hosts 接入与移除 |
| 后台准备 | 全曲库只读扫描、下载补齐、根据 VRChat 房间队列与预计播放时间提前准备视频；两种下载模式可互相切换 |
| 本地存储 | 数据库与完整视频目录独立配置，按资源指纹保存视频，SQLite 保存曲目资料、版本关联和请求统计；路径及归属见[存储契约](storage.md) |
| 容量与统计 | 资源请求热度、视频容量淘汰、请求明细保留期，以及按存储目录持久化累计的播放请求统计 |
| 排障 | 结构化日志、请求与共享下载关联、下载阶段和进度、任务及本地文件统计快照 |

同一资源的并发请求共享下载，不同视频版本独立存储。临时下载完成检查后才发布，活动文件受引用保护。存储根目录由操作系统文件锁独占，具体规则见[统一存储](storage.md)。当前格式不读取原版歌曲库或旧版 StepStash 格式，也不提供迁移。

## 使用与兼容边界

- 游戏使用本地视频需要 HTTP 入口及 hosts 接入；播放器还须接受播放 API 直接返回视频。API 接管、冷/热播放与存储已有分场景实机证据，剩余范围见[台账](live-acceptance-backlog.md)，不将已测样本外推到全部播放器条件。
- SHA 不支持；历史 IP 入口超时不能证明其目前或所有环境下均不可用。
- 通道推荐依据有限采样，仅在所选直连或代理模式内选路，不保证始终最快；下载正文开始后不因低速或断流切换线路。分块下载可在同一次引擎运行内复用仍保留的完整块，停止后按当前需求建立新任务，不保存半块或暂停检查点，也不支持跨重启断点续传；重试与顺序回退边界见[下载并发规则](download-concurrency.md)。
- 本地命中不等待上游查询；缺少映射或可用文件时仍需回源，下载失败不会自动改播其他版本或在已输出的响应中切换内容。
- 容量上限只约束保留的视频，活动视频和临时文件可能使实际占用暂时超限。下载成功不保证视频一直保留。
- 不保证所有 VRChat 平台、播放器后端、其他舞房、RTSP、Redis 鉴权或原版镜像下载器兼容。
- 桌面托盘和一键 hosts 提权面向 Windows；其他平台可使用命令行入口，其游戏兼容性未作承诺。

## 验证依据

可控上游自动化测试覆盖协议、校验、并发、中断、版本和容量策略，运行方法见[开发环境](development.md)，开发记录归入 [validation/](validation/)。实际游戏结果按批次保存在 [acceptance/](acceptance/)，具体范围和证据见[证据索引](evidence/README.md)。

当前剩余游戏场景只在[VRC 台账](live-acceptance-backlog.md)维护，Windows 等环境缺口见[非 VRC 跟进](validation-followups.md)，分工遵循[验证机制](live-acceptance-process.md)。[原版调查遗留问题](history/original-open-questions.md)仅用于理解早期调查边界，不是当前产品待办。
