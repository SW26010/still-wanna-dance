# LIVE-20261014-01 实机验收报告

## 结论与版本

本轮已按用户“已停止，本轮收尾并恢复接入”结束并完成清理。完成前四档顺序播放、128 KiB/s 探索，以及独立的 256 KiB/s、64 KiB/s 正式播放；独立预览拖动、刷新、切节点未测。LA-008、LA-037 均保持待验收，不整项结项。

核心结果：256 KiB/s 的正式播放在卡顿时大部分时间保持 GET，但出现 146 ms 重连空窗；64 KiB/s 正式播放中出现 12–516 ms 空窗。GET 等待数据时仍有 P0，GET 之间则没有当前读者保护。因此“正式播放总是一个 GET 到底”不成立，但本轮未复现实际被其他资源抢占，不能据此确定宽限期长度。

前四首均由一个 WMF GET 读完整文件，用户确认音画正常，但当时没有独立记录正式/预览模式。128 KiB/s 的 6776 用户已无法回忆模式，混合跳转期间同资源有约 18 秒的全部 GET 空窗；该事实保留，但不能外推成正式播放器的 18 秒空窗。

64 KiB/s 的 StopVideo 日志之后，还观察到两个新 WMF GET，最后一个在网关退出时取消，距停止事件约 41.5 秒；这些请求已从“播放中重连”统计中排除，不能用它们推断用户仍在播放。游戏日志只有秒级时间，此残留机制未定位。低带宽下等待和重试是否被区间调度进一步放大，也未作受控归因。

## 遗留问题与下轮积攒
