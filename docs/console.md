# 本地控制台

## 名称与职责

核心网络服务统一称为**播放网关**（Playback Gateway），界面需要强调运行位置时使用「本地播放网关」。

| 名称 | 职责 |
| --- | --- |
| 启用游戏加速 | 用户主操作，一键启动播放网关并完成游戏接入 |
| 播放网关 | 接收 HTTP 播放请求，结合上游选路与本地缓存交付视频，并对受 hosts 影响的 HTTPS 连接透传 TLS 字节 |
| 本地缓存 | 视频存储、索引、校验、容量管理与清理 |
| 上游通道 | 直连或代理等连接出口，以及通道评估、选择与失败切换 |
| 游戏接入 | 当前通过 hosts 将播放 API 域名重定向到本机 |

播放网关和房间队列预缓存独立启停、分别配置自动启动，共用缓存引擎和媒体库。只开队列可以提前准备视频；游戏实际读取本地缓存仍需启动播放网关并完成游戏接入。停止播放网关只关闭 HTTP 播放与 HTTPS 透传入口，队列和独立后台任务仍可运行；退出整个应用才会关闭共享引擎。下载补齐期间会临时暂停队列，结束后按用户开启意图恢复。

当前界面以中文命名为准。为兼容已有配置和诊断工具，`autoStartCDN`、`cdnError`、`cdn_*` 日志事件及现有 API 路径保留原标识，含义仍对应播放网关；历史报告保留当时用语。原版软件或远端 CDN 不属于本次命名范围。

## 首次使用与条款确认

首次打开显示「开始」，介绍 SWD 的用途、四项功能、后台和托盘行为。点击「完整条款」打开弹窗阅读全文；点击弹窗底部「同意完整条款」立即保存 DPAPI CurrentUser 记录，成功关闭弹窗，开始页以绿色对勾表示确认，「阅读并同意」文字不变，再点击下一步。后三页与业务 API 要求有效记录。条款版本或全文摘要变化后须重新确认，导航不代替同意。记录保存在配置实例的 `terms.json`（默认 `data/terms.json`），独立于普通设置，无需 UAC。

同用户在原环境中连同凭据移动目录或更换配置路径时保留确认；仅移动配置、不带其伴生凭据则须重新确认。跨用户或普通独立机器复制、旧明文、损坏、未知格式、解密失败及条款变化均不授予同意，不自动重建记录。域账户/漫游配置可能跨机器解密，不提供严格设备绑定。保护或原子写入失败时保持未同意并显示错误；普通读取错误有诊断并阻止启动。非 Windows 控制台不支持保存确认，不回退明文；独立命令行服务的显式 `-accept-terms` 行为不变。记录不是身份认证、法律签名、亲自阅读或内容授权的证明。

不同意时仍可停止服务、恢复本程序管理的 hosts 并从托盘退出。未同意当前条款时，关闭或离开条款页会尝试通知后台，60 秒后自动退出；重新打开条款页、通过浏览器后退恢复该页或成功同意条款会取消倒计时。切换标签页或最小化不会触发；已同意后关闭网页仍保持后台运行。此机制面向普通单标签页使用，不保证浏览器崩溃、强制结束或多标签页场景；退出不会恢复 hosts。关于页和页脚可随时打开 `/terms`，`/terms.txt` 提供完整文本。版本变更应同步更新条款中的版本号与 `internal/legal/legal.go` 的版本常量。发布包随附相同的 TERMS.txt；MIT 不变。

## 页面导航

未确认条款时，真实 `/` 与 `/terms` 共用完整向导，只开放开始页；完整条款弹窗仍可用；下方「修复已有安装」默认收起，展开后可点击「恢复游戏直连」按钮。已有记录无法验证时自动打开弹窗，须重新明确确认。确认和后续操作保持同一文档，状态断连时保留已保存确认并等待重连；关闭未同意页面的退出倒计时机制不变。

控制台按用途分为五个内容页，桌面使用侧栏导航，窄屏自动换行：

- **开始使用**（`/#/home`）：启用游戏加速、接入状态和请求检测；「高级接入设置」可单独启停播放网关、查看端口及恢复 hosts。
- **准备歌曲**（`/#/library`）：房间队列预缓存、批量检查和下载补齐，以及任务进度和失败记录。可直接下载补齐，无需先扫描。
- **本地缓存**（`/#/cache`）：搜索、排序、删除本地文件，查看占用和覆盖率；缓存效果统计默认折叠。
- **运行状态**（`/#/monitor`）：当前下载、最近请求和网络检测。网络默认展示各环节的可用线路数量，展开后查看技术明细和分项检测。
- **设置**（`/#/settings`）：存储与启动、网络连接和房间队列偏好；代理字段仅在需要时显示，保存后重启生效。

设置的「房间队列与游戏日志」中可调整「提前准备时间 M（秒）」，默认 500 秒，接受 1～86400 的整数。M 越大，越早下载预计播放的内容，也会更早占用带宽和缓存空间；保存后重启应用生效，运行中的下载继续使用原值。配置字段为 `prepareAheadSeconds`，已有配置缺失或为 0 时采用 500；启动窗口为 ReadyBy ≤ now + T + M，见[调度规则](download-concurrency.md)。

设置与帮助页提供「重新打开使用引导」入口。引导（`/#/setup`）独占视口，整页不滚动，长正文在内部滚动。四步依次为开始、存储、网络、启用；侧栏突出当前页，三态圆点不参与门禁。开始页显示名称、口号、用途与功能，完整条款在原生模态弹窗内阅读，底部明确同意后立即保存并关闭弹窗；「阅读并同意」文字不变，以绿色对勾表示有效记录。已有记录无法验证时自动打开同一弹窗；关闭不等于同意，失败留在弹窗并显示原因。恢复操作放在欢迎页下方默认收起的「修复已有安装」，使用明确的「恢复游戏直连」按钮，旁边说明管理员权限及即时影响；展开入口本身不执行操作。网络页提供两项手动检测，接入检查在标题旁提供刷新按钮。高级选项仍在普通设置。

存储页一行显示视频缓存位置、当前路径文本框、默认位置按钮和可用/总容量。点击文本框或按回车打开现代 Windows IFileDialog 文件夹选择器；默认仍为程序文件夹内 `data/storage`，自选须在程序文件夹外。系统 PowerShell STA 承载固定脚本，路径/标题通过 JSON 输入；取消/导航/退出关闭选择请求，每实例只开一个，选择只进入草稿。「缓存空间上限」与设置页共用不限制/限制为单选，限制值允许 0（不持久保留视频），播放/队列/交接保护解除后回收，已有视频同样处理，下方小字说明完整数据约 430 GiB、空间不足时建议限制在 40 GiB 以内；全新配置限制输入框预填 40 GiB，默认仍不限制；切换选项保留数值。未勾选导入时隐藏目录框和两段说明，勾选后展开；点击该框或按回车才选择来源，选中后在框内显示路径。取消选择保留当前勾选和路径；勾选但未选来源不能离页，可取消勾选继续。取消勾选清除来源，并重新隐藏目录框和说明。目录自动检查、不搬迁现有数据；导入保持来源文件并尽量硬链接，导入后不要修改源视频。

每次进入从正式设置预填，本轮草稿与普通设置页的未保存草稿隔离。离开步骤先做合法性检查，通过后仅保留本轮内存草稿，不写正式配置或启动导入。上一步、下一步、侧栏同时检查当前页内容合法性与目标页条款记录门禁，两项独立判断，失败留页。有修改时，浏览器返回或其他导航离开弹出原生确认，取消保留页面与草稿；刷新或关闭也显示浏览器离开提示，确认才丢弃。未修改或改回原值不提示。「放弃更改并退出引导」独立位于侧栏下方，断连或非法输入也可退出；再次进入从正式设置重新开始。底部「恢复本页默认」只恢复当前页出厂默认值，默认未改时禁用。

最后一页对照当前生效值列出上游、存储、容量、导入来源与目标，并提示此前已保存但尚未生效的高级配置。只有「确认并应用」才写正式配置；需要时自动重启，随后在新配置下启动导入。导入源在存储页离开时单独检查，源与最终目标的关系在最后确认时检查。确认请求有持久回执；丢失响应可核对同一清单，不重复导入。重启 60 秒未就绪时，在向导内显示原因并提供「重新连接并核对」和退出；重试、退出后重入或刷新都保留原应用 ID，恢复不重新提交应用、重启或导入。配置被其他窗口修改时拒绝旧清单；重启会中断现有导入/批量/队列任务时要求先结束任务。中断的导入不自动重放，部分失败明确说明配置已保存/导入未启动。普通设置页继续使用原保存/手动重启方式。

条款确认及 hosts 接入/恢复即时生效，放弃引导不会撤销。启用页 hosts 行只提供当前适用的接入或恢复按钮，管理员确认、立即生效、退出后保留及如何恢复放在悬停提示中。标题旁的刷新按钮重新读取 hosts、80/443 端口和生效目录的日志状态。端口 ready 和日志可读才显示绿色对勾，失败给原因；日志显示目录，不表示游戏在线。下方摘要依次为存储默认/自定义、缓存空间上限、导入和网络连接，保留实际变化及中断提示。一次「确认并应用」取得完成回执后直接进入控制台，不再经过接入、开服和完成按钮，也不额外调用这些操作；接入和服务在控制台管理。失败保留原因和恢复入口；刷新/回执恢复确认成功也直接进入控制台，不重复应用。

目录选择等待不向底部导航区写提示；选择失败和导入缺少目录在对应路径框旁显示感叹号小提示框，重选/取消勾选/重置后清除。存储恢复默认时，同一路径检查合并并保留当前容量结果；网络检测预留指标位置，进度随事件更新，不插入会推动布局的临时说明。hosts 成功只更新状态行，不追加重复成功文案；失败原因仍可见。

网络页标题「网络环境检测」旁的上游下拉框默认直连，可选择当前外部 SOCKS5 草稿，统一作用于连通性检测与 CF 并发测速；检测不会保存或应用业务代理配置。确认条款、进入引导、切页、刷新和回执恢复均不自动发起检测。两项检测分别手动启动：向右三角形表示就绪，悬停立即提示准备好日常游戏网络环境并暂停其他下载；方形表示运行中，悬停提示「放弃检测」，点击停止并恢复同一上游在本进程内的上次有效结果。取消请求未确认时显示错误并继续按服务端事件显示实际状态，可再次停止；收到取消状态后才按已取消展示。

连通性检测依次显示歌曲列表、播放地址、视频下载的动态省略号及成功/失败状态，只报告响应时间。CF 测速准备足够视频后复用正式下载器和调度器，先限制单路采样，再解除限制按原有 250 ms 节奏逐渐增路，满路稳定取得足够样本后主动结束；不同资源域名各自固定连接候选，共用同一个调度器。视频正文读取后丢弃，不保存媒体文件或执行完整性校验。单路/满路速度及实际并发数、满路平均 CPU 与正式下载全程 CPU P95 均预留位置；指针在所有下载阶段跟随平滑速度更新。色条为分段对数刻度，以 2 Mbps 为 1×，≤1× 不可用、1–2× 不稳定、>2× 可用。准备不足或未取得完整样本不能覆盖上次有效结果。两个面板通过 SSE 更新，切页/关闭网页不中止后台检测；应用退出会取消并清理。「连接方式」下的直连和代理复选框及按需显示的认证字段保持原有应用流程，技术详情仍在运行状态中。

「使用帮助」（`/help`）内置启动、存储、导入、接入、备份升级、卸载与排错说明，支持离线阅读。Portable README 继续保留。

配置版本使用 `channel.key` 的 HMAC-SHA256，包含密码及不可解密的受保护凭据，并与通道身份使用不同用途前缀；重启保留匹配能力，密钥故障不降级。公开响应隐藏回执内部版本，包括旧回执中的裸摘要。旧裸摘要回执或更换密钥后的待续接清单需重新核对，不自动启动导入。另一窗口替换共享回执后，原窗口使用只读 `/api/setup/receipt` 查询原应用 ID；失败保留 ID 供重试，不重新应用，确认不存在后也须主动退出才清除。存储目标尚未创建时，预检逐层检查已有祖先，提前拒绝 junction 或符号链接。

「关于」和「使用条款」位于页脚，退出应用也位于页脚。「关于」继续使用独立的 `/about` 页面。内容页只显示当前页，支持直接链接、刷新和浏览器前进 / 后退；原来的区域链接仍可打开对应页面和区域，`#service` 自动展开高级接入设置，`#queue` 进入准备歌曲，旧 `/#/upstream` 进入运行状态的网络检测。未知路由返回开始使用。

页内切换保留表单草稿、缓存搜索与选择、删除确认及展开状态，不会提交操作或停止后台任务。整页刷新或进入独立的关于页仍是网页加载，未保存的编辑不持久化。常规控制台状态继续共用一套防重叠轮询，浏览器标签页不可见时暂停、恢复可见时刷新；引导页网络检测独立使用 SSE，导航本身不创建定时器。首次进入本地缓存会自动读取本地文件，之后按需刷新，避免轮询清空选择；删除仍需明确确认。键盘导航显示焦点，当前页使用 `aria-current` 标识，切页后焦点进入主要内容；隐藏页不参与键盘和读屏浏览。

验证命令：`node --test scripts/refresh.test.mjs scripts/navigation.test.mjs` 检查前端状态与导航行为；`go test -tags=no_easytier ./...`、`go vet -tags=no_easytier ./...` 和 `go build -tags=no_easytier ./...` 检查 Go 测试、静态分析与构建。

### 上游通道监测

运行状态的网络检测区域展示 upstreamstate.Monitor 的全部操作 × 线路 × 候选通道结果，旧健康检查已移除。direct 模式检查全部有效直连 IP，proxy 模式检查活跃代理通道（兼容旧 socks5 值），auto 模式两者都检查。同意条款后启动后台调度，每轮完成后默认 5 分钟重测；候选变化及观测即将过期时提前重测。关闭浏览器或停止播放网关不会停止检测，退出应用会取消并等待检测结束。

视频列表、播放地址解析区域分别提供手动检测按钮；视频资源区域提供响应延迟和吞吐速度两个按钮，分别使用带会话令牌的 POST /api/upstream/check/catalog、playback、latency、throughput。手动检测会中止当前自动轮次后执行；列表覆盖三个清单及全部候选，地址解析覆盖两条线路及全部候选，资源吞吐依次测量全部资源候选。地址和资源检测复用有效歌曲样本，必要时查询清单；资源检测先解析合法资源地址，这些依赖请求不覆盖无关区域的结果。手动资源检测不受业务下载暂停规则限制，手动吞吐也不受 配置的吞吐间隔限制；每次仍以 3 秒、16 MiB 或整首完成中先到者停止。手动轮次运行期间按钮禁用，避免重复发起。原有全量立即检测通过带会话令牌的 POST /api/upstream/check 触发；运行中合并请求，距上轮开始不足 10 秒不重复触发。GET /api/status 的 upstreamMonitor 返回纯读取快照，包含全部候选的状态、原因、首字节延迟、样本吞吐、歌曲 ID、观测及有效期。网络配置变化由 Monitor 订阅处理，取消旧检查并重测，仍有效的相同直连通道可保留观测。

业务视频回源（含预缓存）开始时，取消正在进行的自动资源测速，并暂停后续资源测速；全部业务下载结束后自动恢复，被打断的样本不记为通道失败。完整本地缓存读取不会暂停测速。HTTPS 视频透传因无法读取加密请求，保守地在视频连接存续期间暂停；API 透传不触发暂停。界面显示“业务正在加载视频，自动资源测速已暂停”。此规则只作用于自动检测批次，手动检测始终不因业务加载而暂停。

每个清单分别显示响应原始 time：Udon 的顶层 time，Kiva 与 WannaInfo 的 data.time；不将本地观测时间当作清单时间。候选时间不一致时分别保留，缺失时显示未获取。视频列表区分别展示 Udon、Kiva 与 WannaInfo 三个入口及各自的直连 IP / 代理结果。Kiva 与 WannaInfo 检查 HTTP 与业务状态码、版本、歌曲 ID 和 MD5；无效或冲突的 MD5 会标为响应校验失败。每轮分别校验最多 16 MiB 的歌曲列表，从去重有效 ID 中随机选歌，分别查询 node=cf / node=nya 播放接口。同一路线的所有资源候选共用本轮合法资源样本，自动资源检查分为首字节延迟和吞吐两种：原调度频率仅请求 Range bytes=0-0，读取一个正文 byte 后关闭响应，只更新延迟和可用性，不计算吞吐。吞吐检测独立限制为每个配置周期一轮，按轮次开始尝试的时间写入配置实例数据根下的 state/throughput.json 文件；启动时读取记录，首次或已满配置的吞吐间隔时立即测速，否则等到期。DNS 更新、短 TTL 和失败不绕过此间隔；被业务打断的候选恢复后只做轻量检测，不立即重复完整测速。吞吐轮次仍串行遍历资源候选，对真实资源执行连续 Range 读取并校验响应：正文下载满 3 秒、达到 16 MiB、整首下载完毕，任一条件满足即结束；所有线路与候选的视频资源探测依次执行，避免同时占用本地带宽；不写视频缓存。吞吐按正文下载字节 / 实际正文下载时间计算，排除 DNS、握手和响应头等待；3 秒上限内不足 16 MiB 仍保留已收到数据的测速结果，完全没有正文则记超时。界面同时显示实际下载时长、MiB 样本量和独立的测速时间；轻量检查不会刷新测速时间或覆盖吞吐值，最近一次成功吞吐样本会持久化并在重启后恢复，超过配置的吞吐间隔仍作为历史样本展示，不用于当前测速推荐。样本吞吐是本次窗口的有效速率，不代表持续带宽或全部歌曲的可用性。优先使用本轮 Udon 合法样本，Udon 无有效样本时依次使用 Kiva、WannaInfo；三个列表均失败时可在 10 分钟内复用旧歌曲 ID；没有合法样本时不猜测视频地址，未测候选仍显示待测，旧观测到期显示过期。代理凭据不会进入状态快照。

## 启用游戏加速

「开始使用」中的「启用游戏加速」依次检查 hosts 冲突、启动播放网关（HTTP 播放 / HTTPS 透传）、按需调用既有 hosts 提权助手，再等待视频请求。已运行的服务会复用，hosts 已就绪时不请求 UAC。端口或目录错误可按提示处理后重试；UAC 拒绝或 hosts 未完成时，已启动的服务保留，可重试接入或在「高级接入设置」关闭。不会覆盖其他程序的 hosts 映射。执行期间阻止重复提交；浏览器超时不表示后台操作取消，应等待状态刷新。

服务运行、hosts 接入、收到视频请求分别显示。只有接入步骤完成之后到达且通过本地校验的 HTTP GET / HEAD 视频或播放 API 请求（不要求上游解析成功）才计入本次检测，传输成功与否不影响“收到请求”的事实。历史请求、预缓存、控制台轮询、HTTPS 透传均不计入；无法据此确认游戏客户端、起播或播放成功。等待时请在游戏中请求歌曲，必要时重进世界或重启游戏刷新 DNS。HTTP 视频使用本地缓存；HTTPS 保持加密透传，不使用缓存。

页面显示向导开始、检测起点及首个请求的到达时间（浏览器本地时区）。重新检测或重试清空记录；检测起点之前到达、之后才完成解析的请求也不计入。关闭播放网关、服务故障或操作恢复 hosts 会结束检测；刷新网页保留，多标签页共享，退出程序清空。手动单项启动不自动建立检测窗口。hosts 实时状态可能被其他程序改变，应同时核对三个状态；关闭服务或退出仍不会自动恢复 hosts。

## 缓存明细管理

「本地缓存」页的「本地文件」可按歌名、歌曲 ID 或资源指纹查找实际缓存文件，按最近请求、占用或歌名排序，每页最多 50 项。搜索长度前后端统一限制为 300 个 UTF-16 码元，与 HTML maxlength 一致：普通中文占 1 个，补充平面字符（如多数 emoji）占 2 个。点击「查找」或「刷新文件列表」读取本地目录和数据库；不会联网获取曲库、执行正文 MD5 校验、启动播放网关或缓存引擎。播放网关关闭、引擎尚未启动时也可查看。翻页或刷新会清空选择和删除确认；保存设置不切换当前缓存目录，避免操作旧列表。删除或淘汰使当前页超出范围时，保留搜索和排序条件回退到有效页；连续缩减时最多读取三次并退回首页，避免无限重试。未知文件仅展示，不能通过此页面删除或定位。

主行显示歌名、ID、大小和最近请求。该时间来自资源 GET 汇总及仍保留的 HTTP 请求明细，不代表确认播放；共享文件无法推断实际播放歌曲。资源详情显示指纹和每首歌曲的「本地当前引用 / 历史关联」；本地当前引用不是线上最新版本保证。列表只检查存在、普通文件属性和大小，明确显示「完整性未检查」或「大小不符」，不将版本记录冒充校验证明。每个文件最多展示 20 首关联歌曲和每个标题 300 字符，超出数量有提示；搜索涵盖所有关联。

选择文件后点击「删除选中缓存」，确认区会列出文件、大小及影响歌曲数。共用同一文件的所有关联歌曲都会失去该缓存，需要时重新下载；歌曲资料、版本映射、请求历史和累计统计保留。每次最多删除 50 项，逐项反馈已删除、受保护、已不存在、已变化或失败。确认后文件身份、大小、修改时间、模式或关联变化时跳过，须刷新重选。播放、下载、引擎校验、完整待播队列及离队宽限期保护均在删除前重新检查；独立扫描运行时拒绝整批删除。独立本地校验的同进程资源锁也参与保护。

删除统一经过缓存引擎的资源删除预留，阻止同资源的新引用、发布、淘汰或歌曲关联更新与删除交错。引擎未启动时，以独占存储锁执行同一删除逻辑，不启动服务、自动清理或统计保留期清理；其他进程占用目录时拒绝。成功删除使校验凭据失效并更新运行中容量记账。删除和打开操作仍与存储切换串行化。列表读取不持有生命周期锁或状态锁，慢盘不会因此阻塞服务启停与退出；读取完成后复查设置修订号，期间切换过存储（包括切换后又切回）则丢弃旧结果。

「打开缓存目录」和「定位文件」只接受当前存储标识与缓存条目，不接受任意路径。Windows 使用 Explorer 选择文件，macOS 使用 Finder；其他桌面平台打开其所在目录。目录重定向、符号链接及非普通文件会被拒绝。`GET /api/cache?q=…&sort=recent|size|title&offset=…`、`POST /api/cache/delete` 和 `POST /api/cache/open` 均要求合法 Host、会话 token 和同源 Origin（如提供）；写操作绑定存储标识，删除与定位另绑定条目快照。

分页限制的是返回量。为支持全库搜索和排序，每次读取仍枚举整个视频目录并查询本地元数据，不读视频正文；大库或慢盘可能需要等待，服务端 30 秒超时，界面可重试。列表是手动刷新的快照，不能据此保证文件持续存在或未被外部程序改动。请勿在使用时从资源管理器替换缓存目录结构。

验证：完整 `go test ./...`、`go vet ./...` 和前端 71 项测试通过；新增覆盖共享删除影响、关联变化使确认失效、文件变化、未知文件、路径越界、活动引用/队列/校验保护、离线独占、容量记账、分页、关联展示上限和隐藏关联搜索、接口鉴权、存储切换和扫描保护，以及慢读取期间停止/退出、存储切回时的旧结果丢弃、队列等待期间状态读取与取消、更新/重置顺序和删除末页后回退。Windows 当前环境缺少符号链接创建权限，两项符号链接实测跳过；没有 CGO/C 编译器，未执行 race 检查。资源管理器的实际定位行为仍需桌面人工复核。

Windows 桌面版构建、启动（托盘驻留，无命令行黑窗）：

```powershell
.\scripts\build-desktop.ps1
.\bin\SWD.exe
```

首次启动由系统分配空闲的本地控制端口（监听 `127.0.0.1:0`），并自动打开实际地址，`-no-open` 可禁止自动打开。同意条款后关闭网页仍在托盘运行；未同意时的退出机制见上文。原有 `still-wanna-dance.exe` 命令行入口保持可用。

## 托盘与实例避让

托盘菜单包含打开控制台、启动 / 关闭播放网关、停止批量任务、退出 Still Wanna Dance。鼠标或键盘激活图标均可打开控制台；菜单及悬浮提示跟随网页操作更新。Explorer 重建任务栏时重新注册托盘图标。

Windows 普通桌面模式在同一用户会话中只允许一个实例，使用会话级互斥锁 `Local\SWD.Desktop.v1`，控制端口由系统自动分配。主实例在当前用户 `%LOCALAPPDATA%\SWD\console-session-<会话 ID>.json` 记录地址、实际 EXE、配置路径、PID 和进程创建时间。重复启动最多等待 5 秒，核对端口所属进程、操作系统报告的 EXE 与创建时间，以及 `/api/identity` 返回的完整 `swd-console`（协议版本 1）身份。

只有实际 EXE 和配置身份都一致才激活已有控制台，不创建第二个服务、托盘或后台任务；`-no-open` 同样检查身份，但不打开浏览器。不同安装目录或不同配置会报错并显示已有程序、配置和 PID，须自行退出原实例；不会自动切换、停服或终止进程。路径解析支持相对路径、Windows 大小写、短文件名、符号链接和 junction；EXE 还会比较文件身份以识别硬链接；配置则要求规范化路径一致，因为其路径决定数据根和相对设置的基准，不将不同路径的配置硬链接视为同一实例。配置尚未创建时解析已有父目录，不为重复启动创建新数据目录。

首次启动者就绪前崩溃，后启动者可重新取得互斥锁。正常退出先删除本会话记录再释放锁；取得锁的新主实例清除本会话崩溃遗留记录，不扫描或删除其他会话。过期 PID、进程创建时间不符、伪造路径或不匹配的后端身份均不激活。旧 StepStash 实例协议和发现目录不参与选举，不迁移或双写，使用新版前须退出旧测试程序。

显式 `-no-tray` 不参与桌面选举，可配合 `-config`、`-listen` 运行独立开发实例。所有模式仍通过配置数据根的 `config.lock` 在整个进程生命周期独占配置，并受存储根独占锁和端口占用限制。数据根规则见[统一存储](storage.md)。锁文件保留是正常现象；OS 在进程退出或崩溃时释放锁，不要运行时删除。

退出从统一清理入口停止 HTTP 接口、取消批量任务和下载、移除托盘图标，最后释放配置锁和实例锁。注销 / 关机回调最多等待 4 秒；如果系统取消注销，程序继续运行。退出不会恢复 hosts。hosts 提权助手在实例检查前单独执行，修改完成即退出，主程序不会因此提权。

80、443 或手动指定的控制端口冲突时，Windows 下显示占用进程名和 PID；不结束其他进程，也不自动请求 UAC。旧的无托盘版控制台不会持有新实例锁，需要退出旧版后再启动新版。

默认自动选择端口；也可用 `-listen 127.0.0.1:18082` 手动指定（托盘模式同样支持）。自定义控制端口及无托盘运行示例：

```powershell
go build -tags=no_easytier -o bin/still-wanna-dance-console-cli.exe ./cmd/still-wanna-dance-console
.\bin\still-wanna-dance-console-cli.exe -no-tray -listen 127.0.0.1:18082 -config .\other-settings.json
```

该模式不自动打开浏览器，不创建托盘，使用 Ctrl+C 退出。Linux 默认使用无托盘模式。配置独占及现有缓存独占规则仍然生效。

设计参考 [dancing-log desktop_instance.py](https://github.com/SW26010/dancing-log/blob/c3fa28fa3b68879cb43513bc2cb53f1cc03fa1cc/dancing_log/desktop_instance.py)、[tray_app.py](https://github.com/SW26010/dancing-log/blob/c3fa28fa3b68879cb43513bc2cb53f1cc03fa1cc/dancing_log/tray_app.py) 和 [_win_tray.py](https://github.com/SW26010/dancing-log/blob/c3fa28fa3b68879cb43513bc2cb53f1cc03fa1cc/dancing_log/_win_tray.py) 的所有权、身份探测和统一退出机制。Still Wanna Dance 以 Go / Win32 实现，无新增第三方运行依赖。

## 服务与下载独立

- **运行控制台时自动启用播放网关**：位于设置的「控制台启动」，与「运行控制台时自动启用房间队列预缓存」分别配置，两项默认启用。受支持配置中，各自缺失或为 null 时采用默认值，明确保存的关闭选择保留。运行中可修改并保存，统一在重启应用后生效。开启后，下次启动控制台程序时自动触发一次「启动播放网关」，启动检查、结果和错误处理均复用手动启动逻辑；重新打开网页或激活已有实例不会触发。自动启用仍需有效的条款确认记录，不自动修改 hosts。启动失败会在页面显示原因并写入日志，控制台继续运行，队列不因此关闭，可处理后手动重试。配置字段为 `autoStartCDN`。
- **启动 / 关闭播放网关**：同时控制 `127.0.0.1:80` HTTP 播放和 `127.0.0.1:443` HTTPS 透传。启动检查两个端口和目录权限，任一失败均回滚监听；页面分别显示两个端口状态。端口占用时提示关闭原版 CDN 或其他程序，不自动结束其他进程。hosts 缺失不阻止监听，提供独立修复按钮。停止会关闭已有播放连接，但保留独立下载任务。
- **检查缺失视频**：从 Kiva 清单获取歌曲 ID、名称与 MD5，新增和更新本地映射，保留清单中消失的旧 ID。一次枚举视频目录，检查所有被引用的 MD5 文件是否存在；不读取正文、不计算 MD5、不关心孤儿文件。上层直接使用检查结果。可与队列预缓存和播放并行。
- **下载补齐**：每次重新获取清单并更新映射，使用独立的快速缺失检查，只为缺失 MD5 解析 URL 和下载。同 MD5 多首歌曲只下载一份，已有文件不重复检查。映射不变但文件缺失也会补齐；映射变化但文件已存在无需下载。清单不可用时使用本地已接受的 MD5 映射继续处理；本地没有有效清单时明确报错。URL 的 MD5 与清单不一致时记录失败，清单关联保持不变。
- **停止批量任务**：取消排队和当前等待；已开始的共享下载继续执行，直到完成、失败或程序退出，以免打断游戏。关闭播放网关只关闭播放入口，不停止队列预缓存或独立批量下载。退出控制台进程会取消全部下载。
- 成功结果与当前任务进度分开显示。完整任务无接口或读取错误时才替换成功结果；扫描中、失败或取消均保留上次成功计数。任务结束或正常停止时另存进度记录。重启恢复记录，但不会自动继续任务；暂不提供下载断点回源。
- 下载补齐按视频缓存容量预算执行：下载前按完整视频大小预留空间，两首并发共享预算，已有视频不重复计费；剩余预算放不下下一首时自动停止，不计为失败，也不保存为全曲库成功结果。已获准的下载正常完成，界面提供前往设置调整「缓存空间上限」的入口；保存新预算并重启应用，再次点击下载补齐即可继续。0 表示不持久保留缓存，网页禁用下载补齐；选择「不限制」才跳过预算。本轮已使用的预算不会因淘汰而循环释放，避免边下载边淘汰整份曲库。命中和下载计数是过程累计值，当前保留数量与占用空间通过「更新清单并统计覆盖率」更新。
- 缓存概览先检查远端并按版本规则更新本地库，再按本地歌曲 ID 对照 MD5 文件存在性，包含隐藏曲目和保留的旧 ID，共用文件按歌曲分别计入覆盖率；文件数按唯一 MD5 计数。远端失败或候选无效时仍重新计算本地覆盖率，并显示检查错误；本地读取失败才保留上次结果。由用户手动刷新，不自动重复扫描。
- 结果写入配置实例数据根下的 `state/inventory.json`、`state/batch.json` 和 `state/attempt.json`，写入临时文件后替换；文件随便携目录移动。更换存储目录时不会沿用其他目录的结果。

## 实时下载监控

控制台在最近请求上方显示活动共享任务及上游总下载速度。`GET /api/downloads` 使用控制台 token、Host 和 Origin 检查；读取内存中的线程安全快照，按资源共享任务去重，曲目候选从已有索引补全，不读取日志或启动缓存引擎。多个 Range、播放请求和预缓存加入同一任务不会重复计速。

监控读取不获取控制台生命周期锁，启动、停止、保存设置或引擎关闭期间仍可返回当前快照。歌曲资料查询在锁外进行，受查询期限和引擎取消控制；引擎关闭或被替换时丢弃旧任务快照，不等待关闭操作完成。

字节数为从上游正文实际读取的字节；速度是最近约 5 秒的估算值（按秒分桶，启动不足 5 秒按已用时间计算），不是网卡流量，也不是向客户端传输速度，不包含选路探测、API 查询或 HTTPS 透传。停止读取后速度衰减为零，发布及索引阶段速度为零。总大小来自已解析资源的预期大小；字节百分比不是整个任务完成率，下载时同步计算 MD5，随后仍需验证并发布。任务可能先显示本地缓存检查阶段，命中后不回源。

主行突出歌名、进度和上游速度，资源来源按最终响应域名显示，响应前显示线路待定。完整资源指纹、最多 20 首关联曲目（超出时提示更多）、最终主机名（含已验证的重定向）及空闲时间默认折叠在「下载详情」，统计口径放在「下载统计说明」。详情支持键盘展开，轮询保留展开状态与焦点。不暴露签名 URL 或代理凭据。歌名来自显式任务关联和已有资源映射；共用资源标明关联曲目数量及播放歌曲未确定，不推断实际播放歌曲，未知信息明确标注。

活动任务完成、失败或引擎退出后移除，下次轮询更新；关闭播放网关或取消等待者不会取消现有共享下载，因此播放网关关闭时仍可显示继续运行的下载。没有任务时显示空状态；读取失败清空旧列表和速度并自动重试。复用全页面每 5 秒、无重叠的轮询批次，页面隐藏时不再发起新轮询。尚未进入共享下载的容量等待和歌曲地址解析不在此列表中。

## 队列预缓存与刷新频率

队列预缓存的操作和轮询规则见[日志队列预缓存](queue-prefetch.md)。房间队列预缓存展示在「准备歌曲」中，通过独立按钮启停；设置的「控制台启动」中，「运行控制台时自动启用房间队列预缓存」（`autoStartQueue`）默认启用，独立于播放网关，保存后下次启动应用生效。已有配置明确关闭时保留该选择。日志目录默认每次启动按当前用户自动读取，自定义路径需勾选「手动指定 VRChat 日志目录」。开启后等待新队列同步，不会下载历史日志里的歌曲。队列预缓存与全曲库下载互斥，下载补齐期间暂停，结束后仅在用户仍希望开启且应用未退出时恢复，暂停期间关闭则不恢复；视频扫描可与队列预缓存和播放网关播放同时运行。

网页状态在可见时每 5 秒刷新，隐藏时暂停轮询，恢复可见时立即刷新。操作完成后，页面可见时立即刷新，隐藏时等待恢复可见再刷新；已发出的展示请求正常完成。播放网关、下载、日志监听及已启动的扫描任务独立运行，不受网页是否打开或可见影响。

操作请求最多等待 30 秒，hosts 操作因可能等待管理员授权而延长到 120 秒；期限包含响应体读取。超时或响应丢失后解除操作等待，并刷新当前状态供核对，不自动重试。页面提示「结果尚未确认，请勿重复提交」：停止浏览器等待不会取消后台操作，刷新得到的状态也不能证明原请求已经结束。状态查询失败时保留提醒，待连接恢复后继续核对；页面隐藏时延至恢复可见再刷新。

## 上游连接

直连模式使用内置加密 DNS 解析域名，并连接目标 IP，可能影响透明代理的域名分流，使实际连接路径与预期不一致。如需由代理处理域名解析和连接，请选择「强制代理」并配置所选后端。

在「偏好设置」中选择「上游连接」：默认「直连（内置 DNS）」沿用内置 DoH 与多 IP 优选连接；选择「强制代理」或「自动选择直连或代理」，再选择「外部 SOCKS5」后，填写代理软件的 `主机:端口`，例如 `127.0.0.1:7891`，不加 `socks5://` 前缀。端口以代理软件实际的 SOCKS5／混合端口为准。支持无认证及用户名／密码认证；需要认证时同时填写用户名和密码，各限 1～255 字节。

密码以版本化 DPAPI CurrentUser 密文保存在配置文件中，不通过状态接口回传，不写入任务快照。同一 Windows 用户移动目录或覆盖程序后仍可解密；换用户或普通独立机器后可能无法解密，并提示重新输入。不可用的密文会保留，强制代理不会回退直连；Auto 仍按既有直连优先策略运行。非 Windows 不支持保存代理密码。页面区分已保存且可用与凭据不可用；密码框留空保留已有密码，填写新值则替换；清空用户名和密码后保存可移除认证。切换回直连会保留认证配置，便于再次启用。设置 API 省略 `socks5Password` 时保留原值，显式发送空字符串则清除；用户名与密码须配对。变更凭据保存后在重启应用时使用，当前网络客户端保持不变。

选择「内嵌 Mihomo」时，设置页和引导使用同一节点导入界面。选择本地文件或粘贴 YAML 的 `proxies`、逐行 URI 或 Base64 URI 列表（最多 2 MiB / 2048 条），点击检查后逐条核对接受、重复跳过和失败。使用 Mihomo 原生节点解析（含 VMess/WS），拒绝代理组、链式代理、文件或系统网络能力等受限选项，不再按协议维护基础字段白名单。不会加载完整运行配置、下载订阅或自动更新。检查不写配置、不改变当前网络；保存设置或引导最终应用才用成功条目替换整份节点库，全部失败不替换，重启后生效。草稿只在内存保留 2 小时，过期或另一页面更换了节点库时须重新导入。清除本次导入、替换草稿或放弃本轮引导会释放相应草稿配额；进入引导前已有的普通设置草稿仍保留，退出后可恢复。

整份节点快照使用 Windows 当前用户加密保护；无法解密时保留原密文并提示重新导入。页面分别显示已保存、当前已加载和活跃数量。默认最多 5 个节点参与业务与测速，备用节点配置及历史保留；初始集合按稳定身份排序，不代表延迟最低的 5 个；活跃节点失败时不会自动晋升备用节点。需要改用备用节点时，重新导入所需的小规模节点集合、保存并重启；动态准入和轮换留待后续。保存顺序、展示名或活跃上限不改变节点身份，服务器和凭据变更会改变身份。内嵌节点的服务器域名由受控 DNS 解析，业务目标域名交由固定出口处理。通道身份密钥异常时使用本次临时身份并提示，不复用旧测量；没有有效活跃节点时强制代理明确失败。

API 查询、校验和清单、冷缓存播放、队列预缓存、下载补齐和选路测速使用所选出口；应用的 HTTPS 回源也遵循策略，游戏 HTTPS 兼容透传始终直连。外部 SOCKS5 后端把目标域名和端口直接交给 SOCKS5，不在 Still Wanna Dance 中解析目标域名，不使用内置 DoH 或多 IP 直连，不检查代理端如何实现 DNS；代理不可用或拒绝连接时返回错误，不自动回退直连。原域名 Host、TLS SNI 和证书校验保持不变。代理服务器地址本身若填写域名，由本机网络解析；本地代理推荐填写 `127.0.0.1`。

运行中允许保存配置；当前及后续任务继续使用本次应用启动时的配置，重启应用后统一应用新配置。保存不会重建上游客户端或缓存引擎，不取消覆盖率查询。详情见[配置与运行生命周期](settings-lifecycle.md)。旧配置默认直连，切回直连会保留代理地址方便再次启用。播放接口选项仅决定 API 查询参数，资源域名由返回值决定，测速经过当前所选出口；完整缓存的本地读取不经过代理。

SOCKS5 使用本地模拟服务验证域名转交、API HTTPS、缓存回源、游戏 HTTPS 直连分离、取消和设置切换；真实代理线路的持续吞吐与 VRChat 联合播放仍需实机验证。

## 独立 DNS

### 网页 HTTPS 播放

hosts 同时影响 HTTP 和 HTTPS。控制台启动播放网关时提供 TLS SNI 透传，防止网页的视频 HTTPS 请求被映射到本机后遭到连接拒绝。仅接受 `api.udon.dance` 和当前已由有效 API 响应确认的资源域名；新 hosts 接管只写入 API 域名，资源域名不预设，始终通过受控 DNS 直连其 443 端口，不读取系统 hosts；即使应用选择强制代理，兼容透传也不改变路径。不使用额外的 `ud-*` 回源别名，不开放通用代理。网页、封面和统计域名不纳入接管。

转发始终复用下面的独立加密 DNS、TTL 缓存和双栈连接机制，优先尝试 IPv6，必要时尝试 IPv4；直连失败不会改走代理。固定保留域名的原上游，不套用 HTTP 的播放接口参数设置，不跨线路替换路径或签名。TLS 握手及后续密文字节原样传递，浏览器直接验证原站证书；不安装证书、不解密、不改网页、不降级为 HTTP。网页 HTTPS 播放仍消耗上游流量，不命中或填充本地视频缓存，也不计入缓存热度。

只绑定本机 IPv4，最多 128 条连接，ClientHello 限制为 64 KiB / 10 秒，建连最多 15 秒，两分钟双向均无进展的连接关闭。关闭播放网关会取消解析和建连并清理活动连接。此入口不支持无 SNI 或隐藏目标域名的握手，也不提供 QUIC/UDP 443。

回归覆盖 TLS 1.2 / 1.3、原站证书验证、HTTP/2、Range/HEAD、分片 ClientHello 原样转发、未托管域名拒绝、建连和活动连接取消，以及端口冲突/目录失败的回滚与重启。需要浏览器实网复验时，先释放本机 443，使用当次 API 返回的实际资源域名进行本地连接测试，在 PowerShell 中运行 `$env:SWD_HTTPS_LIVE='1'; go test ./internal/console -run '^TestHTTPSLiveBrowser$' -v -count=1`。此显式验收辅助服务先通过两个播放接口发现歌曲 1343 的资源域名并打印集合，仅监听 443，两分钟后自动退出，不改 hosts 或缓存；普通测试和 CI 默认跳过。它仅为手工验收提供连接窗口，测试通过本身不代表视频播放成功，须另行检查浏览器。

历史 Chrome 实测（2026-09-26，切换公开域名前）：通过上述辅助服务从原站点击歌曲 6228，播放器 `readyState=4`、`error=null`，播放时间推进到 13 秒；重新打开当时 node=nya 返回的地址后，重定向到 play.udon.dance，继续播放至 37 秒。当时服务连接的是 `ud-nya.kiva.moe:443` 和 `ud-play.kiva.moe:443`，不代表当前默认目标。没有改写网页、视频 URL、系统证书或 hosts；这是该歌曲当时的连通与播放验证，不代表全曲库或持续吞吐测试。

当前公开域名回源的实网验收见[调查后的实现与验证](playback-domain-observation-20260926.md#调查后的实现与验证)。`SWD_LIVE_UPSTREAM=1` 启用的 `TestLiveHTTPSUpstreams` 会让测试客户端连接临时本地 TLS 透传端口，模拟 hosts 接管，再通过生产 DoH 连接公开域名；验证 API 实际返回地址的视频片段及原站证书，不修改系统 hosts。

### 解析与连接

以下机制适用于直连模式。控制台的歌曲列表、播放地址解析、视频回源均只使用证书验证通过的 HTTPS DNS（RFC 8484 POST），不查询 ISP 或系统 DNS，不读取系统 hosts，也不会在失败时降级到 UDP、HTTP 或自动接受 fake-IP。TLS 使用系统信任库并校验服务域名，拒绝重定向、错误媒体类型、过大或不匹配的 DNS 报文。

内置服务：

| 服务 | HTTPS 入口 | 引导方式 |
| --- | --- | --- |
| 阿里公共 DNS | `https://dns.alidns.com/dns-query` | `223.5.5.5`、`223.6.6.6` 两个独立连接入口，仍验证域名证书 |
| 腾讯 DNSPod | `https://doh.pub/dns-query` | 通过已验证的加密解析获取入口 IP，并按 TTL 缓存 |
| 360 安全 DNS | `https://doh.360.cn/dns-query` | 同上 |
| Cloudflare | `https://cloudflare-dns.com/dns-query` | `1.1.1.1` 引导，验证域名证书 |
| Google | `https://dns.google/dns-query` | `8.8.8.8` 引导，验证域名证书 |

DNSPod 和 360 的入口发现只通过具备固定引导 IP 的 DoH 服务进行，不依赖本地 DNS；同入口并发引导合并，后续读取 TTL 缓存。没有硬编码 DNSPod 已下线的测试 IP。官方依据：[阿里服务资料](https://static-aliyun-doc.oss-cn-hangzhou.aliyuncs.com/download%2Fpdf%2F171662%2FAPI_Reference_intl_en-US.pdf)、[DNSPod 域名接入公告](https://docs.dnspod.cn/notices/mian-fei-ban-dot-dohbu-zai-gong-kai-ipjie-ru-de-gong-gao/)、[DNSPod 旧测试 IP 下线公告](https://docs.dnspod.cn/notices/guan-yu-doh-dotdu-li-ce-shi-ipxia-xian-de-gong-gao/)、[360 官方服务页](https://sdns.360.net/dnsPublic.html)。

直连并发查询 A 与 AAAA，DNS 只维护有效地址池与 TTL，不记录连接胜者。普通建连采用成熟的 Happy Eyeballs 组件，优先尝试 IPv6并自动回退 IPv4；已由 Monitor 测速选定的 IP 则继续固定使用。双栈地址池、连接间隔、代理边界及验证以[上游通道的请求与连接规则](upstream-channels.md#请求与连接)为准。视频请求仍保留原始 HTTP Host，历史 UI 中 HKG 对应查询参数 `node=nya`，不代表资源域名。

全部加密通道失败时明确报错。这保护的是客户端到解析服务的 DNS 链路，仍信任所选解析服务及系统证书信任库；DNS 模块本身不改变视频或 API 请求的 HTTP/HTTPS 协议。曲库业务仅使用 Kiva／WannaInfo 的 MD5 清单，Udon `https://api.udon.dance/Api/Songs/list` 只用于 monitor，不参与本地曲库更新或水位计算；游戏请求的 HTTP→HTTPS 跳转与 HTTPS 透传继续保留；播放地址 API、版本确认、视频下载、测速和 Range 回源统一使用 HTTPS，保留原始 Host、TLS SNI 和证书域名校验；连接或证书失败不降级至 HTTP，也不回退系统 DNS/hosts。此前依赖明文 DNS 劫持产生 fake-IP 的代理路径不再由此模块自动使用。

2026-09-25 本机逐入口真实解析 `api.udon.dance`：阿里双入口、DNSPod、360、Cloudflare、Google 六项均通过 HTTPS 证书验证与 DNS 报文解析。这不代表其他网络始终可达。可选复测：`SWD_LIVE_DOH=1` 后运行 `go test ./internal/console -run '^TestLiveDoHProviders$' -v -count=1`。
控制台与独立命令行服务共用内置 DoH 建连逻辑。两者的上游 API 查询和视频回源均使用 HTTPS，默认视频回源端口为 443；DNS、连接或证书验证失败不回退系统 DNS/hosts 或明文 HTTP。视频重定向仅在目标域名已由有效 API 响应确认且 MD5/大小一致时跟随，最多五次，HTTP Location 升级为 HTTPS 后访问。

## 目录与配置

填写一个存储根目录并保存；不读取旧歌曲库或提供迁移。运行播放网关或批量任务时也可保存目录设置，统一在重启应用后生效；保存时检查存储目录可写性。保存只探测已有父目录的可写性，不提前创建媒体目录；尚未启动引擎的新路径或空目录可直接扫描，显示零视频、零占用；已初始化目录丢失视频目录或无法读取时仍报错并保留上次结果。VRChat 日志目录不创建或修改。

首次成功打开控制台即保存带 `schemaVersion=3` 的规范化配置；无需先点击保存。无版本或不支持的配置被拒绝，遇到未来版本时提示更新程序，同版本未知字段在保存时保留。各平台默认将设置保存在可执行文件旁的 `data/config.json`，不随启动工作目录改变。可通过 `-config` 指定其他配置文件（该参数的相对路径基于启动工作目录）。存储及日志的相对路径基于配置文件所在目录解析。保存时，该目录内的路径转为相对路径，外部路径保留绝对路径，便于整体移动 portable 文件夹。默认存储根目录为 `data/storage`（配置中保存为 `storage`）：正式视频仅存于 `videos/{md5}.mp4`，临时文件位于 `tmp`，歌曲资料与统计位于 `storage.sqlite`。每首歌引用一个当前资源，多首歌可共用同一文件；仍被其他曲目引用或正在使用的旧资源继续保留；下载及发布临时副本另需空间。可设置[视频容量上限及自动淘汰](cache-retention.md)，默认容量不限；无歌曲引用的旧内容作为零分孤儿参与容量淘汰。详见[统一存储](storage.md)。

记录堆栈，但该日志不保证捕获其他 goroutine 的未恢复 panic、系统强杀或断电。

排障时可提供当前日志和轮转文件。日志可能含本机路径、歌曲 ID、视频请求路径

### 统一回源选路

播放地址接口默认 Auto。业务按操作、入口、节点、资源域名和网络模式约束使用 Monitor 提供的实际 Transport。API／清单请求顺序尝试候选，并按剩余时限为备用保留时间。Mihomo 先保留 Monitor 推荐的相对顺序，再追加当前活跃、尚未入列的候选，不因部分节点尚无观测而失去回退；其他后端无有效观测时使用配置通道。强制代理只尝试代理，Auto 同时为直连及活跃代理保留位置。固定模式约束 API node，不从 node 推断资源域名。下载核心不查询歌曲 API，不维护路由缓存，也不现场测速或独立排名。

资源 Range 请求单独保留本次候选进度：首块或后续区块的范围校验、实体标识检查、短读和网络失败可推进到备用通道，不从首选重新开始。后续区块发生重定向时，只在该区块内保留已验证的最终地址，失败后继续该地址的备用通道。API 与资源使用统一的六候选上限；每个资源地址最多尝试六个候选（默认五个活跃代理和一个 Auto 直连），包含尚无推荐的活跃候选；只有一个通道时，区块失败最多再试一次。多个候选按任务剩余期限分配时间，预算覆盖响应头及 206 正文读取，成功返回响应头不会立即取消请求。若确认上游忽略 Range 并返回合法 200 全文，则撤销候选预算，由整个任务剩余期限约束顺序下载。已经输出的区块不替换；全文降级不据此承诺任意拖拽。

即时播放和队列先保护并检查本地资源，同时独立刷新 API 地址。本地完整资源立即使用；本地缺失时先尝试持久化 URL，失败再等待已有查询。地址记录保留完整 URL、API/node、MD5、大小及观测顺序，当前复用窗口为 24 小时，不保证签名始终有效。新观测不替换已打开资源或已有清单映射。

下载补齐按清单 MD5 调度，对同资源关联的歌曲依次查询，取得目标内容后停止。播放、队列和补齐共享 MD5 下载任务、区间数据、容量保护及最终校验。旧拖拽最后一个读者离开后，可取消其前台区间；后台继续补齐未完成区块。已输出正文后不能切换内容。

资源以 API 实际返回域名区分，同域名不代表相同 URL 或相同内容。当前下载任务可继续访问受信任原始域名的同域重定向；跨域仍需来源许可，所有重定向仍校验 MD5 和大小。这不扩大任意入站资源请求的域名权限。独立命令行服务不提供控制台的 Monitor 推荐回调，接入限制见[服务手册](service.md#游戏接入)。

## 播放请求统计

控制台通过 /api/status 的 traffic 字段展示当前存储目录的累计请求命中、节省流量和首正文时延。命中率分母为成功完成的 GET 视频请求（200/206），Range 按请求计数；HEAD、失败、中断和预下载不计入。节省流量是成功命中实际返回的正文大小，不是扣除预下载后的净流量收益。

播放传输次数另行保存，仅计有明确歌曲 ID、成功完成且返回正文的即时 GET。同曲按成功完成的记录时间以 30 秒窗口去重，不使用请求开始时间；记录时间与入队顺序在同一锁内确定。历史累计不回算。该指标不改变需求评分，也不代表客户端起播或完整播放。

首正文时延从 HTTP 请求开始到首次写入正文，包含 API、下载等待和本地验证。HIT/MISS 分别展示均值与样本数，历史响应头计时不混入新口径。不把不同阶段的 Monitor 样本相加，不计算未配对样本的加速比例。完整传输耗时、首正文和客户端首帧是不同指标。

## HTTP 播放 API 接管与 HTTPS 回源

点击「修改 hosts」接入 `api.udon.dance`；旧版托管的资源域名映射会清理，不再预设资源域名。只要仍有本程序拥有的旧资源映射，即使 API 已映射也会标为待迁移、接入未完成；「启用游戏加速」会执行清理并重新检查。自动启动仅启动服务并显示迁移提示，不自动提权。其他程序或用户的条目不属于迁移范围，被修改的托管条目需手动检查。资源集合与历史记录的解释见[资源域名规则](resource-domains.md)。游戏以 HTTP 请求 `/Api/Songs/play?id=…` 时，Still Wanna Dance 使用 HTTPS 解析上游地址，校验资源指纹，然后直接以 HTTP 返回视频；命中复用缓存，未命中边下边播，支持 HEAD 和单段 Range。支持默认线路以及 `node=cf`、`node=nya`，其他线路明确拒绝。非播放 API 的 GET/HEAD 重定向至原站 HTTPS；原有 HTTPS 请求通过 443 透传，不读取或填充缓存。

游戏入口必须仍使用 HTTP，并且播放器需接受 API 地址直接返回视频；当前 HTTP 播放 API 接管的实际游戏兼容性需要实机确认。仅接管 API 的前提是解析器和播放器能通过这个直接返回视频的本地入口完成后续读取。历史上正常解析后请求资源 URL 有证据；“新的播放绕过 API、复用旧资源 URL”则尚无发生证据、频率统计或稳定复现步骤。假设、条件性担忧及实机验证要求见[仅接管 API 的假设与待验证边界](resource-domains.md#仅接管-api-的假设与待验证边界)。服务端改用 HTTPS 回源不改变当前统一存储的资源指纹；此说明不表示兼容旧存储格式。下载和测速最多跟随五次视频重定向，仅接受当前 API 确认的视频域名且 MD5/大小一致的地址；HTTP Location 会升级为 HTTPS 后再访问。其他重定向明确拒绝。

HTTP 播放 API 优先使用受保护且校验通过的本地文件，不等待后台 API。缓存 URL 下载失败时，尚未输出正文可等待本次已有查询再尝试；旧下载与刷新都失败时保留两个阶段的错误。正文输出后仍中止响应，不切换内容。HTTPS 透传不适用；加载边界见[歌曲加载设计](song-loading-design.md)。

可选实网验收：设置 `SWD_LIVE_UPSTREAM=1`，运行 `go test ./internal/console -run '^TestLiveHTTPSUpstreams$' -v -count=1`。仅解析播放 API 并读取每路 1 KiB 视频 Range，不修改 hosts。

## 最近请求监控

导航中的「最近请求」显示按记录时间倒序排列的已结束 HTTP 视频请求。每 5 秒随控制台状态刷新，页面隐藏时暂停；「加载更早记录」每次将近期窗口增加 50 条，上限 500 条。查询先筛选 HTTP 请求，再通过专用部分索引 `request_events_http_time` 按记录时间和事件 ID 倒序读取最多 501 条 HTTP 记录；预缓存不占用窗口，hasMore 也仅统计 HTTP 请求。旧数据库首次读取会补建该索引（只为已有数据库临时打开可写连接，不启动播放网关）；以后轮询仅通过索引读取有限记录，不扫描日志或整个请求表。保留天数与现有请求明细设置一致；没有数据库时显示空列表，不创建数据库或启动播放网关。读取失败单独提示并自动重试，存储切换清空旧窗口。

同一资源连续的 GET Range 请求，记录时间间隔不超过 30 秒时组成请求组；其他资源的交错请求不影响分组，同资源 HEAD / 完整请求会打断分组。组只覆盖当前窗口，边界可能截断，扩展窗口后重新计算。展开状态和仍存在的展开控件焦点在正常刷新时保留；混合缓存、完成、中断和失败结果分别列出次数。×N 是请求次数，不是播放次数。

歌名来自 `song_media` 与 `songs` 的当前资源关联，不保存或展示历史所属歌曲。共用资源显示多首候选歌名，不推断实际播放曲目；无关联时显示未知歌名，展开后显示完整资源标识。主行以歌名为主，缓存与结果使用独立标签，传输量、耗时和速度各自对齐成列；窄屏改为分行网格。多曲目主行最多显示两个标题并提示共享资源，展开后列出完整候选、Range 和资源指纹。每个资源最多返回 20 首、每个标题最多 300 字符，多余关联明确标注。API 不返回签名 URL、主机、源路径或 metadata JSON，非标准 Range 内容被替换。`GET /api/requests?limit=50` 要求当前会话的 `X-SWD-Token`、合法 Host 与同源 Origin（如提供）；limit 必须为 1～500。

实际传输量是响应向客户端写入的字节数，MB 使用十进制，不是视频大小或后台回源量。单次耗时包含地址解析、等待与校验。GET 的记录时间在播放地址解析后更新，但单次耗时从 HTTP 处理开始计量，两者起点不同。多请求组按最早记录时间至最晚「记录时间 + 单次耗时」计算**估算跨度**，包含请求间隔，不相加并行耗时；**估算平均速度** = 字节和 / 估算跨度。这两个组指标均在界面标为估算，不代表精确起止时间；单条请求的耗时与速度仍使用其原始 elapsedMS，0 毫秒显示「—」。

HTTP 200 / 206 不单独决定完成状态；保留记录的 canceled / aborted / failed 语义，旧版写入失败且无错误 HTTP 状态显示「写入失败 / 连接中断」，不能据此断定后台下载失败。读取时会将已知长度下的短传输标为不完整，不修改原始明细或累计统计。处理完成也不证明客户端播放完成。尚在进行、尚未写入、队列溢出丢弃，以及资源识别之前被拒绝的请求不在此列表中。

自动吞吐检测间隔可在 WebUI 设置中调整，默认 20 分钟，允许 1～1440 分钟整数，对应 throughputIntervalMinutes。旧配置未设置时采用默认值。保存并重启应用后，按最近测速尝试时间计算到期时间，不重置计时；缩短后已到期则开始调度。此设置同时决定吞吐样本参与推荐的有效期，首字节检测频率不变。运行中保存不会改变当前监测策略。

## 本地清单与检查状态（2026-10-06）

覆盖率、扫描和下载补齐始终先尝试检查远端、按规则同步本地，再读取本地快照开展业务。远端不可用时使用已有本地清单重新计算，不沿用旧的文件计数；没有有效本地 MD5 清单则提示无法处理。正常联网时也使用同一流程。Udon 清单仍仅用于 monitor。
