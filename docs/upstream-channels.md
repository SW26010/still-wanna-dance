# 上游通道与检查器设计

## 职责与边界

允许的播放 API 来源由 [playbacksource](../internal/playbacksource/source.go) 定义，地址提供层据此解析和筛选候选；通道层只为已获准的入口提供连接。播放、队列、预览和批量补齐的接口不选择 CDN。完整职责与不同查询生命周期见[下载设计](download-resource-design.md#播放地址提供与连接执行)。

DNS 仅维护答案合法且 TTL 未过期的 IP 池、刷新和并发查询合并，不记录连接胜者，不测延迟或吞吐。通道层组合入口与传输路径，维护可执行的候选及稳定身份。Upstream State Monitor 对每个操作、入口、通道分别测量，提供推荐；业务仍负责资源版本校验、下载和失败处理。

`internal/upstreamnet` 统一承载独立 DoH、DNS 池与刷新、双栈拨号及 SOCKS5 adapter；命令行与 Console 直接复用它，分别拥有解析器的关闭责任。`upstreamrequest` 继续定义候选池与拨号契约，Console 只组装配置、连接池及应用生命周期。协议测试随网络实现维护；Console 测试通过相同网络契约注入夹具，不读取解析器私有缓存。现有 CF 实验的细粒度观测仅在 `cf_block_experiment` 构建中提供，正式产品不包含实验探针。

直连候选为 `入口主机 × IP`；SOCKS5 候选为 `入口主机 × 当前代理配置`。SOCKS5 始终传递原域名，让代理解析目标，绝不展开本地 IP。代理凭据不进入候选 ID、检查结果或日志。配置版本由应用请求通道持有，旧版本观测不能用于新版本。

代理后端可选外部 SOCKS5 或内嵌 Mihomo，二者均为单一逻辑出口。内嵌核心使用全部已加载节点，由原生选择组、健康检查与 fallback 管理；zashboard 负责用户选择和连接操作。SWD 不维护活跃子集、每节点排序、迟滞或吞吐历史。配置继续由 SWD 管理，保存后重启生效；面板选择影响新连接。完整职责和控制边界见 [Mihomo 与 zashboard](mihomo-dashboard.md)。

## 模式

- `direct`：不启用代理，只生成直连候选。
- `socks5`：代理，只生成代理候选；失败不得回退直连，也不查询本地目标 DNS。

应用配置只使用 direct/proxy；proxy 映射为底层 socks5 通道模式，不接受旧配置别名。普通业务请求继续使用现有客户端；通道候选和推荐携带实际 Transport，使用推荐时能够固定到被测路径，不在传输时重新选 IP。Monitor 不导入 console/DNS，也不创建代理；基础设施发布候选提供者。

Console 的清单、播放地址和资源请求只在当前模式内选择候选：已测推荐排在前面，补入同模式当前可用且未重复的候选，最多保留六个。部分候选尚无观测不影响其业务回退资格，也不伪造测量。冷启动的清单和播放地址请求在没有候选时按需发现通道；直连执行内置 DNS，代理仅使用配置的出口。发现和请求共用调用者上下文，单条通道失败可继续同模式的下一条，不触发临时测速、不改写 Monitor 结果。没有可用候选或客户端未提供候选接口时保留该模式的普通请求路径。直连不初始化 Mihomo；代理不加入直连候选、不执行本地目标 DNS，也不回退直连。

## 请求与连接

### 业务请求的协议策略

三个清单入口、播放地址解析和视频资源共用 `upstreamrequest.Attempts`：独立请求默认 HTTPS，按既有推荐顺序尝试路径；只有传输错误、超时或正文截断才允许 HTTP 回退。同一路径的 HTTPS 请求成功就直接使用，不比较 HTTP 是否更快。证书校验失败、HTTP 错误状态、完整但非法的内容、取消及本地通道／代理容量错误不授权降级；同一端点本轮出现这些错误时继续允许其余 HTTPS 候选，但不再转 HTTP。原始资源 URL、API 来源身份和业务校验规则不随执行协议改写。DoH 与客户端 TLS 透传不采用这项回退。

每个端点的候选变化、协议回退和同端点 HTTP→HTTPS 升级共用最多六次请求尝试；协议变更不会创建新游标。按候选顺序完成该路径的 HTTPS 及获准的 HTTP 回退，再进入下一路径；不再先枚举全部 HTTPS、只把最后一个名额留给 HTTP。因此，排序较前路径的合格 HTTP 成功可以先于后续路径的 HTTPS 尝试。HTTP 升级只接受原主机、路径及参数完全一致的 HTTPS 端点（301/302/303/307/308），占用一次尝试并禁止本轮再次降级，后续路径也使用 HTTPS。播放 API 返回的视频 Location 仍由业务解析，资源的其它重定向继续遵守其域名、MD5、大小及跳转次数限制。重定向目标的传输失败只记到目标端点，不赋予起始端点降级资格；Monitor 对回到已访问资源端点的跳转按回环失败处理，不重新获得预算。

清单和播放地址的完整读取／校验在一次尝试内完成，所有尝试受调用者期限限制。响应头等待按剩余路径及可能的协议回退分配时间，单候选也为回退留出等待预算；收到响应头后，正文保留原单次尝试和调用者期限，不按候选数量切短正常正文读取，也不因收到响应头延长原期限。视频游标跨响应头、Range 校验及正文失败保留，每次仍使用既有 DownloadTimeout；顺序 200 正文开始后不在中途重开或混合协议续传。独立请求与 Monitor 每次从 HTTPS 开始；没有持久化协议健康缓存、熔断状态或恢复轮询。

短期顺序批量读取可显式使用 `upstreamrequest.Session`，复用本批内完整校验成功的路径及协议，每次读取仍有独立的六次尝试上限。失败立即废弃偏好，并按同一游标尝试其余路径；业务／证书／本地错误仍禁止本次读取继续降级。同一端点由源 scheme、主机和路径限定，查询参数变化可复用；端点变化或新批次重新从源协议和候选顺序开始。Session 不启动任务、不持久化、不跨并发调用者共享；调用者拥有批次期限，连接层继续校验 DNS 和配置有效性。

Monitor 使用同一尝试规则，记录实际执行的 `scheme`，不另建 HTTP/HTTPS 探测矩阵。协议变化时不混合延迟样本，也不将另一协议的历史吞吐用于当前速度估计。健康 HTTPS 即使暂缺吞吐也可参与推荐；同协议内有有效吞吐的候选优先，健康且已有有效测量的路径继续遵守原有切换迟滞。旧 schemaVersion=2 吞吐样本缺少 scheme 时代表历史 HTTPS，新保存的样本明确记录协议。

协议决策与错误分类集中在请求尝试 module，连接 adapter 仍只执行指定路径，清单、播放和下载各自负责内容校验及生命周期。资源 Monitor 与下载模块的整体合并不属于本次调整；不新增另一套资源执行状态或调度机制。

直连 Transport 固定目标 IP，但保留原 URL、HTTP Host、TLS SNI 和证书校验。候选仅允许自己的主机；禁止重定向悄悄变成另一条通道。请求和建立新连接前检查 IP 是否仍在有效 DNS 池中；原地址过期时通过共享解析器重新确认，只有同一 IP 获得有效答案才继续，解析失败或原 IP 已移除仍拒绝，不切换线路。已建立连接和进行中的响应不因 TTL 到期被取消。

未测固定 IP 候选从 IPv6 开始交错排列 IPv6/IPv4，单族继续按有效地址排列，避免冷启动先耗尽同一地址族；Monitor 的已有推荐不受此顺序覆盖。普通双栈竞速只决定 TCP 连接，TLS 或业务请求随后失败时仍由请求层继续候选尝试，不永久禁用某个地址族或固定历史 CF IP。

普通直连和 HTTPS 透传使用双栈拨号。独立 DoH 并发查询 A 与 AAAA，沿用首个可用答案后 200 ms 的收集窗口、整体六秒上限与最多六个 IP 的池；池满时交替保留两种地址，避免先返回的一族占满池。TTL 取收到的有效地址及 CNAME 链的最小值，最多 300 秒。单族无答案或超时不阻塞另一族，超过窗口的答案不加入本轮池。DoH 自身仍使用现有 IPv4 引导地址，因此这里支持双栈网络及仅有 AAAA 的目标，不承诺纯 IPv6 接入网络可用。

通过报文校验的 NOERROR 空答案（含仅返回 CNAME 的情况）是正常的单族无记录，不重试同一 DoH 服务的另一入口 IP、不清除引导缓存，也不建立负缓存或影响另一族的 TTL。HTTP/传输故障与无效报文仍按原规则重试并在入口均失败后清除引导缓存；两族及所有服务均没有可用地址时，整体解析仍报错。

连接阶段复用 [Outline SDK 的 HappyEyeballsStreamDialer](https://pkg.go.dev/golang.getoutline.org/sdk/transport#HappyEyeballsStreamDialer)，适配已有 DNS 池，不读取系统 hosts。两族都有地址时先尝试 IPv6，未连通则按组件默认的 250 ms 间隔交替尝试，明确失败可提前尝试下一地址；每次 TCP 建连最多五秒，同时受调用者期限约束。首个成功连接被使用，其余尝试取消并关闭。应用不另设竞速计时器、连接胜者缓存或 IPv6 评分。Go 原生 Dialer 没有直接接收已解析 IP 列表的入口，故这里保留独立 DoH 并使用允许注入解析结果的组件。DNS 收集仍按上述池机制完成，没有改为流式返回每个解析答案。

“优先 IPv6”适用于普通直连建连；Monitor 已选中的固定 IP 继续按测速结果使用，不因地址族重排或在传输时偷偷换 IP。HTTPS 透传共用双栈拨号，保留原 TLS 与证书校验。SOCKS5 始终传原域名，内嵌 Mihomo 的解析和出口行为保持原配置。候选执行前仍检查配置版本，避免持有旧推荐的调用方在强制代理模式下继续直连。

## 刷新与交接

DNS 提前刷新；相同 IP 的候选身份和测量历史保留，新增 IP 待测。候选变化唤醒 Monitor，TTL 延长而成员不变无需清空结果。读取状态不触发网络查询。旧答案在其真实 TTL 内仍有效；刷新再次返回同一 IP 时，租约取旧到期与本次答案到期的较晚者，短 TTL 不提前撤销旧租约，查询缓存与下次刷新仍按新答案 TTL 计算。失败不延长 TTL，也不为冷启动的零/短 TTL 增设保底有效期。DNS 过期的候选不可获得新推荐。

Monitor 每项成功后立即公布，不等待整轮完成；失败只影响对应候选。调度以配置周期为上限，并在成功观测即将过期前检查，保留刷新余量。没有有效候选时明确返回未知/无推荐，不无限使用旧结果。启动、全体失败和 TTL 过短时无法保证零空档。

网络模式和代理配置改变会发布新版本，取消旧检查，废弃受影响的推荐；仍允许且 IP 不变的直连通道保留历史，替换代理使用新的不含凭据的身份。候选提供者持有连接池，Monitor 不关闭它们。DNS 闲置清理、程序退出和传输关闭均有明确生命周期。

## 测量和推荐

手动 CF 测速的样本准备在所选上游内，共用请求模块的候选顺序、协议回退和调用者期限。清单独立读取；四个播放地址准备 worker 各自持有一个 Session，批内复用已验证路径，避免每首歌重等同一个失败握手。Session 随准备结束丢弃，准备的 30 秒期限、至少 16 个独立视频及 2 GiB 元数据要求保持不变。首个地址不可用不代表整个上游不可用，IPv4／IPv6 不按地址族整体排除。该准备过程只解析元数据；正式计速仍按资源域名固定一个候选，避免一组读数混合不同出口。连通性汇总表示至少有可用候选，不保证排序第一条地址可用。

直连吞吐历史仅在对应入口候选发现成功后清理；DNS 失败或尚未查询的入口保留历史，仍在有效期内的缓存候选可继续使用。代理只保留当前出口的业务诊断，不恢复或持久化代理吞吐样本，不维护内部节点推荐；自动资源检查仅做轻量探测，手动测速仍可使用。候选发现只有当前模式的一份结果。

歌曲列表、播放地址解析比较响应耗时。资源轻量检查保留原调度频率，请求 Range bytes=0-0，读取一个正文 byte 后关闭响应，只更新延迟与可用性，不计算吞吐。吞吐检测每个配置周期一轮，持久化最近尝试时间，启动时已到期则测速，否则等待剩余时间；DNS 更新不绕过该间隔。资源测速复用同轮同一线路解析出的合法 URL，不为每个 IP 重复生成歌曲样本。每个视频通道正文下载满 3 秒、达到 16 MiB、整首资源下载完毕，任一条件满足即停止；3 秒也截断停滞读取。吞吐使用实际正文下载字节除以正文下载时间，连接与握手时间单独计入延迟。视频探测串行执行，避免争抢本地带宽；此窗口测量不保证持续满速带宽。

WebUI 将响应延迟和吞吐样本分区显示，各自关联采样歌曲和观测时间。吞吐的 ThroughputSongID、ThroughputObservedAt 来自实际测速样本，不随轻量检查换歌而更新；SampleSongID 属于最新响应检查。业务下载会暂停自动资源探测，被打断的吞吐样本不记为失败，恢复后只做轻量检查，完整测速等待下个周期。

直连模式保留当前健康通道，挑战者需连续两轮明显更优（默认至少 15%）才切换；资源推荐按 ThroughputObservedAt 识别新的吞吐样本，轻量检查不重复计票，也不清零等待中的胜出次数。当前通道失败、失效或移除时立即选择其它有效候选。读推荐不增加连续胜出次数。推荐只代表当前已测候选，不承诺全网或所有歌曲的全局最优。
