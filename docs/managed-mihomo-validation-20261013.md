## 原生输入和真实业务

原始订阅沿用此前保存在忽略目录的本地快照，本轮未再次下载、刷新或重写。只解 Base64 外层并按行拆分 URI；没有将 VMess JSON、WS 参数或协议字段重新翻译为配置。YAML 合成节点原样放进 provider；不会把用户整份运行配置合并到主配置。

加载检查使用认证控制 API 的 `/providers/proxies`、`/providers/proxies/pN` 与 `/proxies/gN`：分别核对节点数、单成员列表及 `now`。验证模式可以加载 30 个 provider，但没有为其创建正式业务入口；网络测试批次仅创建前两个入口，不代表已实现生产 K=5 准入逻辑。

前两节点均通过证书校验开启的普通 HTTPS 检查。真实 SWD Monitor 使用独立 Channel，执行播放解析和吞吐检查：两条播放线路 × 两节点共 4 个 302 结果，首响应约 **308–412 ms**；两个视频取样均为 206、各 **4,194,304 字节**，资源首响应约 **1,080 / 2,304 ms**，Monitor 传输速度约 **4.05 / 3.64 MiB/s**。随后选用 Monitor 推荐的原 Transport 再请求同一采样歌曲，得到 302。动态签名地址只存在进程内，未进入证据。没有播放完整视频或验证音画。

`CheckPlayback` / `CheckThroughput` 会读取所需前置信息，但本轮没有执行独立 Catalog 验收；证据中六条 Catalog 状态仍为 `unknown`，没有将其计为失败或通过。

## 固定出口与进程边界

| 场景 | 实际观测 / 判定 |
| --- | --- |
| 认证控制 API 与版本 | `/version` 必须返回 `v1.19.32`；无 Bearer secret 返回 401；错误 SOCKS 密码不能发送业务请求 |
| 两个固定出口 | 每个入口绑定自己的单成员 group/provider；并发 20 次分别得到预期 A/B 标记，没有改组或热换节点 |
| 空 provider | `-t` 返回 0，但运行时 provider 为 0；禁止发布。显式 `empty-fallback: REJECT` 的请求失败且可直连目标计数不变 |
| 多节点 provider | 返回 2，单节点发布检查拒绝；没有将其交给业务自动选择 |
| 错误出口名称 | 核心 API 仍然就绪，但请求失败、直连陷阱未被访问。错误发生在请求路径，并非必然在启动时退出 |
| 端口冲突 | 外来 socket 占用端口时 API 仍可用；实际认证/请求在 200 ms 期限内失败，不能以 API 就绪发布 channel |
| 节点失败 | 指定出口失败时，请求不转到可直连测试目标，也不静默切换另一节点 |
| 请求取消 | 两请求设置 200 ms 期限，约 200.63 ms 返回取消/超时；这是 SWD 请求与本地连接的保证，不声称核心内部所有 socket 同时关闭 |
| 核心传输中崩溃 | 两条正文正在传输时终止本轮核心；两个读取均报传输失败，未伪装完整正文；没有拼接新连接 |
| 退役和替换 | 实验驱动在核心退出后显式关闭旧 Pool；旧 Candidate 返回 `ErrUnavailable`；新批次使用不同端口并重新检查映射。**尚无生产自动退出观察器** |
| 主进程强杀 | 独立试验父进程创建 Job，子进程暂停创建、加入 Job 后恢复运行；终止父进程后核心退出，没有孤儿进程 |
| 运行网络边界 | PID 对应的 TCP 监听恰好为两个回环 SOCKS 与一个回环控制端口；SOCKS 端口无 UDP。核心关闭 TUN、redir/tproxy、sniffer、NTP、自动更新、provider 刷新/健康检查；前后 hosts、用户代理、WinHTTP 代理和接口表均不变 |
| DNS | 核心启用独立 DNS，关闭 `use-hosts`、`use-system-hosts`；测试 DNS 同时观测并解析 `proxy.invalid` 和 `extra.invalid`，两出口成功。没有修改真实 hosts 制造污染，因此真实 hosts 劫持后的完整回环回归仍待测 |

主配置通过 `-f -` 的 stdin 交付，命令行不含认证；provider 临时文件确实是明文。写入前撤销运行目录继承 ACL，仅授予当前用户与 SYSTEM；这不隔离同用户恶意进程，也不构成安全沙箱。核心日志视为敏感内容，仅留在该受限忽略目录。核心环境过滤 `CLASH_*`、`MIHOMO_*`、`SAFE_PATHS` 及通用代理环境变量，防止运行模板被环境覆盖。

本轮退出检查：所有受管核心与探针已退出，provider 临时文件剩余 **0**，未发现本轮监听残留；原始订阅及私密诊断本地保留。**主机异常退出后的目录清扫尚未实现**，不能宣称凭据在磁盘永远只有 DPAPI 密文。

## Windows 成本测量

同一台机器、同一版本 SS 回环服务器；3 轮交替先后顺序；每轮新驱动/新核心、1 次冷请求、40 次 HTTP 连接复用请求、8 次 16 MiB 确定性正文，全部长度和 SHA256 一致。比较的是旧 SWD Adapter 与“驱动 + 完整核心”，两种驱动均链接当前仓库代码；服务器夹具不计入资源统计。原始逐请求样本见 `results.json`，汇总为中位数。

| 指标 | 旧内嵌 Adapter | 托管完整核心 |
| --- | ---: | ---: |
| 冷请求首字节 | 1.452 ms | 2.796 ms |
| 复用连接首字节 | 0.094 ms | 0.123 ms |
| 128 MiB 批次吞吐 | 928.47 MiB/s | 214.01 MiB/s |
| 3 轮吞吐范围 | 710.97–931.09 MiB/s | 175.86–216.53 MiB/s |
| 空闲总工作集 | 15.35 MiB | 36.29 MiB |
| 空闲总 Private Bytes | 16.22 MiB | 36.03 MiB |
| 每 128 MiB 批次总进程 CPU 时间 | 0.125 秒 | 0.250 秒 |

托管核心从创建到认证 API 版本可用约 **594 ms**（轮询测量，含启动/解析与等待；不是精确到微秒的核心初始化耗时）。未测旧适配层构造的独立耗时，不能把首请求时延当作完整启动成本。CPU 秒不是 CPU 百分比。结果来自短时间、单机、合成 SS 流量，无置信区间；不同轮次明显波动，应在真正业务负载再测。

这些数据说明本机中转有成本，尤其会影响极高回环吞吐；它们不足以说明用户视频一定慢多少。真实 VMess/WS 取样只有新方案，旧方案无法导入同一节点，**没有对等 A/B 结论**。采用该路线的理由是维护边界与兼容性；发布前仍需核对实际播放、资源预算和启动体验。

## 需要带入正式替换的约束

1. **生产只保留一个 Mihomo 执行后端。** 迁移期间可比较，完成后移除旧协议适配生产路径和依赖；外部 SOCKS5 继续复用标准 Dialer。不继续扩张旧协议白名单。
2. **模板由 SWD 控制，原生载荷由核心解释。** 外层预算、单条结构与能力边界仍由 SWD 检查；YAML 不按协议重建字段；URI 不重写参数。禁止直接/动态组/链依赖、文件引用及特殊网络能力的具体策略必须先落实。公开 provider/proxy API 的节点信息不等于完整解析后配置，数量为 1 不能证明没有 `dialer-proxy` 或文件副作用。本工具没有实现这道安全门禁。
3. **发布门禁覆盖全部入口。** 固定版本、控制认证、每个 provider 恰好 1、group 成员和选中项、生成的 listener 映射、监听所属进程和回环范围、SOCKS 认证都要核对。无需用节点在线成功作为导入条件；实际映射可用受控目标证明。错误/空 provider 必须 REJECT，不能默认为 COMPATIBLE。
4. **运行批次不可变。** 新凭据与端口、最多 K 个活跃入口；禁止原端口换节点后沿用旧 channel。核心退出时先撤销全部通道并关闭 Pool，进程重启与普通节点失败分开处理；有界策略不恢复已退役 Candidate。
5. **身份以保守配置指纹为目标。** YAML 用通用结构规范化并分离展示名，URI 保留原始协议数据，用受保护 HMAC；允许等价写法重新测量，禁止关键变化错误继承。旧 DPAPI 快照/身份版本、重新导入提示和历史保存策略须显式设计，不静默重解释原快照。
6. **保留现有业务职责。** Monitor、Direct/Auto/强制代理、下载/缓存回退、游戏 HTTPS 兼容直连仍归 SWD。新进程管理接入现有条款、草稿、原子保存、重启生效和错误 UI 后，再更新对应实机步骤。
7. **凭据和交付如实记录。** 当前用户受限运行目录、崩溃清扫、原始输出隔离、Job 所有权、核心缺失/版本不符/启动失败需要产品实现；不加入自动下载/升级。按实际交付组件更新许可/源码/打包核验，是否随包附带核心另行决定。

## 失败历史、自动检查与实机状态

第一次补测因为试验工具将 Monitor 资源期限设为 10 秒，违反现有 ≤3 秒接口约束，初始化失败；修正后 Monitor 已获取有效播放/视频结果，但工具的后续业务请求漏加歌曲 ID，返回 404。修正请求后最终返回 302。两个失败均是工具错误，不能归为节点故障或生产回归；原失败观测和构建身份保存在 `history.json`。早期亚毫秒计时精度不足的样本不用于最终性能表。沙箱内只读 CIM/netsh 查询被拒绝，后在已授权的隔离脚本执行环境完成网络前后检查；没有为此修改网络配置。

**开发验证完成，生产替换待实施。待实机验收仍为 LA-034 / LA-035 / LA-036**；与进程退出相关的 LA-018 继续积攒。本次工具和测试夹具不改变产品运行行为，因此不新增实机编号。既有台账中的旧身份/无新增入站等步骤仍描述当前生产实现；正式替换时必须在同一变更中改为新约定，不能用本报告提前将其标为通过。
