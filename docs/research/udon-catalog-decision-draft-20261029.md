## 已确认的规则

### 来源、版本与主表

| 事项 | 目标行为 |
| --- | --- |
| 来源职责 | Udon 为 canonical，默认先取 Udon；Kiva 与 WannaInfo 同级，均可提供备选清单、资源资料和映射补缺。不因来源名称或历史更新慢排除其中之一，也不将任一备选变为运行的必需依赖。全部获取失败时保留已接受的本地数据 |
| 版本裁决 | 已取得的合法完整清单以较新版本为准，不回退本地水位；同版本优先 Udon。同级备选或同来源同版本内容冲突时，保留已接受数据并报错。为补映射取得的备选清单也参与比较，不因 Udon 可用而忽略已发现的较新版本 |
| 旧备选的用途 | 旧清单仍可提供合法资源资料和缺失映射，但不能回退歌曲主表或当前成员集合；清单版本不代表全部歌曲的 MD5 都已同步 |
| 异常警告 | Kiva 或 WannaInfo 版本高于 Udon 时，后台记录来源、双方版本和观察时间；警告不阻止采用合法较新清单。Udon 获取失败本身不等于备选较新，不为检测这一情况新增轮询 |
| 主表字段 | 发布前将字段命名及语义对齐 Udon，只保留两种格式共同的歌曲信息。Kiva/WannaInfo 共用集中适配；父级分组名称等共同信息可拍平保存，不能机械取单条记录的字段名交集 |
| 存储范围 | 保留歌曲资料、资源属性、当前映射及 URL 观察的职责划分。不恢复完整清单 JSON、完整分组树、标签翻译、顶层新歌集合或额外集合表；现有逐歌数组不因改名扩大保存范围，不自动新增冗余 `danceid` |

### 保留数据与操作范围

清单同步继续“增、改，但不删”：清单缺席不删除已积累的歌曲资料、资源记录、当前映射、统计或偏好。已有 `catalog_members` 在接受完整清单的同一事务中更新，表达当前成员；更新成员关系不等于删除歌曲资料，不新增删除标记或历史成员表。获取失败、校验失败和旧候选不能清空成员，API 或预置映射创建的占位歌曲也不自动成为成员。

| 操作 | 范围及行为 |
| --- | --- |
| 全量下载补齐 | 仅处理 `catalog_members`。缺 MD5 的当前歌曲按 ID 查询，不能静默跳过；旧歌缺文件不影响当前全量补齐完成情况 |
| 覆盖率 | 分母为全部当前成员；已知映射且确认本地有对应文件的歌曲计入覆盖。缺映射单独显示“资源待识别”，不误称为文件缺失。尚未取得有效完整歌曲清单时显示未知 |
| 曲库展示 | 展示完整歌曲与资源，不按当前成员强制过滤；保留搜索、分页和用户主动筛选 |
| 指定歌曲或资源下载 | 不要求歌曲或资源的关联歌曲属于当前成员，照常执行既有地址获取、屏蔽及预算规则。指定资源保持目标 MD5；成员过滤不能下沉为通用下载准入 |
| 本地文件保留 | 继续遵守资源预算、保护和淘汰规则；资料增改不删不表示永久保留所有视频 |

例如清单从 1、2、3 变为 2、3、4：歌曲资料保留 1、2、3、4，全量补齐及覆盖率只看 2、3、4。曲库仍显示歌曲 1，用户可单独下载；该操作不会把 1 加回当前成员。歌曲 4 缺映射时仍参与全量处理与覆盖率分母。

### 资源映射、API 观察与预置

| 事项 | 目标行为 |
| --- | --- |
| 映射补缺 | `song_media` 缺少歌曲映射时，合法 Kiva/WannaInfo 候选、有效 Udon 播放 API 观察及预置映射均可补充；两个备选采用相同校验及补缺规则 |
| 已有映射覆盖 | 仅由新取得、校验通过且时序有效的 Udon 播放 API 观察更新。Kiva、WannaInfo 和预置映射始终只填空，即使其清单版本更高也不覆盖已有映射 |
| 写入一致性 | 接受新 API 结果时，在同一事务更新 `song_urls`、资源属性和当前映射；复用查询顺序，防止迟到旧请求覆盖新值。读取旧 URL 缓存不是新观察，不为每条映射增加来源标识 |
| 预置内容 | 随程序提供 `media` 的 MD5 和 `song_media`，记录预置快照版本；大小未知可为空，不要求大小全部已知。装载遵守外键及只补缺规则，后续程序携带新版种子也不覆盖已有映射。本轮不预置 URL |
| 快照版本含义 | 版本标识分发的预置数据，不代表运行后整张映射表仍属于该版本，不与歌曲清单水位或数据库格式版本混用。资源记录可积累；新增资源仍需补充，已有 MD5 不必随歌曲换映射改写 |
| 逐步校正 | 正常播放解析、监测等入口取得新 API 结果时共用写入机制，自然更新预置映射；不另设整库刷新任务或用户操作。未查询或查询失败的歌曲继续保留已有映射 |

映射更新不改变已经开始传输的资源身份。本地命中仍立即播放并后台查询，更新影响后续请求，不混合不同 MD5 的字节；旧资源文件按原保留规则处理。

### 导入与监测补缺

外部视频计算出的正文 MD5 在 `media` 中有记录，即可通过资源身份准入。不要求属于当前清单或已有 `song_media`；缺映射、缺清单水位或刷新失败不单独阻塞已有资源资料的导入开始。继续验证文件正文、执行已知歌曲屏蔽及存储规则；大小可辅助检查，不能代替 MD5。

预算按实际文件大小计算。超预算取舍通过 `song_media` 关联歌曲分数和收藏等信息；无关联资源沿用零歌曲分数及既有保护机制，不能推断其歌曲偏好，不新增特殊宽限期。

“后台补资料”指 API 连通性监测顺便补 URL、MD5 和大小，继续复用现有监测轮次，不另起后台整库任务。候选从歌曲出发，不要求先有 MD5；主要补缺 URL 的歌曲，按歌曲分数排序。

曲库刷新发现当前成员缺映射时，可顺便尝试 Kiva/WannaInfo。两者失败不阻止接受 Udon 清单或已有资源导入，不新增独立轮询。

## 实施细节与可选改善

实施时按现有约定完成下列关联工作，无需把普通实现选择再列为产品决策：

- 核对最终字段、逐歌数组表示、数据库 DDL、摘要投影及调用方。开发期旧库继续遵守[不兼容、不迁移、不改写](../storage.md#打开失败与未来升级)的现行约定。
- 确定预置数据格式、版本落盘位置及生成工具；保持可验证的快照、外键一致和补缺写入，不新增通用同步框架。
- 统一主表候选比较与提交，覆盖前台更新、监测回调和为补映射取得的候选，避免较旧请求晚完成后回退数据。
- 细化监测中缺大小、失败记录和地址时效的筛选。建议沿用现有“补缺而非整库续期”的边界：单纯超过播放 URL 复用期不等于缺资料，不因此周期性重查全库；依据见[候选说明](../../internal/cacheproxy/song_metadata_candidates.go#L11)。
- 验证无映射歌曲不会按空 MD5 合并为同一下载任务，当前覆盖率不会遗漏未知映射，曲库展示与单项下载不受成员过滤影响。

**自动追随新 MD5 属于可选改善。** 手动全量或单歌曲下载期间是否自动重排，不作为本轮前提；指定资源始终保持身份。不能简单删除 `expectedMD5` 校验：多首歌共用任务时，某首歌换资源后不得把其他歌误记为已完成。保留字节一致和失败如实记录，不引入无界重试或重排。

HTTP/HTTPS 选型、预置 URL、完整集合建模及额外后台任务不纳入此次曲库改造。实施验证应覆盖空库、仅 Udon 资料、同级备选版本与失败、仅资源种子、陈旧映射种子、并发 API 观察、导入预算、覆盖率及历史目标单项下载；不自动启动 VRC 或修改 hosts。

## 实施进度（2026-10-29）
