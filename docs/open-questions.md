# 待验证清单

目前足以设计和启动第一版，但完整兼容规格尚未冻结。下列测试优先使用隔离目录与原版黑盒完成，最后再进入游戏验收。

## 实现前优先补齐

| 编号 | 问题 | 建议实验 | 完成标准 |
| --- | --- | --- | --- |
| Q01 | e/s 是否被严格校验 | 分别改变 e、s，使用同 ID 的不同内容、截断文件、缺失/错误元数据 | 明确 HIT/MISS/拒绝/重下及落盘规则 |
| Q02 | 同 ID 内容更新怎样失效 | 改变文件名内容标识和 checksum，测试同域及跨域版本 | 不把“本次 CF/HKG 共用”误当成永久按 ID 缓存 |
| Q03 | 同曲并发怎样处理 | 同时请求完整文件、开头、不同中段，并中断其中一个 | 记录回源次数、各响应完整性、临时文件和最终文件 |
| Q04 | 下载与进程中断怎样恢复 | 下载中取消请求、断网、终止原版，再重启 | 区分续传、重下、残留文件清理，不发布半文件 |
| Q05 | 上游错误怎样传播 | 可控上游返回错误码、错误长度、中途断开、校验不符 | 明确客户端响应和缓存状态；真实网络故障只作辅助证据 |

可控上游环境的接入方式尚未建立；不能假定更改 SNI 映射就一定能重定向原版的 HTTP 回源。应先验证实际生效配置，再设计故障注入。

## 第一版验收矩阵（提议）

2026-09-25 StepStash 自身验收结果见[验收记录](acceptance.md)，原版黑盒问题仍与实现验收分别记录。以下通过项只覆盖已记录的样本，不是全量兼容保证。

- [x] 直接配置已有 `wannadance-song` 库即可复用有效视频，无需迁移或重下，纯读取不改写原文件。
- [x] 兼容完整/简化元数据及缺少 `download.txt` 的库；新增缓存由原版回读验证格式兼容。
- [x] 存储兼容的其余验收项通过，见[存储兼容要求](storage-compatibility.md)。
- [ ] 原版对照测试中核心请求的内容和必要响应字段一致。
- [x] CF、HKG 各自从空缓存完成一首歌，MD5/大小正确，再次读取本地命中。
- [x] Auto 根据本次解析结果工作，而非写死某节点。
- [x] 无效/越界 Range 有明确响应，不出现原版那样的异常长度和工作线程 panic。
- [x] 同曲并发、客户端中断和重启后没有错误发布的半文件。
- [x] 缓存版本变化可以识别，不返回过期内容。
- [x] 游戏从零播放、恢复进度、切歌及多人中途加入通过本轮样本（CF 慢连接负例另记）。
- [x] 网络异常可以结合游戏与服务日志定位到解析、回源、文件响应或客户端阶段。
- [x] 测试结束恢复接入设置，并释放进程和端口。

以上已勾选项依据 StepStash 本身的自动化和本轮联合实机证据，不因原版调查通过而预先勾选。核心协议字段的逐项原版自动对照仍保留为未完成项。

SHA 是否属于第一版支持范围，应在拿到有效响应后决定。若选择暂不支持，需在范围文档明确写出，而非隐式回退或宣称四节点完整兼容。
