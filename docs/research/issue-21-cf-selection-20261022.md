## 标准、网络与产品语义

[RFC 1035 §3.2.1](https://www.rfc-editor.org/rfc/rfc1035.html#section-3.2.1)允许零 TTL 答案用于当前事务而不缓存。[RFC 2181 §5.4、§8](https://www.rfc-editor.org/rfc/rfc2181.html)要求 DNS RRset 不任意拼接，TTL 是缓存上限；相同 RRset 的 TTL 可更新。现行 `max(旧租约到期,新答案到期)` 是 SWD“仍有效观测保留”的应用候选契约，不是 RFC 指定的算法，也不等于完整 DNS RRset 缓存实现。本轮未修改来源级撤回或产品租约期限。

当前普通直连的 `lookupShared` 会返回本次成功查询的地址，即使 TTL 为零；用于推荐的 `Addresses/CurrentAddresses` 则只返回尚未到期租约，固定 Transport 也检查资格。现有夹具覆盖零 TTL 和旧有效租约保留；本轮未增加最低 TTL 或修改系统 DNS。

现行 `operationClients` 无推荐时仍用配置的普通客户端；Mihomo 运行时的候选补齐另保留普通直连回退。因此固定实验候选为空不能直接证明产品无法下载。本轮复用既有业务回退测试核对边界；静态实验成员资格未用于产品。本轮未取得零 TTL 导致普通业务失败的实网证据。

Cloudflare 官方说明，大陆客户端访问全球网络通常由境外节点服务，IPv4/IPv6 可以走不同路径；[China Network](https://developers.cloudflare.com/support/troubleshooting/general-troubleshooting/geographic-traffic-routing/)是独立接入产品，换 IP 不会取得其服务。用户指定本机 Wi-Fi 为大陆直连接入；本轮以显式 socket 绑定和逐连接证据确认实际使用该网卡，结论只覆盖这个网络及观察时段，不推定所有大陆用户。

[Range 官方文档](https://developers.cloudflare.com/cache/reference/range-requests/)说明适用的 Origin Range Requests 可按 1 MiB 边界回源。不能由我们的块大小推断目标启用了此功能；客户端读到的正文也不是 CDN 回源或网卡总字节。记录 HIT/MISS、Age、远端与连接复用，仅作解释字段，不把 colo 或邻近 IP 当作独立路径证明。

## 首轮结果（凌晨，原证据保留）

### 低流量 DNS 观察

复用已冻结 `cc9198a7…` 构建和绑定 Wi-Fi 配置，120 次观察、约 242 秒完成；六次合并查询 TTL 依次为 203、60、0、30、5、133 秒。全部观察仍保留三个 IPv4、三个 IPv6。提供者记录中 `doh.360.cn` 有一次成功零 TTL；其他完成答案包含正 TTL。未先收到的提供者因收集窗口取消，不记为线路故障。

本窗记录到零 TTL 查询，旧有效租约在该次查询前后仍可用；该结果不能追溯解释先前失败，也不覆盖所有旧租约到期后的状态。实际提供者/族与合并时序见[脱敏汇总](../evidence/cf-selection-20261022/dns-summary.json)，原始 `dns.json` 保留本地。

### 传输与筛选校准

按[校准协议](../../experiments/cf-block-paths/SELECTION.md)完成首轮。DNS 和额外地址具有相同实验成员资格；这一比较测量线路传输及筛选结果，不覆盖现行产品选路的端到端可靠性。冻结构建、原始文件哈希、相对时间及完整/缺测计数见[证据清单](../evidence/cf-selection-20261022/manifest.json)。

新 EXE `7e7e4626909a2064fa9cc33c9063857dbe1be932476bf65678a22a3f09ff7ab9` 的旧式 smoke 失败：bootstrap 和 API 已完成，固定双栈媒体集合为空，未运行 Monitor；网卡记录没有绑定失败。因为该 smoke 没有冻结失败点 DNS 快照，不能确定此次一定是零 TTL。失败保留，未重跑。新协议随后通过查询返回值取得六个 DNS 地址，首个完整内容基准加载成功；这是新的路径测量方法，不能把 smoke 失败改记为通过。

首窗约 422 秒，实读媒体正文 **2,431,591,237 字节（约 2.26 GiB）**。14 地址完成 28 次冷连接短测；10 地址至少一次正确交付，随后全部完成两次训练，包括按短测速度会淘汰的地址。其余四个两次短测均失败：三个新随机地址在 TCP 阶段超时；`172.64.144.1` 已取得正确 206 和验证过的 TLS，但正文两次超时。四者没有完整训练，不能声称已测得其多连接吞吐。

完整加载 **51 次**：1 次训练内容基准、20 次训练、3 次留出内容基准、9 次预热、18 次正式。2,252 个分块请求全部为正确 206、完整长度、预期远端及匹配 SHA256，无请求错误或重试，全部 CDN HIT。每次新建客户端池，但 CDN 并非冷缓存。1,259 个成功 TCP 连接均匹配指定 Wi-Fi 的源地址、接口索引与目标；另有 136 次取消、6 次连接超时。取消包含 DoH/双栈竞争，不等于媒体失败。

### 复核失败与稳定性

首窗后预先登记一次同构建、同参数复核，计划用首窗各来源赢家预测后窗。第二窗在歌曲 1343 的播放 API 准备阶段收到 **HTTP 523**，约 4.1 秒后停止，媒体正文为 0；30 次评估未执行，无法生成配对或历史迁移结论。绑定核对通过，未改歌、跳过 API、补样或重跑该目录；此 API 失败未计为待选视频 IP 的传输失败。

首轮阶段只有一个有效性能窗口，另一次复核未进入媒体测量。既有两组 +26.9%、四组不完整窗口的正收益、Wi-Fi 旧协议失败及本轮结果各自保留；路径、基线、时段与协议不同，未合并成跨时段统计。第二窗缺失不计为负收益样本。此后新增的晨间校准和晨间、午间产品对照分别见下文；跨日、晚高峰、换网历史以及其他大陆网络仍未验证。

### 成功响应的 trace 缺陷与记录器修订

复核发现 v1 普通直连的一条成功媒体响应将 DoH 远端 `1.12.12.12` 写入媒体记录。异步 DNS callback 可能晚于媒体 GotConn 到达，因此媒体请求成功不能保证最后一个 GotConn 属于该请求。v1 的所有未固定地址 trace 均标为未验证，不作远端或连接复用归因，也未以其他响应的地址填补。该窗的任务时间、实际 HTTPS 响应、产品 MD5 与发布证据保留。

v2 只改变观测，按 TLS 已验证的 ServerName 匹配目标主机并加锁隔离迟到 callback；方法修订在午间采样前登记。独立 smoke 的三个实际预取通过，158 个媒体块的连接均取得目标主机的验证，92 个成功 TCP 连接绑定 Wi-Fi；此 smoke 用于记录器验证，不计入策略收益样本。策略和预算不变，两个构建分别标识，晨间原始证据保留。

### 共享 DNS 的产品观测修复

使用两个本地证书验证的 HTTPS 服务复现嵌套请求：外层业务请求触发 `lookupShared → exchangeDoH`，原实现向外层 trace 交付两次 GotConn、TLS 握手完成和首字节回调，其中一次连接属于 DoH。`context.WithoutCancel(parent)` 解除调用者取消，但保留 context 中的 trace；该行为发生在产品共享 DNS 调用链中。

修复后，共享查询从解析器自身的 `d.ctx` 派生超时，移除原有取消桥接，不再继承首个调用者的 HTTP trace。回归确认三类回调各一次、且连接属于目标；既有独立调用者取消、共享查询超时、解析器关闭、刷新和租约测试继续通过，Windows race 通过。upstreamrequest 测试通过；upstreamstate 全包先遇已知沙箱 `renameat: The handle is invalid`，宿主同组复验通过，原失败日志保留。三个包的 vet 通过。具体回执与源码/日志指纹见 [DNS trace 回归](../evidence/cf-selection-continuation-20261022/dns-trace-regression.json)。

影响边界：Monitor 的 API 排序使用首字节延迟，资源显示也包含首字节延迟；在普通解析或固定候选到期复验经过 DoH 时可能受到嵌套回调影响。资源排序使用单独的正文计时，本次复现未证明该排序错误。晨间任务秒表与完整文件校验独立于 trace；由于缺少逐请求原始首字节序列，无法事后修正其 Monitor 延迟或量化此缺陷对任务结果的影响。午间使用 `c96a037b…` 冻结 v2（已隔离实验记录器，尚无产品 DNS 修复），保持性能对照的产品基线；产品修复单独验证。

### 阈值方法与媒体需求的适用范围

[JMLR 2026 的 APGAI](https://www.jmlr.org/papers/v27/24-0680.html)研究给定门槛下寻找满足阈值的候选，支持固定预算和 anytime 使用；其 §1.1 假设每个候选具有固定分布、次高斯观测及给定阈值。本轮未验证 SWD 的跨时段变化、超时截尾及不同字节/时间成本是否满足这些假设，也未实现或测量该算法。

[RFC 6349 §2、§5](https://www.rfc-editor.org/rfc/rfc6349.html#section-5)面向可管理网络的持续 TCP 稳态测量，并明确不预测慢启动瞬态；其长时间及不同时段测量建议不直接规定 SWD 每个候选的探测时长。本轮实际任务为数秒量级，计时包含启动、并发缓增等过程；前置搜索成本另列，并计入会话总耗时。

随后只读检查本轮已发布文件，复用[已有媒体研究解析器](../../scripts/video-metadata-study/analyze.py)，重新核对大小和 MD5，取得[三份容器元数据](../evidence/cf-selection-continuation-20261022/product-media-metadata.json)：1344 为 201.503 秒、平均总码率 1.610 Mbps；10552 为 511.765 秒、1.612 Mbps；10553 为 219.200 秒、0.757 Mbps。三者 moov 均在首个 1 MiB 内。这是事后解释性检查，不改变预登记性能指标。平均码率不等于瞬时需求或播放不卡顿门槛，moov 前置也不直接证明首块已可播放；现行调度还涉及多个需求、Seek、缺块阻塞和期限。本轮未验证 5 MB/s、参考最佳的 90% 或三首平均码率与任务期限、首段等待及播放体验之间的对应关系。
