# LIVE-20261116-02：一次提前 504 的正式播放观察

本批次继续 [issue #51 研究](../research/issue-51-retry-handoff-followup-20261116.md)：当播放器长时间没有收到数据，取消旧请求后再次索取同一个缺口，临时夹具只返回一次 504，观察是否更早重新加载、请求坏块之后的数据并恢复画面。本记录包含八笔已结束的观察，其中一笔手动刷新未满足“卡住后刷新”的条件，单独保留。预读 504 的跨歌曲重复结果另见 [LIVE-20261116-03](live-acceptance-20261116-03.md)。

## 条件与构建

固定产品源码为 `96d95141db7afbf7baaecb34601a33e339ca444d`，下载截止保持 `need-by + 30 秒`。实验程序运行真实 SWD 块调度器，以本机受控来源供数；不是发行包验收。Windows、VRChat 版本及实际程序 SHA256 见[构建身份](../evidence/live-20261116-02/provenance.json)。本批均为非 owner，好友控制房间播放；关闭本机预览。

块大小为 1 MiB，两个普通下载槽，无限缓存。受阻块先收到 128 KiB，随后暂停，未收到 EOF，因而不能发布完整块；受阻范围之外可正常下载。首个播放器 GET 后约 66 秒解除停供。解析 GET 不触发故障计时。实验去除条件缓存请求头，保留 Range，避免 304 无正文干扰。

夹具位于播放器与隔离 SWD 之间，识别条件为：前次响应未完整结束，恰好供到已知坏块起点，结束前至少 25 秒没有新增供数；两秒内的新 GET 从该位置或向前回退不超过 8 KiB 处开始、仍覆盖坏块，且故障尚未解除。每笔最多注入一次 504，之后正常转发。参数只用于实验，不是产品规则。1 MiB 按 2 Mbps 换算约 4.2 秒，播放器的重试阈值和跳转粒度需单独测量。

夹具直接对选中的请求返回 504，该请求跳过 SWD 的需求登记与交接。其余请求正常转发，坏块之后的数据由 SWD 从本机受控上游下载并交给播放器。本批据此观察播放器收到 504 后的反应。产品侧实施同一策略的下载成本和公网持续低速时的表现均未测量。

## 最初四笔结果

下表卡顿和黑屏时长取人工反馈，约秒级。精确请求时间均在[逐笔证据](../evidence/live-20261116-02/playback.json)中按各自首 GET 归零；不同样本不能共用零点。

| 场景 | 注入 504 次数 | 卡顿／黑屏 | 请求与坏块状态 | 结束观察 |
| --- | ---: | --- | --- | --- |
| 4598，坏块 2–3 MiB，关闭提前 504 的基线 | 0 | 约 55 秒／未报告黑屏 | 来源约 t=66 解除停供后，请求转到 15,941,632 字节处；不能算提前绕过持续坏块 | 两次爆音后正常，人工确认自然结束 |
| 4598，坏块 2–3 MiB，开启一次提前 504 | 1 | 约 31 秒／6 秒 | t=33.223 返回 504；t=39.832 请求 9,240,576 字节处，已越过仍不可读的坏块；人工约 t=40.080 恢复 | 恢复后正常，人工确认自然结束 |
| 换为 2502，坏块 2–3 MiB | 0 | 约 29 秒／未报告黑屏 | 原请求截止后，t=37.018 请求 10,534,912 字节处，坏块仍不可读；没有命中提前 504 | 人工确认自然结束；存在额外起播事件，单独保留条件 |
| 4598，坏块后移至 4–5 MiB | 1 | 约 25 秒／6 秒 | t=34.255 返回 504；t=40.910 请求 10,649,600 字节处，越过仍不可读的坏块；人工约 t=40.095 恢复 | 游戏记录 t=133.095 自然结束；本地人工结束记录未附精确时间 |

原位置同歌配对中，提前 504 一笔的人工卡顿比基线少约 24 秒，两笔起播至结束均约 133 秒。这是一次配对结果，不是重复统计。坏块后移一笔也观察到注入后绕过坏块，但没有该位置的同期关闭注入对照，不能给出该位置的收益差值。

人工恢复时刻与 HTTP 前跳可能相差不足一秒，不能按这点误差判定画面严格先于新请求。基线人工恢复也略早于服务器精确放行时刻，应解释为放行附近的秒级反馈，不作为放行前恢复的证据。

## 提前 504 后的实际请求顺序

4598 原位置样本中：

1. 第一条播放器请求供出 2 MiB，在约 t=32.720 结束。
2. t=33.223 重新请求，从缺口前 8 KiB 开始，夹具立即返回一次 504。
3. 游戏记录视频错误，约五秒后出现世界 `Retrying load`。
4. t=39.483 再次请求原缺口前 8 KiB；收到这 8 KiB 后结束。
5. t=39.832 改为请求 9,240,576 字节之后的数据，画面恢复；后段响应在 t=59.009 完成，早于 t≈66 的坏块放行。

坏块后移一笔也先重新请求旧缺口前的 8 KiB，再请求后段；后段响应在 t=58.889 完成，同样早于坏块放行。两笔不是“收到 504 后下一条请求立即跳过”，而是错误、重新加载及同步流程之后出现前跳。服务器响应完成与画面正常结束分别记录。

## 2502：未注入 504 的另一条路径

2502 在初次起播后约两秒又出现起播事件，服务端同时记录新的解析请求。操作者明确表示好友没有再次重播或切歌，具体内部原因未确定。之后播放器重复索取缺口前 8 KiB；约 t=37.009，SWD 截止该响应，下一请求于 t=37.018 直接取较后段数据。

在报告卡顿至恢复的区间，没有新增世界 `Retrying load` 记录，也没有夹具注入的 504；此时坏块仍不可读。因此这笔不计为提前 504 的重复成功，也不能继续把“卡住后必须再发生一次世界重新加载，才能绕过坏块”写成既定规律。此前的额外起播事件保留，不以此单笔证明所有播放器状态下都能直接跳过。

## 三个连续坏块

4598 的受阻范围扩大为 2–5 MiB。操作者报告“从开头卡住”，不能将游戏起播回调解释为开头流畅。t=32.293 返回一次 504，t=38.928 请求从 9,240,576 字节开始的后段，已越过三个仍不可读的块；人工约 t=39.120 报告继续播放，来源在 t≈66 才解除停供。之后人工确认自然结束，游戏也记录结束事件。

本笔与坏块后移样本都观察到一次 504 后前跳，但没有各自同期关闭注入的配对，不能给出各自的净收益差值。

## 手动刷新：分别保留正常播放与卡住后刷新

4598 一笔是在正常播放时点击刷新，约三秒后画面恢复。首个播放器 HTTP 请求晚于人工报告的起播，而且起点为 4,329,165 字节，已在 2–3 MiB 缺块之后。该笔没有证明播放器曾等待该缺块，不计为“卡住后刷新绕过坏块”的成功；旧缓存影响是可能解释，未确定。

改用此前未在本轮播放的 8935 后，人工报告先起播、约五秒后卡住，点击刷新后很快恢复，未提供精确恢复秒数。游戏记录按钮点击及重新加载回调约在 t=13.541；新请求先从零读取，随后在 t=15.782 请求 3,178,496 字节之后的数据，越过仍不可读的 2–3 MiB 缺块。后段响应约 t=28.914 完成，早于 t≈66 的坏块放行。游戏记录自然结束。

8935 的旧播放器 GET 直到 t=25.173 才结束，新播放器 GET 从 t=15.378 开始，两者重叠约 9.8 秒。因此不能概括为所有重新加载都发生在旧 GET 完全退出之后。

## 预读 504：一次延后黑屏的观察

5396 将缺块移到 16–17 MiB。以下时间从首个播放器 GET 起算：

| 事件 | 相对秒数 |
| --- | ---: |
| 人工报告起播 | 2.735 |
| 已供出 16 MiB 的请求结束 | 48.376 |
| 对后续重试返回一次 504 | 48.440 |
| 来源解除停供，缺块恢复可读 | 66.001 |
| 人工报告黑屏 | 101.735 |
| 再次解析视频 | 107.047 |
| 新播放器 GET | 107.493 |
| 人工报告画面恢复 | 107.735 |

操作者约定未报告的音画异常视为正常；本笔在 504 后未立即报告黑屏，约 53 秒后才报告黑屏，约六秒后恢复，最终正常结束。来源在黑屏前已恢复供数，但 504 后直到重新加载才出现新的播放器 GET。

这笔支持“预读重试收到 504 后，画面没有立即中断”的样本结论；不能由此断言 504 不影响后续播放。本批只有一笔，没有同条件关闭注入的对照；后续跨歌曲重复见 [LIVE-20261116-03](live-acceptance-20261116-03.md)。不能把服务器已写出的字节数等同于播放器实际已消费的位置。

## 证据边界

- 2502 未注入 504；正常播放时刷新 4598 未满足卡住条件；两笔均保留，不计为目标条件的成功复现。
- 实际注入均针对一个受控客户端；没有实现产品中的重复请求识别，也没有比较 2 秒与 15 秒交接。
- 本批固定来源恢复时刻，未覆盖持续低速的真实网络、主动回看、竞争用户或连续多次拒绝，不能选择通用阈值。
- 初始沙箱启动未维持后台服务，没有形成播放器样本，作为准备失败保留。
- 后续 [LIVE-20261116-03](live-acceptance-20261116-03.md)已完成三首提前 504 的重复观察及另一首关闭注入的观察；结果单独记录，不与本批拼成同歌配对。
