# CF 额外候选与产品双栈自动推荐：分块对照（两组探索已完成）

**首个时段显示明显收益，但尚不足以判断跨时段稳定性，也不能证明胜过全部 DNS/IPv6 候选。** 2026-10-21 下午，额外候选 `104.24.0.1` 在三个未参与训练的视频上，12 对分块下载全部快于当前算法推荐的 `104.26.4.28`；配对吞吐增益中位数 **26.9%**，完整下载耗时下降中位数 **21.2%**。后续按用户要求改为[IPv4/IPv6 四组补充实验](cf-family-paths-20261021.md)，不与本报告合并统计；证据充分性判断、机制调查结论和修订后的跨时段计划均以该报告为准。本报告保留两组探索的原始计划及结果。

本次只新增显式标签启用的实验入口、统计工具和证据，不修改产品代码路径、默认配置、hosts、代理设置、正式媒体库，不启动 VRC。首批进程已正常退出；未 commit / push。

## 方法与预先规则

完整固定规则见[实验说明](../../experiments/cf-block-paths/README.md)。实验直接调用当前产品的 DoH 双栈解析、`upstreamstate.Monitor`、固定候选 Transport、`cacheproxy.DiscardLoader`。后者与普通资源下载共用块加载器、范围验证、重试和全局调度器：1 MiB 块、默认软上限 16、每 250 ms 增加一路。没有另外实现线程池模拟产品。

基线是在隔离实例中从当前 DNS 候选得到的产品推荐，保留默认 15%/两轮切换策略；没有读取用户正在运行应用的持久历史或私人代理。因此这是**当前代码、默认直连策略**的复现，不是既有桌面实例的现场状态快照。额外组从固定的 `103.21.244.1`、`104.16.0.1`、`104.24.0.1`、`162.158.0.1` 四个地址中使用相同 Monitor 选择。它检验额外候选能否提供更快通道，尚未实现 DNS 与额外候选联合回退。

训练固定用歌曲 1343，两组交替顺序完成三轮。正式评估固定歌曲 1344、10552、10553，大小按原始文件约 38.67、98.34、19.78 MiB。每资源每组先完整预热一次，然后四轮相邻配对，AB/BA 各两次，资源顺序轮换；每组新建连接池和加载器，组间两秒。训练结束固定 IP，正式结果不能用于挑选新的赢家。

三轮通过产品手动测速入口连续执行，不模拟默认每 20 分钟的后台巡检节奏。下午 DNS 组训练累计约 77.3 秒，额外组约 50.2 秒（含 API 与失败候选等待）；这些准备成本没有计入下载增益。额外组仍单独运行前置 API 流程，因此其全部训练时间不能直接当成未来联合候选实现的净新增成本。

每请求核验实际远端、原 Host/SNI/TLS、206、精确范围和长度、identity 编码及同一强 ETag；每块 SHA256 与基线预热比较。测量包含建连、TLS、块调度、正文和哈希；加载器创建、输出文件写入和后续连接池清理不计入。完成时覆盖完整资源的全部区间，但没有产品最终 MD5 发布、磁盘读写或真实播放器阻塞读。前 8 MiB 指这些块校验完成时间，不等同于首帧时间。

每组 90 秒、每窗口 30 分钟；正式与预热正文计数上限 6 GiB。协议/内容异常或 429/503 停止，连续两组失败停止；失败、缺测仍保留。训练采用产品原有失败处理，训练正文未单独精确计量，其理论上限为 `3 × (6 + 4) × 16 MiB = 480 MiB`，另有 API、预检和协议开销。

## 对一般性结论的限制

1. **包含 IPv6 不等于证明比最优 IPv6 更快。** 三轮训练实际覆盖三个 IPv4 和三个 IPv6，均得到可用吞吐样本。默认迟滞在三轮后仍保留第一轮选中的 `104.26.4.28`。最后一轮 `2606:4700:20::681a:41c` 的轻量吞吐约 3.16 MiB/s，高于当前推荐约 1.44 MiB/s，但尚未满足当前策略切换条件。此次分块对照符合“当前自动推荐”基线，却不能区分全部收益来自扩大地址范围，还是部分来自现有选择策略滞后。没有事后改选更慢基线，也没有将这条 IPv6 的轻量读数当成完整分块结果。
2. 首轮样本对当前程序有实用价值，三个资源方向一致；只有一个真实时段，尚未满足稳定收益判据。四轮重复嵌套于同一资源/时段，1,580 个块请求不能当成独立统计样本。
3. 均为同一主机、接入网络和资源域名，未隔离整机其他网络流量，也不能排除网关透明转发。全部 HIT，尚不覆盖缓存未命中、其他用户网络、长期 IP 可用性或跨运营商收益。
4. 三个后续条件须一起判断：各时段方向一致、整体中位增益至少 15% 且配对胜率至少 80%、每资源中位收益非负；同时失败率不增加，前 8 MiB 中位就绪时间不恶化超过 10%。达标也只能支持已测环境中的有限候选优化，不能称为所有 CF 地址/用户的普遍加速。
