# 功能范围与验证边界

本文说明 SWD 支持的播放方式、选路与存储行为。实机报告按构建记录测试条件和结果。使用方法见[WebUI 与桌面程序](console.md)。

## 目标

为 Windows 上的 VRChat WannaDance 提供本地视频存储、本地未命中边下边播和后台预加载。SWD 根据实际观察到的播放协议独立实现这些功能。

## 已实现的范围

| 功能 | 行为与入口 |
| --- | --- |
| HTTP 本地视频存储 | 有效 API 响应动态确定的资源域名、GET/HEAD、单段 Range、条件请求；本地未命中共享下载，校验大小和 MD5 后发布 |
| HTTP 播放 API | 已有关联且本地文件可用时直接读取，后台检查地址；缺失时解析并回源，向播放器直接返回视频 |
| HTTPS 透传 | 桌面程序同时监听 80/443；HTTPS 保持原站加密连接，不读取本地视频或填充视频块缓存 |
| 回源连接 | [固定协议](upstream-channels.md#业务请求的协议策略)：Udon 清单、播放 API、有效视频资源使用 HTTP，Kiva/WannaInfo 按需备用清单使用 HTTPS；内置 DoH 与客户端 HTTPS 透传保留证书校验；桌面程序支持在 API 返回域名集合中测速优选 |
| 桌面程序 | 本地网页、Windows 托盘、单实例、设置持久化、可选启动时启用播放网关、hosts 接入与移除 |
| 后台准备 | 全曲库只读扫描、下载补齐、根据 VRChat 房间队列与预计播放时间提前准备视频；两种下载模式可互相切换 |
| 本地存储 | 数据库与完整视频目录独立配置，按资源指纹保存视频，SQLite 保存曲目资料、版本关联和请求统计；路径及归属见[存储契约](storage.md) |
| 容量与统计 | 资源请求热度、视频容量淘汰、请求明细保留期，以及按存储目录持久化累计的播放请求统计 |
| 排障 | 结构化日志、请求与共享下载关联、下载阶段和进度、任务及本地文件统计快照 |

同一资源的并发请求共享下载，不同视频版本独立存储。临时下载完成检查后才发布，活动文件受引用保护。存储根目录由操作系统文件锁独占，具体规则见[统一存储](storage.md)。当前格式不读取原版歌曲库或旧版 StepStash 格式，也不提供迁移。

## 使用与兼容边界

- SWD 为 WannaDance 的 HTTP 播放提供本地视频与边下边播，通过 hosts 接入。API 直接返回视频、冷／热播放、中途接入及恢复已有[分场景实机证据](live-acceptance-backlog.md)。视频解码、房间播放时间轴和游戏内刷新按钮由世界／播放器控制；传输结果与这些行为分别判断。
- 游戏内 CDN 选择 Auto、CF 或 HKG，SHA 暂不支持。早期报告中的 IP 入口超时记录对应当时的网络。
- 直连下载综合近期的下载、采样与测速结果选择 IP。遇到线路故障，下一次尝试可使用其他候选 IP。代理模式使用配置的代理出口。同一次运行内可复用仍保留的完整块，中断的半块重新下载。重启后按当前需求建立新任务。详见[分块选路与重试](download-upstream-routing.md)及[下载并发规则](download-concurrency.md)。
- 本地命中不等待上游查询；缺少映射或可用文件时仍需回源，下载失败不会自动改播其他版本或在已输出的响应中切换内容。
- 容量上限只约束保留的视频，活动视频和临时文件可能使实际占用暂时超限。后续按存储预算与使用保护决定保留哪些视频。
- 兼容性以 Windows 上 WannaDance 的 HTTP 播放链路为目标，实测的播放器后端和版本列在各批报告中。其他舞房、RTSP、Redis 鉴权及原版镜像下载器不在当前兼容范围内。
- 产品运行和部署面向 Windows；跨平台测试用于验证共用代码。
