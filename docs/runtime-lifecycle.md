# 运行文件生命周期

本页描述当前实现。分类原则见[持久化数据职责与边界](persistence-design.md)，实现范围与验证状态见[迁移计划](persistence-migration-plan.md)。应用持有独立业务数据库和固定块工作区，视频引擎借用数据库；桌面与 CLI 的完整视频均直接使用所选目录。两个入口的发布／导入暂存均位于实际视频目录的 `.swd-tmp/`，视频锁为 `.swd.lock`。

首次发布采用固定路径，不迁移旧测试格式、不双写旧名称、不增加定时扫描。配置实例、块工作区与媒体库各有独立 OS 锁。默认实例根为 EXE 所在目录；自定义 `name.json` 的实例根为 `name.json.d/`，主 JSON 仍在指定位置。

## 文件归属

| 文件/状态 | 备份和恢复价值 | 数量/体积边界及处理条件 |
| --- | --- | --- |
| 主配置 JSON、其中的 DPAPI 代理凭据 | 比较重要，承载程序运行设置；通常可重新配置，建议保留以便恢复。唯一一份凭据或导入资料按实际价值保管 | 一个主文件；错误格式拒绝读取，无法解密的凭据保留原密文，不因清理重置。文件复制不保证跨用户/机器 DPAPI 恢复 |
| `terms.json` | 可重新确认的跨会话状态 | 一个文件、最多 8 条独立加密凭据；最新优先匹配，满额按保存顺序淘汰最早记录。格式及失败语义见[存储契约](storage.md#json凭据与二进制身份)，临时文件永远不授予同意 |
| `channel.key` | 可选保留，维持稳定通道身份与旧观测关联；不属于核心个人数据 | 固定 32 字节，每实例首次使用时读取／准备一次，仅缺失时创建。成功或失败结果在该实例内不重读；损坏时原地保留并告警，网络可使用进程内临时身份；从备份恢复原密钥才能恢复旧关联。不自动轮换 |
| `data/state/throughput.json` | 可重建；持久化冷却可避免重启反复大流量测速 | 一个文件；候选更新时修剪失效样本。损坏/不支持的观测格式不恢复，下次成功写入原子替换，不生成损坏副本 |
| `data/state/inventory.json` | 可重建；保留耗时的上次成功扫描 | 一个当前结果，不累积多次扫描；保存失败保留本次内存结果并提示，磁盘旧结果不变 |
| `data/state/batch-last-success.json`、`data/state/batch-last-attempt.json` | 非核心任务结果；分别保留上次成功结果、最近结束/中止的结果，原失败列表不能靠重扫还原 | 各一个结果，失败列表随本次任务规模变化，不追加多轮任务。重启不续跑，强杀前未发布结果不恢复；保存失败仍发布本次内存结果并提示 |
| 旧 `state/setup*.json` 及其工作槽 | 已停用，不参与运行恢复 | 不再读写，保留已有文件；不会重放导入或影响自动启动 |
| 健康检测、活动下载、队列、导入回执、普通网页视图状态 | 不备份，运行时重建 | 仅内存；不为简单页面恢复新增文件。源文件删除仍需本次有效导入回执与完整目标校验 |
| `logs/app.log` 及轮转 | 排障时选备 | 每份 5 MiB、3 份历史；每个配置实例固定一套，不按启动/版本命名 |
| `.<目标文件名>.swd-tmp` | 不备份，不恢复成正式文件 | 主配置、条款和现行状态每个目标一个工作槽。排他创建、写入、Sync、关闭、原子替换；配置锁持有者在创建 Console/Monitor 前清理已知目标。旧引导、未知名称及正式文件保留，不递归清理，异常类型拒绝启动 |
| `config.lock` | 不需备份 | 固定 OS 锁媒介，存在不代表有进程运行；永不通过删除文件解锁 |
| 所选数据库文件（建议名 `storage.sqlite`）、SQLite WAL/SHM/journal（如有） | 最高备份优先级：包含大量歌曲、资源信息和几乎不可重建的个人积累，恢复所需伴随文件随库保管 | 启动垃圾清理不删除；请求明细按配置保留期处理，累计统计不随明细删除 |
| 所选视频目录 `{md5}.mp4` | 完整视频可重新下载，但重建比较费劲，按需备份；完整媒体库备份须覆盖所选数据库和视频位置 | 启动垃圾清理不删除；受显式删除和现有容量策略管理 |
| `EXE/work/<实例>/download-block-<数字>.part` | 不备份，不视为完整视频 | 完整块由引擎运行期持有、发布后随最后读取引用清理；应用取得本工作区锁后，在安装文件日志及打开数据库前清理已知块残留，不依赖视频盘。只识别 Go 临时文件数字后缀 |
| 视频目录 `.swd-tmp/download-publish-<数字>.part` | 不备份，不视为完整视频 | 发布暂存仍在视频卷，持有媒体锁并校验数据库后清理；不移到块工作区 |
| `EXE/work/<实例>/.lock` | 不需备份 | 工作区所有权持续到全部引擎停止；外置配置不改变 work 所在卷，不删除锁文件解锁 |
| 视频目录 `.swd-tmp/import-<数字>/` | 不备份，不保存源文件删除授权 | 只清理空目录或恰好一个普通 `video` 文件。未知内容或异常类型整体保留并告警，不递归删除。硬链接仅解除临时链接，跨卷暂存仅删除临时副本 |
| 数据库旁 `<文件名>.lock`、视频 `.swd.lock` | 不需备份 | 分别保护数据库与视频；不兼容开发期旧程序的父目录 `.lock`，旧程序应退出后再使用这些资源，使用中的资源不得由另一个实例清理 |
| Windows `.swd-probe-*` | 不备份 | 外部目录写权限探测使用系统 delete-on-close，关闭/进程终止即回收；不扫描外部目录。Linux 仅预检查有效用户权限，实际写入由引擎判定 |
| `%LOCALAPPDATA%/SWD/console-session-<会话>.json` | 不备份 | 沿用 #24，每个 Windows 会话一个记录；退出清理，崩溃残留由取得本会话互斥锁的实例处理，不扫描其他会话/旧名称 |
| hosts 备份、未知文件、旧格式证据 | 保留，hosts 恢复材料应备份 | 不属于垃圾。旧 `.settings-*`、`.snapshot-*`、`.throughput-*`、`.terms-*`、`.corrupt-*` 不迁移、不扫删；当前代码不再生成这些随机写入/损坏备份 |
| 系统 hosts 同目录 `.hosts.swd-<数字>` | 不备份，不用于恢复 | 仅本次权限准备或安全替换的暂存；正常完成／报错后清理自己的文件，强制终止残留不回放、不跨实例扫描。内容与权限规则见 [hosts 契约](console.md#hosts) |

“一个文件”是数量上限，不承诺固定字节大小：配置保留用户字段，扫描/任务结果随本次规模变化，媒体默认不长期保留，但使用中与临时视频仍可占用空间；日志才有固定轮转体积。

## 安全与失败

桌面入口取得配置锁及固定工作区锁，先清理本实例块残留，再安装文件日志、清理配置工作槽并创建 Console。CLI 也在打开数据库及创建引擎前准备独立工作区；明确建库并退出的命令只创建数据库，不启动引擎或工作区。CLI 普通启动使用已有数据库和视频目录，缺失时报错；目录已有完整视频时必须明确提供本次保留预算。已关闭的 lease 拒绝清理；重复实例拿不到锁。写入沿用现有串行化约束，固定工作槽占用时拒绝写入，不打开并截断它。桌面应用打开已有数据库，错误独立显示，Monitor 和个人资料操作不启动视频引擎。应用退出先停止消费者和引擎，再排空数据库已接受的写入并关闭它。媒体引擎在资源锁、目录检查和 SQLite 格式校验之后回收发布／导入暂存；拒绝格式时不清理这些媒体侧残留。块清理由独立工作区所有者先完成，未知项和其他类别文件保留。

目录及祖先拒绝符号链接和 Windows 重解析点。文件必须为普通文件；Windows 按已打开的根句柄定位，禁止中间重解析点，独占打开并核对身份后按句柄删除。其他进程打开文件（包括硬链接别名）时删除失败；解除硬链接不改写共享内容。Linux 采用受根目录约束的 unlink，依赖配置/存储锁排除其他 SWD 写入者，不将 Unix 的打开描述符当作独占锁。

识别到的工作名称若内容或类型异常，记录 `temporary_cleanup_skipped` 并保留；其他未知项直接保留。实际 I/O 错误、只读文件、占用句柄等返回错误；工作区清理失败阻止应用继续启动，媒体启动失败释放相应锁，配置清理失败阻止 Console 创建。成功项记录 `temporary_cleanup_removed` / `config_work_cleanup_removed`，配置失败记录 `config_work_cleanup_failed`；快照和吞吐读取失败另有告警，不把磁盘故障当成清理成功。

## 重启、切库、备份和覆盖

- 重启：保留正式配置、凭据、密钥、数据库、视频和最后发布结果，按上述规则回收工作产物；任务停止，不恢复未提交写入。
- 切库：设置重启后生效，库存/任务快照采用格式 2，按数据库与视频组合匹配，旧格式忽略；曲库文件操作已按数据库与视频组合校验，歌曲偏好按数据库校验。快照不作为文件存在或删除授权，每次任务重读当前库；旧库不搬运、不清理。吞吐属于网络通道，继续保留。
- 备份：正常退出后优先备份数据库及恢复所需的 SQLite 伴随文件，建议同时保留主配置；视频按需备份。若做完整媒体库备份，则应同时保存数据库和全部完整视频。日志、可重建状态、工作槽、临时媒体和锁可跳过。
- 覆盖：退出后只覆盖发行文件，保留实例根和外置库；运行文件名不带版本，启动走同一回收流程。不增加旧格式迁移或自动销毁损坏核心数据的流程。

验证及剩余实机场景见 [issue #25 验证记录](validation/issue-25-validation.md)。
