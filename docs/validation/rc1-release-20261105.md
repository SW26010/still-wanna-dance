# v1.0.0-rc.1 冻结与发布验证（2026-11-05）

本轮冻结 `6390078f` 的业务功能，目标版本为 `v1.0.0-rc.1`，标记 Pre-release，不设 Latest。冻结后只整理发布检查和证据，不新增业务能力。源码、许可及公开交付规则继续以[打包说明](../packaging.md)为准。

## 功能与兼容范围

相对 beta.4，当前功能包括首页与侧栏整理、程序日志查看和导出、可配置的视频块位置与存储路径校验、视频覆盖率估算、收藏保留预算修正、完整 Mihomo 配置导入及摘要、SOCKS5 服务检测、设置字段反馈、故障时打开 WebUI 和稳定版更新检查。网络诊断与共享引擎的生命周期整理保留既有业务行为。

配置仍为 v8，数据库仍为 v9。打开受支持的 v8 数据库会按现行契约迁移至 v9；升级前退出并备份，迁移后旧程序不能直接打开该库。完整配置、数据库及视频升级边界见[存储约定](../storage.md)。更新检查只提示稳定 Release，RC 从发布页手动下载。

## 失败、诊断与最小修正

- [check #45](https://github.com/SW26010/still-wanna-dance/actions/runs/41859623410)的 `TestHostsPolicyBrowser` 在退出时匹配到两个同文 Toast，本机原场景复现。DOM 探针确认退场过渡后收敛为一个；只先检查数量再检查可见性仍存在两次读取之间的竞争。最终将可见性和唯一性合并为一个 `toHaveCount(1)` 等待断言，原真实 Console 场景五轮通过。保留持续重复和隐藏通知的失败条件，没有延长超时或改产品通知实现。
- 首页辅助提示按卡片容器宽度隐藏；旧测试假定 1280px 一定隐藏，在侧栏变窄后不成立。1024px 又使网格转为单列，同样不是窄卡片条件；最终用实际窄屏检查隐藏，并保留宽屏、启停按钮位置和接入策略断言。
- 两个块重叠场景在当前 16px 方块和更宽正文下不再实际重叠。缩小测试视口，重新建立真实重叠，保留像素层叠、命中、切换、固定详情及窄屏完整端点检查。
- 许可证内容已移到「许可证与声明」页签，Mihomo 简化流程已移除旧的导入说明。测试改按现行入口检查 GPL、历史 MIT、内容权利边界、原文链接和保存后重启提示；没有改写历史文案快照或恢复失效产品文案。
- SOCKS5 失败通知的宽泛文本定位同时匹配 Fluent 的辅助技术播报节点和可见 Toast，改用通知的 `listitem` 角色定位。
- 首轮候选 EXE 许可校验拒绝 `golang.org/x/mod v0.41.0`：稳定版更新检查开始实际链接其 semver 包，但此前声明只覆盖旧的 EXE 模块集合。核对已锁定模块的 Go h1、LICENSE、PATENTS 及 semver 版权头后补入原文和 117 模块清单，同步内嵌声明；许可门禁 2/2 及实际 EXE 的 115 个模块覆盖检查通过。未升级依赖或修改业务代码，后续从新提交重新执行完整打包。
- 曲库紧凑行测试首轮得到白页和零行；原失败截图保留。未修改该用例，成组定向检查三轮及后续完整套件通过，未确认白页原因，不能宣称根因已修复。
- `TestCustomConfigurationsKeepIndependentStateAfterMove` 再次发生 `os.Rename` 的 `Access is denied`，与[v9 验证中的既有观察](storage-v9-20261101.md#已发现的失败及边界)一致。显式检查 Console 和配置锁关闭错误后，20 轮中仍有一次搬迁失败，关闭均成功。临时探针在失败后检查本测试目录的删除共享及当前进程句柄；30 轮出现三次失败，检查时删除访问均成功、未发现当前进程持有目标文件句柄。未确认瞬时占用的来源，不据此归罪于特定系统进程；保留原断言，不添加重试、等待或产品兜底。探针已移除，仅保留关闭错误检查。
- 许可修正后的第二次候选在 `TestSnapshotFollowsPortableMoveAndSeparatesLibraries` 出现同类目录重命名失败。随后独立 Go 标准库最小对照只创建目录、`os.WriteFile` 关闭文件并移动目录，不加载 SWD、SQLite、锁或后台 goroutine；C 盘 500 次中 3 次复现，代码不变、仅改用 D 盘隔离临时目录后 500 次全部通过。这说明失败可以独立于产品资源关闭发生，仍不能认定具体系统进程。两个原搬迁用例在 D 盘各重复 20 轮全部通过；正式预演沿用此临时环境，不削弱断言或隐式重试。
- [PR check #46](https://github.com/SW26010/still-wanna-dance/actions/runs/41881135431)的浏览器、真实 Console 联调及代表性 race 通过，但 Go 全包中的 `TestCalibrationLoopsDiscardedVideoAndSnapshots` 失败：旧用例假定 300ms 内至少循环完整的 32MiB 来源，runner 实际只完成 21 块／约 21MiB，仍正常按 `time_limit` 结束。改用同包已有的 `testing/synctest` 驱动原时限与每块 2ms 的夹具延迟，保留全部循环、重读和快照断言；定向普通检查 5 轮、Windows race 3 轮及测速完整包通过。未增加超时、删弱断言或修改测速产品实现。
