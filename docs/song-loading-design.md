# 歌曲加载与下载中随机读取

确认日期：2026-10-06。状态：已确认的目标设计，尚未完成实现与验收；现有共享下载、spool、MD5 校验和资源保护应优先复用并调整。

本文记录即时播放、队列预加载、下载补齐的流程及公共边界，不以计时统计指导架构。不新增通用解析框架或万能资源获取模块，不预先固定 `OpenSong`、handle 等接口名称。

资源身份、清单及数据库基础分别见 [MD5 视频资源管理](md5-resource-design.md)和[曲库设计](song-catalog-design.md)。本文补充地址缓存、共用加载流程和任意进度读取的目标行为；不表示这些能力已在当前版本提供。

## 内容与地址的关系

- 资源唯一身份为 MD5，大小用于一致性检查，不加入资源键。歌曲 ID 和 URL 均不作为文件身份。
- 正常情况下假设同时期清单与播放 API 指向相同内容。API 返回 URL 必须通过格式及来源验证，并能解析资源 MD5。
- 无论本次是否使用返回内容，都应把有效的新 URL 写入对应歌曲的地址记录，并更新观测时间。URL 相同的成功查询也更新观测时间；失败查询不清除已有地址或伪造刷新成功。
- 地址记录区分完整 URL、解析出的 MD5、来源 API/node 和观测时间。API node 不等于资源域名；不同路径或参数的 URL 不能仅因同域名就被合并。完整 URL 保留用于请求，日志应隐去敏感查询参数。
- “最近观测到的有效 URL”不等于完整视频已验证可下载。下载校验结果与 API 观测时间分开表达。并发刷新不能让较早发起、较晚返回的结果倒退覆盖更新的观测；具体写入排序机制在实现时确定。
- 若 URL MD5 与已有歌曲映射不同，记录歌曲 ID、预期 MD5、实际 MD5、来源等警告。新 URL 仍写入地址记录；不能因未采用其内容而丢弃观测。
- 极端冲突下优先 API 内容是后续可评估方向。本轮不增加来源冲突裁决：已有清单关联不因 URL 自动覆盖；未知关联可沿用现有规则由解析结果补充。已打开的读取句柄绑定确定 MD5，不替换内容、不打断正在播放的流。
- 本地缺失时，播放与队列可以取得 API/缓存 URL 指向的内容，并对映射冲突告警；这不更新已有清单关联。补齐则必须取得清单指定 MD5，不能把另一资源算作成功。

歌曲—URL 表的具体表名、索引、容量和失效规则尚未固定。暂不设计返回“旧值和未来新值”的公共接口；使用普通查询、等待和写入操作即可。地址持久化方向对应 [issue #3](https://github.com/SW26010/still-wanna-dance/issues/3)。

## 即时播放与队列共用歌曲加载流程

两者对地址新鲜度采用相同流程，预加载同样有紧迫性，不强制等待刷新后才下载。

1. 检查歌曲映射及本地文件，同时发起 API 地址查询。已有本地资源在检查/打开期间获得保护，不能在等待网络时被淘汰。
2. 本地文件存在则立即使用，不等待 API。后台查询继续更新地址观测；不自动替换文件。
3. 本地缺失但存在有效缓存 URL 时，直接通过该地址加入或启动下载，不先联网验证缓存地址。API 查询独立进行。
4. 无 node 限制时，缓存地址失败后先逐个尝试本次已取得的其他有效缓存地址，去重已尝试地址；明确 node 配置仍限制候选。没有缓存 URL 或候选耗尽后，才等待本次已有查询的结果。不额外发起查询，失败标记仍受观测版本约束。HTTP 仅在尚未输出正文时切换，队列使用相同候选推进规则。
5. 一旦选定并打开资源，本次句柄始终绑定该 MD5。随后到达的 API 结果可以更新地址表，但不能切换已输出的内容。

播放和队列仅在消费结果及持有期限上不同：

| 调用方 | 行为 |
| --- | --- |
| 即时播放 | 获取独立读取器，响应播放器请求；持有期间保护资源 |
| 队列预加载 | 不读取正文，等待完整准备完成；队列及离队交接期持续保护资源 |

队列可以保护多个资源。队列变化取消的是该任务的等待与队列持有，不影响已经加入的播放器。已有交接保护及后台下载额度规则继续适用，不由这次流程统一额外改变。

队列下载到一半时，若播放选中了同一 MD5，必须加入已有任务，创建独立读取器，并按播放器需要的偏移读取。不得重复整首下载，也不得等待整首完成后才允许播放。

## 下载补齐

1. 检查并更新清单，以清单更新歌曲—MD5 关联。
2. 使用现有快速文件检查，按 MD5 去重得到缺失资源及关联歌曲 ID。已有文件不逐首查询播放 API。
3. 对每个缺失 MD5，通过对应歌曲 ID 查询 URL并更新歌曲—URL 记录，再下载；不假设能从 MD5 直接构造 URL。
4. 同 MD5 对应多个歌曲时依次尝试 ID，直到成功取得并准备好目标 MD5，随后停止尝试其余 ID。查询、下载失败或返回其他 MD5 时，可继续尝试下一 ID；所有候选失败才报告该资源失败。
5. 不符合目标 MD5 的地址仍按地址观测规则保存，但不能冒充补齐成功。取消、退出、容量预算停止及本地存储失败均不继续遍历其他 ID 来绕过。
6. 复用现有完整文件容量预留及资源保护；同 MD5 不重复计费。下载等待调用者取消时，不能提前释放仍在执行的共享任务所占额度。

补齐保留独立清单调度流程，共用 URL 查询基础函数和下载能力；不强行经过即时播放的“先用缓存、后台刷新”编排。

## 下载模块边界

公共下载核心接受完整 URL及校验所需的 MD5、大小，负责下载、临时存储、下载中读取、完成校验和发布。它不查询歌曲 API，不决定清单映射，不管理地址刷新，不自行选择另一个内容版本。

本地文件检查、加入已有下载、前后台额度及容量准入使用上层已有能力，不要求建立新的通用资源获取层。同 MD5 的共享任务仍复用现有实现；共享前校验已知大小等约束，不能混入不一致的内容。备用地址用于同内容重试，选路职责继续遵循 [issue #2](https://github.com/SW26010/still-wanna-dance/issues/2)，不在这里新增性能选优体系。

下载句柄至少支持：取得已知大小等元信息、创建独立的按偏移读取器、等待完整完成、释放本次持有。后台等待完成无需读完并丢弃正文。

## 下载中偏移读取与任意进度拖拽（必需能力）

这两项是本轮核心要求，不以“顺序下载到该位置再返回”作为最终实现。对于支持有效 Range 的上游，拖拽到尚未下载的位置必须触发相应区间的获取，不能等待从文件开头下载完整个前缀。尾部 MP4 元数据读取同样适用。

### 数据与调度

- 复用一个按资源管理的下载任务及临时存储，跟踪实际完成的字节区间。稀疏文件长度、预分配长度及下载字节累计值均不能代表某区间可读。
- 读取已完成区间立即返回；读取未完成区间提出范围需求并等待对应数据，支持取消。播放器需要的区间优先于后台顺序补全，避免所有连接长期被后台占满。
- 同任务中的相同或重叠范围需求合并，限制单资源及全局请求并发。快速连续拖拽不能无限创建连接；不再需要的范围请求可按使用者引用取消，但不能影响其他读取者。
- 前台取所需区间，后台继续补全空洞，直到整个资源完整。预加载、补齐及多个播放器共享已完成区间，不因拖拽重新下载整首。
- 读取器偏移相互独立；数据写入完成并登记可读区间后再唤醒读取者。单个读取器关闭只释放自身引用。

### HTTP 与一致性

- HTTP 入口负责客户端 Range 解析、响应状态及头部；下载层负责上游区间请求和数据可用性。播放器拖拽可能表现为多个 HTTP 请求，不能只靠一个 Reader 的 Seek 方法满足要求。
- 验证上游 206、Content-Range、完整大小及实际区间长度，处理短读、断流、重试、取消和越界；禁止把错误范围写进指定偏移。
- 上游忽略 Range 返回 200 时，不得将全文当作所请求区间。必须识别该能力限制并报告明确结果；只有在不破坏既有读取与校验的情况下才可降级整文件下载。此降级不算通过任意进度拖拽验收。
- 同一任务绑定 MD5 和一致的大小，所有分段必须属于同一内容；切换地址和重定向保留现有来源与内容校验约束。若有可用的实体校验标识，应评估用于防止分段间实体变化。
- 乱序接收不能直接按网络到达顺序累计整文件 MD5。必须覆盖全部区间后按文件顺序完成完整校验，或使用经证明等价的方案；全部覆盖且大小、MD5 正确后才发布正式文件。
- 下载失败必须唤醒等待者并返回错误，不能永久等待；不得把失败或有空洞的临时文件当作缓存命中。已交付的流式字节无法在最终校验失败时撤回，不承诺流式输出已经通过完整 MD5 校验。

范围块大小、连接数量、调度算法、临时文件布局及具体 Go 接口待实现前细化；任意位置按需获取、区间正确性及共享读取不是可选项。上游不支持 Range 时的客观限制须明确暴露，不承诺任何服务器条件下都能立即拖拽播放。

## 抽象范围

仅明确共用歌曲加载流程（播放、队列）与现有共享下载核心（播放、队列、补齐）。普通地址查询/写入和现有保护机制继续复用；不新增双结果解析接口、通用刷新框架、通用保护框架或万能获取模块。是否使用 `OpenSong` 命名在实现时决定，不作为架构验收条件。

## 实施验证要求

以下为待实现的验收要求，不是已通过的测试结果：

- 本地命中不被慢 API 阻塞；有效 API 地址始终落库并更新时间，冲突警告不改变当前播放内容或已有清单关联。
- 播放与队列使用相同加载流程；缓存地址可直接用，失效后利用本次已有查询，队列不额外等待刷新。
- 同 MD5 多歌曲依次查址，任一成功后停止；错误 MD5 不算成功，取消及预算停止不被回退绕过。
- 队列下载中加入播放，共享任务；队列取消不影响播放，保护交接及容量额度不提前释放。
- 可控 Range 上游中，将文件前部下载故意阻塞，请求尾部及任意未下载区间仍能发起对应 Range 并正确返回；不能通过等待前缀完成冒充拖拽支持。
- 多读取器、重叠范围、反复前后拖拽和尾部元数据读取的数据正确性、请求合并及连接上限。
- 错误/忽略 Range、大小变化、短读、断流、取消、重定向和最终 MD5 失败不会发布坏文件或让读取者永久等待。
- 乱序下载最终文件与原文件逐字节一致，完整 MD5 正确；临时空洞不被误判可读或完成。
- 在真实播放器中验证冷加载、预加载中接入、向前/向后拖拽和恢复播放。HTTP 范围测试通过不等于播放器可播放或首帧验收通过。


## 2026-10-07 实现收敛

本节记录本轮代码与自动化验证边界；前文保留原目标设计，真实游戏验收另见历史报告，不把本轮测试当作新游戏验收。

- 地址保存、写盘、发布和索引错误以 `ErrLocalStorage` 延续到上层，停止换通道、节点、歌曲 ID。引擎保留首个本地故障，拒绝后续新下载；已有完整文件仍可验证读取，失败任务释放容量。修复存储后需要重启应用创建新引擎，单独启停 CDN/队列不恢复。不新增自动探测或手动恢复入口。
- API 查询只负责地址观测；歌曲与资源关联由下载完成后的调用方确认。前台登记独立于 HTTP 等待者，短读、断开后仍可完成；一致映射跳过重复事务但继续更新内存保护。既有清单映射冲突规则不变。
- 外部 URL 入口统一校验并返回元数据；内部队列预取直接使用已解析资源。后台只等待共享任务，不创建读取器；前台每次尝试结束立即关闭读取器，失败 spool 在替代下载前释放。
- 删除无效 `reductionPercent` 和旧响应头延迟输出，停止累积/写入旧延迟样本。历史列原样保留，命中数、未命中数、节省字节及首正文统计继续工作。
- Monitor、队列和失败列表复用相同数据的节点。测速样本随时间过期仍会刷新；设置统一重启生效及队列/CDN 独立语义保持不变。
