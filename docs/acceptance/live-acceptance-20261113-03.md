## 结论与构建

本轮专门验证用户提出的“need-by + 30 秒后，被 SWD 主动拒绝”。1343 CF 预览的实际视频 GET 3 在自身截止时返回 **504 / expired**；播放器约 12 毫秒后重新 GET。用户看到持续加载／黑屏，没有明确错误提示；解除限速后自动恢复，音画正常。该场景通过。

这是响应正文尚未交付时的截止样本，不覆盖已经返回 200/206 并交付部分正文后的中断表现，不代表播放器会显示 SWD 的具体拒绝原因。

- 产品与前两批相同，源码 `a7e8c175fd4a6300e4fbf384d8180721897b0bec`，版本 `dev-live-20261113-01`，实际 EXE SHA256 `8494befe3312ef85faae0b25f10db3aca4d54162727f1b8f0e4b918249c98da5`。原构建时工作区干净，本批直接复用 EXE；当前未提交差异为此前报告、证据和实验中继，不混入产品身份。中继补丁及二进制指纹单独保存。

## 干扰与边界

- 尽管用户确认旧预览已关闭，仍收到上一首 1344 的残留 WMF GET，并在低速阶段反复重请求。公开时间线把这些请求标为 `targetSong=false`，1343 的 need-by、截止和重请求按独立资源与请求编号关联。该干扰影响带宽竞争条件，不把本批记为单首吞吐或无后台竞争实验。
- 同一资源也存在并发 GET；15 秒交接的创建已有证据，但本批没有独立验证“无其他需求时，15 秒到期取消”的极限，也不能量化交接带来的复用或起播收益。这些内部边界继续引用[开发回归](../validation/block-scheduler-validation.md)。
- 本批没有更改产品源码或新增测试机制，沿用前两批构建与已通过实验包回归的中继；不重复不受影响的产品测试。前两批起播、拖动结论分别保留，不重写历史证据。
- 没有完整正式视频文件的独立 MD5 复算、CPU/帧时间、多人同步或所有网络条件结论。零容量与 HTTP MISS 不等同于不存在同进程块复用。
