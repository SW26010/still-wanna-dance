# 无 VRC 的并发 CPU 与完整缓存补测

`run_followup.py` 驱动 `internal/cacheproxy/cpu_followup_windows_test.go` 中的显式 opt-in 开发实验。普通测试跳过，产品默认值不变。输出全部写入忽略的 `artifacts/cf-cpu-followup`，正式结果另脱敏交付。不得用这些结果将 LA-037 标记为游戏通过。

## 冻结设计

- 本地独立进程提供 TLS/HTTP 1.1 Range fixture；独立信任本次生成的证书，保留域名验证，不关闭 TLS 验证。实际连接仅 IPv4 回环，外网流量为零。
- 上游全局发送节拍为 16 MiB/s，64 KiB 一片，每个请求固定 20 ms 响应头延迟。发送时隙共享；取消后已经预约的时隙不会退回。模拟上游的 CPU 不计入目标进程，但两者仍共享实机 CPU；不模拟 CF 网卡、路由、丢包或 CDN 行为。
- 等速实验：4/8/16/32 路分别传输 96 个 1 MiB 区间，总量相同。比较新连接与每 worker 预热一个块后的连接复用，每块验证 Range、长度、EOF、ETag、SHA256。原始区间内容是公开确定性 fixture，不是实际视频。连接池容纳 64 个空闲连接，明确验证热组的 TLS 次数。
- 完整引擎：每文件 64 MiB，场景为单文件预缓存、两文件预缓存后 250 ms 冷读第三文件并跳到倒数第二块、两文件预缓存 250 ms 后取消并关闭引擎。经真实 spool、写盘、最终 MD5 和发布；结束后在计时外独立读取正式文件核对 MD5。读取客户端为模块内 spoolReader，不运行游戏、解码或播放器 HTTP 服务。
- 候选版本只通过 Go `-overlay` 改实验构建的后台 worker 数，测试中在开始工作前设置每个实例的请求预算。标签 4 是当前产品基线：总请求 6 / 后台 4 / 单视频后台 worker 3。标签 8 是 8/6/7，16 是 16/14/15，32 是 32/30/31。全局始终不超过 32，保留两个前台额度。这是成套预算策略比较，不能当作只改变单个常量的因果实验。
- 固定随机种子 2026101402；五轮，每轮一个 6 秒空闲采样基线、8 个等速组、12 个引擎组，共 105 组。逐组新进程、独立缓存目录；正式组不覆盖、不按性能删样本。
- 正式本地传输预算 12 GiB，包含已保存组的上游字节与预热，并给未完成的预实验/竞态组预留 1 GiB、下一组预留 512 MiB。每组超时 70 秒，原点最多存活 45 分钟，ETW 单段最多 10 分钟。出错保存当前组并停止该批。

## 计时与观测

固定 fixture 内容/参考哈希和 TLS 证书准备在计时外。计时内包括新连接、缓冲分配、读写、原始实验逐块 SHA256，或完整引擎初始化、最终 MD5、发布与关闭。两种模式的 CPU 绝对值不能直接相减。

每 100 ms 记录进程 user/kernel 时间、runtime/metrics 堆对象字节、私有内存、工作集、句柄和 goroutine。内存采样避免每次调用 ReadMemStats 的全局暂停；分配量与 GC 总量只在首尾读取。采样的内存峰值可能漏掉短峰，CPU 短峰采用 ETW 调度区间。HTTP 观测记录从 RoundTrip 到 Body.Close；取消时计数以 Close 观察值为准，上游写出字节另列，不能当作精确网卡线速流量。

沿用 `analyze_cpu.py` 的微秒调度解析、DPC/ISR 区间扣除、10/100 ms 峰值以及 xperf 独立总量校核。完整引擎没有持续稳态假设，主要比较整个生命周期。开始/结束标记不包含 JSON 输出及第二次独立 MD5 校核。

## 执行

先确认受限 ETW 助手 ready/stopped，再依次运行 `run_followup.py build`、`helper-check`、`pilot`、`build-race`、`race`。检查预实验后冻结代码与 EXE 哈希，再逐轮运行 `round --round 1` 至 `5`。所有编译、race、ETW 导出/分析都与正式测量错开。完成采集后调用 `quit`，确认助手与所属会话退出，再分析。原点由每轮 finally 关闭；JSON 结果和日志不覆盖。

本次只修改开发工具和 opt-in 测试，不新增产品设置，不启动 VRC，不修改 hosts、系统优先级、亲和性、电源方案或正式缓存。
