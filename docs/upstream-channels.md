# 上游通道与检查器设计

## 职责与边界

DNS 仅维护答案合法且 TTL 未过期的 IP 池、刷新和并发查询合并，不记录连接胜者，不测延迟或吞吐。通道层组合入口与传输路径，维护可执行的候选及稳定身份。Upstream State Monitor 对每个操作、入口、通道分别测量，提供推荐；业务仍负责资源版本校验、下载和失败处理。

`internal/upstreamnet` 统一承载独立 DoH、DNS 池与刷新、双栈拨号及 SOCKS5 adapter；命令行与 Console 直接复用它，分别拥有解析器的关闭责任。`upstreamrequest` 继续定义候选池与拨号契约，Console 只组装配置、连接池及应用生命周期。协议测试随网络实现维护；Console 测试通过相同网络契约注入夹具，不读取解析器私有缓存。现有 CF 实验的细粒度观测仅在 `cf_block_experiment` 构建中提供，正式产品不包含实验探针。

直连候选为 `入口主机 × IP`；SOCKS5 候选为 `入口主机 × 当前代理配置`。SOCKS5 始终传递原域名，让代理解析目标，绝不展开本地 IP。代理凭据不进入候选 ID、检查结果或日志。配置版本由应用请求通道持有，旧版本观测不能用于新版本。

代理后端可选外部 SOCKS5 或内嵌 Mihomo B2，后者从单个完整核心捕获固定出口对象，最多激活五个已保存节点，不执行订阅中的分组、规则、入站或系统网络配置。二者共用 `Proxy{ID,Dial}` 与候选策略，持久化通道仍沿用 `socks5` 前缀。B2 容量不足、运行时退役与调用者取消仅更新独立诊断，保留已有质量和吞吐样本，不延长其有效期；真实超时与响应错误仍会影响质量。设置保存后重启生效，详见 [B2 集成记录](validation/issue-14-b2-integration.md)。

## 模式

- `direct`：不启用代理，只生成直连候选。
- `socks5`：强制代理，只生成代理候选；失败不得回退直连，也不查询本地目标 DNS。
- `auto`：平等选择，直连 IP 与代理候选参与同一操作的测量。DNS 失败不移除代理候选。未有测量的候选不视作最优。

已有 direct/socks5 配置保持兼容。普通业务请求继续使用现有客户端；通道候选和推荐携带实际 Transport，使用推荐时能够固定到被测路径，不在传输时重新选 IP。Monitor 不导入 console/DNS，也不创建代理；基础设施发布候选提供者。

## 请求与连接

直连 Transport 固定目标 IP，但保留原 URL、HTTP Host、TLS SNI 和证书校验。候选仅允许自己的主机；禁止重定向悄悄变成另一条通道。请求和建立新连接前检查 IP 是否仍在有效 DNS 池中；原地址过期时通过共享解析器重新确认，只有同一 IP 获得有效答案才继续，解析失败或原 IP 已移除仍拒绝，不切换线路。已建立连接和进行中的响应不因 TTL 到期被取消。

普通直连和 HTTPS 透传使用双栈拨号。独立 DoH 并发查询 A 与 AAAA，沿用首个可用答案后 200 ms 的收集窗口、整体六秒上限与最多六个 IP 的池；池满时交替保留两种地址，避免先返回的一族占满池。TTL 取收到的有效地址及 CNAME 链的最小值，最多 300 秒。单族无答案或超时不阻塞另一族，超过窗口的答案不加入本轮池。DoH 自身仍使用现有 IPv4 引导地址，因此这里支持双栈网络及仅有 AAAA 的目标，不承诺纯 IPv6 接入网络可用。

通过报文校验的 NOERROR 空答案（含仅返回 CNAME 的情况）是正常的单族无记录，不重试同一 DoH 服务的另一入口 IP、不清除引导缓存，也不建立负缓存或影响另一族的 TTL。HTTP/传输故障与无效报文仍按原规则重试并在入口均失败后清除引导缓存；两族及所有服务均没有可用地址时，整体解析仍报错。

连接阶段复用 [Outline SDK 的 HappyEyeballsStreamDialer](https://pkg.go.dev/golang.getoutline.org/sdk/transport#HappyEyeballsStreamDialer)，适配已有 DNS 池，不读取系统 hosts。两族都有地址时先尝试 IPv6，未连通则按组件默认的 250 ms 间隔交替尝试，明确失败可提前尝试下一地址；每次 TCP 建连最多五秒，同时受调用者期限约束。首个成功连接被使用，其余尝试取消并关闭。应用不另设竞速计时器、连接胜者缓存或 IPv6 评分。Go 原生 Dialer 没有直接接收已解析 IP 列表的入口，故这里保留独立 DoH 并使用允许注入解析结果的组件。DNS 收集仍按上述池机制完成，没有改为流式返回每个解析答案。

“优先 IPv6”适用于普通直连建连；Monitor 已选中的固定 IP 继续按测速结果使用，不因地址族重排或在传输时偷偷换 IP。HTTPS 透传共用双栈拨号，保留原 TLS 与证书校验。SOCKS5 始终传原域名，内嵌 Mihomo 的解析和出口行为保持原配置。候选执行前仍检查配置版本，避免持有旧推荐的调用方在强制代理模式下继续直连。

## 刷新与交接

DNS 提前刷新；相同 IP 的候选身份和测量历史保留，新增 IP 待测。候选变化唤醒 Monitor，TTL 延长而成员不变无需清空结果。读取状态不触发网络查询。旧答案在其真实 TTL 内仍有效；刷新再次返回同一 IP 时，租约取旧到期与本次答案到期的较晚者，短 TTL 不提前撤销旧租约，查询缓存与下次刷新仍按新答案 TTL 计算。失败不延长 TTL，也不为冷启动的零/短 TTL 增设保底有效期。DNS 过期的候选不可获得新推荐。

Monitor 每项成功后立即公布，不等待整轮完成；失败只影响对应候选。调度以配置周期为上限，并在成功观测即将过期前检查，保留刷新余量。没有有效候选时明确返回未知/无推荐，不无限使用旧结果。启动、全体失败和 TTL 过短时无法保证零空档。

网络模式和代理配置改变会发布新版本，取消旧检查，废弃受影响的推荐；仍允许且 IP 不变的直连通道保留历史，替换代理使用新的不含凭据的身份。候选提供者持有连接池，Monitor 不关闭它们。DNS 闲置清理、程序退出和传输关闭均有明确生命周期。

## 测量和推荐

吞吐历史清理分别判断直连与代理候选集合是否已确认。auto 模式下 DNS 失败但 SOCKS5 可用，仅确认代理集合，保留恢复的直连历史；DNS 查询成功后才清理已消失的直连通道。代理历史按当前配置身份清理，不以代理兜底成功代替 DNS 查询成功。

歌曲列表、播放地址解析比较响应耗时。资源轻量检查保留原调度频率，请求 Range bytes=0-0，读取一个正文 byte 后关闭响应，只更新延迟与可用性，不计算吞吐。吞吐检测每个配置周期一轮，持久化最近尝试时间，启动时已到期则测速，否则等待剩余时间；DNS 更新不绕过该间隔。资源测速复用同轮同一线路解析出的合法 URL，不为每个 IP 重复生成歌曲样本。每个视频通道正文下载满 3 秒、达到 16 MiB、整首资源下载完毕，任一条件满足即停止；3 秒也截断停滞读取。吞吐使用实际正文下载字节除以正文下载时间，连接与握手时间单独计入延迟。视频探测串行执行，避免争抢本地带宽；此窗口测量不保证持续满速带宽。

WebUI 将响应延迟和吞吐样本分区显示，各自关联采样歌曲和观测时间。吞吐的 ThroughputSongID、ThroughputObservedAt 来自实际测速样本，不随轻量检查换歌而更新；SampleSongID 属于最新响应检查。业务下载会暂停自动资源探测，被打断的吞吐样本不记为失败，恢复后只做轻量检查，完整测速等待下个周期。

保留当前健康通道，挑战者需连续两轮明显更优（默认至少 15%）才切换；资源推荐按 ThroughputObservedAt 识别新的吞吐样本，轻量检查不重复计票，也不清零等待中的胜出次数。当前通道失败、失效或移除时立即选择其它有效候选。读推荐不增加连续胜出次数。推荐只代表当前已测候选，不承诺全网或所有歌曲的全局最优。

## 验证

验证模式隔离、代理远端 DNS、直连固定 IP 与 Host/SNI、TTL 变化和配置切换失效、相同 IP 刷新保留历史、新 IP 待测、失败隔离、推荐迟滞、候选复用及无 I/O 读取。既有普通 Transport 测试入口保留兼容。

2026-10-18 双栈开发验证：受控测试覆盖 AAAA 解析及 CNAME 最小 TTL、非公网地址拒绝、双族池容量、单族缺失、IPv6 优先、立即失败回退、无响应时 250 ms 后尝试 IPv4、调用者取消与落败连接关闭。IPv4/IPv6 本地 TLS 测试检查固定 IP 的 Host/SNI、TTL 失效和 HTTPS 透传的 TLS 1.2/1.3、HTTP/2、Range 正文。

审查补充验证使用本地证书验证的 DoH 服务：A/AAAA 正常空答及仅 CNAME 答复均只请求一次，完整保留已有引导 IP 与到期时间；HTTP 503 和不匹配的 DNS 报文仍尝试两个入口并清除失效引导缓存。地址池另外覆盖单族空答不改变有效答案 TTL，以及全部空答明确失败。

`go test -tags=no_easytier ./cmd/... ./internal/...`、同范围 `go vet`、桌面程序 `-mod=readonly` 构建及许可证清单核验通过（新增 Outline SDK 一个模块，未升级已有依赖）。Windows 使用已有便携 GCC 对 DNS、DoH、HTTPS、固定候选与代理模式测试执行 `-race` 并通过。首次 race 发现新测试记录器的共享切片未加锁，修复测试后复验通过；首次失败与复验日志均保留在本次忽略目录。

同日通过 `SWD_LIVE_DUALSTACK=1 go test -tags=no_easytier ./internal/console -run '^TestLiveDirectDualStack$' -v -count=1` 实测真实 CF API 及视频：`api.udon.dance`、`play.udon.dance` 均返回 IPv4 `104.26.4.28`、`104.26.5.28`、`172.67.69.58` 和 IPv6 `2606:4700:20::681a:41c`、`2606:4700:20::681a:51c`、`2606:4700:20::ac43:453a`。强制 IPv4、强制 IPv6、普通双栈、HTTPS 透传均通过证书校验并返回 206/1024 bytes；普通双栈与透传实际连接 IPv6。此检查证明连通和协议行为，不是速度对比，也不代表 VRC 播放体验；原始日志保留在忽略目录 `artifacts/dualstack-20261018/`，不记录签名 URL。

SOCKS5 持久化身份使用[配置实例数据根](storage.md)的 `channel.key` 中的本地随机密钥，对代理地址、用户名、密码计算 HMAC-SHA256。相同配置在重建连接池及重启后身份保持一致，任一字段变化则隔离旧吞吐样本；标识和样本文件不包含明文凭据。每个应用实例准备一次身份，各网络与诊断入口共享同一成功或失败结果；持久化失败时使用临时身份，不认领旧观测。密钥丢失后生成新身份，旧样本不会匹配。吞吐快照采用独立 schemaVersion=1；无版本、其它版本、旧节点键和进程内序号样本均不迁移，重新采样。需要延续旧通道身份和观测时可按需保留该文件；它不是代理凭据的解密密钥，也不要求普通用户专门备份，分类依据见[持久化职责](persistence-design.md#配置与辅助资料)。

自动吞吐检测间隔可在 WebUI 设置中调整，默认 20 分钟，允许 1～1440 分钟整数，对应 throughputIntervalMinutes，未设置时采用默认值。Monitor 策略固定为创建时快照；保存不改变当前监测，应用重启后按新间隔与已持久化的最近测速尝试时间计算到期时间，不重置计时，已到期则进入正常调度。此设置同时决定吞吐样本参与推荐的有效期，首字节检测频率不变。保存无需先停止网关或任务，现行生效契约见[配置生命周期](settings-lifecycle.md)。
