# 下载并发与播放优先

## 当前实现（全局块调度，2026-10-15）

需求层将 GET、读取窗口、队首、普通队列和补齐转换成独立的块需求，先按来源过滤、再汇总每块属性；调度器只认识内容块、完成期限、有效租约和实际读取阻塞。旧 P0～P4 与每视频固定 worker 已移除。

| 约束 | 当前行为 |
| --- | --- |
| 内容及执行 | 1 MiB 固定块；MD5、大小与块号共同标识，资源会话保证实体/选路一致性；同块只执行一次 |
| 全局并发 | 16 路软上限：普通需求受当前开放额度及软上限约束，Blocking 缺块立即执行，可突破 16 路；首请求、重试、重定向和顺序 200 回退统一由块调度管理，底层 HTTP 只跟踪生命周期 |
| 启动节奏 | 普通需求从 1 路开始，每 250 ms 最多新增一路；Blocking 不等缓升或恢复冷却，其超限启动不直接抬高普通需求的开放额度。超限时普通新请求等待实际执行数回落；已有额度可立即复用，空闲不积攒 |
| 供数估算 | 每 500 ms 在有执行时采样，按去重剩余量/完成期限估算目标；迟到采用 2 秒追赶窗口，增路无收益时回退并冷却 5 秒 |
| 暂停保留 | 最多 32 个检查点，文件长度合计最多 512 MiB（含空洞）；超限淘汰最早暂停者；已有读者引用释放后才删除，淘汰后的新需求重新下载 |
| 候选窗口 | 每资源滚动提交最多 8 个补齐候选；每读取位置另保留当前块与后面 2 块；不会把整个库展开成任务 |
| 元数据 | 最多 32 个资源会话、4,096 个已注册块；核心最多 32,768 份需求，产品按块提交一份摘要；需求管理层每块最多 128 份活跃来源与交接记录。MaxDownloads 继续限制本地验证并发，不再决定视频网络席位 |
| 交接 | GET 取消/关闭后最多 2 秒；队首消失后最多 20 秒；普通队列删除直接撤销。Blocking 撤销，ReadyBy 在原期限与当前时间的较晚者上分别延后 2/5 秒，不随无关事件滑动 |

Blocking 只在 Read 确实等待缺失内容时成立，GET 到达、预读窗口或刚结束的读取都不自动取得此标记。多读者独立撤销，不同 Blocking 块均立即放行；同等非阻塞期限按不透明 Owner 公平分配；普通块优先比较最早有限 ReadyBy。每份需求保留自身租约，过期或关闭句柄不能被迟到更新复活。来源仍有效才续 30 秒租约，资源协调器每 10 秒确认存活；交接租约不续期。

同块存在有效 GET 时，交接不参与调度属性竞争，但仍按自己的固定租约存活；独立的队首/普通队列期限照常参与。过滤后 Blocking 取实际等待的或、ReadyBy 取最早有限值；任何有效来源都能维持块存活。管理层按每份租约最早到期时间重新汇总，交给核心的最晚 LeaseUntil 仅是最终存活上限，不能代替各来源独立到期。

读取正常推进/Seek、块完成和关闭引擎不创建交接；队首与普通队列互换时原地更新来源和时间。队列连续存在时保留来源标识，删除后重加或重置产生新标识，旧地址解析结果不能复活已撤销来源。交接只保留计算后的时间和非阻塞属性，原始来源与原因仅写入转换日志，不进入交接的运行时数据模型；交接不再产生交接。

当前没有经过验证的完整媒体字节/时间映射。因而不把 HTTP Range 或歌曲裁剪 start/end 当作播放时间：冷启动期限取 1 秒，读取附近按每块 2 秒启发式准备，远处补齐取启动后 60 秒加块偏移；队列按 10 秒启动窗口、后续位置每项 30 秒及块偏移估计。全部是有限、可观测的调度估计，不声称预测了播放器缓冲或保证提前。VRC 日志只提供队列顺序；实际需要的块由本地读取事件确定。

Blocking 新请求立即启动；后台带宽竞争的让位仍给现有工作 200 ms 完成机会。持续阻塞或即将到期的待执行块遇到竞争超过该时间后，可选择性暂停较不紧急且尚未收到字节或剩余超过 64 KiB 的块。正文关闭和部分前缀写入完成后才归还执行能力，非阻塞恢复至少冷却 500 ms；仍有阻塞时不重复恢复刚让位的后台块，暂停块自身变为 Blocking 则立即恢复。单纯身份变化不立即取消在途传输。顺序 200 无安全分段续传，暂停后下一会话重新下载。

文件仍由资源层管理：完整块和部分前缀保存在受管临时文件，暂停元数据只在当前引擎内并受上述保留上限约束；恢复沿已验证终点、强 ETag 和原候选进度，不重访已失败通道。所有响应仍校验状态、Content-Range、长度及编码，弱/缺失 ETag 依赖最终 MD5。收到全部声明字节但未通过 EOF/超长检查的块不会提前发布。完整文件大小与 MD5 正确才发布；关闭等待执行/读者清理，异常残留由下次启动处理。

需求变化在资源的有限窗口内协调，只有摘要改变的块才更新核心及索引堆，成本估算按 500 ms 合并；等待租约、恢复冷却和最近期限使用统一计时器。排队不分配分块缓冲，实际执行各自取得缓冲；复用池最多留 16 份，Blocking 超限执行按需额外分配、归还时不扩大复用池；失效 Seek 窗口释放任务元数据。丢弃/重试的执行样本不用于提升供数估算；顺序 200 回退按全文件成本计算。Debug 事件记录排队、放行、过期、让位、目标变更与无收益回退，另以 block_demand 记录汇总来源/交接覆盖、block_demand_handoff 记录转换前的来源及原因。

API、清单、测速和空闲连接不属于这里的 16 路视频下载软上限。队列与批量任务的上层两个解析/下载调用者仍用于限制来源准备；资源一旦接入就按块竞争，不再占独立的视频网络席位。活动文件和仍被旧读者引用的文件不计入“暂停检查点”上限，该上限不是整个临时目录的磁盘配额。调度不提供总带宽整形或游戏帧时间保证。旧对照结果保留于历史开发文档，不能直接证明新策略的效果；本次自动验证和替代测试映射见[开发记录](block-scheduler-validation.md)，实机范围为 LA-040 并联动 LA-008/018/037/038/039。

## 2026-09-26 历史评估

以下保留当时的实现、建议和环境限制；“尚未实现 Range”“没有播放抢占”及 race 工具缺失不代表当前状态。

Auto 下的下载补齐、队列预缓存先查询 node=cf，失败后查询 node=nya；固定模式仅选择查询参数。资源来源以 API 的实际返回域名集合为准，不与 CF/HKG 名称绑定。同内容候选可用于失败回退，相同 URL 不重复尝试。通过快速存在性检查命中的 MD5 文件直接复用，缺失内容按 MD5 去重。已有共享下载继续当前传输，避免重复下载。

### 当时的并发与限制

| 层级 | 当前行为 | 扩大并发所需修改 |
| --- | --- | --- |
| 下载补齐 | `batch.go` 固定两个 worker | 将 worker 数连接到后台并发设置 |
| 队列预缓存 | `queue.go` 同时处理最多两首，只准备设定的预缓存范围 | 同步调整 active 上限和结果通道容量；保留队列顺序及失效取消 |
| 下载引擎 | `cache.go` 后台额度为 `max(1, min(2, MaxDownloads-1))`，默认总额度三份 | 显式配置后台额度并保证总额度至少多一份，不能仅提高 MaxDownloads |
| 同一资源 | 共用下载、校验和发布，多个请求不重复占用名额 | 保留共享任务的额度归属 |
| 取消任务 | 取消等待者；已开始的共享下载继续占后台额度 | 不能在调用者取消时提前归还额度 |

两首后台下载和一个冷缓存播放可以同时占用三个名额。预留的是任务名额，不是带宽；当前没有带宽限速或播放抢占。队列预缓存和下载补齐互斥，但只读扫描可同时运行，扫描仍会竞争网络请求和磁盘校验资源。

### 当时的可行方向

优先考虑可配置的跨歌曲并发：保留默认两首，先在下载补齐试验三至四首，同时保留一个播放名额。队列预缓存范围已可设为 1～100 个位置（默认 3），并发数仍为两首。扩大并发需要覆盖调度器和引擎，而不是只修改 HTTP 连接池。

单视频 Range 分段并发需要额外设计：检测真实 Range 支持、验证每段 Content-Range 与长度、约束分段总连接数、协调失败及取消、合并后全文件 MD5 校验。现有 spool 按连续写入字节数向播放器开放数据，不能直接改为乱序写入；需先跟踪连续可读区间。两线路元数据不一致时不能拼接内容。其复杂度明显高于跨歌曲并发，本次未实现。

吞吐收益尚未实网测量。后续可用相同的冷缓存歌曲集合比较 1/2/3/4 首并发，记录总耗时、总吞吐、错误与重试次数、同时播放的首字节延迟及磁盘占用；分别测试纯下载与播放共存，避免仅凭小段延迟判断大文件吞吐。本次保持现有并发上限。
