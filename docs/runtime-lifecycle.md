# 运行文件生命周期

首次发布采用固定路径，不迁移旧测试格式、不双写旧名称、不增加定时扫描。配置实例与媒体库各有独立 OS 锁。默认实例根为 EXE 旁 `data/`；自定义 `name.json` 的实例根为 `name.json.d/`，主 JSON 仍在指定位置。

## 文件归属

| 文件/状态 | 备份和恢复价值 | 数量/体积边界及处理条件 |
| --- | --- | --- |
| 主配置 JSON、其中的 DPAPI 代理凭据 | 必须备份 | 一个主文件；错误格式拒绝读取，无法解密的凭据保留原密文，不因清理重置。文件复制不保证跨用户/机器 DPAPI 恢复 |
| `terms.json` | 建议备份 | 一个凭据；缺失、损坏、版本不匹配不视为同意，临时文件永远不授予同意 |
| `channel.key` | 必须备份，维持 SOCKS5 通道身份及历史样本关联 | 固定 32 字节，仅缺失时创建。损坏时原地保留并告警，网络使用进程内临时身份；从备份恢复原密钥才能恢复旧关联。不自动轮换 |
| `state/throughput.json` | 可重建；持久化冷却可避免重启反复大流量测速 | 一个文件；候选更新时修剪失效样本。损坏/不支持的观测格式不恢复，下次成功写入原子替换，不生成损坏副本 |
| `state/inventory.json` | 可重建；保留耗时的上次成功扫描 | 一个当前结果，不累积多次扫描 |
| `state/batch.json`、`state/attempt.json` | 可重建；分别保留上次成功结果、最近结束/中止的结果 | 各一个结果，失败列表随本次任务规模变化，不追加多轮任务。重启不续跑，强杀前未发布结果不恢复 |
| `state/setup.json`、`state/setup-apply.json`、`state/setup-apply-<sha256>.json` | 建议随配置备份；应用回执用于防止重复应用/导入 | 进度、当前应用及逐 ID 回执；不含代理密码。正式回执不由启动清理删除，临时文件不当作成功回执 |
| 健康检测、活动下载、队列、导入回执、普通控制台视图状态 | 不备份，运行时重建 | 仅内存；不为简单页面恢复新增文件。源文件删除仍需本次有效导入回执与完整目标校验 |
| `logs/app.log` 及轮转 | 排障时选备 | 每份 5 MiB、3 份历史；每个配置实例固定一套，不按启动/版本命名 |
| `.<目标文件名>.swd-tmp` | 不备份，不恢复成正式文件 | 主配置、条款、状态与应用回执每个目标一个工作槽。排他创建、写入、Sync、关闭、原子替换；配置锁持有者在创建 Console/Monitor 前清理已知目标。逐 ID 回执只匹配 `.setup-apply-[0-9a-f]{64}.json.swd-tmp`；未知名称/正式文件保留，不递归清理，异常类型拒绝启动 |
| `config.lock` | 不需备份 | 固定 OS 锁媒介，存在不代表有进程运行；永不通过删除文件解锁 |
| 媒体 `storage.sqlite`、SQLite WAL/SHM/journal（如有）、`videos/{md5}.mp4` | 必须作为完整媒体库备份 | 启动垃圾清理不删除。视频受显式删除和现有容量策略管理；请求明细按配置保留期处理，累计统计不随明细删除 |
| 媒体 `tmp/download-<数字>.part`、`download-publish-<数字>.part` | 不备份，不视为完整视频 | 活动数量随下载并发限制；持有媒体锁、布局/数据库格式校验成功且尚未启动线程时回收，只识别 Go 临时文件的数字后缀 |
| 媒体 `tmp/import-<数字>/` | 不备份，不保存源文件删除授权 | 只清理空目录或恰好一个普通 `video` 文件。未知内容或异常类型整体保留并告警，不递归删除。硬链接仅解除临时链接，跨卷暂存仅删除临时副本 |
| 媒体 `.lock` | 不需备份 | 与配置锁独立；使用中的库不得由另一个实例清理 |
| Windows `.swd-probe-*` | 不备份 | 外部目录写权限探测使用系统 delete-on-close，关闭/进程终止即回收；不扫描外部目录。Linux 仅预检查有效用户权限，实际写入由引擎判定 |
| `%LOCALAPPDATA%/SWD/console-session-<会话>.json` | 不备份 | 沿用 #24，每个 Windows 会话一个记录；退出清理，崩溃残留由取得本会话互斥锁的实例处理，不扫描其他会话/旧名称 |
| hosts 备份、未知文件、旧格式证据 | 保留，hosts 恢复材料应备份 | 不属于垃圾。旧 `.settings-*`、`.snapshot-*`、`.throughput-*`、`.terms-*`、`.corrupt-*` 不迁移、不扫删；当前代码不再生成这些随机写入/损坏备份 |

“一个文件”是数量上限，不承诺固定字节大小：配置保留用户字段，扫描/任务结果随本次规模变化，媒体默认不限容量；日志才有固定轮转体积。

## 安全与失败

桌面入口取得配置锁、安装日志、清理工作槽，再创建写入器。已关闭的 lease 拒绝清理；重复实例拿不到锁。写入沿用现有串行化约束，固定工作槽占用时拒绝写入，不打开并截断它。媒体引擎在锁、旧布局检查、SQLite 格式校验之后回收；拒绝格式时不清理残留。

目录及祖先拒绝符号链接和 Windows 重解析点。文件必须为普通文件；Windows 按已打开的根句柄定位，禁止中间重解析点，独占打开并核对身份后按句柄删除。其他进程打开文件（包括硬链接别名）时删除失败；解除硬链接不改写共享内容。Linux 采用受根目录约束的 unlink，依赖配置/存储锁排除其他 SWD 写入者，不将 Unix 的打开描述符当作独占锁。

未知项记录 `temporary_cleanup_skipped` 并保留。实际 I/O 错误、只读文件、占用句柄等返回错误；媒体启动失败并释放锁，配置清理失败阻止 Console 创建。成功项记录 `temporary_cleanup_removed` / `config_work_cleanup_removed`，配置失败记录 `config_work_cleanup_failed`；快照和吞吐读取失败另有告警，不把磁盘故障当成清理成功。

## 重启、切库、备份和覆盖

- 重启：保留正式配置、凭据、密钥、数据库、视频和最后发布结果，按上述规则回收工作产物；任务停止，不恢复未提交写入。
- 切库：设置重启后生效，库存/任务快照仅在所记库路径与当前库匹配时恢复。快照不作为文件存在或删除授权，每次任务重读当前库；旧库不搬运、不清理。吞吐属于网络通道，继续保留。
- 备份：退出后保存主配置、实例根及整个外置库。可跳过日志、状态、工作槽、临时媒体和锁；不要遗漏视频或 SQLite 恢复文件。最简单可靠的操作仍是停机完整备份。
- 覆盖：退出后只覆盖发行文件，保留实例根和外置库；运行文件名不带版本，启动走同一回收流程。不增加旧格式迁移或自动销毁损坏核心数据的流程。

验证及剩余实机场景见 [issue #25 验证记录](issue-25-validation.md)。
