# 上游请求、检测与直连通道

## 职责与边界

> 持久化地址使用数据库 v9 的[媒体地址模型](song-catalog-design.md#媒体地址模型)，没有 TTL 或失败失效状态。DNS TTL、检测样本寿命、请求期限和诊断时间继续各自独立。

允许的播放 API 来源由 [playbacksource](../internal/playbacksource/source.go) 定义，地址提供层据此解析和筛选候选；通道层只为已获准的入口提供连接。播放、队列、预览和批量补齐的接口不选择 CDN。完整职责与不同查询生命周期见[下载设计](download-resource-design.md#播放地址提供与连接执行)。

当前生效配置由 Console 持有，HTTP 请求与 HTTPS 透传共用其上游。职责分为：

| 模块 | 职责与适用范围 |
| --- | --- |
| 上游 HTTP 客户端／拨号器 | 所有模式的请求出口；代理传原域名，由外部 SOCKS5 或 Mihomo 解析和连接 |
| `catalogsync` | 所有模式共享的缺项选歌进度与业务更新时间；不请求网络、不自行调度、不依赖 Monitor |
| Console 内的 `networkDiagnostics` | 拥有连通性、外部 SOCKS5 检查和测速的运行生命周期、定时、取消、状态订阅与关闭；复用既有 `Calibration`，借用当前生效的网络与业务能力 |
| `upstreamcheck` | 所有模式共用的轻量请求流程、本次观测与手动下载测速；不发现候选、不计算历史健康或推荐 |
| Console | 组装访问方式、业务同步入口、自动周期和手动操作，共用检测状态与生命周期 |
| `upstreamrequest.Resources` | 应用独立持有的已验证资源域名与业务下载活动，不依赖 Channel |
| DNS、Channel、`upstreamstate.Monitor` | 仅直连；保留已有 IP 池、观测、推荐及自动资源检测，按现有能力维护，不扩展选路实现 |

清单入口的 ID、URL 与顺序由 [catalogmeta](../internal/catalogmeta/sources.go) 统一定义，候选发现、实际请求、后台同步和存储来源标识共同引用。

统一检测只接收 Console 已组装的清单、播放地址和资源请求能力。直连访问方式内部复用业务请求已有的推荐顺序及未测候选容错；Monitor 未启动时也能通过现有候选池完成指定缺项。候选发现、固定协议请求和正文校验共用请求期限与尝试预算。代理只提供当前客户端；自动与手动使用同一访问方式。`catalogsync` 和 `upstreamcheck` 不导入 Monitor，不发现、枚举或推荐 Channel。

`internal/upstreamnet` 统一承载独立 DoH、DNS 池与刷新、双栈拨号及 SOCKS5 adapter；Console 负责解析器的关闭。`upstreamrequest` 继续定义候选池与拨号契约，Console 只组装配置、连接池及应用生命周期。协议测试随网络实现维护；Console 测试通过相同网络契约注入夹具，不读取解析器私有缓存。现有 CF 实验的细粒度观测仅在 `cf_block_experiment` 构建中提供，正式产品不包含实验探针。

直连候选为 `入口主机 × IP`。代理客户端不实现候选接口、不发布 Channel、不创建 Monitor，也不创建 SWD 目标 DNS 解析器。SOCKS5 始终传递原域名，Mihomo 使用核心自己的解析和出口策略；两者失败都不回退直连。

代理后端可选外部 SOCKS5 或内嵌 Mihomo，二者均为单一逻辑出口。内嵌核心使用全部已加载节点，由原生选择组、健康检查与 fallback 管理；zashboard 负责用户选择和连接操作。SWD 不维护活跃子集、每节点排序、迟滞或吞吐历史。配置继续由 SWD 管理，保存后重启生效；面板选择影响新连接。完整职责和控制边界见 [Mihomo 与 zashboard](mihomo-dashboard.md)。

## 模式

- `direct`：保留内置 DNS、直连候选与 Monitor。
- `proxy`：外部 SOCKS5 或 Mihomo；直接使用当前客户端，不经过 SWD 候选或推荐。

应用配置只使用 direct/proxy，不接受旧配置别名。直连候选和推荐携带实际 Transport，固定到被测路径；Monitor 不导入 Console 或 DNS，也不创建代理。

Console 的直连清单、播放地址和资源请求保留已有候选顺序：推荐优先，补入当前可用且未重复的候选，最多六个；冷启动按需发现 DNS 地址，发现和尝试共用调用者期限。没有可用候选时沿用普通直连请求。代理的同类业务请求直接使用当前客户端，不访问 Monitor 或候选提供者。

## 请求与连接

### 业务请求的协议策略

SWD 主动请求使用固定协议，入口定义分别归 catalogmeta、playbacksource 和资源执行层，不提供协议配置或自动协商：

| 请求 | 固定协议 |
| --- | --- |
| Udon 主完整清单 | HTTPS |
| Udon 备用完整清单、播放 API | HTTP |
| 已通过资源规则验证的视频（包括重定向后的资源） | HTTP |
| Kiva、WannaInfo 备用完整清单 | HTTPS |

API 返回或数据库保存的视频 URL 保留原协议、Host、路径和参数作为证据；执行时仅将协议归一为 HTTP。HTTP 清单及播放链路的安全代价已接受；MD5 校验仍用于资源一致性，不能替代服务器认证或传输完整性。DoH、Mihomo 自身连接、客户端 HTTPS 透传及本地非播放 API 的 307 兼容响应不属于主动业务请求的协议策略。

歌曲清单的四个来源并行请求：Udon HTTPS 为主来源，Udon HTTP、Kiva HTTPS、WannaInfo HTTPS 为同级备用；主来源成功立即采用，主来源失败则等待全部结果后按版本选取，完整规则见[清单同步](song-catalog-design.md#清单同步与增改不删)。各入口固定协议，不做自动协商、批内协议记忆或跨协议推荐；HTTP 入口遇到强制 HTTPS 的清单或 API 明确失败；视频的同端点升级归一后回到已访问 URL 时按回环失败处理。合法 API→视频及资源重定向继续校验域名、MD5、大小和跳转上限，不因原始 URL 写作 HTTPS 就跳过这些规则。

清单和播放地址按既有候选顺序尝试，最多六条路径；完整读取和内容校验在同一次尝试内完成。响应头等待按剩余候选共享调用者期限，收到头后正文保留原单次尝试与调用者期限，不切短正常正文读取。资源候选游标继续跨响应头、Range 校验和正文失败保留，每次使用既有 DownloadTimeout；单一路径的正文重试仍有界，顺序 200 正文开始后不自动重开。

Monitor 记录实际执行协议，但不进行协议间排序、恢复检查或样本分流。资源推荐只使用 HTTP 测量；持久化格式 2 仅恢复明确标记 http 的有效样本，旧 HTTPS 或未标记协议的样本丢弃，合法的测速冷却时间保留。播放记录兼容旧 Udon HTTPS 来源的范围见[存储约定](storage.md)。

连接 adapter 只执行指定路径；清单、播放和下载分别负责内容校验及生命周期。协议简化不改变独立 DNS、代理隔离、候选有效期或调度机制；资源 Monitor 与下载模块的整体合并另行处理。

直连 Transport 固定目标 IP，但保留原 URL、HTTP Host、TLS SNI 和证书校验。候选仅允许自己的主机；禁止重定向悄悄变成另一条通道。请求和建立新连接前检查 IP 是否仍在有效 DNS 池中；原地址过期时通过共享解析器重新确认，只有同一 IP 获得有效答案才继续，解析失败或原 IP 已移除仍拒绝，不切换线路。已建立连接和进行中的响应不因 TTL 到期被取消。

未测固定 IP 候选从 IPv6 开始交错排列 IPv6/IPv4，单族继续按有效地址排列，避免冷启动先耗尽同一地址族；Monitor 的已有推荐不受此顺序覆盖。普通双栈竞速只决定 TCP 连接，TLS 或业务请求随后失败时仍由请求层继续候选尝试，不永久禁用某个地址族或固定历史 CF IP。

普通直连及直连模式的 HTTPS 透传使用双栈拨号。独立 DoH 并发查询 A 与 AAAA，沿用首个可用答案后 200 ms 的收集窗口、整体六秒上限与最多六个 IP 的池；池满时交替保留两种地址，避免先返回的一族占满池。TTL 取收到的有效地址及 CNAME 链的最小值，最多 300 秒。单族无答案或超时不阻塞另一族，超过窗口的答案不加入本轮池。DoH 自身仍使用现有 IPv4 引导地址，因此这里支持双栈网络及仅有 AAAA 的目标，不承诺纯 IPv6 接入网络可用。

通过报文校验的 NOERROR 空答案（含仅返回 CNAME 的情况）是正常的单族无记录，不重试同一 DoH 服务的另一入口 IP、不清除引导缓存，也不建立负缓存或影响另一族的 TTL。HTTP/传输故障与无效报文仍按原规则重试并在入口均失败后清除引导缓存；两族及所有服务均没有可用地址时，整体解析仍报错。

连接阶段复用 [Outline SDK 的 HappyEyeballsStreamDialer](https://pkg.go.dev/golang.getoutline.org/sdk/transport#HappyEyeballsStreamDialer)，适配已有 DNS 池，不读取系统 hosts。两族都有地址时先尝试 IPv6，未连通则按组件默认的 250 ms 间隔交替尝试，明确失败可提前尝试下一地址；每次 TCP 建连最多五秒，同时受调用者期限约束。首个成功连接被使用，其余尝试取消并关闭。应用不另设竞速计时器、连接胜者缓存或 IPv6 评分。Go 原生 Dialer 没有直接接收已解析 IP 列表的入口，故这里保留独立 DoH 并使用允许注入解析结果的组件。DNS 收集仍按上述池机制完成，没有改为流式返回每个解析答案。

“优先 IPv6”适用于普通直连建连；Monitor 已选中的固定 IP 继续按测速结果使用，不因地址族重排或在传输时偷偷换 IP。HTTPS 透传使用当前生效上游的拨号器；直连使用双栈拨号，代理传原域名，始终保留原 TLS 与证书校验。SOCKS5 始终传原域名，内嵌 Mihomo 的解析和出口行为保持原配置。候选执行前仍检查配置版本，避免持有旧推荐的调用方在强制代理模式下继续直连。

## 刷新与交接

DNS 提前刷新；相同 IP 的候选身份和测量历史保留，新增 IP 待测。候选变化唤醒 Monitor，TTL 延长而成员不变无需清空结果。读取状态不触发网络查询。旧答案在其真实 TTL 内仍有效；刷新再次返回同一 IP 时，租约取旧到期与本次答案到期的较晚者，短 TTL 不提前撤销旧租约，查询缓存与下次刷新仍按新答案 TTL 计算。失败不延长 TTL，也不为冷启动的零/短 TTL 增设保底有效期。DNS 过期的候选不可获得新推荐。

Monitor 每项成功后立即公布，不等待整轮完成；失败只影响对应候选。调度以配置周期为上限，并在成功观测即将过期前检查，保留刷新余量。没有有效候选时明确返回未知/无推荐，不无限使用旧结果。启动、全体失败和 TTL 过短时无法保证零空档。

网络设置保存后重启生效。直连实例发布、释放自己的 Channel，候选变化取消旧检查；仍有效的相同直连 IP 保留历史。代理实例不发布 Channel。连接池与解析器由应用关闭，Monitor 不拥有它们。

## 上游检测与测速

诊断生命周期集中在 `networkDiagnostics`：Console 在条款准入后组装当前网络配置、请求能力、曲库同步与故障通知回调，再通过自动启动、手动控制和快照方法使用诊断。诊断自行持有状态锁；网络与业务回调在锁外执行，不借用 Console 的状态锁。`BeginShutdown` 只请求诊断关闭，由诊断停止定时器、拒绝新任务、取消检查并通知订阅者；后续 `Close` 等待所有检查及结果回调结束，再由 Console 关闭业务存储。诊断的关闭可重复调用，单独调用 `close` 也会先请求关闭。当前客户端、连接池、解析器和数据库的所有权仍在应用侧。

外部 SOCKS5 模式另有独立的服务检查：同意条款并启动上游服务后立即执行，之后每次完成后间隔 30 秒重查，单次上限 5 秒。只连接当前生效的代理地址，协商无认证或用户名／密码认证；协商及必要认证结束即关闭，不发送 CONNECT、不指定外网目标。服务选择无认证时明确显示「服务无需认证」，不宣称已校验配置的密码。凭据不可解密时直接显示凭据不可用，不尝试无认证或其他出口。它不依赖曲库、业务连通性轮次、测速和页面可见性，保存但未重启的设置不改变检查对象。网络页显示当前生效的 SOCKS5 地址及端口，经现有 `/api/status` 的 `socks5Service` 快照显示结果、成功耗时、实际检查时间和下次时间；读取与切页不触发探测。卡片标题右侧复用首页上游的刷新图标、旋转和禁用样式，通过 `POST /api/network/socks5/check` 手动触发同一检查，进行中重复触发合并且不排队，完成后重算下次自动检查；请求失败用通知反馈，不常驻展示周期说明。失败与恢复在下一次实际检查更新，结果只保留在本进程；退出取消并等待检查。该结果只证明 SOCKS5 协商及所选认证方式可用，不代表代理的外网出口或业务站点可达。

网络页的连通性检测与下载速度测试始终针对当前生效上游；没有上游选择器，不接受未保存或待重启的配置。读取状态与进入页面都不发起测试。以下自动周期与手动操作共用同一流程，替代此前“连通性仅手动、曲库独立周期请求”的定义。

连通性全量检测并行启动清单、播放地址和资源检查，三者共用当前生效上游；清单内部也同时请求四个来源，与前台刷新共用[选择规则](song-catalog-design.md#清单同步与增改不删)。主来源成功接受后立即发布选中结果及可复用歌曲样本，不等其他清单请求；其他请求自然结束并逐项显示真实状态、延迟和观测时间，不覆盖已选清单。主来源不可用时等待全部结果再选择备用。首页歌曲列表延迟使用选中来源的实际响应时间；全部失败时保留实际失败观测。清单有效正文交给既有曲库入口；本地存储错误取消尚在进行的检查，不触发来源兜底，已经完成的网络观测按实际保留。

全量检测的播放地址检查按既有分数与公平遍历规则选择一首待补齐歌曲，无缺项时在已接受清单中轮换歌曲；本地没有歌曲样本时等待本轮清单。单项播放地址或资源检测不推进轮换，仍优先选择待补齐歌曲；没有缺项时复用 10 分钟内的有效样本，缺少样本则跳过。CF 的有效响应交给既有事务更新 `media_urls`、`song_media`、`media`。全量资源检查优先使用本地已保存且符合探测大小上限的合法地址，并以 `Range: bytes=0-0` 读取一个正文 byte；没有可用地址时等待本轮播放地址。旧地址检测失败且本轮取得不同的新地址时，使用新地址重试；已成功的同域名不重复检测。重试因存储故障中止时保留本轮已完成的观测。网络测量不含选歌或数据库写入耗时；写入失败单独报告，不改变网络结果，不撤销之前已提交的数据。结果只表示实际请求及其有界容错，不挑最快值、不平均历史、不发布直连推荐。

同意条款后的服务启动立即执行一轮，常规在每轮结束后间隔 5 分钟，每轮补齐一首。自动与手动共用运行槽、补齐进度和结果；全量手动开始时若已有全量轮次则合并，完成后重算下一轮。首页还可手动指定清单、播放地址或资源项目：只发布所选项目的新结果，保留其他观测及时间；清单检测仍复用响应更新曲库，并保留有效歌曲样本供后续检测使用，不提前推进缺项遍历；资源检查先使用同一流程解析必要的播放地址并复用业务写入，但不覆盖播放地址检测结果。单项操作保留原自动检测的绝对截止时间，跨过截止时间则完成后立即调度；已有检测运行时拒绝新的单项请求，单项运行期间也拒绝全量开始请求，不排队。首次完整清单未接受时，在每轮结束后按 5、10、20、40、60 秒退避，之后保持 60 秒；额外重试只检查清单，只更新这些行的观测时间，其他结果保留各自原时间。成功接受清单后恢复常规周期。调度不订阅 DNS 或候选变化，不受浏览器可见性和网关启停影响。退出停止定时器、取消并等待请求，再关闭数据库。

下载速度测试仅手动触发，与轻量连通性检测独立运行、分别取消；启动任一项无需等待另一项结束，连通性自动周期也不等待测速。每项自身仍只运行一轮。两项均记录完成时间，失败也记录；连通性各行另存实际观测时间，未检查项不生成新时间。播放地址或资源未取得新观测时（包括缺少样本或清单存储错误导致提前结束），保留并标明 `retained` 的上次实际观测及其原时间；缺少样本时还保留本轮跳过结果。再次取得新观测后替换旧记录，不将历史成功当成本轮成功。取消放弃本轮显示，保留上次结果及其对应时间；连通性自动周期仍启用，全量操作取消后 5 分钟继续，单项操作保留原截止时间，取消不推进初始化退避。测速失败保留上次有效速度，同时分别标明本次测试时间和保留结果时间。状态只在本进程中保留；重连读取快照，不重新测试。完成／取消后清理 HTTP 闲置连接及无等待者的拨号，不关闭仍在使用的连接或退休 Mihomo 核心。

下载测速每轮先读取允许节点的合法资源地址，按 MD5 去重，沿用共用视频解析器与资源协议；不为验证已有地址提前查 API 或下载视频。只有备料不足时才解析当前资料链路不完整的本地歌曲，通过 `catalogsync.SelectSongExcept` 共用优先级与公平遍历。占位或历史保留歌曲也可成为缺项，不要求当前清单成员或本地文件。测速不请求清单，本地读取失败仅保留已取得的候选。

候选读取与响应入库遵循[媒体地址模型的调用方边界](song-catalog-design.md#地址使用刷新与后台补齐)；已有地址优先、缺样本再解析及准备结束后才下载的流程保持，不新增时间字段或排序状态。

已有 URL 与实时解析共用视频 MD5 去重和备料目标；已有可用 URL 的歌曲不重复查询。四个播放地址 worker 调用连通性检测相同的播放访问入口，沿用当前上游的候选选择、回退和请求期限。成功响应交给已有的 `syncPlaybackURL`，统一登记资源来源并更新 `media_urls`、`song_media.md5` 和资源大小；测速不另行实现评分、映射或写库规则。旧 URL 读取不算新观察，新响应即使未凑足备料目标也正常保存。本地读取、播放请求和入库共用 30 秒准备期限；达到 16 个独立视频立即结束准备，不要求视频总大小。未达到目标则在期限到达时根据已有样本决定：至少一个进入下载，零个反馈准备不足。候选提前处理完后等待期限，不额外轮询曲库；仍在进行的选歌、播放请求和入库继续使用期限。小于 16 MiB 的合法视频也可使用。达到目标后取消多余请求，已收到的有效响应仍在准备期限内完成入库；用户取消不进入下载。所有准备请求与入库回调收尾后才开始计速，不混入下载 CPU 采样。

正式下载使用 `DiscardLoader`，通过普通 `addPreparation` 等待引擎容量，不另设同时加载视频数和排队总大小限制。资源请求使用与业务引擎相同的 `resourceTransports`，共用线路选择、块调度、Range 校验、候选回退及顺序 200 支持。每个视频完成后重新请求同一资源，正文仍从上游读取并丢弃；同一资源不同时启动多次完整加载。单个资源按既有有界重试失败后计入失败数并退出本轮，其余样本继续循环；所有样本失败则提前报错。失败或取消均不修改持久化地址，不判定 URL 失效；下载阶段不再查询播放地址。

测速下载阶段正常运行至少 10 秒、最多 120 秒，不包括准备和清理，也不设下载字节上限。先限制单路，完成 1 秒预热和累计 3 秒合格单路采样后按原 250 ms 节奏逐渐增路；开放额度与实际并发达到 16 路后，完成 1 秒满路预热和累计 3 秒合格满路采样。两个窗口均完成且下载阶段已满 10 秒时主动结束；未完成则最多运行至 120 秒。用户取消和全部样本失败可提前结束。很小或只支持顺序响应的少量资源不保证能达到满路；到期未完成不覆盖上次有效结果。读取状态不查询曲库，测速不修改使用统计或设置、不启动业务视频引擎、不落盘视频，也不参与 Monitor 历史或推荐。Mihomo 自身选点和 HTTP 连接复用可能使样本经过不同节点，结果代表当前上游使用体验，不是节点排名。

测速页面复用连通性检测状态和活动下载接口；连通性检测正在运行，或业务引擎存在下载任务／当前 GET 请求时，显示“当前有其他网络请求，测速结果可能受影响。”。空闲时隐藏，单独开启网关或批量任务状态不触发提示。提示随页面观测更新，不阻止测速、不自动暂停其他任务。独立测速实例不计入这份业务活动快照。

### 测速地址恢复的取舍

2026-11-01 确认保留上述流程：测速共用媒体地址数据、节点与 URL 校验、上游访问及下载调度，但不新增测速专属的“记录失败、测后刷新、重新计速”流程，也不为测速增加跨轮失败状态或地址有效期。已有地址够用时不额外查询播放 API；测速计量使用独立加载器从上游读取并丢弃正文，避免本地文件或缓存命中影响测量，也不产生普通下载的存储和统计副作用。

单个资源请求失败后，其余样本继续，不代表本轮一定能得到有效速度：如果剩余样本不足以完成测量窗口，测速可能失败或没有完整结果。由于失败不修改地址记录，也不触发测速专属刷新，下一轮可能再次选择相同地址并重复失败；其他播放、检测或正常查询取得同一资源的新地址后，可以按共同写入规则更新该资源地址。一次请求失败不证明 URL 已失效，也不保证同一地址之后仍会失败。

本轮评审在隔离服务中复现了旧地址请求失败、API 可返回新地址时连续两轮测速仍复用旧地址；现有受控回归也覆盖一个样本失败而其余样本完成测速。这些结果只证明各自的测试条件，不能推断真实地址失败的频率或有效期。当前没有足够收益支持为这一场景另建恢复编排；若以后需要统一地址恢复，应结合普通播放、固定资源和测速共同评估复用，而不是只增加测速专用的重复流程。

## 直连测量和推荐

直连吞吐历史仅在对应入口候选发现成功后清理；DNS 失败或尚未查询的入口保留历史，仍在有效期内的缓存候选可继续使用。旧代理吞吐记录忽略，不恢复、不继续采样。以下调度与推荐规则仅适用于直连。

Monitor 只定期检查 Udon HTTPS 主清单，不维护 Udon HTTP、Kiva/WannaInfo 的健康、推荐或专用恢复调度；需要备用清单时由普通请求路径按需发现候选。歌曲列表、播放地址解析比较响应耗时。资源轻量检查保留原调度频率，请求 Range bytes=0-0，读取一个正文 byte 后关闭响应，只更新延迟与可用性，不计算吞吐。吞吐检测每个配置周期一轮，持久化最近尝试时间，启动时已到期则测速，否则等待剩余时间；DNS 更新不绕过该间隔。资源测速复用同轮同一线路解析出的合法 URL，不为每个 IP 重复生成歌曲样本。每个视频通道正文下载满 3 秒、达到 16 MiB、整首资源下载完毕，任一条件满足即停止；3 秒也截断停滞读取。吞吐使用实际正文下载字节除以正文下载时间，连接与握手时间单独计入延迟。视频探测串行执行，避免争抢本地带宽；此窗口测量不保证持续满速带宽。

WebUI 将响应延迟和吞吐样本分区显示，各自关联采样歌曲和观测时间。吞吐的 ThroughputSongID、ThroughputObservedAt 来自实际测速样本，不随轻量检查换歌而更新；SampleSongID 属于最新响应检查。业务下载会暂停自动资源探测，被打断的吞吐样本不记为失败，恢复后只做轻量检查，完整测速等待下个周期。

直连模式保留当前健康通道，挑战者需连续两轮明显更优（默认至少 15%）才切换；资源推荐按 ThroughputObservedAt 识别新的吞吐样本，轻量检查不重复计票，也不清零等待中的胜出次数。当前通道失败、失效或移除时立即选择其它有效候选。读推荐不增加连续胜出次数。推荐只代表当前已测候选，不承诺全网或所有歌曲的全局最优。
