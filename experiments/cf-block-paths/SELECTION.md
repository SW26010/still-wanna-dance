# Issue #21：有限候选的 HTTPS 选址校准

2026-10-22 新研究协议，采样前建立。目标是决定额外 CF 入口是否值得继续产品化，以及哪些低成本信号足以保留有用候选。用户指定本机 Wi-Fi，截止北京时间 15:00。旧 FAMILY / FAMILY-WIFI 的失败、次数、二进制和判据保持其历史含义；本研究不补齐或合并那些窗口。

## 优先顺序与停止依据

1. **低成本辨因**：复核 DNS 标准和现行契约，使用已有绑定网卡的 DNS 记录器观察提供者 TTL。零 TTL 不任意加保底；受控测试区分普通即时解析、可推荐的缓存候选、固定线路传输。历史三次失败仍不可回溯归因。
2. **公平的线路与筛选校准**：在有限集合中给 DNS 来源和额外来源相同的实验成员有效期，共用产品固定 Transport、正常 TLS、内容校验和分块加载器。测量的是这些地址的传输表现，不是现行产品候选发现可用率。DNS 生命周期缺口独立报告，不用人为延长产品 DNS TTL 解决实验中断。
3. **有信号再做留出资源、留出时段**：比较相同选择方法下 DNS 与联合候选的表现；统计搜索成本和退步。若实际 HTTPS 候选普遍不可用、收益无法超过测量噪声，或开销明显无法摊销，停止扩大扫描，转为明确的暂缓结论。
4. **决策与交付**：来源核验、结果复算、有限范围结论、最小实施路径及剩余不确定性；更新 #21，必要提交仅保存在本地。

## 本阶段的已知方法缺陷

- 旧实验的 DNS 候选受真实 TTL 约束，额外候选为固定 45 分钟；候选资格失效不等于媒体线路失败。
- 旧 auto 与分块选址使用不同训练和迟滞，不能把全部增益归因于扩大地址池。
- 完整训练数分钟、之后的纯下载收益不等于用户净收益；单流短测不保证预测缓增至 16 路的分块下载。
- 缺失淘汰者复测、选址与评估使用同资源、只报告成功样本、嵌套 DNS trace 污染媒体远端，均会使结论偏乐观。

## 采样约束

- 显式使用 `-cfexp-network local/cf-network.json`，以网卡 GUID、源地址、出口接口读回和逐连接日志证明绑定；用户指定该 Wi-Fi 代表大陆直连接入。保留其为一个接入网络的边界，不外推三网或全国。不开游戏，不改 hosts/路由/代理。
- 本阶段只测试 HTTPS:443 的 `play.udon.dance`，保留 Host、SNI、证书、强 ETag、精确 206/Range/长度和内容校验。实际 URL 从 API 获取，签名 URL 和身份资料只留忽略目录。
- 在新输出目录记录构建、源码、候选来源、全部计划/执行/未执行项、时间和正文成本。超过预算、网卡绑定失效、内容不一致、429/503 均终止，不覆盖或重跑同一失败批次。
- 候选间大流量测试串行；候选内继续使用产品分块调度。运行速度测量期间不并行编译、另一测速或大文件下载。记录连接复用、CF 缓存状态及 Age，区分客户端冷连接与 CDN HIT/MISS。
- 初步上限：最多 14 个候选（最多 6 个本轮 DNS 地址、4 个既有成功候选、4 个固定种子的官方范围样本），每个窗口 30 分钟、正文 3 GiB。进一步采样须由实际结果支持并在采样前追加方法说明，不以凑齐预设成功次数为目的。
- 先比较真实资源 1 MiB / 8 MiB 单流短测与完整训练资源的产品分块结果，再冻结所选地址，在未参与训练的资源上比较。对有限集合中可用候选补做完整分块测量，保留未晋级者，以测量漏选；请求失败与未执行分开统计。
- 吞吐统一由实际字节/实际耗时计算。报告连接开始至完成的时间，不能将仅正文速率等同任务速度。参考最优只限充分测量的有限集合；90% 仅作离线筛选质量指标。
- 首次同步搜索净时间为实际搜索耗时加留出任务耗时；另算连续任务累计节约和摊销点。历史复验必须使用较早窗口结果预测后续窗口，不能把同一窗口事后赢家算作历史策略。

## 首轮校准冻结参数

入口 `TestCFSelectionExperiment`，方法 `equal-membership-cold-probes-v1`。DNS 取本轮查询实际返回的最多六个地址，按字符串排序；历史地址为 `103.21.244.1`、`104.16.0.1`、`104.24.0.1`、`172.64.144.1`，只作待复验种子。将 2026-10-22 官方 15 个 IPv4 范围以 Go `rand/v2.NewPCG(20261022,21)` 打乱，取前四个范围，各随机一个地址，去重；不是扫描全部 `/24`，也不声称四个样本代表整个范围。

训练歌曲 1343，上限 64 MiB。先用排序后的首个 DNS 地址完整加载，取得逐块内容基准（其选择不以速度为依据）。候选顺序用独立种子 `NewPCG(21,20261022)` 打乱；先各测一次 1 MiB，再反序各测一次 8 MiB，两档均新建连接池，单探测 15 秒上限、间隔 1 秒。两次都未交付正确内容的地址列为资格失败，不用速度值填补；至少一次有效的候选全部做两轮完整产品分块加载，第二轮反转第一轮顺序，包含按速度会被淘汰的候选。资格失败仍是方法的漏选边界，不能声称已全面测得这部分地址的吞吐。

8 MiB 完整用时最短分别选择 `dns-short`（只限 DNS）和 `union-short`（全部候选），选择发生在完整分块校准之前。第三组 `union-block` 从两次干净完整训练均成功者按平均耗时选择，属于高成本参考策略，不冒充低成本算法。三组即使相同 IP 也分别运行，作为同地址噪声对照。

评估资源 1344、10552、10553，总大小上限 200 MiB。每资源先经 `dns-short` 获取完整内容基准，再三组各预热一次，最后两轮完整比较；第二轮与第一轮反序，所有两两顺序均平衡。预热、校准和正式评估分开统计；评估不反过来挑选赢家。单次完整加载沿用 90 秒上限，正常产品重试保留；任何请求错误均记录，即使最终完整也不列为干净成功。

3 GiB 为已读取媒体正文的取消阈值，在途读取可有少量越界；包含内容基准、短测、训练、预热、正式和失败请求。API、四次 1-byte 预检、HTTP/TLS/DoH 协议流量另计，不能标为网卡总流量。DNS 参考集合只反映发现时刻；静态实验成员资格不等于 DNS 租约延长，也不证明零 TTL 产品候选问题已解决。每个窗口使用新连接池、新目录并绑定构建指纹。先执行这一轮再决定下一轮必要范围。

## 首轮后追加：一次同协议复核

首轮 14 个候选中 10 个能完成短测及两轮完整训练，两个短测策略选中同一个 DNS 地址，完整训练赢家也为 DNS。此前两组实验曾有正增益，但基线、选路与网络绑定不同；本轮同地址配对也出现约 -5.5% 至 +11.3% 的波动。因此再用同一冻结 EXE、新目录执行一次相同协议，观察这一否定信号与短测排名是否重复；不增加地址、资源、轮数或放宽失败判据。上限仍为 30 分钟、3 GiB，两窗不合成独立时段或全国样本。

第二窗之后不继续本协议以追求正结果。离线用第一窗完整训练的 DNS/额外来源各自赢家预测第二窗训练排名，作为短期历史复用的探索性检查；这是事先指定的跨窗口预测，但只覆盖相邻会话、相同训练资源，不能代替跨日/高峰稳定性。若仍无额外地址净收益信号，停止本轮测速并给出暂缓产品化决定；若方向冲突，报告不确定性，后续只保留真正能区分假设的独立时段验证。
