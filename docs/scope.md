# 功能范围与验证边界

本文描述当前源码实现的功能；运行结果按构建版本记录。旧版测试通过不代表当前构建已完成相同的实机验收。使用方法见[本地控制台](console.md)和[命令行服务](service.md)。

## 目标

为 Windows 上的 VRChat WannaDance 提供本地视频缓存、冷缓存边下边播和后台预缓存。以可观察的播放协议为依据独立实现，不要求恢复原版源码或复现原版错误行为。

## 已实现的范围

| 功能 | 行为与入口 |
| --- | --- |
| HTTP 视频缓存 | CF/HKG 视频域名、GET/HEAD、单段 Range、条件请求；冷缓存共享下载，校验大小和 MD5 后发布 |
| HTTP 播放 API | 接管播放地址查询并直接返回视频；解析失败时可使用已确认且校验通过的本地版本 |
| HTTPS 透传 | 控制台同时监听 80/443；HTTPS 保持原站加密连接，不读取或填充缓存。独立命令行入口不监听 443 |
| 回源连接 | HTTPS、内置 DoH、原域名证书校验；控制台支持 Auto 小段测速优选或固定 CF/HKG |
| 桌面控制台 | 本地网页、Windows 托盘、单实例、设置持久化、可选启动时启用 CDN、hosts 接入与移除 |
| 后台准备 | 全曲库只读扫描、下载补齐、VRChat 日志队列设定的预缓存范围预缓存；两种下载模式可互相切换 |
| 统一存储 | 单一存储根目录、按资源指纹保存视频、SQLite 保存曲目资料、版本关联和请求统计 |
| 容量与统计 | 资源请求热度、视频容量淘汰、请求明细保留期，以及按存储目录持久化累计的播放请求统计 |
| 排障 | 结构化日志、请求与共享下载关联、下载阶段和进度、任务及本地文件统计快照 |

同一资源的并发请求共享下载，不同视频版本独立存储。临时下载完成检查后才发布，活动文件受引用保护。存储根目录由操作系统文件锁独占，具体规则见[统一存储](storage.md)。当前格式不读取原版歌曲库或旧版 StepStash 格式，也不提供迁移。

## 使用与兼容边界

- 游戏使用本地缓存需要 HTTP 入口及 hosts 接入；播放器还须接受播放 API 直接返回视频。当前 API 接管及存储实现仍需补做联合游戏验收。
- SHA 不支持；历史 IP 入口超时不能证明其目前或所有环境下均不可用。
- Auto 是有限采样下的选路，不保证始终最快；下载正文开始后不因低速或断流切换线路，不支持断点回源。
- 本地降级只覆盖播放地址解析失败；合法地址的后续下载失败不会自动改播旧版本。
- 容量上限只约束保留的视频，活动视频和临时文件可能使实际占用暂时超限。下载成功不保证视频一直保留。
- 不保证所有 VRChat 平台、播放器后端、其他舞房、RTSP、Redis 鉴权或原版镜像下载器兼容。
- 桌面托盘和一键 hosts 提权面向 Windows；其他平台可使用命令行入口，其游戏兼容性未作承诺。
