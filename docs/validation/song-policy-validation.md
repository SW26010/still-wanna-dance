# 歌曲屏蔽与收藏开发验证

业务规则见[下载需求与资源管理设计第 8 项](../download-resource-design.md#8-歌曲屏蔽与收藏已确认待实现)。本记录按实际完成范围增量维护，不代表尚未完成的控制台或游戏行为已经验证。

## 存储与本地资源管理（2026-10-21）

数据库 v3 新增互斥的歌曲偏好记录，保留冻结的 v2 DDL 和二进制夹具；v2 打开失败且文件字节不变。测试覆盖事务失败回滚、恢复普通时删除记录、目录重开保留偏好、曲库更新不改偏好和摘要。收藏操作本身不创建需求、块使用或下载。

受控 HTTP 与资源夹具覆盖：

- 被屏蔽歌曲的 GET/HEAD、队列准备和手动预取在需求创建前拒绝，不回源；已有共享文件不让歌曲绕过判断，普通关联仍能保留该文件。
- 完整队列保留未知条目、屏蔽队首及中间条目的时长，后续开始时间、位置和块需求集合不受筛选干扰。
- 全部关联屏蔽的完整视频在预算未满及不限容量时均回收，已有资源引用和使用保护继续延迟删除；临时块复用同一回收机制，不扩大收藏保护。
- 收藏完整视频在零预算和单视频超预算时发布，原评分不变；占用仍计入同一预算，普通视频使用剩余空间，取消最后一个收藏后恢复普通淘汰。
- 发布前重新核对屏蔽和收藏状态；普通批量预算停止后，收藏资源预留仍可准入，同一 MD5 只计量一次。

执行与结果：

- 存储层完整 `./scripts/with-test-temp.ps1 go test -tags=no_easytier ./internal/cacheproxy`：通过（46.386 秒）。初次沙箱运行因 Windows 硬链接、目录联接权限失败；使用同一隔离临时目录脚本在允许这些操作的环境重跑。
- 新增策略及预算回归：通过（1.376 秒）。开发过程中修正了夹具未实际写入文件、保护表未初始化的问题；零预算发布夹具显式关闭激进回收，单独验证完整资源的发布资格，另有用例确认收藏不会改变激进块回收。
- 完整回归暴露旧测试的两个假设：最小预算服务夹具未初始化偏好数据库，以及 `TestHTTPDateRangeUsesActualPlaybackOffset` 在正文返回后立即使用尚未完成后台发布的媒体记录。前者补齐数据库夹具，后者等待后台工作结束，不改变生产时钟或调度行为。两项连续 10 次回归通过（1.490 秒）。
- 更新后完整 `./scripts/with-test-temp.ps1 go test -tags=no_easytier ./internal/cacheproxy -count=1 -timeout=180s`：通过（48.783 秒）。

本轮未启动 VRChat、修改 hosts 或验证实际播放器面对 403 时的表现。核心需求集合、块使用管理和块下载调度器实现未修改；控制台来源筛选、偏好界面及其端到端验证仍在接入中。
