# 基于下载结果的共享 IP 选路

本页定义资源下载的直连选路与自动采样规则。清单、播放地址及手动诊断见[上游通道](upstream-channels.md#直连测量和推荐)，任务生命周期与尝试预算见[下载需求与资源管理设计](download-resource-design.md#单次尝试超时与下载延续截止)。

## 现状与目标

同一主机上的视频可能走不同 IPv4 或 IPv6 地址。下载执行在每次尝试前读取近期观测，使一次正文重置可以影响另一个视频的下一次选路。

## 共享状态与选路

每个生效的直连上游持有一份线路状态，按实际请求的资源主机与候选 IP 索引。播放、预取、批量下载等执行实例共用该状态，观测可跨块、跨视频复用。同一主机的内置 IP 与有效 DNS 地址共用候选池和线路观测，成员规则见[上游通道](upstream-channels.md#业务请求的协议策略)。

- **尝试前选择**。下载执行层在每次发起尝试前读取共享状态，结合目标主机的有效直连候选、本块已尝试的候选和剩余预算，决定下一条线路。首次尝试和块内重试都使用这套规则。状态更新从下一次选路生效，已发出的请求沿用自己的生命周期。
- **尝试后记录**。执行层按实际请求的主机与 IP 写回每次尝试的结果。完整读完且通过网络响应校验的 Range 提供成功证据。可归因到线路的连接失败、正文重置或超时可降低该线路的优先级。任务取消、来源 need-by 到期、本地写盘失败和仅由资源自身造成的错误对线路可用性保持中性。共享状态保存选路所需的近期信息，逐次明细由日志记录。

每个目标 URL 首次直连时，若池中没有有效固定候选，则在当前预算内发现一次候选，用共享观测排序。发现最多等待 1 秒，且至多占用剩余时间的一半。发现后仍无候选，或已尝试的固定 IP 租约在重试前全部到期时，剩余尝试额度内可走一次普通直连。仍有效的固定候选已全部试过时结束选路，单一路径沿用已有的一次正文重试。普通直连计入同一 URL 的尝试上限。确认实际连接的 IP 后，该请求计入该线路的在途数，换连接或尝试结束时释放。只有已确认的 IP 才能获得本次观测。

冷启动时，预制 IP 可立即首发。每个块对同一 URL 最多尝试六次，额度由当前候选共用。给尚未返回的 DNS 地址预留一次，会少试一条已入池的线路。业务下载在每次重试前重读候选池，已返回的 DNS 地址即可参与选路。若六次预制线路尝试都在可用的 DNS 答案返回前失败，接受本次块请求失败。资源连通性检测按开始时取得的候选列表执行，因此即使 DNS 在检测期间返回，也接受本轮报告失败。后续请求可以使用新地址。若实际播放中反复出现首次加载失败、DNS 返回后重试即恢复，再评估冷启动策略。

第一版将可供重启复用的直连成功观测持久化到 `data/state/download-routes.json`。保留原始观测时间，重启后允许仍在有效期内的样本参与选路，并按当前直连候选约束 IP 的使用。临时降级和在途计数由当前进程建立。

## 选路倾向

- **DNS 基线**。从同一资源主机的多次 DNS 结果中，记录反复出现的一批 IP 作为基线。每次选择只考虑当前仍有效的候选。基线尚未形成时，使用当前有效的直连候选作为起点。
- **急需的块**。每次尝试前按最新 need-by 判断余量。优先使用未降级的候选，在同一降级状态下先找出近期完整 1 MiB 耗时最短的 IP。耗时在最快值的 110% 以内、且预计能在剩余时间内完成的线路，才按在途数分散；在途数相同时选耗时更短的。预计都赶不上时选最快的，耗时相同仍可分散。块内重试时以剩余候选重新计算。缺少近期完整块耗时且线路均未降级时，先选 DNS 基线，再在基线内按在途数分散。
- **余量充足或无期限的块**。优先给过去表现尚可、观测已变旧的线路一次更新机会，也用部分尝试探索新出现或尚无下载观测的 IP。随重试时间增加，有限期限的块按最新余量调整选路倾向。
- **并发分散**。候选均适合当前块时，倾向选择在途尝试较少的 IP，让并发负载更均匀，同时积累不同线路的实际下载观测。线路被选中后计入该 IP 的在途尝试，尝试收尾后释放。急需块优先考虑能否及时交付，分散只在适合它的候选中起作用。

## 单次尝试时限

第一版直连业务下载在还有未尝试的有效备用 IP 时，对当前 IP 的单次尝试设 30 秒上限。从发起尝试开始计时，到完整读取并校验本次 Range 为止，计时覆盖连接、等待响应头和接收正文。现有响应头预算和父级截止可更早结束尝试。最后一个候选沿用现有单次尝试时限，给慢速线路保留完成机会。

30 秒到期时结束当前尝试、关闭已有响应，并按当前 IP 记录一次块下载超时。若响应头等待因给备用候选预留时间而提前结束，或上游返回无效的重定向地址，该次结果对线路保持中性。共享块仍有其他需求时，重试忽略已经过去的来源截止，继续服从当前任务的取消信号和单次尝试时限。

## 自动测速

独立采样器接替 Monitor 的定时单字节资源检查和自动吞吐测速。每次采样针对某个资源的某一块，默认串行执行（并发为 1）。通用连通性检测、歌曲列表和播放地址检测沿用现有流程。

「视频资源加载」中的手动检测也统一为块采样，取代早期草案中保留 Monitor 手动资源诊断的方案。原「检测响应延迟」按钮和单字节延迟接口已移除。「立即采样」每次只测一条线路，要比较已有记录的 IP，可逐行点击「采样」。页面不再提供一轮遍测全部直连候选的操作。采样衡量从请求到读完整块的时间。即使首字节很快返回，正文传输慢仍会表现为整块耗时长或采样超时。仅凭这个结果无法单独判断首字节延迟。

采样优先使用近期资源来源。缺少近期来源时，直连自动采样每轮取一个已保存地址，下轮从该地址之后继续，到末尾再从头查找。即使当前主机没有有效直连候选，或候选都在使用或冷却中，下轮也能检查其他地址。代理的采样间隔由所有主机共享，冷却期间保留位置。采样被取消时也保留位置。资源返回 403 或 404 只影响样本选择，线路评价保持中性。

采样有独立的短时限，向上游请求 Range，校验响应并边读边丢弃正文。即使本地已有该块，采样也实际读取上游。DNS 发现和各次重定向共用同一总时限。前序发现或跳转已占用预算时，总时限耗尽仅结束采样；当前 IP 独立发生的连接失败、超时或正文短读仍归入该线路。响应关闭并完成清理后，才可开始下一次采样。

- **直连**。第一版允许采样与业务下载并行，采样器自身仍串行执行。可较频繁地采样，补充近期下载观测。触发方只提供资源和块号，由采样执行侧结合有效直连候选和近期观测选择 IP。采样和业务下载按实际请求的资源主机与 IP 更新同一份下载观测，业务执行读取这份记录并独立决定后续选路。
- **代理**。请求使用当前配置的唯一代理上游，DNS 由代理处理。仅在业务下载不活跃时偶尔采样，用于更新该代理上游的实测速度。

直连页面的「立即采样」按共享规则选一路，表格中每行的「采样」指定该主机和 IP。两者都跳过 5 分钟间隔，共用串行采样器与观测记录。指定线路需要该主机的有效资源地址和当前空闲的直连候选。采样重定向的每一跳都重新检查在途数，即使上一跳刚用过该 IP。候选失效、正在使用或指定线路的资源跨主机跳转时，页面提示本次无法完成。等待仅占用采样按钮。手动采样请求断开时，已排队的采样在出队时跳过，执行中的采样随请求取消。块资源使用管理、块下载调度器和 WebUI 块需求视图继续服务业务下载。采样因取消或让位而结束时，线路可用性观测保持中性。

## WebUI 线路观测

网络页「当前连接」的资源观测按资源主机展示直连 IP 的近期表现排名，统一使用自动采样和业务下载的共享观测。记录标出最近结果、来源和时间，以及最近一次成功下载完整 1 MiB 块的耗时和时间。从向该 IP 发起单次网络尝试开始计时，到读取并校验完整块为止，涵盖连接、响应头等待和正文读取。

排名用于比较近期线路表现。具体任务的选路仍由执行层结合当时的有效直连候选、need-by 和在途尝试决定。

## 职责与范围

调度器按块需求管理启停和并发，并提供动态 need-by。下载执行层管理选路、重试、预算和结果记录。基于 IP 的自动选路仅适用于直连，沿用[现有资源下载协议](upstream-channels.md#业务请求的协议策略)。Monitor 可作为诊断手段，业务选路以共享下载观测为依据。

## 首版参数

- 当前有效的 DNS 答案中，同一主机与 IP 的租期在两次选路之间得到续期，即视为重复出现。无其他偏好时沿用地址池的双栈交错顺序。
- need-by 在 30 秒以内时优先选有完整块观测的快线。余量充足时优先更新至少 10 分钟未经观测或尚未使用的线路，在可比候选间分散在途请求。每个块对同一资源 URL 最多尝试六次；单一路径的正文失败可重试一次。
- 可归因的网络失败降级 1 分钟。并行结果按完成登记顺序更新，成功后即可解除降级。短尾块只更新可用性，完整 1 MiB 才更新用于比较的耗时。
- 成功观测从原时间起保留 24 小时。变化合并后每 5 秒原子保存，关闭时刷新。代理观测仅在本次运行中使用。
- 启动后及每轮收尾后等待 30 秒检查下一次采样机会。直连按资源主机与 IP 计算 5 分钟最小间隔，代理的所有资源共用当前代理的一份间隔。最近一次自动尝试开始，或业务下载、采样产生可归因观测，都会推迟下次采样。直连跳过已有在途请求的候选；当所有候选都有近期观测或没有可确认的固定 IP 时，本轮跳过资源请求。重定向属于同一次采样，共用 10 秒总时限。代理只在空闲时采样，业务到达时取消采样。
- 网络页按主机分组，同组优先显示有近期完整块耗时的线路，按耗时升序排列，处于失败降级期的排在组末。

## 验证场景

以下场景覆盖共享状态与下载生命周期的交界。

- 一个视频在首选 IP 上发生正文重置后，另一个视频的新尝试优先使用其他有效候选。
- 当前 IP 持续返回正文但无法在 30 秒内完成块下载时，有效备用 IP 可接续尝试。最后一个候选可在现有尝试时限内完成慢速下载。
- 普通直连回退可继续下载。确认实际目标 IP 时观测归入该线路，无法归因时各 IP 的观测保持原状。
- 仅取消单个任务时，共享状态保留该 IP 原有的线路观测。
- 急需块有近期快线时优先使用快线，缺少近期观测时回到 DNS 基线。仅由 DNS 提供的 IP 在租约到期后退出候选。
- 余量充足或无期限的块能更新旧观测和探索未知 IP。并发且有多条合适候选时，尝试分布到不同 IP。
- 已有本地块仍会发起上游采样。默认设置下重复触发时最多一个采样在途，取消后等响应清理完成再开始下一次，采样正文不落盘。
- 独立采样启用后，Monitor 的自动轮次继续检查歌曲列表和播放地址，资源采样由独立采样器执行。手动资源检测由同一采样器执行。
- 直连可在业务下载进行时并行采样，采样结果可供后续业务选路使用。代理在业务空闲时使用配置的唯一上游采样，结果用于记录该上游的实测速度。
- 重启后可复用仍有效的成功观测。候选资格按当前直连候选池判断，样本有效期按原始观测时间计算。
- WebUI 的直连线路观测可反映自动采样和业务下载的结果，完整块耗时对应同一 IP 上的一次成功尝试。
