# Mihomo 与 zashboard 的职责

SWD 将外部 SOCKS5 和内嵌 Mihomo 都视为一个逻辑代理出口。代理模式不再展开节点候选、保留五节点活跃子集、按节点测速排序或维护节点吞吐历史。直连 IP 的发现、推荐、迟滞与自动测速保持原有规则。

## 配置和运行

SWD 接受 Mihomo 原生 YAML/JSON 配置文件、完整配置的 Base64，以及一次性 HTTP/HTTPS 下载 URL。三种来源共用同一配置处理流程；不接受 URI 节点列表或其 Base64。文件或解码后的内容限 2 MiB，配置内直接声明的节点和代理组分别限 2048 个。允许使用核心默认值的最小合法配置，不另建“完整字段”要求。URL 下载使用独立直连 HTTP 客户端，不使用待导入配置；下载入口 URL 不记录、不保存、不自动刷新；配置正文内部的 provider URL 和原生更新行为仍保留。

保存使用现有 DPAPI CurrentUser 封套保护原始完整配置字节，包含注释、原名称、凭据和引用，不保存修改后的运行配置或明文原件。旧节点快照按普通非法配置处理，不迁移、不提供专门引导，失败仍保留旧密文。草稿只保留在进程内存中，保存才替换，保存后重启生效。SWD 状态和检查报告只含配置文件名、导入时间、配置内节点／原组数量与固定诊断，不含节点名称、正文或原生解析错误中的私密值。

设置中的 Mihomo 配置区只有两项：只读的「当前配置文件」汇总文件名、配置节点数、原代理组数与导入时间；「导入配置文件」在同一行选择文件／Base64／URL、填写输入并提供「导入」按钮。文件输入只读，点击或 Enter/Space 打开浏览器文件选择器，只显示所选文件名，不提供直接粘贴配置文本入口。选择文件不触发检查。显式导入与保存设置时的自动导入共用同一个请求；输入未检查时，保存先导入校验，通过后再保存，失败不提交设置。已检查的草稿在保存重试时复用，不重复下载；「放弃更改」沿用设置表单的统一清理。

文件名和导入时间作为普通展示元数据 `proxyConfigInfo`，与配置密文在同一原子事务中保存；Mihomo 原文仍使用原来的 DPAPI 载荷，不新增密文格式。节点／组数量从原文派生，不重复落盘。导入来源类型不保存，URL/Base64 的显示名称为通用名称，不保存入口 URL。旧配置未记录名称或时间时显示未记录，不推测时间。展示元数据本身不要求重启，实际原文和运行设置仍遵循重启契约。

每次校验和创建核心都从原始内容生成独立配置，统一调用同一个覆盖入口。保留节点、原代理组、DNS、配置内 hosts、规则、provider 等原生设置及其引用；不推断主组、不自动裁剪规则、不修复原配置的循环依赖。强制关闭导入的入站端口、listeners、tunnels、TUN、TUIC 服务端、iptables、NTP、嗅探和外部面板／控制器；DNS 不监听端口、不读取系统 hosts，以免使用 SWD 的游戏域名映射。全局出站接口／路由标记、进程匹配、原生日志由 SWD 管理，Geo 定期更新关闭；这不阻止核心校验所需资源的首次下载，也不关闭 provider 自身更新。运行目录固定为本实例的受管目录，原配置旁的附属文件不自动复制。

完整原生解析会构造 adapter、触及全局状态并可能下载资源，因此草稿检查通过独立校验进程执行，凭据只经 stdin 传递，原生输出丢弃；校验使用受管资源目录，超时或取消终止校验进程，不调用 ApplyConfig、不更换当前运行核心。实际核心仍沿用 ParseRawConfig → ApplyConfig，每进程只启动一次，确认条款后才应用配置；失败或退出后通过应用重启恢复。导入失败不改变已保存配置或已运行出口。

SWD 在原组之前添加统一入口 select 组及「自动故障切换」fallback 组，默认选择自动。两个组直接引用原配置声明的全部代理组，不展开每个组中的节点；没有原组时使用核心原生 include-all 纳入配置内节点与 provider。生成名称与已有节点／组冲突时使用带序号的名称，不重命名原对象或重写原引用。自动组沿用每 300 秒、lazy、https://www.gstatic.com/generate_204 的检查，首次检查仍会运行；空候选拒绝连接。SWD 的业务直接调用该入口组拨号，不遍历原分流规则；原规则仍可能服务于 DNS 等原生行为。

用户可以在原版 zashboard 中操作 SWD 入口和原有 select 组，自动策略组保持自动策略，不开放手动固定。手动选择影响新连接，已有 HTTP 连接池和下载继续运行。原组包含 DIRECT 时，允许其按原生选择走直连；SWD 不另外增加失败后的直连兜底。面板检查或策略组健康检查可能产生并发连接，不经过 SWD 的 160 个业务准入槽，不为保留的原配置另做测速调度。首次打开面板将「切换时自动断开连接」初始化为关闭，同一来源保留用户后续偏好。

Mihomo 按原始显示名保存／恢复选择，SWD 不再为节点增加身份摘要，也不依赖 channel.key；配置内名称必须满足核心要求。名称或组结构变化后，旧选择可能无法匹配，按核心默认处理。原始配置加密与原生缓存是不同契约：本实例 data/state/mihomo/ 下的选择缓存、provider 缓存和资源文件交由 Mihomo 原生管理，可能含明文名称、节点参数或凭据，SWD 不增加缓存加密／转换。原生 cache.db 不可用仍只提示本次选择不会保存，代理和面板继续工作。

`cache.db` 是明确交给 Mihomo 管理的可重建选择缓存，不是凭据备份或异常材料保全文件。文件缺失时原生初始化；Bolt 格式、校验或版本错误时允许原生删除并重建该文件，不增加备份、格式迁移或恢复机制。这个边界仅适用于这一已知组件缓存，不授权清理同目录其他未知文件、配置、密钥或业务数据库。启动时无法打开缓存，SWD 记录告警并在设置中提示本次节点选择不会保存；代理、面板选点与 Console 继续运行，选择只在本进程内有效，存储问题修复后重启再尝试打开。已打开缓存的后续写入失败仍按上游机制处理。

单一出口有 160 个无队列连接准入槽，沿用旧五节点合计的容量上限，覆盖拨号、连接和关闭完成；默认拨号期限 10 秒。退休立即拒绝新请求，核心、连接、提供者与缓存的关闭共用 3 秒退出预算。Mihomo 负责原生连接统计，面板可查看和手动断开这些连接。

## 监测与界面

SWD 的曲库同步、URL 落库与资源成员登记不依赖 Monitor，复用统一上游检测取得的响应。代理模式不启用 SWD DNS、Channel 或 Monitor；自动和手动轻量检测均使用当前生效客户端，包含读取一个资源正文 byte 的可访问性检查。下载速度测试仅手动触发，不保存直连 Monitor 的通道吞吐样本；自动周期、初始化退避与结果时间统一见[上游检测与测速](upstream-channels.md#上游检测与测速)。核心选择和长连接复用可能使测速覆盖不同节点，不能据此为节点排名。

设置中的配置摘要显示已保存或本次导入的配置，实际生效仍遵循保存与重启的生命周期。网络页常驻连通性检测与下载速度测试，直连另显示当前连接；外部 SOCKS5 另显示[服务协商与认证检查](upstream-channels.md#上游检测与测速)；Mihomo 在检测下方显示 zashboard。未保存草稿和已保存但尚未重启的配置不提前切换页面或测试对象。

两种代理模式均隐藏并停用「当前连接」的歌曲列表、播放地址解析、视频资源加载观测。不提供页内入口栏、视图切换或游戏接入卡片；`#network-tests` 定位检测，旧 `#network` 在代理模式定位整页，两者都保留面板。旧 `#service`、`#network-access` 转到加速卡片，端口状态在「视频服务」的 Tooltip 中查看。检测始终使用生效配置，无上游下拉框，不读取设置草稿。从侧栏进入网络页查看与操作检测；设置页不再提供检测跳转入口。

SWD 使用标准同源 iframe 承载未修改的面板，外层导航、反馈和布局遵循 Fluent v9；面板内部保留上游组件、主题与偏好，不注入样式或改写内部导航。只在网络页显示面板且浏览器页面可见时加载；切页或页面隐藏时卸载，关闭面板实时订阅，返回后重新从当前实例入口加载。此操作不关闭核心或更改节点选择；面板的临时筛选、滚动和内部页面可能重置，不另建恢复状态。核心不可用、后台断开或状态读取失败时显示 SWD 反馈，可通过侧栏进入设置，缓存告警不阻止面板使用。没有新增手动开关或持久化配置。

## 本地控制与分发

zashboard 的原版固定静态包内嵌在 EXE，通过 `/proxy/ui/` 提供，打开 `/proxy/` 自动接入当前实例。原生控制器只监听随机回环端口并使用独立随机 secret，浏览器经 SWD 同源 `/api/mihomo` 转发。沿用实例 Host、条款与 token 门禁；普通 HTTP 用 Bearer token，WebSocket 用 token 参数。核心 secret 不传给浏览器。

只有面板引导页 `/proxy/` 和静态面板 `/proxy/ui/` 的响应使用 `frame-ancestors 'self'`，允许 SWD 同源页面嵌入；其他 Console 页面和控制接口继续禁止被嵌入。iframe 有描述性标题，保留浏览器原生焦点与键盘导航，不把同源嵌入当作对面板脚本的安全隔离。

面板入口使用固定版 zashboard 的 `setup/api-list` 和 `setup/active-uuid` 添加或更新当前实例，设为活动后端，再用 `location.replace` 直接进入 `#/proxies`。从设置打开网络页后，浏览器后退一次回到原设置标签，前进一次重新打开面板。应用重启更换 token 时，同一地址的受管记录沿用原 UUID，列表中的其他后端继续保留。如果浏览器无法读取或保存连接设置，引导页会提示检查本站点存储。升级面板时用真实浏览器复核这两个存储键和导航行为。

面板偏好由 zashboard 保存在浏览器的 localStorage，按浏览器和完整来源（含端口）隔离。默认启动优先复用上次 WebUI 端口；回退到新端口时，浏览器会使用该来源的另一组面板偏好。节点选择由核心缓存保存。

上游面板的 IPv6 检测启用并取得结果时，可能把节点显示名写入浏览器本地存储。显示名可能含地址；原生选择缓存和浏览器存储均不受 SWD 配置的 DPAPI 保护。

只开放节点/分组/规则/状态的读取与健康检查、受管入口和原有 select 组选择、连接查看和关闭。配置修改、GLOBAL 选择、TUN、核心/面板升级、重启、原始日志及任意文件/存储接口均不开放。GLOBAL 组不开放修改；面板仍可能展示上游的通用设置，受管写入会明确提示到 SWD 设置修改。应用退出取消转发与流式连接。

固定的 Mihomo v1.19.32 在选择器和内存统计缓存中存在未同步读写，真实浏览器 race 验证可复现。接入层同步原生 Selector 的选中状态，拨号在取得原生选择后释放锁；fallback/url-test 自动组不暴露手动固定接口，避免原生未同步的固定状态被并发读写。`/memory` 使用同一个原生进程内存查询函数直接输出，绕过与 `/connections` 并发读写的缓存，因此连接快照中的可选 `memory` 字段为零，面板内存图表以 `/memory` 为准。上述兼容处理不修改依赖源码，也不新增选点算法；升级核心时需检查是否可以移除。

发行使用未修改的 zashboard v3.30.0 `dist-no-fonts.zip`；版本、提交及 SHA256 由 [release.json](../internal/dashboard/release.json) 固定。面板和核心随 SWD 更新。静态资源不依赖 CDN；上游面板仍会检查 GitHub 新版本，部分可选 IP/地理功能会联网。断网不影响本地选择、状态与连接控制；上游的更新检查可能留下 fetch 失败记录。不能将面板概览中的浏览器外网测试当成 SWD 出口测试。
