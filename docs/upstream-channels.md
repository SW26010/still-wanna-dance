# 上游通道与检查器设计

## 职责与边界

DNS 仅维护答案合法且 TTL 未过期的 IP 池、刷新和并发查询合并，不记录连接胜者，不测延迟或吞吐。通道层组合入口与传输路径，维护可执行的候选及稳定身份。Upstream State Monitor 对每个操作、入口、通道分别测量，提供推荐；业务仍负责资源版本校验、下载和失败处理。

直连候选为 `入口主机 × IP`；SOCKS5 候选为 `入口主机 × 当前代理配置`。SOCKS5 始终传递原域名，让代理解析目标，绝不展开本地 IP。代理凭据不进入候选 ID、检查结果或日志。配置版本由应用请求通道持有，旧版本观测不能用于新版本。

## 模式

- `direct`：不启用代理，只生成直连候选。
- `socks5`：强制代理，只生成代理候选；失败不得回退直连，也不查询本地目标 DNS。
- `auto`：平等选择，直连 IP 与代理候选参与同一操作的测量。DNS 失败不移除代理候选。未有测量的候选不视作最优。

已有 direct/socks5 配置保持兼容。普通业务请求继续使用现有客户端；通道候选和推荐携带实际 Transport，使用推荐时能够固定到被测路径，不在传输时重新选 IP。Monitor 不导入 console/DNS，也不创建代理；基础设施发布候选提供者。

## 请求与连接

直连 Transport 固定目标 IP，但保留原 URL、HTTP Host、TLS SNI 和证书校验。候选仅允许自己的主机；禁止重定向悄悄变成另一条通道。建立新连接前重新检查 IP 是否仍在有效 DNS 池中。已建立连接和进行中的响应不因 TTL 到期被取消。

普通直连拨号保留错峰尝试多个 IP 的容错，但不把连接胜者写回 DNS。代理候选始终通过 SOCKS5 域名请求。候选执行前检查配置版本，避免持有旧推荐的调用方在强制代理模式下继续直连。

## 刷新与交接

DNS 提前刷新；相同 IP 的候选身份和测量历史保留，新增 IP 待测。候选变化唤醒 Monitor，TTL 延长而成员不变无需清空结果。读取状态不触发网络查询。旧答案在其真实 TTL 内仍有效；失败不延长 TTL。DNS 过期的候选不可获得新推荐。

Monitor 每项成功后立即公布，不等待整轮完成；失败只影响对应候选。调度以配置周期为上限，并在成功观测即将过期前检查，保留刷新余量。没有有效候选时明确返回未知/无推荐，不无限使用旧结果。启动、全体失败和 TTL 过短时无法保证零空档。

网络模式和代理配置改变会发布新版本，取消旧检查，废弃受影响的推荐；仍允许且 IP 不变的直连通道保留历史，替换代理使用新的不含凭据的身份。候选提供者持有连接池，Monitor 不关闭它们。DNS 闲置清理、控制台退出和传输关闭均有明确生命周期。

## 测量和推荐

歌曲列表、播放地址解析比较响应耗时；资源比较限量读取的有效吞吐。资源测速复用同轮同一线路解析出的合法 URL，不为每个 IP 重复生成歌曲样本。64 KiB 样本是短请求有效速率，不是持续满速带宽。探测并发有界。

保留当前健康通道，挑战者需连续两轮明显更优（默认至少 15%）才切换；当前通道失败、失效或移除时立即选择其它有效候选。读推荐不增加连续胜出次数。推荐只代表当前已测候选，不承诺全网或所有歌曲的全局最优。

## 验证

验证模式隔离、代理远端 DNS、直连固定 IP 与 Host/SNI、TTL 变化和配置切换失效、相同 IP 刷新保留历史、新 IP 待测、失败隔离、推荐迟滞、候选复用及无 I/O 读取。既有普通 Transport 测试入口保留兼容。
