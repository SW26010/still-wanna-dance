# 非 VRC 验证分流（2026-10-16）

本文件承接[旧台账](live-acceptance-backlog-20261016-archive.md)中不需要启动游戏的验证，避免迁出后失去跟进。它不是新的逐改动登记表，也不要求把原 46 项全部换个地方重测。执行者为负责相关变更的开发者/agent：先核对已有证据与当前实现，只补不足部分；正常结果记回对应开发验证文档，真实阻塞写清环境和下一步。

**本次只完成分类，没有重跑历史产品测试，也没有宣布迁出项通过。** 下表的“已有依据”是复用入口，不代表任意新构建都已验证。原子文件写入、真实重启、系统控件或账号隔离不能由不覆盖这些行为的内存夹具冒充。

## 已知失败优先处理

- **LA-010：控制台只显示 HTTP 503，缺少存储原因和重启提示。** 依据 [LIVE-20261015-01](live-acceptance-20261015-01.md)。该报告已覆盖创建失败抑制、完整缓存读取及重启恢复；写入/发布失败仍缺覆盖。后续 agent 先核对当前实现是否已修复，若未修复则在隔离服务注入存储故障并修复错误展示，用浏览器/API 验证持续原因、恢复提示及重启生效；写入/发布分支用受控故障注入补齐。修复完成须补实现和实际验证依据，不能仅把条目迁出就结案，无需用户进游戏复现。
- **LA-020/040：限速 Seek 未恢复/长等待和聚合慢网卡顿。** 游戏复测留在[LA-040](live-acceptance-backlog.md#la-040慢网拖动多播放器与后台竞争)；开发者继续基于历史日志定位、构造可控回归和核对后续修复，不能预设 A3 容量修复或其他自动回归已解决其根因。

## 如何收尾

非游戏验证不足时，完成说明明确“开发验证尚缺某具体检查/环境”，不能笼统说“开发完成，等用户实机”。已有充分证据的范围直接引用并收尾，环境阻塞不扩散到无关功能。分流范围无需永久留作一套强制门禁；补齐后在相应开发文档写结果，本文件仅保留迁移依据和未解决的实际问题。

新发现确实只有游戏能回答的事实，才按[准入标准](live-acceptance-process.md#vrc-台账准入与合并)并入当前场景或新建最小场景；不因旧文档仍写“实机待验”自动回填。
