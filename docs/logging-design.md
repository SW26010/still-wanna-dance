# 日志调整记录

状态：2026-11-13 已实施，后续收口撤回了新增的目录按钮与接口。本文保留本轮取舍、选型失败与验证范围；现行格式、轮转、WebUI 范围和职责边界统一以[日志说明](logging.md)为准，路径与故障行为分别见[存储契约](storage.md)和[程序日志](console.md#程序日志)。本文不再作为待实施方案或另一份现行规范。

## 目标与取舍

2026-11-14：按用户确认新增按时间打包诊断资料，取代本文当时“不提供导出”的范围限制；现行入口及边界见[收集诊断信息](logging.md#收集诊断信息)。其余历史取舍保留。

原始文件是主要排障材料，用户、开发者和 AI 都可以读取；程序或 WebUI 无法启动时，人工仍能离线阅读。因此选择一份可读的结构化文本，移除产品阅读器及查询／导出链路，不保留两套格式或另做离线转换工具。

- 本地时间便于对照用户钟表；每行保留偏移量，避免依赖文件头、启动记录或其他行解释时区。固定四位小数只多于毫秒一个字符，保留部分相邻事件区别，不承诺时钟具有该测量精度。
- 时间、级别和中文摘要作为行首，业务属性仍采用标准 `key=value`。英文 `event_name` 保留原事件类别，脚本按稳定字段判断；中文摘要在业务产出处随实际结果维护，不设置全局翻译表、事件注册框架或多语言系统。
- `slog.TextHandler` 承担编码、引用转义、分组与并发，`internal/applog` 只做受控行首薄适配。业务结果判定、已有日志级别、请求历史和故障策略不在本轮改造范围内。
- 文件按本地自然日和大小组织，Writer 在写入时判断日期；不反解析正文，不为午夜增加定时器。旧 JSON 文件保持原样，统一参与有界保留，不进行格式迁移或混写。
- WebUI 相对调整前的 HEAD 只做清理，保留原有路径展示和日志级别设置。初次接入曾新增目录打开按钮，但它主要省一次手动定位，收益有限，最终连同专用接口及测试一起撤回，不再增加系统调用与失败反馈链路。
- 测试和 Portable 验收工具读取断言所需字段，在这些工具内兼容旧 JSON；通用查询、筛选和产品解析器随阅读器一起删除。

文本不保证恢复 JSON 的类型及嵌套结构；字段内容和关键关联标识仍保留。选择可读文本接受这一边界，以减少产品读取链路和依赖。后续若出现明确的机器消费需求再评估，不为假想需求先维护双写或类型恢复机制。

## Handler 选型复核

讨论期间曾首选 [tint v1.2.1](https://github.com/lmittmann/tint/releases/tag/v1.2.1)，普通字符串、四位时间和并发等隔离样例通过。进一步复核 `NoColor` 路径发现：合法 UTF-8 字符串 `before�after`（中间为 U+FFFD）以及含非法 UTF-8 字节的字符串都会被截去后缀；标准 `TextHandler` 保留后缀并完成必要转义。问题来自其[字符串去色实现](https://github.com/lmittmann/tint/blob/v1.2.1/handler.go#L583)，不只是删除色彩码。

该失败推翻此前的 Handler 首选。最终使用标准库薄适配，不引入依赖、不 fork tint，也不为其增加通用修补层。此结论仅针对本轮核对的版本和路径，不外推所有版本；早期有限样例的通过不等于全部文本安全。

## 讨论期间的隔离证据

- Windows/amd64、Go 1.27.3 下连续三轮、每轮 500 万次 `time.Now()`，观察到的最短相邻不同读数间隔约 0.50 毫秒，典型间隔约 0.52～1.00 毫秒。这只是本机当次取时的观察，不是所有平台的精度保证，也未测量系统时间与真实 UTC 的误差。相关实现见 [Go Windows/amd64 源码](https://go.dev/src/runtime/time_windows_amd64.s)。
- tint 和标准库薄适配曾通过四位时间、普通特殊字符串、大整数、带 `WithAttrs`／`WithGroup` 的 8×100 次并发写入和写入错误传递样例，同时观察到 ANSI 处理差异。后续 U+FFFD／非法 UTF-8 对照记录了上述 tint 失败；正常中文两者均保留。
