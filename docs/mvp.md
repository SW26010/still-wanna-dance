# StepStash MVP

第一版是 Go 标准库实现的本地 HTTP 视频缓存服务。已通过可控上游测试、真实 CF/HKG 下载与原版回读。VRChat 联合验收及发现的问题见[验收记录](acceptance.md)。

## 启动

需要 Go 1.25 或更高版本。Windows PowerShell：

```powershell
go test ./...
go vet ./...
go build -o bin/stepstash.exe ./cmd/stepstash
.\bin\stepstash.exe -listen 127.0.0.1:18080 -cache-dir .\stepstash-cache
```

默认监听 `127.0.0.1:18080`，默认目录相对于启动时的工作目录。Ctrl+C 取消后台下载，清理临时文件并关闭服务。启动不修改 hosts、不改代理，也不扫描整个歌曲库。所有日志为 stderr 上的 JSON。

验证 HTTP 请求时须使用视频 Host 和有效的完整 URL，例如保留 API 返回的真实路径、e、s，通过 curl 的 `--resolve play.udon.dance:18080:127.0.0.1` 访问 `http://play.udon.dance:18080/files/...`。直接访问 localhost 首页会得到 400，MVP 不提供网页界面。

直接使用已有原版歌曲库：

```powershell
.\bin\stepstash.exe -songs-dir 'D:\your-library\wannadance-song'
```

目录布局为 `<歌曲ID>/video.mp4` 和 `metadata.json`。有效视频直接读取，无需导入、复制或重下；热缓存不修改视频、元数据和附属文件。新增下载继续发布为此布局，完整元数据的额外字段保留，`download.txt` 可有可无。不要把歌曲库设置为 `-cache-dir`，后者是独立的应用状态目录。

请求 e/s 对应的视频大小和 MD5 是读取依据。元数据缺失、JSON 损坏或 checksum 不一致会记录警告，但视频独立校验通过仍可读取；纯读取不自动修复元数据。更新时如果已有元数据 JSON 损坏，拒绝覆盖并记录错误，需先由用户修复或移走该元数据。新增元数据采用原版样本的简化字段；两首真实样本已通过原版回读。

## 游戏接入

1. 先停止占用本机 80 端口的原版服务，再以 `-listen 127.0.0.1:80` 启动 StepStash；需要时在有相应权限的终端运行。
2. 备份 hosts，只将 `play.udon.dance`、`nya.xin.moe` 映射到 `127.0.0.1`。如果之前映射过 `api.udon.dance`，先恢复它的正常解析。
3. API 保持原始网络路径，选择 CF 或 HKG；Auto 继续由 API 决定视频地址。测试后恢复 hosts 并停止服务。

MVP 仅处理已观测到的 HTTP 视频链路，不监听 443，也不实现 `/Api/`、`/v/` 或 SHA。两个视频域名的其他 HTTPS 用途不会被此服务处理。更详细的原版接入记录见[复现手册](testing-runbook.md)，其中原版命令不能直接当作 StepStash 命令使用。

## 缓存和下载规则

- 接收两个视频 Host（允许附带端口）的 GET/HEAD；路径限定为 `/files/<数字目录>/<正整数ID>-<字母数字版本>.mp4`。e 必须为 MD5，s 为正数且不超过上限。重复 e/s、错误转义、其他 Host 和路径返回 400，其他方法返回 405。
- 先直接检查歌曲库。应用状态中的版本键为歌曲 ID、文件名版本、MD5、长度的 SHA256；域名和目录不参与键。同内容可跨 CF/HKG 复用。新下载的完整版本保留在应用状态中，同时发布到歌曲库；歌曲库中每个 ID 只有一个当前版本。
- 每次读取校验完整大小和 MD5，响应前再次验证打开的句柄，避免并发替换导致返回错误版本。这会增加磁盘读取成本；目前没有索引数据库、淘汰策略或配额管理。应用状态可以删除重建，不是读取现有库的前提。
- 未命中时共享一次整文件回源；各客户端独立读取逐渐增长的下载文件，按其 Range 返回已到达的区间，尚未到达的区间等待上游。保持原视频 Host，连接独立回源地址，不使用系统代理环境变量，不跟随上游跳转。默认 CF 为 `ud-play.kiva.moe:80`，HKG 为 `ud-nya.kiva.moe:80`。
- 下载到应用状态目录的 `download-*.part`，严格检查长度、MD5，然后复制到用于发布的临时文件，同步关闭后重命名为完整版本。下载文件句柄保留至最后一个读取者结束，兼容 Windows 文件占用限制。发布歌曲库时使用歌曲目录内的 `.stepstash-*.part`，再次验证后替换正式文件。上游错误、截断、超长、非预期压缩、校验失败均不改动现有歌曲。MD5 仅是协议完整性检查，不是来源认证。
- 同键并发共享后台任务，回源节点取首次请求；尚在下载时切 CDN 仍复用这一任务，不会自动换源。客户端取消后任务继续，受全局超时和下载数量限制；不同歌曲超过容量返回 503，可稍后重试。
- 应用状态目录由操作系统文件锁独占。正常退出或进程死亡会释放锁，重启清理其中的下载残留；歌曲目录中的本服务临时文件在下次向该歌曲发布时清理。`.lock` 文件保留是正常现象，不应在运行时删除。不要让多个进程用不同状态目录同时写同一歌曲库，也不要与原版同时写库。

发布时分别替换视频和元数据，**两个文件不是跨文件原子事务**。两次替换之间若进程崩溃，可能留下完整的新视频和旧元数据；读取仍须按 e/s 校验视频并输出元数据警告，不会将半文件当成完整内容。Windows 有其他读取句柄时可能拒绝替换，返回 502 并保留已下载的应用状态版本；旧播放结束后重试无需再回源。若准备响应期间歌曲版本已变化，返回 503 让客户端重试。

**冷缓存边下边播，只有校验通过的完整内容才发布到缓存。** 已发送的前段数据尚未完成整文件校验；完整 GET 的最后一个字节会等到校验和发布成功后才发送。若失败，服务中断仍在等待的响应，不让它以完整成功的文件结束；已完成的局部 Range 不能撤回。首次流式响应没有 Last-Modified，ETag 仍按请求 MD5 设置。HEAD 不等待整文件完成。

当前没有断点回源，真正断电后的磁盘持久性也未作承诺。缓存无自动淘汰，下载及发布期间可能同时存在多份视频数据，应预留磁盘空间，停服后可删除不需要的应用状态文件。

## HTTP 和诊断

热缓存以及下载完成后的响应支持完整 200、单段 Range 206、后缀 Range 和条件请求；使用 Go `http.ServeContent`，ETag 为带引号的 MD5。无效或越界 Range 返回 416，多区间请求明确返回 416。HEAD 忽略 Range。完整 200 不添加原版非标准的 Content-Range。

`X-StepStash-Cache` 表示 HIT 或 MISS；共享同一次冷下载的请求都会返回 MISS。`X-Request-ID` 可与 JSON 日志关联。日志记录请求状态、发送字节数、Range、缓存来源、下载键和失败原因，不记录完整查询参数。

尚未开始响应时，上游/完整性/发布失败返回 502，后台验证或下载超时返回 504，容量不足/正在关闭/文件变化返回 503，本地响应文件无法打开返回 500。流式响应已经开始后，无法更改状态码，失败会中断连接并记录 `stream_failed`。其他故障见 `cache_failed`、`cache_invalid`、`library_mismatch`、`metadata_warning`、`open_failed`；客户端取消记录 `client_disconnected`。错误响应不会把内部错误详情暴露给播放器。

| 参数 | 默认值 |
| --- | --- |
| `-listen` | `127.0.0.1:18080` |
| `-cache-dir` | `stepstash-cache` |
| `-songs-dir` | `wannadance-song` |
| `-cf-origin` | `ud-play.kiva.moe:80` |
| `-hkg-origin` | `ud-nya.kiva.moe:80` |
| `-download-timeout` | `10m`，包含缓存校验 |
| `-max-file-bytes` | `2147483648`（2 GiB） |
| `-max-downloads` | `3`，包括正在校验的不同文件 |

回源参数是 TCP `host:port`，不是 URL。不要将回源地址配置到本服务，也不要在 hosts 中把回源域名映射回本机。默认仅用于本机；无鉴权，不建议监听公网地址。配置受信任，外部请求不能任意指定回源目标。

## 验证范围

`go test ./...` 使用独立临时目录、随机端口和可控上游，覆盖：CF/HKG 冷缓存、跨 Host 命中、Range/HEAD/条件请求、非法输入、错误上游/跳转/截断/超长/校验失败、同曲并发、调用方取消、版本隔离、同长度损坏、旧库直接读取、元数据和附属文件保留、更新失败保留旧视频、活动读取期间的版本替换、缓存独占、容量和超时、关闭及重启清理。

CI 配置 Windows/Linux 的测试、vet、构建，以及 Linux race 检测。本地 Windows 未配置 C 工具链时不能运行 `go test -race`。CI 尚未在远程执行。

2026-09-25 修复版验证：`go test ./...`、`go vet ./...`、Windows 构建通过，核心包语句覆盖率 82.6%；Linux 服务和测试程序交叉编译通过（未在 Linux 本机执行）。真实 CDN、原版回读和 VRChat 样本见验收记录。测试进程已退出，临时 hosts 修改已恢复，原版歌曲库样本前后哈希不变。

初版在真实游戏中因完整下载等待触发 20 秒客户端超时和自动重试，已据此加入共享渐进读取及断流回归测试。最新实机结果以[验收记录](acceptance.md)为准。
