# WebUI 与桌面程序

## 名称与职责

「程序／SWD」指后台运行的应用，「WebUI」指浏览器中的操作界面。托盘的「打开 WebUI」只打开浏览器；关闭网页与退出程序不同。右上角「已连接后台程序」仅表示网页成功读取了程序状态，不代表游戏已接入或加速已开启。文案统一遵循[程序与界面术语](webui-content.md#程序与界面术语)。

核心网络服务统一称为**播放网关**（Playback Gateway），界面需要强调运行位置时使用「本地播放网关」。

| 名称 | 职责 |
| --- | --- |
| 开始加速 | 用户主操作，配置游戏连接并启动播放网关；队列按配置随网关启用 |
| 播放网关 | 接收 HTTP 播放请求，结合上游选路与本地视频交付视频，并对受 hosts 影响的 HTTPS 连接透传 TLS 字节 |
| 本地视频 | 视频存储、索引、校验、容量管理与清理 |
| 上游通道 | 直连或代理等连接出口，以及通道评估、选择与失败切换 |
| 游戏接入 | 当前通过 hosts 将播放 API 域名重定向到本机 |

日常启停按[配置生命周期](settings-lifecycle.md)统一编排；自动与手动一键加速共用完整流程，默认队列随网关启停，日志读取失败单独提示。后台保留独立启停能力，共用本地资源引擎和媒体库。下载补齐不暂停或恢复队列，停止网关不影响独立手动下载，退出程序才会关闭共享引擎。

当前界面以中文命名为准。诊断字段及日志中的 `cdnError`、`cdn_*` 日志事件及现有 API 路径保留原标识，含义仍对应播放网关；历史报告保留当时用语。原版软件或远端 CDN 不属于本次命名范围。

## 首次使用与条款确认

首次打开显示「开始」，介绍 SWD 的用途、四项功能、后台和托盘行为。点击「阅读并同意条款」打开弹窗阅读全文；点击弹窗底部「同意完整条款」立即保存 DPAPI CurrentUser 记录，成功关闭弹窗，开始页显示「条款已确认」，再点击下一步。后三页与业务 API 要求有效记录。条款版本或全文摘要变化后须重新确认，导航不代替同意。记录保存在配置实例的 `terms.json`（默认 `data/terms.json`），独立于普通设置，无需 UAC。

同用户在原环境中连同凭据移动目录或更换配置路径时保留确认；仅移动配置、不带其伴生凭据则须重新确认。跨用户或普通独立机器复制、旧明文、损坏、未知格式、解密失败及条款变化均不授予同意，不自动重建记录。域账户/漫游配置可能跨机器解密，不提供严格设备绑定。保护或原子写入失败时保持未同意并显示错误；普通读取错误有诊断并阻止启动。非 Windows 桌面程序不支持保存确认，不回退明文；独立命令行服务的显式 `-accept-terms` 行为不变。记录不是身份认证、法律签名、亲自阅读或内容授权的证明。

不同意时仍可停止服务、恢复本程序管理的 hosts 并从托盘退出。未同意当前条款时，关闭或离开条款页会尝试通知后台，60 秒后自动退出；重新打开条款页、通过浏览器后退恢复该页或成功同意条款会取消倒计时。切换标签页或最小化不会触发；已同意后关闭网页仍保持后台运行。此机制面向普通单标签页使用，不保证浏览器崩溃、强制结束或多标签页场景；退出按当前游戏接入策略清理，不新申请管理员权限。帮助、关于页和页脚可随时打开 `/terms`，`/terms.txt` 提供完整文本。版本变更应同步更新条款中的版本号与 `internal/legal/legal.go` 的版本常量。发布包随附相同的 TERMS.txt；MIT 不变。

## 页面导航

未确认条款时，真实 `/` 与 `/terms` 共用完整向导，只开放开始页；完整条款弹窗仍可用；没有独立恢复直连操作。已有记录无法验证时自动打开弹窗，须重新明确确认。确认和后续操作保持同一文档，状态断连时保留已保存确认并等待重连；关闭未同意页面的退出倒计时机制不变。

WebUI 侧栏提供视频加速、时间线、曲库、设置、关于五个入口；桌面可收起侧栏，窄屏使用抽屉。页面归属、共享表单与交互规则以 [WebUI 设计](webui-design.md)及[内容约定](webui-content.md)为依据：

- **视频加速**（`/#/home`）：默认落点，加速条件和真实状态、一键开启、当前 GET、共享下载、房间队列及按需块诊断；结束运行通过退出程序。
- **时间线**（`/#/timeline`）：按处理时身份查询全部保留期内的 GET 历史，以及独立的最近 72 小时首正文分组统计。
- **曲库**（`/#/library`）：歌曲／资源视图、完整视频实际占用、偏好、文件管理、逐项下载与全库补齐、视频及 VRCX 导入。
- **设置**（`/#/settings`）：常规、存储、预加载与下载、网络四类；网络内保留连接检测、代理设置和接入诊断。
- **关于**（`/#/about`）：介绍、帮助、用户协议、许可证与第三方声明；帮助保留重新进入引导和实际路径。

「设置 → 预加载与下载 → 房间队列与游戏日志」中可调整「提前准备时间（秒）」，默认 500 秒，建议 200～2000 秒，接受 100～16000 的整数。时间 M 越大，越早下载预计播放的内容，也会更早占用带宽和视频存储空间；保存后重启应用生效，运行中的下载继续使用原值。配置字段为 `prepareAheadSeconds`，已有配置缺失或为 0 时采用 500；启动窗口为 ReadyBy ≤ now + M，见[调度规则](download-concurrency.md)。

首次条款门禁进入使用引导（`/#/setup`），之后从帮助页主动重新进入；手动引导进度不改变日常启动落点。四步依次为开始、存储、网络、启用，布局与条款弹窗遵循 [WebUI 内容约定](webui-content.md)。开始页的「阅读并同意条款」打开完整条款，明确同意后立即保存并显示「条款已确认」。已有记录无法验证时自动打开同一弹窗；关闭不等于同意，失败留在弹窗并显示原因。欢迎页不提供独立启停或恢复直连操作。网络页提供两项手动检测，接入检查在标题旁提供刷新按钮。高级选项在各功能所属页面管理。

存储页先显示「视频存储预算」，再显示可展开的「本地存储目录」；目录区域包含当前路径按钮、默认位置按钮和可用/总容量。目录的收起、禁用及路径保留与设置的存储标签共用[目录交互规则](webui-content.md)。允许编辑时，点击路径按钮或按回车打开现代 Windows IFileDialog 文件夹选择器；默认仍为程序文件夹内 `data/storage`，自选须在程序文件夹外。系统 PowerShell STA 承载固定脚本，路径/标题通过 JSON 输入；取消/导航/退出关闭选择请求，每实例只开一个，选择只进入草稿，选择期间暂时禁用预算选项。「视频存储预算」与设置的存储标签共用「不保留 / 限制为 / 不限制」单选，默认及「恢复本页默认」均为「不保留」。该选项在运行时等价于零预算，普通视频不长期保存，开启「优先保留收藏视频」时，收藏的完整视频可突破预算保留。仍可使用视频块缓存，回收遵守既有使用保护；具体规则见[歌曲偏好](download-resource-design.md#8-歌曲屏蔽与收藏)。「限制为」接受正数预算，最多两位小数；切换选项保留输入的有效容量，下方小字说明完整数据约 430 GiB、空间不足时建议限制在 40 GiB 以内。选择行为单独写入配置，字段和运行时映射见[本地视频保留与预算](cache-retention.md)。未勾选导入时隐藏目录框和两段说明，勾选后展开；点击该框或按回车才选择来源，选中后在框内显示路径。取消选择保留当前勾选和路径；勾选但未选来源不能离页，可取消勾选继续。取消勾选清除来源，并重新隐藏目录框和说明。目录自动检查、不搬迁现有数据；导入保持来源文件并尽量硬链接，导入后不要修改源视频。

每次进入从正式设置预填，本轮草稿与普通设置页的未保存草稿隔离。离开步骤先做合法性检查，通过后仅保留本轮内存草稿，不写正式配置或启动导入。上一步、下一步、侧栏同时检查当前页内容合法性与目标页条款记录门禁，两项独立判断，失败留页。有修改时，浏览器返回或其他导航离开弹出确认对话框，取消保留页面与草稿；刷新或关闭也显示浏览器离开提示，确认才丢弃。未修改或改回原值不提示。「放弃草稿并退出引导」位于引导顶部，断连或非法输入也可退出；再次进入从正式设置重新开始。底部「恢复本页默认」只恢复当前页出厂默认值，默认未改时禁用。

最后一页对照当前生效值列出上游、存储、容量、导入来源与目标，并提示此前已保存但尚未生效的高级配置。只有「确认并应用」才写正式配置；需要时自动重启，随后在新配置下启动导入。导入源在存储页离开时单独检查，源与最终目标的关系在最后确认时检查。确认请求有持久回执；丢失响应可核对同一清单，不重复导入。重启 60 秒未就绪时，在向导内显示原因并提供「重新连接并核对」和退出；重试、退出后重入或刷新都保留原应用 ID，恢复不重新提交应用、重启或导入。配置被其他窗口修改时拒绝旧清单；重启会中断现有导入/批量/队列任务时要求先结束任务。中断的导入不自动重放，部分失败明确说明配置已保存/导入未启动。各功能配置表单继续使用保存／手动重启方式。

条款确认即时生效，放弃引导不会撤销。启用页只检查接入条件，不在最终应用前修改 hosts；刷新按钮重新读取 hosts、80/443 端口和日志状态。摘要由后端核对是否重启，并按设置说明自动加速及队列动作。最终应用成功后才执行一次自动加速，收到配置完成回执后进入首页，实际加速失败由首页状态和错误说明。回执恢复不重复应用或导入。

目录选择等待不向底部导航区写提示；选择失败和导入缺少目录在对应路径框旁显示感叹号小提示框，重选/取消勾选/重置后清除。存储恢复默认时，同一路径检查合并并保留当前容量结果；网络检测预留指标位置，进度随事件更新，不插入会推动布局的临时说明。接入检查只刷新状态，失败原因仍可见。

网络页标题「网络环境检测」旁的上游下拉框默认直连，可选择当前外部 SOCKS5 草稿，统一作用于连通性检测与 CF 并发测速；检测不会保存或应用业务代理配置。确认条款、进入引导、切页、刷新和回执恢复均不自动发起检测。两项检测分别手动启动：向右三角形表示就绪，悬停立即提示准备好日常游戏网络环境并暂停其他下载；方形表示运行中，悬停提示「放弃检测」，点击停止并恢复同一上游在本进程内的上次有效结果。取消请求未确认时显示错误并继续按服务端事件显示实际状态，可再次停止；收到取消状态后才按已取消展示。

连通性检测依次显示歌曲列表、播放地址、视频下载的动态省略号及成功/失败状态，只报告响应时间。CF 测速准备足够视频后复用正式下载器和调度器，先限制单路采样，再解除限制按原有 250 ms 节奏逐渐增路，满路稳定取得足够样本后主动结束；不同资源域名各自固定连接候选，共用同一个调度器。视频正文读取后丢弃，不保存媒体文件或执行完整性校验。单路/满路速度及实际并发数、满路平均 CPU 与正式下载全程 CPU P95 均预留位置；指针在所有下载阶段跟随平滑速度更新。采用 Fluent GaugeChart 线性刻度，范围至少 0–3 倍并随样本扩展；以 2 Mbps 为 1×，≤1× 不可用、1–2× 不稳定、>2× 可用。准备不足或未取得完整样本不能覆盖上次有效结果。两个面板通过 SSE 更新，切页/关闭网页不中止后台检测；应用退出会取消并清理。「连接方式」下的直连和代理复选框及按需显示的认证字段保持原有应用流程，技术详情位于「设置 → 网络」的检测结果及「线路诊断」。

「帮助」（`/#/help`）内置启动、存储、导入、接入、备份升级、卸载与排错说明，支持离线阅读。Portable README 继续保留。

配置版本使用 `channel.key` 的 HMAC-SHA256，包含密码及不可解密的受保护凭据，并与通道身份使用不同用途前缀；重启保留匹配能力，密钥故障不降级。公开响应隐藏回执内部版本，包括旧回执中的裸摘要。旧裸摘要回执或更换密钥后的待续接清单需重新核对，不自动启动导入。另一窗口替换共享回执后，原窗口使用只读 `/api/setup/receipt` 查询原应用 ID；失败保留 ID 供重试，不重新应用，确认不存在后也须主动退出才清除。存储目标尚未创建时，预检逐层检查已有祖先，提前拒绝 junction 或符号链接。

「关于」通过标准标签呈现介绍、帮助、用户协议和许可证；业务页面页脚保留退出入口；`/help`、`/about`、`/terms` 兼容地址规范为对应 Hash 路由。内容页只显示当前页，支持直接链接、刷新和浏览器前进／后退。普通导航回到页面顶部；明确区域链接进入对应页面并展开、定位目标：`#service` 进入设置 → 网络的高级接入，`#queue` 进入视频加速，旧 `/#/upstream`、`/#/monitor` 进入设置 → 网络。未知路由返回视频加速。

应用内切页（包括帮助、关于）保留表单草稿、本地视频搜索与选择、删除确认及展开状态，不会提交操作或停止后台任务；整页刷新不持久化未保存的编辑。常规程序状态继续共用一套防重叠轮询，浏览器标签页不可见时暂停、恢复可见时刷新；引导页网络检测独立使用 SSE，导航本身不创建定时器。首次进入本地视频会自动读取本地文件，之后按需刷新，避免轮询清空选择；删除仍需明确确认。键盘导航显示焦点，当前页使用 `aria-current` 标识，切页后焦点进入主要内容；隐藏页不参与键盘和读屏浏览。

前端类型、浏览器回归及 Go 验证命令见[开发说明](development.md)；浏览器覆盖和平台边界见[可访问性与浏览器验收](webui-accessibility.md)。

### 上游通道监测

设置 → 网络的「连接检测 → 当前连接」展示 upstreamstate.Monitor 的全部操作 × 线路 × 候选通道结果，旧健康检查已移除。direct 模式检查全部有效直连 IP，proxy 模式检查活跃代理通道（兼容旧 socks5 值），auto 模式两者都检查。同意条款后启动后台调度，每轮完成后默认 5 分钟重测；候选变化及观测即将过期时提前重测。关闭浏览器或停止播放网关不会停止检测，退出应用会取消并等待检测结束。

视频列表、播放地址解析区域分别提供手动检测按钮；视频资源区域提供响应延迟和吞吐速度两个按钮，分别使用带会话令牌的 POST /api/upstream/check/catalog、playback、latency、throughput。手动检测会中止当前自动轮次后执行；列表覆盖三个清单及全部候选，地址解析覆盖两条线路及全部候选，资源吞吐依次测量全部资源候选。地址和资源检测复用有效歌曲样本，必要时查询清单；资源检测先解析合法资源地址，这些依赖请求不覆盖无关区域的结果。手动资源检测不受业务下载暂停规则限制，手动吞吐也不受 配置的吞吐间隔限制；每次仍以 3 秒、16 MiB 或整首完成中先到者停止。手动轮次运行期间按钮禁用，避免重复发起。原有全量立即检测通过带会话令牌的 POST /api/upstream/check 触发；运行中合并请求，距上轮开始不足 10 秒不重复触发。GET /api/status 的 upstreamMonitor 返回纯读取快照，包含全部候选的状态、原因、首字节延迟、样本吞吐、歌曲 ID、观测及有效期。网络配置变化由 Monitor 订阅处理，取消旧检查并重测，仍有效的相同直连通道可保留观测。

业务视频回源（含预加载）开始时，取消正在进行的自动资源测速，并暂停后续资源测速；全部业务下载结束后自动恢复，被打断的样本不记为通道失败。完整本地视频读取不会暂停测速。HTTPS 视频透传因无法读取加密请求，保守地在视频连接存续期间暂停；API 透传不触发暂停。界面显示“业务正在加载视频，自动资源测速已暂停”。此规则只作用于自动检测批次，手动检测始终不因业务加载而暂停。

每个清单分别显示响应原始 time：Udon 的顶层 time，Kiva 与 WannaInfo 的 data.time；不将本地观测时间当作清单时间。候选时间不一致时分别保留，缺失时显示未获取。视频列表区分别展示 Udon、Kiva 与 WannaInfo 三个入口及各自的直连 IP / 代理结果。Kiva 与 WannaInfo 检查 HTTP 与业务状态码、版本、歌曲 ID 和 MD5；无效或冲突的 MD5 会标为响应校验失败。每轮分别校验最多 16 MiB 的歌曲列表，从去重有效 ID 中随机选歌，分别查询 node=cf / node=nya 播放接口。同一路线的所有资源候选共用本轮合法资源样本，自动资源检查分为首字节延迟和吞吐两种：原调度频率仅请求 Range bytes=0-0，读取一个正文 byte 后关闭响应，只更新延迟和可用性，不计算吞吐。吞吐检测独立限制为每个配置周期一轮，按轮次开始尝试的时间写入配置实例数据根下的 state/throughput.json 文件；启动时读取记录，首次或已满配置的吞吐间隔时立即测速，否则等到期。DNS 更新、短 TTL 和失败不绕过此间隔；被业务打断的候选恢复后只做轻量检测，不立即重复完整测速。吞吐轮次仍串行遍历资源候选，对真实资源执行连续 Range 读取并校验响应：正文下载满 3 秒、达到 16 MiB、整首下载完毕，任一条件满足即结束；所有线路与候选的视频资源探测依次执行，避免同时占用本地带宽；不写本地视频存储。吞吐按正文下载字节 / 实际正文下载时间计算，排除 DNS、握手和响应头等待；3 秒上限内不足 16 MiB 仍保留已收到数据的测速结果，完全没有正文则记超时。界面同时显示实际下载时长、MiB 样本量和独立的测速时间；轻量检查不会刷新测速时间或覆盖吞吐值，最近一次成功吞吐样本会持久化并在重启后恢复，超过配置的吞吐间隔仍作为历史样本展示，不用于当前测速推荐。样本吞吐是本次窗口的有效速率，不代表持续带宽或全部歌曲的可用性。优先使用本轮 Udon 合法样本，Udon 无有效样本时依次使用 Kiva、WannaInfo；三个列表均失败时可在 10 分钟内复用旧歌曲 ID；没有合法样本时不猜测视频地址，未测候选仍显示待测，旧观测到期显示过期。代理凭据不会进入状态快照。

## 开始加速

「视频加速」中的「开始加速」先检查条款和 hosts 冲突，完成游戏接入，再启动播放网关（HTTP 播放 / HTTPS 透传）并复核 hosts。只有两项同时就绪才报告成功。已运行的服务和已授权助手复用；任何步骤失败，只撤销本次新增网关和接入变更，保留操作前已有的正常接入与服务。助手内保存最近一次接入操作前后的内容用于撤销，不回放长期备份；若 hosts 被并发修改则拒绝覆盖并报告未能撤销，页面展示真实状态。撤销成功、失败均不关闭仍可用助手，重试不重复申请 UAC。不会覆盖其他程序的映射，执行期间阻止重复提交；浏览器超时不表示后台操作取消，应等待状态刷新。

服务运行、hosts 接入、收到视频请求分别显示。只有接入步骤完成之后到达且通过本地校验的 HTTP GET / HEAD 视频或播放 API 请求（不要求上游解析成功）才计入本次检测，传输成功与否不影响“收到请求”的事实。历史请求、预加载、网页状态轮询、HTTPS 透传均不计入；无法据此确认游戏客户端、起播或播放成功。等待时请在游戏中请求歌曲，必要时重进世界或重启游戏刷新 DNS。HTTP 视频使用本地视频；HTTPS 保持加密透传，不使用本地视频和视频块缓存。

页面显示向导开始、检测起点及首个请求的到达时间（浏览器本地时区）。重新检测或重试清空记录；检测起点之前到达、之后才完成解析的请求也不计入。关闭播放网关、服务故障或操作恢复 hosts 会结束检测；刷新网页保留，多标签页共享，退出程序清空。手动单项启动不自动建立检测窗口。hosts 实时状态可能被其他程序改变；总状态结合服务与连接配置，收到请求仍不代表播放成功。重新检测仅重置观察窗口，不重新开启已关闭的队列。

## 从 VRCX 导入历史偏好

引导的存储页与曲库提供可跳过的「历史偏好」：新库或空 `song_usage` 默认勾选，非空默认不勾选。引导只显示选项和一行说明，自动使用 VRCX 默认路径，在「启用 → 接入检查」显示结果；只有最后「确认并应用」才写入所选存储目录，检查不通过则跳过导入。非空用户勾选时不警告，最终应用确需覆盖时才再次确认。曲库的「导入 VRCX 历史需求统计」首次展开后提供手动选择数据库、预览和即时导入入口，使用当前生效目录；折叠或切页保留本轮选择与预览，仍受服务端预览有效期约束。导入不下载视频或持续同步，详见[历史初始化契约](song-catalog-design.md#vrcx-历史初始化)。

## 歌曲偏好

「曲库 → 按歌曲」提供本地歌名/ID 查找、普通/收藏/屏蔽筛选和按 ID 设置。选择即保存，恢复普通会删除偏好记录。收藏只做标记，不启动下载；列表分别展示标记与完整文件是否存在，不把标记当作下载成功。屏蔽拒绝新的歌曲 API 请求并跳过预加载、手动补齐；已接纳的请求继续。共享资源、计时与预算规则统一见[设计第 8 项](download-resource-design.md#8-歌曲屏蔽与收藏)。

后台接口 `GET /api/songs?q=&policy=&offset=` 只读当前库，每页 50 首；`POST /api/songs` 接受 `storageID`、字符串歌曲 `id` 和 `normal/blocked/favorite` 的 `policy`。两者沿用会话令牌及来源校验；写入核对当前库身份，旧页面不能写到已切换的库。读取不启动引擎或补库；标记操作也不启动引擎、播放网关、队列或补齐任务。引擎未启动时直接写入离线库，不先执行预算淘汰或临时清理；之后正常启动时使用已保存偏好。

## 本地视频明细管理

`POST /api/batch/download` 接受 `storageID` 及二选一的 `songID`／`resource`，复用现有补齐任务、单轮预算、重试和完整视频发布流程；与全库补齐共用运行槽及停止操作，不建立追加待办集合。选中歌曲尚无映射时可正常解析；按资源下载只使用当前关联歌曲，没有关联时报告无法处理，不猜测历史关联。单项操作不联网刷新整个清单，只固定并保护选中的资源快照；结果标明 `target`，不覆盖上次全库成功覆盖结果。运行中不暂停或恢复房间队列。

`GET /api/library?view=songs|resources&q=&sort=id|title|score|size|recent&filter=&offset=` 提供曲库的歌曲／资源视图，每页最多 50 项。歌曲可按普通／收藏／屏蔽、本地已保存／缺失筛选；资源按已保存／缺失筛选。`song` 与 `resource` 是精确对象查询，用于历史链接，查不到时返回空列表，不改写历史身份。歌曲需求分数与下载排序、保留取舍共用衰减规则，屏蔽独立于分数。

资源范围为完整本地文件与当前 `song_media` 关联的并集，未关联且缺失的底层记录不返回，也不删除。占用按目录内普通 MD5 视频文件去重计量，与搜索、分页及保留模式无关；歌曲行通过同一资源映射取得文件身份、保护和删除快照。只打开当前页文件获取身份，不读取视频内容；缺少已知大小或实测时长时返回 null，不使用下载调度的估算值。页面读取不创建存储、启动引擎或联网；鉴权与已有曲库接口一致。

「曲库 → 按资源」可按歌名、歌曲 ID 或资源指纹查找，并按分数、最近请求、占用或歌名排序，每页最多 50 项；按「已保存完整视频」筛选管理本地文件。搜索长度限制为 300 个 UTF-16 码元，与 HTML maxlength 一致。查找和「刷新曲库与本地占用」只读取本地目录和数据库，不联网获取曲库、校验视频正文或启动引擎；清单更新是独立操作。翻页或刷新清空选择，确认过程中快照改变时拒绝旧选择。保存设置不切换当前目录；删除或淘汰使当前页超出范围时回到第一页，保留查找条件。未知文件仅展示，不能通过页面删除或定位。

资源行显示指纹、已知大小／时长、当前关联歌曲及本地状态，已存在文件同时显示最近请求。该时间来自资源 GET 汇总及仍保留的 HTTP 请求明细，不代表确认播放；共享文件无法推断实际播放歌曲。当前关联不是线上最新版本保证，不恢复历史关联。列表只检查存在、普通文件属性和大小，明确显示「完整性未检查」或「大小不符」，不将版本记录冒充校验证明。每个文件最多展示 20 首关联歌曲和每个标题 300 字符，超出数量有提示；搜索涵盖所有关联。

选择文件后点击「删除选中视频」，确认区会列出文件、大小及影响歌曲数。共用同一文件的所有关联歌曲都会失去该本地视频，需要时重新下载；歌曲资料、版本映射、请求历史和累计统计保留。每次最多删除 50 项，逐项反馈已删除、受保护、已不存在、已变化或失败。确认后文件身份、大小、修改时间、模式或关联变化时跳过，须刷新重选。播放、下载、引擎校验、完整待播队列及离队宽限期保护均在删除前重新检查；独立扫描运行时拒绝整批删除。独立本地校验的同进程资源锁也参与保护。

删除统一经过本地资源引擎的资源删除预留，阻止同资源的新引用、发布、淘汰或歌曲关联更新与删除交错。引擎未启动时，以独占存储锁执行同一删除逻辑，不启动服务、自动清理或统计保留期清理；其他进程占用目录时拒绝。成功删除使校验凭据失效并更新运行中容量记账。删除和打开操作仍与存储切换串行化。列表读取不持有生命周期锁或状态锁，慢盘不会因此阻塞服务启停与退出；运行目录在保存后重启时切换；读取完成后复查退出状态，已进入退出则丢弃旧结果。

「打开视频目录」和「定位文件」只接受当前存储标识与本地视频条目，不接受任意路径。Windows 使用 Explorer 选择文件，macOS 使用 Finder；其他桌面平台打开其所在目录。目录重定向、符号链接及非普通文件会被拒绝。`GET /api/cache?q=…&sort=recent|size|title&offset=…`、`POST /api/cache/delete` 和 `POST /api/cache/open` 均要求合法 Host、会话 token 和同源 Origin（如提供）；写操作绑定存储标识，删除与定位另绑定条目快照。

分页限制的是返回量。为支持全库搜索和排序，每次读取仍枚举整个视频目录并查询本地元数据，不读视频正文；大库或慢盘可能需要等待，服务端 30 秒超时，界面可重试。列表是手动刷新的快照，不能据此保证文件持续存在或未被外部程序改动。请勿在使用时从资源管理器替换本地存储目录结构。

验证：完整 `go test ./...`、`go vet ./...` 和前端 71 项测试通过；新增覆盖共享删除影响、关联变化使确认失效、文件变化、未知文件、路径越界、活动引用/队列/校验保护、离线独占、容量记账、分页、关联展示上限和隐藏关联搜索、接口鉴权、存储切换和扫描保护，以及慢读取期间停止/退出、存储切回时的旧结果丢弃、队列等待期间状态读取与取消、更新/重置顺序和删除末页后回退。Windows 当前环境缺少符号链接创建权限，两项符号链接实测跳过；没有 CGO/C 编译器，未执行 race 检查。资源管理器的实际定位行为仍需桌面人工复核。

Windows 桌面版构建、启动（托盘驻留，无命令行黑窗）：

```powershell
.\scripts\build-desktop.ps1
.\bin\SWD.exe
```

首次启动由系统分配空闲的本地控制端口（监听 `127.0.0.1:0`），并默认自动打开实际地址；常规设置可关闭下次启动自动打开，`-no-open` 同样禁止自动打开。同意条款后关闭网页仍在托盘运行；未同意时的退出机制见上文。原有 `still-wanna-dance.exe` 命令行入口保持可用。

## 托盘与实例避让

托盘菜单包含打开 WebUI、开始加速、退出 Still Wanna Dance。尚未同意当前条款或同意记录失效时，加速项显示灰色不可点击的「开始加速（需先同意条款）」；「打开 WebUI」和退出仍可用，菜单顺序与位置不变。打开 WebUI 进入现有条款确认流程，同意成功后加速项在下次展开菜单时恢复正常状态，无需重启；是否自动加速仍遵循现有引导及启动设置。

「开始加速」与首页共用[完整加速流程](settings-lifecycle.md)，处理中显示「正在处理…」并禁用；网关和 hosts 均就绪且无需补充退出恢复权限时显示禁用的「加速运行中」。网关已运行但接入缺失，或仍需准备退出恢复权限时，保留开始加速入口。菜单及悬浮提示同时跟随网页、自动加速和托盘操作更新，悬浮提示区分加速未运行、未就绪、处理中和运行中。鼠标或键盘激活图标均可打开 WebUI；Explorer 重建任务栏时重新注册托盘图标。

Windows 普通桌面模式在同一用户会话中只允许一个实例，使用会话级互斥锁 `Local\SWD.Desktop.v1`，控制端口由系统自动分配。主实例在当前用户 `%LOCALAPPDATA%\SWD\console-session-<会话 ID>.json` 记录地址、实际 EXE、配置路径、PID 和进程创建时间。重复启动最多等待 5 秒，核对端口所属进程、操作系统报告的 EXE 与创建时间，以及 `/api/identity` 返回的完整 `swd-console`（协议版本 1）身份。

只有实际 EXE 和配置身份都一致才激活已有程序实例，不创建第二个服务、托盘或后台任务；`-no-open` 同样检查身份，但不打开浏览器。不同安装目录或不同配置会报错并显示已有程序、配置和 PID，须自行退出原实例；不会自动切换、停服或终止进程。路径解析支持相对路径、Windows 大小写、短文件名、符号链接和 junction；EXE 还会比较文件身份以识别硬链接；配置则要求规范化路径一致，因为其路径决定数据根和相对设置的基准，不将不同路径的配置硬链接视为同一实例。配置尚未创建时解析已有父目录，不为重复启动创建新数据目录。

首次启动者就绪前崩溃，后启动者可重新取得互斥锁。正常退出先删除本会话记录再释放锁；取得锁的新主实例清除本会话崩溃遗留记录，不扫描或删除其他会话。过期 PID、进程创建时间不符、伪造路径或不匹配的后端身份均不激活。旧 StepStash 实例协议和发现目录不参与选举，不迁移或双写，使用新版前须退出旧测试程序。

显式 `-no-tray` 不参与桌面选举，可配合 `-config`、`-listen` 运行独立开发实例。所有模式仍通过配置数据根的 `config.lock` 在整个进程生命周期独占配置，并受存储根独占锁和端口占用限制。数据根规则见[统一存储](storage.md)。锁文件保留是正常现象；OS 在进程退出或崩溃时释放锁，不要运行时删除。

退出从统一清理入口停止 HTTP 接口、取消批量任务和下载、移除托盘图标，最后释放配置锁和实例锁。注销 / 关机回调最多等待 4 秒；如果系统取消注销，程序继续运行。网页退出、托盘退出及应用重启共用当前的 hosts 退出策略，详见下方 hosts 契约。权限助手在实例检查前进入独立入口，在本次运行内复用，主程序不提权；退出只使用已有助手，绝不新申请 UAC。系统会话结束只在系统允许的时间内尽力清理，不能保证关机或断电时恢复。

80、443 或手动指定的控制端口冲突时，Windows 下显示占用进程名和 PID；不结束其他进程，也不自动请求 UAC。旧的无托盘版程序不会持有新实例锁，需要退出旧版后再启动新版。

默认自动选择端口；也可用 `-listen 127.0.0.1:18082` 手动指定（托盘模式同样支持）。自定义控制端口及无托盘运行示例：

```powershell
go build -tags=no_easytier -o bin/still-wanna-dance-console-cli.exe ./cmd/still-wanna-dance-console
.\bin\still-wanna-dance-console-cli.exe -no-tray -listen 127.0.0.1:18082 -config .\other-settings.json
```

该模式不自动打开浏览器，不创建托盘，使用 Ctrl+C 退出。Linux 默认使用无托盘模式。配置独占及现有本地存储独占规则仍然生效。

设计参考 [dancing-log desktop_instance.py](https://github.com/SW26010/dancing-log/blob/c3fa28fa3b68879cb43513bc2cb53f1cc03fa1cc/dancing_log/desktop_instance.py)、[tray_app.py](https://github.com/SW26010/dancing-log/blob/c3fa28fa3b68879cb43513bc2cb53f1cc03fa1cc/dancing_log/tray_app.py) 和 [_win_tray.py](https://github.com/SW26010/dancing-log/blob/c3fa28fa3b68879cb43513bc2cb53f1cc03fa1cc/dancing_log/_win_tray.py) 的所有权、身份探测和统一退出机制。Still Wanna Dance 以 Go / Win32 实现，无新增第三方运行依赖。

## 服务与下载独立

- **启动程序时自动开启视频加速**：常规设置的 `autoAccelerate` 默认开启，保存后重启生效。有效同意条款且首次引导最终应用成功后，每进程调用一次完整加速流程（可能请求 UAC）；刷新网页不重复，失败不自动重试。初始化或回执续接失败不会提前启动，用户可修复后手动开启。
- **后台网关生命周期**：同时控制 `127.0.0.1:80` HTTP 播放和 `127.0.0.1:443` HTTPS 透传。启动检查两个端口和目录权限，任一失败均回滚监听；页面分别显示两个端口状态。端口占用时提示关闭原版 CDN 或其他程序，不自动结束其他进程。后台独立监听不以 hosts 为前置条件；WebUI 统一通过一键加速检查和修复接入。停止会关闭已有播放连接，但保留独立下载任务。
- **检查缺失视频**：从 Kiva 清单获取歌曲 ID、名称与 MD5，新增和更新本地映射，保留清单中消失的旧 ID。一次枚举视频目录，检查所有被引用的 MD5 文件是否存在；不读取正文、不计算 MD5、不关心孤儿文件。上层直接使用检查结果。可与队列预加载和播放并行。
- **下载补齐**：每次重新获取清单并更新映射，使用独立的快速缺失检查，只为缺失 MD5 解析 URL 和下载。同 MD5 多首歌曲只下载一份，已有文件不重复检查。映射不变但文件缺失也会补齐；映射变化但文件已存在无需下载。清单不可用时使用本地已接受的 MD5 映射继续处理；本地没有有效清单时明确报错。URL 的 MD5 与清单不一致时记录失败，清单关联保持不变。
- **停止批量任务**：取消排队和当前等待；已开始的共享下载继续执行，直到完成、失败或程序退出，以免打断游戏。网关停止时按随动设置停止队列，不停止独立批量下载。退出程序会取消全部下载。
- 成功结果与当前任务进度分开显示。完整任务无接口或读取错误时才替换成功结果；扫描中、失败或取消均保留上次成功计数。任务结束或正常停止时另存进度记录。重启恢复记录，但不会自动继续任务；暂不提供下载断点回源。
- 下载补齐按视频存储预算执行：下载前按完整视频大小预留空间，并发任务共享预算，已有视频不重复计费；剩余预算放不下下一首普通视频时停止普通补齐，开启优先保留收藏视频时，本轮收藏继续处理，不计为失败，也不保存为全曲库成功结果。已获准的下载正常完成，界面提供前往「设置 → 存储」调整保留空间的入口；保存新预算并重启应用，再次点击下载补齐即可继续。0 表示普通视频不持久保留，网页仍可启动补齐以处理收藏；收藏计入实际占用，开启优先保留时可超出预算，选择「不限制」时所有候选跳过容量限制。屏蔽歌曲在创建需求前跳过，不计为下载失败。本轮已使用的预算不会因淘汰而循环释放，避免边下载边淘汰整份曲库。命中和下载计数是过程累计值，当前保留数量与占用空间通过「刷新曲库与本地占用」更新。
- 本地视频概览先检查远端并按版本规则更新本地库，再按本地歌曲 ID 对照 MD5 文件存在性，包含隐藏曲目和保留的旧 ID，共用文件按歌曲分别计入覆盖率；文件数按唯一 MD5 计数。远端失败或候选无效时仍重新计算本地覆盖率，并显示检查错误；本地读取失败才保留上次结果。由用户手动刷新，不自动重复扫描。
- 结果写入配置实例数据根下的 `state/inventory.json`、`state/batch.json` 和 `state/attempt.json`，写入临时文件后替换；文件随便携目录移动。更换存储目录时不会沿用其他目录的结果。

## 实时下载监控

视频加速首页显示活动共享任务及上游总下载速度。`GET /api/downloads` 使用网页会话 token、Host 和 Origin 检查；读取内存中的线程安全快照，按资源共享任务去重，曲目候选从已有索引补全，不读取日志或启动本地资源引擎。多个 Range、播放请求和预加载加入同一任务不会重复计速。

监控读取不获取应用生命周期锁，启动、停止、保存设置或引擎关闭期间仍可返回当前快照。歌曲资料查询在锁外进行，受查询期限和引擎取消控制；引擎关闭或被替换时丢弃旧任务快照，不等待关闭操作完成。

字节数为从上游正文实际读取的字节；速度是最近约 5 秒的估算值（按秒分桶，启动不足 5 秒按已用时间计算），不是网卡流量，也不是向客户端传输速度，不包含选路探测、API 查询或 HTTPS 透传。停止读取后速度衰减为零，发布及索引阶段速度为零。总大小来自已解析资源的预期大小；字节百分比不是整个任务完成率，下载时同步计算 MD5，随后仍需验证并发布。任务可能先显示本地视频检查阶段，命中后不回源。

主行突出歌名、进度和上游速度，资源来源按最终响应域名显示，响应前显示线路待定。完整资源指纹、最多 20 首关联曲目（超出时提示更多）、最终主机名（含已验证的重定向）及空闲时间默认折叠在「下载详情」，统计口径放在「下载统计说明」。详情支持键盘展开，轮询保留展开状态与焦点。不暴露签名 URL 或代理凭据。歌名来自显式任务关联和已有资源映射；共用资源标明关联曲目数量及播放歌曲未确定，不推断实际播放歌曲，未知信息明确标注。

活动任务完成、失败或引擎退出后移除，下次轮询更新；关闭播放网关或取消等待者不会取消现有共享下载，因此播放网关关闭时仍可显示继续运行的下载。没有任务时显示空状态；读取失败清空旧列表和速度并自动重试。复用全页面每 5 秒、无重叠的轮询批次，页面隐藏时不再发起新轮询。尚未进入共享下载的容量等待和歌曲地址解析不在此列表中。

## 队列预加载与刷新频率

队列预加载的轮询规则见[日志队列预加载](queue-prefetch.md)。`queueWithGateway` 默认开启，队列随网关启动、停止和失败撤销；配置保存后重启生效。目录默认按当前用户识别，仍可手动指定。开启后等新队列同步，不下载历史日志歌曲；手动下载与队列共用调度，互不暂停。

网页状态在可见时每 5 秒刷新，隐藏时暂停轮询，恢复可见时立即刷新。操作完成后，页面可见时立即刷新，隐藏时等待恢复可见再刷新；已发出的展示请求正常完成。播放网关、下载、日志监听及已启动的扫描任务独立运行，不受网页是否打开或可见影响。

操作请求最多等待 30 秒，hosts 操作及显式启动播放网关因可能等待管理员授权而延长到 120 秒；期限包含响应体读取。超时或响应丢失后解除操作等待，并刷新当前状态供核对，不自动重试。页面提示「结果尚未确认，请勿重复提交」：停止浏览器等待不会取消后台操作，刷新得到的状态也不能证明原请求已经结束。状态查询失败时保留提醒，待连接恢复后继续核对；页面隐藏时延至恢复可见再刷新。

## 上游连接

直连模式使用内置加密 DNS 解析域名，并连接目标 IP，可能影响透明代理的域名分流，使实际连接路径与预期不一致。如需由代理处理域名解析和连接，请选择「强制代理」并配置所选后端。

在「设置 → 网络 → 代理设置」中选择「上游连接」：默认「直连（内置 DNS）」沿用内置 DoH 与多 IP 优选连接；选择「强制代理」或「自动选择直连或代理」，再选择「外部 SOCKS5」后，填写代理软件的 `主机:端口`，例如 `127.0.0.1:7891`，不加 `socks5://` 前缀。端口以代理软件实际的 SOCKS5／混合端口为准。支持无认证及用户名／密码认证；需要认证时同时填写用户名和密码，各限 1～255 字节。

密码以版本化 DPAPI CurrentUser 密文保存在配置文件中，不通过状态接口回传，不写入任务快照。同一 Windows 用户移动目录或覆盖程序后仍可解密；换用户或普通独立机器后可能无法解密，并提示重新输入。不可用的密文会保留，强制代理不会回退直连；Auto 仍按既有直连优先策略运行。非 Windows 不支持保存代理密码。页面区分已保存且可用与凭据不可用；密码框留空保留已有密码，填写新值则替换；清空用户名和密码后保存可移除认证。切换回直连会保留认证配置，便于再次启用。设置 API 省略 `socks5Password` 时保留原值，显式发送空字符串则清除；用户名与密码须配对。变更凭据保存后在重启应用时使用，当前网络客户端保持不变。

选择「内嵌 Mihomo」时，设置 → 网络的「代理设置」和引导使用同一节点导入界面。选择本地文件或粘贴 YAML 的 `proxies`、逐行 URI 或 Base64 URI 列表（最多 2 MiB / 2048 条），点击检查后逐条核对接受、重复跳过和失败。使用 Mihomo 原生节点解析（含 VMess/WS），拒绝代理组、链式代理、文件或系统网络能力等受限选项，不再按协议维护基础字段白名单。不会加载完整运行配置、下载订阅或自动更新。检查不写配置、不改变当前网络；保存设置或引导最终应用才用成功条目替换整份节点库，全部失败不替换，重启后生效。草稿只在内存保留 2 小时，过期或另一页面更换了节点库时须重新导入。清除本次导入、替换草稿或放弃本轮引导会释放相应草稿配额；进入引导前已有的普通设置草稿仍保留，退出后可恢复。

整份节点快照使用 Windows 当前用户加密保护；无法解密时保留原密文并提示重新导入。页面分别显示已保存、当前已加载和活跃数量。默认最多 5 个节点参与业务与测速，备用节点配置及历史保留；初始集合按稳定身份排序，不代表延迟最低的 5 个；活跃节点失败时不会自动晋升备用节点。需要改用备用节点时，重新导入所需的小规模节点集合、保存并重启；动态准入和轮换留待后续。保存顺序、展示名或活跃上限不改变节点身份，服务器和凭据变更会改变身份。内嵌节点的服务器域名由受控 DNS 解析，业务目标域名交由固定出口处理。通道身份密钥异常时使用本次临时身份并提示，不复用旧测量；没有有效活跃节点时强制代理明确失败。

API 查询、校验和清单、冷播放、队列预加载、下载补齐和选路测速使用所选出口；应用的 HTTPS 回源也遵循策略，游戏 HTTPS 兼容透传始终直连。外部 SOCKS5 后端把目标域名和端口直接交给 SOCKS5，不在 Still Wanna Dance 中解析目标域名，不使用内置 DoH 或多 IP 直连，不检查代理端如何实现 DNS；代理不可用或拒绝连接时返回错误，不自动回退直连。原域名 Host、TLS SNI 和证书校验保持不变。代理服务器地址本身若填写域名，由本机网络解析；本地代理推荐填写 `127.0.0.1`。

运行中允许保存配置；当前及后续任务继续使用本次应用启动时的配置，重启应用后统一应用新配置。保存不会重建上游客户端或本地资源引擎，不取消覆盖率查询。详情见[配置与运行生命周期](settings-lifecycle.md)。旧配置默认直连，切回直连会保留代理地址方便再次启用。播放接口选项仅决定 API 查询参数，资源域名由返回值决定，测速经过当前所选出口；完整本地视频的本地读取不经过代理。

SOCKS5 使用本地模拟服务验证域名转交、API HTTPS、视频回源、游戏 HTTPS 直连分离、取消和设置切换；真实代理线路的持续吞吐与 VRChat 联合播放仍需实机验证。

## 独立 DNS

### 网页 HTTPS 播放

hosts 同时影响 HTTP 和 HTTPS。桌面程序启动播放网关时提供 TLS SNI 透传，防止网页的视频 HTTPS 请求被映射到本机后遭到连接拒绝。仅接受 `api.udon.dance` 和当前已由有效 API 响应确认的资源域名；新 hosts 接管只写入 API 域名，资源域名不预设，始终通过受控 DNS 直连其 443 端口，不读取系统 hosts；即使应用选择强制代理，兼容透传也不改变路径。不使用额外的 `ud-*` 回源别名，不开放通用代理。网页、封面和统计域名不纳入接管。

转发始终复用下面的独立加密 DNS、TTL 缓存和双栈连接机制，优先尝试 IPv6，必要时尝试 IPv4；直连失败不会改走代理。固定保留域名的原上游，不套用 HTTP 的播放接口参数设置，不跨线路替换路径或签名。TLS 握手及后续密文字节原样传递，浏览器直接验证原站证书；不安装证书、不解密、不改网页、不降级为 HTTP。网页 HTTPS 播放仍消耗上游流量，不读取本地视频或填充视频块缓存，也不计入视频需求热度。

只绑定本机 IPv4，最多 128 条连接，ClientHello 限制为 64 KiB / 10 秒，建连最多 15 秒，两分钟双向均无进展的连接关闭。关闭播放网关会取消解析和建连并清理活动连接。此入口不支持无 SNI 或隐藏目标域名的握手，也不提供 QUIC/UDP 443。

回归覆盖 TLS 1.2 / 1.3、原站证书验证、HTTP/2、Range/HEAD、分片 ClientHello 原样转发、未托管域名拒绝、建连和活动连接取消，以及端口冲突/目录失败的回滚与重启。需要浏览器实网复验时，先释放本机 443，使用当次 API 返回的实际资源域名进行本地连接测试，在 PowerShell 中运行 `$env:SWD_HTTPS_LIVE='1'; go test ./internal/console -run '^TestHTTPSLiveBrowser$' -v -count=1`。此显式验收辅助服务先通过两个播放接口发现歌曲 1343 的资源域名并打印集合，仅监听 443，两分钟后自动退出，不改 hosts 或本地视频；普通测试和 CI 默认跳过。它仅为手工验收提供连接窗口，测试通过本身不代表视频播放成功，须另行检查浏览器。

历史 Chrome 实测（2026-09-26，切换公开域名前）：通过上述辅助服务从原站点击歌曲 6228，播放器 `readyState=4`、`error=null`，播放时间推进到 13 秒；重新打开当时 node=nya 返回的地址后，重定向到 play.udon.dance，继续播放至 37 秒。当时服务连接的是 `ud-nya.kiva.moe:443` 和 `ud-play.kiva.moe:443`，不代表当前默认目标。没有改写网页、视频 URL、系统证书或 hosts；这是该歌曲当时的连通与播放验证，不代表全曲库或持续吞吐测试。

当前公开域名回源的实网验收见[调查后的实现与验证](history/playback-domain-observation-20260926.md#调查后的实现与验证)。`SWD_LIVE_UPSTREAM=1` 启用的 `TestLiveHTTPSUpstreams` 会让测试客户端连接临时本地 TLS 透传端口，模拟 hosts 接管，再通过生产 DoH 连接公开域名；验证 API 实际返回地址的视频片段及原站证书，不修改系统 hosts。

### 解析与连接

以下机制适用于直连模式。桌面程序的歌曲列表、播放地址解析、视频回源均只使用证书验证通过的 HTTPS DNS（RFC 8484 POST），不查询 ISP 或系统 DNS，不读取系统 hosts，也不会在失败时降级到 UDP、HTTP 或自动接受 fake-IP。TLS 使用系统信任库并校验服务域名，拒绝重定向、错误媒体类型、过大或不匹配的 DNS 报文。

内置服务：

| 服务 | HTTPS 入口 | 引导方式 |
| --- | --- | --- |
| 阿里公共 DNS | `https://dns.alidns.com/dns-query` | `223.5.5.5`、`223.6.6.6` 两个独立连接入口，仍验证域名证书 |
| 腾讯 DNSPod | `https://doh.pub/dns-query` | 通过已验证的加密解析获取入口 IP，并按 TTL 缓存 |
| 360 安全 DNS | `https://doh.360.cn/dns-query` | 同上 |
| Cloudflare | `https://cloudflare-dns.com/dns-query` | `1.1.1.1` 引导，验证域名证书 |
| Google | `https://dns.google/dns-query` | `8.8.8.8` 引导，验证域名证书 |

DNSPod 和 360 的入口发现只通过具备固定引导 IP 的 DoH 服务进行，不依赖本地 DNS；同入口并发引导合并，后续读取 TTL 缓存。没有硬编码 DNSPod 已下线的测试 IP。官方依据：[阿里服务资料](https://static-aliyun-doc.oss-cn-hangzhou.aliyuncs.com/download%2Fpdf%2F171662%2FAPI_Reference_intl_en-US.pdf)、[DNSPod 域名接入公告](https://docs.dnspod.cn/notices/mian-fei-ban-dot-dohbu-zai-gong-kai-ipjie-ru-de-gong-gao/)、[DNSPod 旧测试 IP 下线公告](https://docs.dnspod.cn/notices/guan-yu-doh-dotdu-li-ce-shi-ipxia-xian-de-gong-gao/)、[360 官方服务页](https://sdns.360.net/dnsPublic.html)。

直连并发查询 A 与 AAAA，DNS 只维护有效地址池与 TTL，不记录连接胜者。普通建连采用成熟的 Happy Eyeballs 组件，优先尝试 IPv6并自动回退 IPv4；已由 Monitor 测速选定的 IP 则继续固定使用。双栈地址池、连接间隔、代理边界及验证以[上游通道的请求与连接规则](upstream-channels.md#请求与连接)为准。视频请求仍保留原始 HTTP Host，历史 UI 中 HKG 对应查询参数 `node=nya`，不代表资源域名。

全部加密通道失败时明确报错。这保护的是客户端到解析服务的 DNS 链路，仍信任所选解析服务及系统证书信任库；DNS 模块本身不改变视频或 API 请求的 HTTP/HTTPS 协议。曲库业务仅使用 Kiva／WannaInfo 的 MD5 清单，Udon `https://api.udon.dance/Api/Songs/list` 只用于 monitor，不参与本地曲库更新或水位计算；游戏请求的 HTTP→HTTPS 跳转与 HTTPS 透传继续保留；播放地址 API、版本确认、视频下载、测速和 Range 回源统一使用 HTTPS，保留原始 Host、TLS SNI 和证书域名校验；连接或证书失败不降级至 HTTP，也不回退系统 DNS/hosts。此前依赖明文 DNS 劫持产生 fake-IP 的代理路径不再由此模块自动使用。

2026-09-25 本机逐入口真实解析 `api.udon.dance`：阿里双入口、DNSPod、360、Cloudflare、Google 六项均通过 HTTPS 证书验证与 DNS 报文解析。这不代表其他网络始终可达。可选复测：`SWD_LIVE_DOH=1` 后运行 `go test ./internal/console -run '^TestLiveDoHProviders$' -v -count=1`。
桌面程序与独立命令行服务共用内置 DoH 建连逻辑。两者的上游 API 查询和视频回源均使用 HTTPS，默认视频回源端口为 443；DNS、连接或证书验证失败不回退系统 DNS/hosts 或明文 HTTP。视频重定向仅在目标域名已由有效 API 响应确认且 MD5/大小一致时跟随，最多五次，HTTP Location 升级为 HTTPS 后访问。

## hosts

接入、恢复及退出共用同一权限助手。接入或显式启用时先检查 hosts 内容、冲突和恢复权限，已有助手直接复用；需要写入或为默认模式准备退出恢复、且尚无助手时，才请求 Windows UAC。映射正确且选择持久化时不重复申请权限；用户或其他工具的映射不纳入本程序恢复范围。自动加速复用同一流程，必要时申请 UAC；单纯读取状态及下载不申请 UAC。

「设置 → 常规 → 高级游戏接入设置 → 退出时恢复游戏直连」（`restoreHostsOnExit`）默认开启，缺失/null 也使用开启值。保存成功后即用于本次退出；修改草稿不触发权限或策略改变。由关闭改为开启且有托管接入时，保存流程先准备恢复权限，再写入全部设置；失败保留原配置及退出策略。没有托管接入时不申请 UAC。两种模式只在退出清理上不同：开启时助手移除本程序标记映射后退出，关闭时助手保留映射并退出。后台独立恢复能力仍可供生命周期使用；WebUI 没有恢复直连、停止网关或队列启停入口。

退出路径不创建助手、不重新提权。默认模式复用已有托管映射时，也要在接入/显式启用阶段取得恢复权限；只有后台独立启动过服务、尚未准备权限时，页面提示先点击「开始加速」，直接退出会保留旧映射。正常退出明确发送最近成功保存的策略。主程序意外断开且助手仍存活时，仅按最近接入操作确定的备用策略尽力清理；保存阶段只准备权限，不改变该备用策略，避免配置写入失败提前改变恢复行为。助手故障、条目被改写、文件写入失败会据实报告，不能保证断电或系统强制结束时恢复。失败允许应用退出，下次启动可主动修复。

Windows 通信复用已有 go-winio 命名管道组件：随机会话名、当前用户/管理员 ACL、拒绝远程连接、双方核对内核返回的进程 ID；提权客户端使用匿名模拟级别，普通主程序不能借连接模拟管理员。协议只接受固定接入、恢复、权限准备、本次接入回滚及关闭操作，没有自定义路径、文件内容或任意命令。连接失败后废弃该会话，不将迟到回执当作后续操作的结果。

- 仅添加播放 API 域名 `api.udon.dance` 到 `127.0.0.1`，新增使用 `# SWD managed` 标记，恢复时精确识别旧 `# Still Wanna Dance managed` 和 `# StepStash managed` 标记。

### 统一回源选路

播放地址接口默认 Auto，忽略游戏请求中的 CDN 选择：需要查询新地址时固定先请求 `node=cf`，失败后尝试 `node=nya`。即时播放、队列预加载和下载补齐共用这个入口顺序，Monitor 推荐不改变 CF 优先；WebUI 手动固定 CF/HKG 时只使用指定接口。此规则不改变本地视频、持久化地址和已有共享下载的优先复用，也不从 node 推断最终资源域名。

业务按操作、入口、节点、资源域名和网络模式约束使用 Monitor 提供的实际 Transport，Monitor 仍负责各入口内的连接通道选择。API／清单请求顺序尝试候选，并按剩余时限为备用保留时间。Mihomo 先保留 Monitor 推荐的相对顺序，再追加当前活跃、尚未入列的候选，不因部分节点尚无观测而失去回退；其他后端无有效观测时使用配置通道。强制代理只尝试代理，连接方式的 Auto 同时为直连及活跃代理保留位置。下载核心不查询歌曲 API，不维护路由缓存，也不现场测速或独立排名。

资源 Range 请求单独保留本次候选进度：首块或后续区块的范围校验、实体标识检查、短读和网络失败可推进到备用通道，不从首选重新开始。后续区块发生重定向时，只在该区块内保留已验证的最终地址，失败后继续该地址的备用通道。API 与资源使用统一的六候选上限；每个资源地址最多尝试六个候选（默认五个活跃代理和一个 Auto 直连），包含尚无推荐的活跃候选；只有一个通道时，区块失败最多再试一次。多个候选按任务剩余期限分配时间，预算覆盖响应头及 206 正文读取，成功返回响应头不会立即取消请求。若确认上游忽略 Range 并返回合法 200 全文，则撤销候选预算，由整个任务剩余期限约束顺序下载。已经输出的区块不替换；全文降级不据此承诺任意拖拽。

即时播放和队列先保护并检查本地资源，同时独立刷新 API 地址。本地完整资源立即使用；本地缺失时先尝试持久化 URL，失败再等待已有查询。地址记录保留完整 URL、API/node、MD5、大小及观测顺序，当前复用窗口为 24 小时，不保证签名始终有效。新观测不替换已打开资源或已有清单映射。

下载补齐按清单 MD5 调度，对同资源关联的歌曲依次查询，取得目标内容后停止。播放、队列和补齐共享 MD5 下载任务、区间数据、容量保护及最终校验。旧拖拽最后一个读者离开后，可取消其前台区间；后台继续补齐未完成区块。已输出正文后不能切换内容。

资源以 API 实际返回域名区分，同域名不代表相同 URL 或相同内容。当前下载任务可继续访问受信任原始域名的同域重定向；跨域仍需来源许可，所有重定向仍校验 MD5 和大小。这不扩大任意入站资源请求的域名权限。独立命令行服务不提供桌面程序的 Monitor 推荐回调，接入限制见[服务手册](service.md#游戏接入)。

## 播放请求统计

WebUI 通过 /api/status 的 traffic 字段展示当前存储目录的累计请求命中和节省流量。命中率分母为成功完成的 GET 视频请求（200/206），Range 按请求计数；HEAD、失败、中断和预下载不计入。节省流量是成功命中实际返回的正文大小，不是扣除预下载后的净流量收益。

播放传输次数另行保存，仅计有明确歌曲 ID、成功完成且返回正文的即时 GET。同曲按成功完成的记录时间以 30 秒窗口去重，不使用请求开始时间；记录时间与入队顺序在同一锁内确定。历史累计不回算。该指标不改变需求评分，也不代表客户端起播或完整播放。

首正文等待由 `/api/latency` 读取最近 72 小时窗口，按首字节前是否实际等块分为 Blocking 与缓存／本地，分别展示 P50、P95 和有效样本数；没有正文的请求不计样本。不把不同阶段的 Monitor 样本相加，不计算未配对样本的加速比例。完整传输耗时、首正文和客户端首帧是不同指标。

## HTTP 播放 API 接管与 HTTPS 回源

通过手动或自动一键加速接入 `api.udon.dance`；旧版托管的资源域名映射会清理，不再预设资源域名。只要仍有本程序拥有的旧资源映射，即使 API 已映射也会标为待迁移、接入未完成；「开始加速」会执行清理并重新检查。自动一键加速遵循同意及首次引导门禁，必要时通过权限助手申请授权；失败撤销本次变更。其他程序或用户的条目不属于迁移范围，被修改的托管条目需手动检查。资源集合与历史记录的解释见[资源域名规则](resource-domains.md)。游戏以 HTTP 请求 `/Api/Songs/play?id=…` 时，Still Wanna Dance 使用 HTTPS 解析上游地址，校验资源指纹，然后直接以 HTTP 返回视频；命中复用本地视频，未命中边下边播，支持 HEAD 和单段 Range。接受不带 node、`node=cf` 和 `node=nya` 的请求，但它们不影响桌面程序的回源选择，统一遵循上述策略；其他线路仍明确拒绝。非播放 API 的 GET/HEAD 重定向至原站 HTTPS；原有 HTTPS 请求通过 443 透传，不读取本地视频或填充视频块缓存。

游戏入口必须仍使用 HTTP，并且播放器需接受 API 地址直接返回视频；当前 HTTP 播放 API 接管的实际游戏兼容性需要实机确认。仅接管 API 的前提是解析器和播放器能通过这个直接返回视频的本地入口完成后续读取。历史上正常解析后请求资源 URL 有证据；“新的播放绕过 API、复用旧资源 URL”则尚无发生证据、频率统计或稳定复现步骤。假设、条件性担忧及实机验证要求见[仅接管 API 的假设与待验证边界](resource-domains.md#仅接管-api-的假设与待验证边界)。服务端改用 HTTPS 回源不改变当前统一存储的资源指纹；此说明不表示兼容旧存储格式。下载和测速最多跟随五次视频重定向，仅接受当前 API 确认的视频域名且 MD5/大小一致的地址；HTTP Location 会升级为 HTTPS 后再访问。其他重定向明确拒绝。

HTTP 播放 API 优先使用受保护且校验通过的本地文件，不等待后台 API。已保存 URL 下载失败时，尚未输出正文可等待本次已有查询再尝试；旧下载与刷新都失败时保留两个阶段的错误。正文输出后仍中止响应，不切换内容。HTTPS 透传不适用；地址记录见[曲库设计](song-catalog-design.md)，当前下载与资源边界见[下载需求与资源管理设计](download-resource-design.md)。

可选实网验收：设置 `SWD_LIVE_UPSTREAM=1`，运行 `go test ./internal/console -run '^TestLiveHTTPSUpstreams$' -v -count=1`。仅解析播放 API 并读取每路 1 KiB 视频 Range，不修改 hosts。

## 最近请求监控

请求在进入处理时记录到达时间，在完成时记录结束时间，覆盖地址解析失败、取消及无视频正文的请求。明确歌曲 ID 来自有效播放请求；资源路径中的编号及当前歌曲关联都不作为请求身份。实际所用资源和歌曲 ID 固化在记录中，后续清单映射变化只影响当前关联资料。非标准 Range 内容被替换；接口不返回签名 URL、主机或源路径。

新接口 GET /api/history 支持 from（含）、to（不含）的 Unix 毫秒范围和 cursor 游标，按到达时间、事件 ID 倒序读取 GET 请求。每页默认 50 条，limit 为 1～500；nextCursor 与 hasMore 可继续查询保留期内全部记录，不限制总数为 500。采用时间索引及键集分页；预加载与 HEAD 不计入历史页。原 GET /api/requests 保留给首页最近一条结果摘要，同时返回新事实字段；时间线不再使用该近期窗口。所有接口验证会话 token、Host 与提供时的同源 Origin，读取不创建数据库、不启动引擎、不修复不受支持的结构。

交付比例的分子只计成功写出的视频正文，分母来自实际 200／206 响应所采用的完整长度或 Content-Range。If-Range 未匹配而返回整视频时使用整视频长度，不按原始 Range 猜测；416 等错误正文、HEAD、304 无适用比例。范围未知时返回 NULL。完成、客户端取消、失败、传输不完整和原因未确定的中止独立保存；交付完成不证明客户端已收到或播放。

GET /api/latency 在每次读取时计算最近 72 小时，以原始到达时间筛选。首字节前确实因缺块等待过的分为 Blocking，其余可读块／完整本地读取归为缓存／本地；读取前已就绪或首字节之后才等待均不改为 Blocking。只有成功写出视频正文的请求有样本，后续取消或失败不抹掉已发生的首正文观察。SQLite 按组计算最近秩 P50、P95 与样本数，仅返回两组汇总，不把全量明细传给页面。

采集开始及明细清理水位持久化，跨重启计算有效覆盖区间；不足 72 小时明确 partial，缺少新口径字段的受支持记录不参与样本，空组分位数为 NULL，不补零。旧累计 playback_latency 已删除，不再混入新统计；存储格式 v4 拒绝旧库且不迁移，见[存储契约](storage.md)。明细保留期和异步有界写入机制不变，队列溢出会记录 usage_dropped；这些观测不是完整的客户端播放审计。

此前网络页分组、旧累计耗时及索引迁移验收只适用于当时版本；新查询、采集及界面验收见[WebUI 验证记录](validation/webui-validation.md)。

手动吞吐检测（含全量手动检测中的吞吐阶段）在首个资源通道开始测速前，重置并持久化自动吞吐的配置周期计时；同轮后续通道不重复重置。手动视频列表、播放地址解析、响应延迟检测不改变该计时，尚未取得合法资源而未开始测速也不重置。

吞吐持久化文件兼容旧时间戳格式，新格式同时保存最近尝试时间和每个通道的最近成功样本（歌曲编号、采样时间、字节数、正文耗时），不保存资源 URL 或凭据。恢复样本不恢复通道健康状态。资源区显示独立的下次自动吞吐测速时间，以及等待间隔、业务暂停、准备样本、等待有效播放地址、自动调度未启动等状态；历史样本过期会明确标注，保存失败也会提示。

自动吞吐检测间隔可在「设置 → 网络 → 代理设置」中调整，默认 20 分钟，允许 1～1440 分钟整数，对应 throughputIntervalMinutes。旧配置未设置时采用默认值。保存并重启应用后，按最近测速尝试时间计算到期时间，不重置计时；缩短后已到期则开始调度。此设置同时决定吞吐样本参与推荐的有效期，首字节检测频率不变。运行中保存不会改变当前监测策略。

## 本地清单与检查状态（2026-10-06）

覆盖率、扫描和下载补齐始终先尝试检查远端、按规则同步本地，再读取本地快照开展业务。远端不可用时使用已有本地清单重新计算，不沿用旧的文件计数；没有有效本地 MD5 清单则提示无法处理。正常联网时也使用同一流程。Udon 清单仍仅用于 monitor。

界面分别显示最后检查时间和本地数据水位。最后检查时间只在完整校验并完成版本比较或事务更新后推进，包括同版同内容及合法旧版本；网络、解析、版本冲突或写入失败不推进。水位是已接受的 Kiva／WannaInfo 共享 songs 版本，旧候选不会降低它。错误独立展示，重启保留；已有数据库没有历史检查记录时显示未检查，不用其他时间代替。覆盖率结果记录计算所用水位；本地水位变化后提示重新刷新。

检查状态独立从当前存储目录的数据库读取；离线重启或保存设置关闭引擎后仍可恢复，不使用旧覆盖率快照中的检查状态，也不会为读取状态启动引擎或创建数据库。monitor 的 MD5 候选校验／同步失败会记录错误；同轮旧镜像检查成功不掩盖其它候选的冲突，后续成功轮次清除错误。

## 当前 GET 观测

`GET /api/downloads` 另返回 `gets: {total, requests}`，与既有共享上游下载任务分开。仅观测当前 GET 处理器，最多返回按请求序号排列的最早 50 项；HEAD、非播放 API 重定向及后台预下载不混入。歌曲在验证 API ID 后、资源在解析后记录，重试更换资源时同步更新；不暴露完整 URL 或凭据。`responseBytes` 在实际有效视频响应确定前为 null，`bytes` 仅累加成功写出的视频正文。请求完成、失败或 panic 均释放观测，不新增持久化和任务状态，不访问磁盘或上游。只在注册／释放和读取快照时使用独立短锁，视频写入增加原子计数，不占用调度锁。
