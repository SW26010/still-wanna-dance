# #21：协议、候选名单与通用测速的统一对照

本协议在采样前冻结，方法 `cf-triad-v1`。研究工具仅进入 `windows && cf_block_experiment` 测试构建，复用[网卡绑定](network.md)与真实 API 资源准备，不改变产品。此前虚拟机 v1427 测量仅作历史背景，不与本轮单线路数据混算。

公开文本移除了内部任务来源，实验方法保持原样；冻结原版与公开副本分别记录指纹。公开证据仅保留采样日期、粗粒度时段、持续时间及相对先后间隔；精确绝对时间、网络拓扑和备份操作明细仅保留于私有原件。

## 问题和候选

1. 同 IP、同资源、同 Range 的 HTTP:80 与 HTTPS:443 差异；这是路径/协议/端口组合，不能归为 TLS 加密成本。
2. v1427 的固定 104 IPv4（A）是否比同规模 CF 抽样更容易交付真实视频；分别使用地址空间等概率不放回的 B_uniform、15 个前缀近等额分层的 B_stratified。后者代表前缀均衡设计，不冒充地址空间均匀总体。
3. `speed.cloudflare.com/__down` 的排序能否预测相邻 HTTP/HTTPS 视频，以及下一窗口的另一视频。

官方 IPv4 表于 2026-10-22 核对，15 前缀。`prepare_triad.py` 从已核对的 v1427 私有反编译文件提取地址事实；固定 Python Random 种子 202610220421 / +1，完整池、顺序和输入指纹写 `candidates.json`。不按测速结果换样；重合地址保留池成员关系。C 为每窗真实 DoH 返回的全部 IPv4/IPv6，单列为产品候选基线，不与 104 地址池宣称同等搜索规模。普通 DNS 请求另作实际选路基线。固定 DNS IP 是当窗实验快照，不赋予产品额外 TTL。

## 顺序、流量和截止

- 小规模 pilot：1343，同一 8 MiB 视频区间，Speedtest 2 MiB。5 个历史代表地址、每个随机池预定前 2 个地址及当前 DNS；两轮，轮转 IP 顺序并翻转 HTTP/HTTPS 顺序。每请求 20 秒（Speedtest 10 秒），新连接、串行。
- 完整池窗口 W1：1343，A/B_uniform/B_stratified 各 104，按冻结随机顺序交错三池；C 插入等距位置。每 IP 相邻进行三种 1 KiB/4 秒可用性检查；任一成功则进行三个 2 MiB/10 秒吞吐请求。全失败地址每池按冻结顺序前 8 个仍进行完整吞吐，用于漏选检查，其余保留为筛选失败而非消失。每种端点均单独记录筛选和交付失败。四种方法排列（S/H/T、S/T/H、H/T/S、T/H/S，H=HTTP，T=HTTPS）按 IP 位置轮换，使 HTTP 与 HTTPS 相邻并平衡先后。
- W2 在 W1 开始至少 60 分钟后执行同样流程，视频改为未参与 W1 的 1344，三池名单不变、IP 顺序反转、方法排列偏移两位。先固定 W1 选择，再查看 W2；W2 的候选全量实测给出有限池参考最佳。另重复相同 pilot 的 1343 协议差异对照。
- 每窗（含 pilot）最多 3 GiB 应用读取正文、150 分钟，准备阶段有独立 90 秒期限。读取有长度上限；部分失败也计入流量。全部新连接、HTTP/1.1、无代理、无重定向跟随、正常证书校验；无并发测速竞争。不是 v1427 原八路并发算法复刻。
- 429/503、内容不一致、网卡绑定失效、证据写入失败或总预算耗尽停止整个窗口，保留未测计划。单 IP 超时、拒绝连接、重定向或其他状态保留并继续。若遇这些全局停止条件，不自动延长预算或删除失败重跑。

## 内容与观测

资源来自真实 API；同一路径/query 分别使用 HTTP 和 HTTPS。每窗通过普通 HTTPS 获得前 8 MiB 参考，记录并核对精确 206、Content-Range、Content-Length、identity、强 ETag 及 SHA256。所有视频长度的哈希对同窗参考切片校验；Speedtest 要求 200、精确请求字节、正常 TLS，记录内容哈希但不假定随机正文跨请求相同。记录 TCP、TLS、首字节、头完成、正文完成和 256 KiB 进度，以及源/远端、CF-Ray、HIT/MISS、Age、协议、连接复用。HTTP 重定向单列，不能计成功。所有 URL、源地址、GUID 和原始错误只保存在私有目录。

## 预定分析

- 每窗分别给出池的筛选/吞吐成功率、超时/重定向、有效交付吞吐分布、最佳值和相对同期 DNS；将全部预定候选纳入分母。筛选全失败但未复测者为未取得完整交付证据，不伪造耗时或全文吞吐。
- HTTP/HTTPS 同 IP 配对：双方成功的耗时比、仅一方成功、双方失败分别报告；按首字节与正文阶段分解。pilot 8 MiB 不能与完整池 2 MiB 混算。CF-Ray/前缀只作描述，不声称机房或因果。
- Spearman 分两种：完整成功共同子集；全部实际测量候选中失败并列最低、成功按完整正文/总耗时排序的分析。筛选未复测者另列，不赋予零速再冒充实测。Top-1/3/5 集合与视频 Top-5 交集、是否包含视频最佳、所选吞吐/有限参考最佳、以及 Speedtest 成功但视频失败或低于视频最佳 50% 的比例。
- W1 按 Speedtest/真实视频选出的每池 Top-1/3/5 在 W2 独立视频中评价；不在 W2 再选后称预测成功。W1/W2 逐窗结果是两个网络会话，候选数/分块数不是时间重复样本。只有两个窗口，不声称跨时段统计显著或稳定。
- B_uniform 的全量 1 KiB 筛选成功率给有限总体抽样近似 Wilson 95% 区间；B_stratified 给逐层筛选成功率及按地址规模加权估计/分层 bootstrap 95% 区间。完整 2 MiB 交付中未复测者只进入未知上下界，不能用筛选结果补造完整交付成功率。区间只描述当前网络窗口下抽样不确定性，不覆盖网络时间波动；A 是固定名单普查而非随机总体样本。只抽一个池时不以样本最佳值推断整体显著优势。
- 不依赖 VRC；指定网络之外、跨日、晚高峰、CDN MISS、完整视频/首帧/播放体验仍属未验证。报告必须基于实际结果回答三个问题，不能预设接入方案。

## 采样期发现的方法偏差

W1 pilot 采样时复核发现 v1 将方法排列绑定到了轮转后的执行位置；16 个候选、第二轮起点加 7 与方法加 1 相抵后，同一个 IP 两轮的 HTTP/HTTPS 先后相同。W1 的方法顺序跨 IP 平衡，但不满足每 IP 两轮翻转的原意。原 EXE、协议快照与全部 W1 数据保留，完整池顺序不受这一缺陷影响，不据此删除或补跑 W1。后续 v2 将 pilot 方法排列绑定到候选的稳定位置，新增覆盖 15/16/17 个候选和两个窗口的配对顺序检查。

代码复核另确认 Go `httptrace` 允许请求结束后的迟到回调；v1 的回调共享返回行，并在正文读取期间持锁。v2 将回调写入独立状态，在 RoundTrip 返回时复制快照并释放锁，避免迟到回调与返回行竞争或被正文读取阻塞；新增迟到回调夹具。没有证据表明 W1 已发生数据竞争，不能据此将其性能结果判为无效。普通 DNS 可能尝试多个地址，单一 TCP 时间无法确定属于最终使用的连接，两版均不以该字段解释普通 DNS 的连接阶段；固定 IP 的配对分析另列。W2 使用这两项修订并单列指纹，其余请求、候选、预算和完整池规则保持原冻结定义。
