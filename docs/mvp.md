# StepStash MVP

本地 HTTP 视频缓存服务使用 Go 实现，SQLite 请求统计使用纯 Go 驱动，无需安装数据库服务。当前统一存储通过可控上游测试；真实 CF/HKG 下载与原版回读记录来自旧存储版本。VRChat 联合验收及发现的问题见[验收记录](acceptance.md)。

## 启动

需要 Go 1.25 或更高版本。Windows PowerShell：

```powershell
go test ./internal/... ./cmd/...
go vet ./internal/... ./cmd/...
go build -o bin/stepstash.exe ./cmd/stepstash
.\bin\stepstash.exe -listen 127.0.0.1:18080 -storage-dir .\stepstash-data
```

默认监听 `127.0.0.1:18080`，默认目录相对于启动时的工作目录。Ctrl+C 取消后台下载，清理临时文件并关闭服务。启动不修改 hosts、不改代理，会清理已被取代的旧版本。所有日志为 stderr 上的 JSON。

验证 HTTP 请求时须使用视频 Host 和有效的完整 URL，例如保留 API 返回的真实路径、e、s，通过 curl 的 `--resolve play.udon.dance:18080:127.0.0.1` 访问 `http://play.udon.dance:18080/files/...`。直接访问 localhost 首页会得到 400，MVP 不提供网页界面。

统一存储位于 `-storage-dir` 指定的根目录：`videos/<资源指纹>.mp4` 是唯一正式视频，`tmp` 保存下载临时文件，`stepstash.sqlite` 保存歌曲、版本和请求统计。不读取旧格式，不提供迁移。详见[统一存储](storage.md)。

## 游戏接入

1. 先停止占用本机 80 端口的原版服务，再以 `-listen 127.0.0.1:80` 启动 StepStash；需要时在有相应权限的终端运行。
2. 备份 hosts，将 `play.udon.dance`、`nya.xin.moe` 映射到 `127.0.0.1`，接管 HTTP 视频请求。若还需接管 HTTP 播放 API，可额外映射 `api.udon.dance`。
3. 选择 CF 或 HKG。CLI 将播放 API 的查询参数传给 HTTPS 上游；未指定 node 时由上游决定视频地址。测试后恢复 hosts 并停止服务。

本页 `stepstash.exe` 命令行入口支持 HTTP 视频请求及 `api.udon.dance/Api/Songs/play?id=…` 的 GET/HEAD，接受省略 node、`node=cf` 或 `node=nya`。它通过 HTTPS 获取上游视频地址，按资源指纹命中缓存或边下边播，直接以 HTTP 返回视频，支持单段 Range。游戏入口须使用 HTTP，播放器须接受 API 地址直接返回视频；游戏内兼容性仍待实测。其他 API 路径的 GET/HEAD 返回 307，指向原站 HTTPS。

CLI 不监听 443，也不支持 `/v/` 或 SHA。hosts 同时影响 HTTP/HTTPS，因此映射后的域名若被客户端通过 HTTPS 访问（包括上述 307），CLI 单独运行无法承接该连接。需要同时兼容网页 HTTPS 播放时，使用 `stepstash-console.exe`：其 CDN 同时启动 HTTP 缓存和 HTTPS 透传，详见[本地控制台](console.md#网页-https-播放)。透传不使用本地缓存。更详细的原版接入记录见[复现手册](testing-runbook.md)，其中原版命令不能直接当作 StepStash 命令使用。

## 缓存和下载规则

- 接收两个视频 Host（允许附带端口）的 GET/HEAD；路径限定为 `/files/<数字目录>/<正整数ID>-<字母数字版本>.mp4`。e 必须为 MD5，s 为正数且不超过上限。重复 e/s、错误转义、其他 Host 和路径返回 400，其他方法返回 405。
- 按 URL 资源编号、文件名版本、MD5、长度的 SHA256 定位 `videos/<资源指纹>.mp4`；域名和目录不参与键。同一版本可跨 CF/HKG 复用。每个版本只有一份正式视频，不同版本相互独立。多首曲目可以引用同一资源；显式曲目预取更新引用须经歌曲 API 确认，旧资源仍被其他曲目引用或正在使用时保留。纯视频 URL 不推断曲目关系。
- 本地文件首次使用时校验完整大小和 MD5；同版本在活动引用期间共享校验任务、成功结果及打开的文件句柄，响应不再重复整文件校验。各响应使用独立读取位置，保留句柄避免路径被替换后读到另一文件。最后一个工作任务或请求释放引用时关闭句柄并清除验证结果，下次使用重新校验。可选的容量上限与优先级淘汰见[缓存保留策略](cache-retention.md)。歌曲和版本信息存数据库，读取不依赖每首歌的 JSON 文件。
- 未命中时共享一次整文件回源；各客户端独立读取逐渐增长的下载文件，按其 Range 返回已到达的区间，尚未到达的区间等待上游。保持原视频 Host，连接独立回源地址，通过内置 DoH 解析并建立 HTTPS 连接，保留原域名的 TLS SNI 和证书校验，不使用系统代理环境变量，不回退系统 DNS/hosts 或明文 HTTP。默认 CF 为 `ud-play.kiva.moe:443`，HKG 为 `ud-nya.kiva.moe:443`。
- 视频回源最多跟随五次重定向，仅接受受支持视频域名、合法视频路径且 MD5/大小与原资源一致的目标。HTTP Location 升级为 HTTPS 后访问，每次连接继续使用内置 DoH；不接受任意域名跳转。播放 API 的重定向作为视频地址解析，再进入同一缓存链路。
- 下载到 `tmp/download-*.part`，严格检查长度、MD5，再复制到发布临时文件，同步关闭后重命名到 `videos`。下载句柄保留至最后一个读取者结束，适应 Windows 文件占用限制；随后临时文件删除。上游错误、截断、超长、非预期压缩和校验失败不发布正式视频。MD5 仅用于协议完整性检查。
- 同键并发共享后台任务，回源节点取首次请求；尚在下载时切 CDN 仍复用这一任务，不会自动换源。客户端取消后任务继续，受全局超时和下载数量限制；不同歌曲超过容量返回 503，可稍后重试。
- 整个存储根目录由操作系统文件锁独占。正常退出或进程死亡释放锁，重启清理 `tmp/download-*.part`。`.lock` 文件保留正常，不应在运行时删除。

视频文件与数据库不构成跨资源原子事务。先发布已校验文件，再提交歌曲及版本记录；若崩溃发生在两者之间，下次命中时补齐记录。数据库是必需组件，打开失败则引擎启动失败，不覆盖原数据库。不同版本使用不同路径，不会替换正在播放的旧版本。

**冷缓存边下边播，只有校验通过的完整内容才发布到缓存。** 已发送的前段数据尚未完成整文件校验；完整 GET 的最后一个字节会等到校验和发布成功后才发送。若失败，服务中断仍在等待的响应，不让它以完整成功的文件结束；已完成的局部 Range 不能撤回。首次流式响应没有 Last-Modified，ETag 仍按请求 MD5 设置。HEAD 不等待整文件完成。

当前没有断点回源，真正断电后的磁盘持久性也未作承诺。默认清理被取代的旧版本；配置容量上限后再按优先级淘汰当前视频。下载及发布期间可能同时存在多份视频数据，应预留磁盘空间，停服后可以清理临时文件；数据库应随视频一并备份。

## HTTP 和诊断

### 资源请求统计

自动维护 SQLite `resource_usage` 汇总表与 `request_events` 请求明细表，用于计算缓存保留优先级；设置有限容量上限后自动淘汰低优先级视频，默认不限。详见[缓存保留策略](cache-retention.md)。控制台与命令行都使用存储根目录中的 `stepstash.sqlite`，同一数据库同时保存 `songs` 和 `video_versions`。清理 `tmp` 或淘汰视频不会删除资料和统计。

每个资源一行，按资源指纹跨 CDN 汇总；纯视频 URL 无法判断实际曲目，播放 API 则提供显式歌曲 ID：

| 字段 | 含义 |
| --- | --- |
| `resource_key` | 资源指纹（文本） |
| `get_count` | 进入缓存处理的 GET 请求数，包括下载失败和重试 |
| `demand_count` | 去重后的需求次数，同一资源距离上一次计数达到 30 秒才再次计数 |
| `first_requested_at` | 首次请求时间 |
| `last_requested_at` | 最近一次 GET 时间，重复请求也更新 |
| `last_demand_at` | 最近一次去重计数时间 |

时间统一为 UTC Unix 毫秒。HEAD、预缓存、手动批量下载和提前拒绝的多区间请求只留明细，不增加汇总热度；非法 URL 和不支持的方法不进入资源统计。单区间请求在缓存处理后才验证 Range，其错误也可能计入 GET。数据表示本机代理观察到的请求需求，不能作为真实播放次数；30 秒只是简单去重规则，长播放中的后续 Range 仍可能再次计数。去重不删除明细，后续可以重新定义统计窗口。

`request_events` 每次请求一行，包含资源指纹、请求开始时间、内容版本键、CDN 主机、来源（`http` / `prefetch`，队列与批量预取均属后者）、方法、原始 Range、缓存结果（`HIT` / `MISS` / `UNKNOWN`）、结果（`completed` / `failed` / `canceled` / `aborted`）、文件大小、响应传输字节数、耗时毫秒、HTTP 状态码和是否参与需求汇总。HTTP 状态可能为 0（尚未发送响应），取消/中断也可能已有 200/206，需结合结果字段判断。预取不是 HTTP 响应，其状态和响应传输字节数为 0；这不是上游实际下载流量，不能直接当作节省下载量。共享下载的预取取消后，后台下载仍可能继续。

需求汇总在有效 GET 进入缓存处理时入队，取统计时间和入队使用同一把锁，后台按进入顺序更新；明细使用该时间，在请求结束时另行入队，保留最终状态、字节数和耗时，不再次更新汇总。长短请求反序完成不影响去重次数。明细可用于计算近期频率、请求间隔和预取后的实际访问；已建立资源/时间及时间索引。不记录用户身份或完整 URL，不自动清理明细。

后台队列最多 1024 条，每批最多 128 条以事务落盘；进入和完成事件可能位于不同事务，不能保证一条明细与对应汇总同时提交。CLI 停服先等待 HTTP 优雅关闭最多 5 秒，超时强制断开连接，再等待活动请求结束、取消剩余下载并排空统计队列；5 秒是连接关闭宽限，不是全部落盘耗时的上限。统计队列满或统计写入失败会记录 `usage_dropped` 或 `usage_write_failed`；数据库打开失败则启动失败，歌曲或版本记录提交失败则本次缓存任务失败。异常退出可能留下已有汇总但尚无完成明细的请求；队列溢出或写入失败也可能使两者不一致。数据库失败不自动覆盖旧文件，不迁移旧数据库。

停服后可用 SQLite 工具查询，例如按最近请求查看：

```sql
SELECT resource_key, demand_count, last_requested_at
FROM resource_usage ORDER BY last_requested_at DESC;
```

### 响应和日志

热缓存以及下载完成后的响应支持完整 200、单段 Range 206、后缀 Range 和条件请求；使用 Go `http.ServeContent`，ETag 为带引号的 MD5。无效或越界 Range 返回 416，多区间请求明确返回 416。HEAD 忽略 Range。完整 200 不添加原版非标准的 Content-Range。

`X-StepStash-Cache` 表示 HIT 或 MISS；共享同一次冷下载的请求都会返回 MISS。`X-Request-ID` 可与 JSON 日志关联。日志记录请求状态、发送字节数、Range、缓存来源、下载键和失败原因，不记录完整查询参数。

尚未开始响应时，上游/完整性/发布失败返回 502，后台验证或下载超时返回 504，容量不足/正在关闭/文件变化返回 503，本地响应文件无法打开返回 500。流式响应已经开始后，无法更改状态码，失败会中断连接并记录 `stream_failed`。其他故障见 `cache_failed`、`cache_invalid`、`open_failed`；客户端取消记录 `client_disconnected`。错误响应不会把内部错误详情暴露给播放器。

| 参数 | 默认值 |
| --- | --- |
| `-listen` | `127.0.0.1:18080` |
| `-storage-dir` | `stepstash-data` |
| `-cf-origin` | `ud-play.kiva.moe:443` |
| `-hkg-origin` | `ud-nya.kiva.moe:443` |
| `-download-timeout` | `10m`，限制共享工作任务（含其中的缓存校验、下载和发布）；不限制额度用尽时的独立本地校验路径 |
| `-max-file-bytes` | `2147483648`（2 GiB） |
| `-max-cache-bytes` | `0`，缓存容量不限；单位为字节 |
| `-max-downloads` | `3`，限制共享工作任务（包括正在校验的不同文件）；各缓存获取入口的本地文件校验统一受同样大小的 `localChecks` 池限制 |

回源参数是 HTTPS 服务的 TCP `host:port`，不是 URL；修改端口不会切换成 HTTP。自定义地址仍通过内置 DoH 解析，并验证对应视频原域名的证书，不受系统 hosts 影响。不要将回源地址配置到本服务。默认仅用于本机；无鉴权，不建议监听公网地址。配置受信任，外部请求不能任意指定回源目标。

## 验证范围

`go test ./internal/... ./cmd/...` 使用独立临时目录、随机端口和可控上游，覆盖：CF/HKG 冷缓存、跨 Host 命中、Range/HEAD/条件请求、非法输入、错误上游/跳转/截断/超长/校验失败、同曲并发、调用方取消、版本隔离、同长度损坏、单份正式视频、数据库资料保留、下载失败保留旧版本、活动读取期间的版本隔离、缓存独占、容量和超时、关闭及重启清理。

CI 配置 Windows/Linux 的测试、vet、构建，以及 Linux race 检测。本地 Windows 未配置 C 工具链时不能运行 `go test -race`。CI 尚未在远程执行。

旧存储版本的历史验证（不代表当前重构的实机验证）：`go test ./internal/... ./cmd/...`、`go vet ./internal/... ./cmd/...`、Windows 构建通过，核心包语句覆盖率 82.6%；Linux 服务和测试程序交叉编译通过（未在 Linux 本机执行）。真实 CDN、原版回读和 VRChat 样本见验收记录。测试进程已退出，临时 hosts 修改已恢复，原版歌曲库样本前后哈希不变。

初版在真实游戏中因完整下载等待触发 20 秒客户端超时和自动重试，已据此加入共享渐进读取及断流回归测试。最新实机结果以[验收记录](acceptance.md)为准。

### 后台下载并发

控制台的「下载补齐」和房间队列预缓存均支持最多同时处理 2 首；仅扫描检查支持分别配置地址请求并发（默认 4，范围 1～16）和本地校验并发（默认 1，范围 1～4），扫描地址请求统一按 150ms 节拍启动。两种下载模式保留现有互斥切换方式，后台额度由下载引擎统一管理，切换或取消不会提前释放仍在运行的下载名额。同一视频的并发请求继续共享下载。

默认共享工作任务并发为 3，后台最多占用 2 个，为游戏播放保留 1 个名额；若配置为 2，后台最多占用 1 个；配置为 1 时允许单个后台任务，但无法预留播放名额。名额预留不等于带宽预留，目前没有后台限速。

下载名额或后台额度用尽时，已有本地文件仍可校验并直接返回 HIT，适用于播放和预缓存，不占下载名额。此路径、共享工作任务和 HTTP 响应阶段的本地文件校验统一使用 `localChecks` 池，并发上限为 `-max-downloads`；同版本的活动引用共享校验，复用成功结果不重复占用校验额度。额度用尽时的本地命中路径受调用方上下文及服务关闭取消控制，不使用 `-download-timeout`（`DownloadTimeout`），也没有额外固定超时。该池与控制台「仅扫描检查」的本地校验并发设置互不关联。

缺失或校验未通过的文件仍需下载名额：额度用尽时，播放返回 503，预缓存等待空位；等待可由调用方取消或服务关闭终止。`-download-timeout` 从共享工作任务启动时计时，不包含此前等待名额的时间，也不限制 HTTP 响应传输的耗时。响应阶段复用活动引用保留的验证句柄；若尚无验证句柄（例如下载刚完成），则通过同一 `localChecks` 池校验本地文件，该校验受请求上下文及服务关闭取消控制。
