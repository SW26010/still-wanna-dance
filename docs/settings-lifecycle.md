# 配置与运行生命周期

本页描述当前实现。配置、核心数据库与辅助状态的目标职责见[持久化数据职责与边界](persistence-design.md)，实施顺序见[迁移计划](persistence-migration-plan.md)；核心、CLI 与桌面已接通独立数据库和完整视频位置，桌面应用持有数据库。

配置模块在 `internal/console/settings.go` 统一字段定义、默认值、字段校验、路径转换与设置请求解码；`config_file.go` 统一文件加载及更新，内部处理格式版本、未知字段和受保护凭据，复用现有凭据保护与 `workfiles.Write`。普通设置和 VRCX 忽略选择共用文件更新入口；加载只返回规范化结果，不准备数据库、视频目录或网络，也不改写文件。启动日志仍通过轻量入口读取 `logLevel`，复用相同格式检查，不提前执行完整初始化。

WebUI 草稿从后端完整的已保存快照初始化，只转换输入文本与显示单位，不另行补配置默认值；字段范围提示和交互校验仍由表单负责，后端保留最终校验。

`settings_save.go` 保留应用保存流程：在 `lifecycleMu` 下合并最近保存的主题、凭据和节点草稿，检查及准备变更的资源位置与所需权限，写入成功后才更新内存快照。主题和 VRCX 选择同样经过该生命周期锁；原子替换不代替整个读改写过程的串行。业务继续接收当前生效参数。文件缺失字段采用启动默认值，设置请求则保留原有缺省语义：仅指定的可选字段补默认，主题和密码省略时保留已保存值，必需模式字段缺失仍报错；两种入口不共用整份默认请求。此职责整理保持配置 v8 与现有保存、重启行为。

当前配置版本为 8，统一使用 `vrchatLogDir`、`videoBudgetBytes`、`aggressiveBlockReclamation`、`downloadConcurrencySoftLimit` 和 `restoreHostsOnStopOrExit`。此次发布前整理不迁移旧配置、不读取旧名称别名；旧版本拒绝打开且保留原文件。当前 v8 配置中已停用的 `upstreamMode=auto` 是一个明确例外：读取时转换为 `proxy`，启动校验通过后仅原子写回该字段，保留代理凭据、节点及其他字段，不增加格式版本。设置请求只接受 direct/proxy。迁移当次运行首次进入首页时弹出简短通知，同一浏览器标签刷新不重复；迁移已落盘，后续启动不再通知。写回失败则启动报错，不宣称迁移成功。数据库及其他状态格式不因字段调整改变，版本边界见[存储契约](storage.md#持久化格式与语义)。

`vrchatLogDir` 表示用户指定的 VRChat 日志输入目录，缺失、null、空串或仅空白表示自动识别；非空路径相对配置文件解析，实例内路径落盘为相对路径。`settings` / `activeSettings` 在自动模式下始终保留空串，读取日志时才解析当前用户的默认目录；`defaultLogDir` 仅向界面提供默认路径展示，不回写配置。指定和恢复默认均保存后重启生效，不再单独保存手动模式布尔值。

配置可以在服务或任务运行时保存。保存校验、写入配置文件并更新已保存快照；除下述主题与停止／退出策略外，当前 Console 的配置、网络连接、共享本地资源引擎、监测策略、扫描与任务保持不变。

「主题」自动保存后立即生效，「停止加速或退出时恢复游戏直连」保存即用于停止加速和本次退出；其余运行设置在应用重新启动后生效，包括没有任务运行时保存的设置。单独停止、启动播放网关或任务不会应用待生效配置。

「程序日志级别」（`logLevel`）默认 `info`，支持 `off/error/warn/info/debug`，缺失、null 或空串采用默认值，未知值拒绝。保存后重启整个程序生效，参与 `settings` / `activeSettings` / `restartRequired`；关闭不删除已有日志，也不影响游戏日志输入、请求历史或运行统计。初始化先复用配置格式校验读取该字段，以覆盖 Console 构造期日志；完整设置继续走原加载流程。行为与字段口径见[日志](logging.md)。

播放地址入口固定为 CF，已移除 `downloadUpstream` 设置。旧配置中的该字段不生效，再次保存时移除；其他未知字段仍按原规则保留，不增加配置版本或迁移流程。

歌曲屏蔽与收藏属于本地曲库偏好，不属于本页的启动配置。其保存后对后续决策的生效边界见[歌曲偏好设计](download-resource-design.md#8-歌曲屏蔽与收藏)；不纳入 `activeSettings` / `restartRequired`，也不因标记变更启动下载任务。

「忽略 VRCX 导入建议」是当前配置实例的界面选择，主配置以 `vrcxImportDismissed` 保存；不进入可编辑的 `settings` / `activeSettings`，不应用待重启设置，普通设置保存保留该字段。默认与完整生命周期统一见[历史初始化契约](song-catalog-design.md#vrcx-历史初始化)。

「激进的缓存回收策略」保存为显式枚举 aggressiveBlockReclamation=auto/on/off，初始为 auto。自动只在视频保留选项为「不保留」时开启，「限制为」及「不限制」时关闭；使用有效预算判断，不受界面记住的预算输入值或当前剩余额度影响。手动开启/关闭不随预算变化，选回自动后恢复跟随。该选项仅在设置的存储标签编辑；状态快照保留策略本身，实际行为由当前运行配置计算。仅切换策略也参与待重启，配置格式为 8，不迁移旧格式。

「高级下载设置」中的下载并发软上限与增长间隔也遵循此规则。配置字段 `downloadConcurrencySoftLimit` 与 `downloadGrowIntervalMS` 缺失或 null 时分别使用 16 和 250，明确保存的 0 ms 表示关闭缓增；范围与执行语义见[下载并发](download-concurrency.md)。

「优先保留收藏视频」（`retainFavorites`）默认开启，保存后重启应用生效；关闭时收藏只做标记，按普通预算取舍。切换选项不启动下载、补齐或恢复文件。规则见[歌曲屏蔽与收藏](download-resource-design.md#8-歌曲屏蔽与收藏)。

「是否保留历史请求明细」使用显式三选项，默认永久保留，保存后重启应用生效；不保留会停止新增并清理已有明细，累计统计不受影响。限定天数、CLI 及配置规则统一见[请求明细保留期](cache-retention.md#请求明细保留期)。

「本地存储」中的本地延续保护时长也在应用重新启动后生效。`localProtectionGraceSeconds` 缺失或 null 时默认 300，接受 0～10000 的整数；显式 0 表示不延续保护。保护资格、起算点和回收边界见[本地保护](download-resource-design.md#本地保护)。

状态接口中的 `settings` 是已保存配置，`activeSettings` 是当前运行配置，`restartRequired` 是两者规范化后的差异。两份配置均不返回代理密码；密码差异仍参与待重启判断。保存请求省略密码时保留最近保存的密码，显式空串清除密码。

设置表单展示已保存配置；运行信息、本地视频列表与监测展示当前配置。保存失败不会更新已保存快照；把配置改回当前值会清除待重启提示。

默认由播放网关带动队列预加载：`queueWithGateway` 为 true 时，启动网关会开启队列；停止、运行故障及加速失败撤销网关时，等待队列停止并撤销队列来源需求。为 false 时，网关不启动队列。队列启停仅由网关生命周期管理。共享引擎由 Console 持有，懒创建后保留到应用退出。队列的 `desired` 表示实际启用意图，`running` 表示读取任务是否运行；日志读取失败单独报告，不改变 hosts 与网关共同决定的加速结果。手动下载不暂停或恢复队列。

引擎记录的首个本地存储故障通过状态接口 `storageError` 展示；无故障时省略该字段。WebUI 公共错误栏持续显示原因、停止新下载的影响及修复后退出并重新打开应用的步骤，本地视频能否读取取决于故障位置，不把数据库或视频盘不可用描述为仍可正常读取。修复目录、成功读取本地视频、启停播放网关或队列都不会清除此错误；新应用实例创建新引擎后重新判断。此字段直接读取应用打开数据库的结果、业务存储错误及已有引擎错误；没有视频引擎时仍显示数据库故障，不额外持久化，也不改变表示配置差异的 `restartRequired`。

首页与托盘的「开始加速」共用同一完整流程：检查及配置 hosts 接入、启动网关、复核就绪后开始游戏请求检测；失败撤销本次变更，保留原有接入及已运行网关。已有正确 SWD 映射时，缺少退出恢复权限不阻止加速、不申请 UAC，恢复权限由游戏连接状态中的「修复」单独准备，具体见 [hosts 契约](console.md#hosts)。缺少映射仍按原流程授权写入，冲突仍拒绝覆盖。首页和托盘运行时显示「停止加速」，停止后显示「开始加速」。停止共用 `/api/activation/disable` 对应的生命周期流程：HTTP 播放和 HTTPS 透传均停止，队列随网关停止；恢复直连选项开启时复用已有助手移除本程序托管映射，关闭时保留接入。停止不创建助手、不请求 UAC，助手继续驻留供下次开始加速复用；恢复失败仍停止网关与队列，并明确报告原因和实际接入状态。共享引擎及独立手动下载保持运行。外部控制提供开始／停止加速、恢复权限准备、退出与重启入口，不另开 hosts 写入／恢复或队列控制接口。

加速状态的 `activation.error` 保留完整操作错误，`activation.connectionError` 单独报告接入检查、授权、复核、回滚及停止时恢复直连的错误；不存在时省略，不持久化。新一次启停操作开始时清除旧接入错误，失败后保存本次原因，成功后保持为空。主动修复取得恢复权限后，仅清除此前停止时因缺少该权限产生的接入错误，依据内部错误来源判断；保留检测窗口、历史操作错误及其他故障，取消或失败不清除。视频服务继续由 `cdnError` 和当前端口检查报告，队列继续由 `actionErrors.queue`、`queue.logError/error` 报告故障。目录可读取且监控已启动即视为正常，`queue.file` 仅用于说明当前日志或等待日志出现；空目录、旧日志及日志暂未更新不构成读取错误，过期队列仍按[日志队列规则](queue-prefetch.md#日志检测与频率)撤销。端口启动与接入回滚同时失败时，各自状态保留自己的原因，完整操作错误仍包含两者；前端不解析错误文案猜测归属，也不把历史请求失败视为当前组件故障。

状态接口的端口可用性与网关运行状态取自同一次快照。端口空闲或已由当前网关持有时视为可用；引擎仍在初始化时保持「启动中」，不把自身监听报告为冲突，也不提前报告「运行中」。绑定、释放与端口探测共用状态锁，引擎初始化与连接排空仍在锁外；其他监听者即使属于同一进程也照常报告冲突。启动失败和停止时释放监听并清除归属。

常规设置提供「启动程序时自动开启视频加速」（`autoAccelerate`，默认 false）；预加载与下载设置提供「随视频网关启用队列预加载」（`queueWithGateway`，默认 true）。保存后重启生效，不是即时操作开关。自动加速每进程执行一次，与首页和托盘手动加速共用接入、网关和回滚流程，可能请求 UAC。刷新网页、激活已有实例或重复调用启动入口不会重试。

自动加速只依赖有效条款记录与已保存的 `autoAccelerate`。程序启动时已有有效记录则执行一次；尚未同意则保留本进程的待启动意图，明确同意并成功保存后再消费。关闭自动加速时不启动；重复确认、刷新网页或再次调用启动入口不重复执行。自动加速失败不自动重试，用户处理原因后可手动一键加速。旧引导进度、回执及待续接导入不再参与启动。

配置版本 8 使用上述字段，缺失或 null 时 `autoAccelerate` 默认 false、`queueWithGateway` 默认 true，明确保存的布尔值保留；不读取或迁移旧自动启动字段。版本 7 及更旧配置拒绝打开并保留原文件。

待应用配置会显示「立即重启并应用」。有尚未保存的表单更改时按钮禁用。重启请求使用现有 Host、Origin 和会话令牌校验；先返回响应，再由程序入口停止服务与任务。`run()` 返回并完成全部延迟清理（包括配置锁、桌面单实例锁及日志文件）后，`main()` 才启动替代进程。

重启保留绝对配置路径、实际网页服务端口及托盘模式，避免重复打开浏览器。页面等待新实例的会话令牌出现后刷新；响应丢失不会重复发送重启请求。60 秒内未确认新实例时显示手动恢复提示。批量任务不自动续跑；按已保存的自动加速和队列随动配置启动，仍受使用条款限制。退出和重启同时到达时，首次被接受的操作决定结果。

托盘退出、WebUI 退出／重启、已确认的 Windows 会话结束及条款页超时共用同一退出决定；后到的请求回执返回实际生效的 `action`，不会将已接受的退出改为重启。`/api/lifecycle` 是只读 WebSocket，每个 WebUI 文档一条连接，先发送当前状态，决定退出／重启后推送 `action: exit/restart`；`running` 仅表示尚无退出决定，不作为后台健康检查。订阅不依赖当前页面、可见性或条款接受，不启动业务任务；校验 Host、同源 Origin 和 Fetch Metadata，不在 URL 携带会话令牌，也不接收业务指令。

通知表达“退出／重启已被接受”，不证明清理成功。收到通知与收到操作回执共用一个前端处理入口，停止业务刷新和事件订阅，迟到结果不覆盖已接受的决定；重启等待只启动一次，确认框等待期间收到退出决定后不再提交旧操作。通知连接意外断开不改变后台健康判定，下一次成功读取状态时尝试恢复订阅；离开文档释放连接，页面恢复时重新连接。未收到通知时继续按状态请求的实际结果显示读取／更新失败，不能据此认定程序崩溃或正常退出。WebSocket 不占用现有 SSE 的普通 HTTP 长连接槽位；复用锁定的 `coder/websocket`，不引入通用消息总线或持久队列。升级连接由应用显式收尾，通知写入有期限，写完直接关闭连接，不等待网页回应关闭帧；最终清理仍有宽限，慢网页不阻塞退出。订阅在握手成功响应发出前登记，关停开始后拒绝新的升级；已获准但握手尚未返回的订阅也纳入通知与清理，宽限耗尽后取消。未经过已接受退出请求的清理只关闭连接，不补造正常退出通知。

数据库文件（databasePath）与完整视频目录（videoDir）独立配置。首次打开时，应用自动准备实例下的 data/database/storage.sqlite 与 videos，并将相对路径写入配置，立即供曲库、收藏、历史、后台资料同步及下载等入口共用；无需进入设置、手动建库或重启。两项仍为空的未配置实例同样适用；其他已有设置保留。数据库初始化不启动视频引擎、请求采集或网络访问，其他辅助文件仍按功能需要生成。

自动准备只适用于未指定两个位置、且默认位置没有数据库及其伴随文件或完整视频的实例。已经配置的数据库丢失、为空、损坏或版本不支持时只报告故障，绝不改建空库；未配置实例发现已有默认资料时保留原状，由用户选择数据库及视频保留策略。不探测历史布局或旧安装标记，不解析迁移旧配置，不扫描任意外置资源；未知文件原样保留。自定义位置继续保存后重启生效：设置中的新建操作只创建数据库，不保存或启用配置，也不创建视频目录；打开已有文件不补表。新选择的数据库先只读验证 v8，新选择的视频目录在保存时可以创建；未变化的位置不做可写性探测，失联视频盘不会阻止无关设置保存或被重新建为空目录。

程序目录内仅允许当前实例的默认数据库和视频位置，自定义位置应在程序目录外；选择已有资料与新建共用路径规则。现有数据库继续验证 v8，视频目录继续验证类型与可用性。

WebUI 所有本地路径共用 Windows 原生选择器。点击只读路径框直接选择，旁边仅有“恢复默认”；系统窗口内可导航、输入路径或创建目录。SWD 数据库通过同一个文件对话框选择已有文件或新文件名，确认按钮为“选择”，不提供覆盖提示；选定后 `/api/storage/prepare-database` 只读验证现存数据库，仅对不存在的新文件调用已有建库机制，损坏、版本不符或不可读文件保持原状并报错。已保存或当前生效的数据库文件丢失时，选择原路径仍报错，必须恢复原文件或另选新文件名。数据库选择不保存或启用配置，也不创建视频目录。VRCX 使用文件打开对话框，完整视频、视频导入和 VRChat 日志使用目录对话框；视频导入和 VRCX 读取均需另行触发。

恢复默认只更新本处草稿，不启动选择器、建库、搬迁或导入。数据库和视频回到实例默认位置，仍需保存／重启；日志恢复自动识别（`vrchatLogDir=""`），选择目录则将路径保存为 `vrchatLogDir`。VRCX 清除自选路径并释放旧预览，重新使用检测得到的默认路径；视频导入清空来源。统一选择接口 `/api/path/select` 校验会话、来源和条款，整个程序同时只允许一个选择窗口。前端使用可取消等待，后端保留 5 分钟上限，避免普通 API 的 15 秒超时中断查找；关闭选择器保留草稿，关闭页面或退出程序取消对应请求和窗口。原生窗口继承所属窗口的 SWD 图标，复用内嵌 ICO，经标准输入传给助手，不落临时图标文件。

变更数据库或视频位置且目标已有完整视频时，保存前必须确认当前保留策略和所选数据库中的收藏依据。复用失联视频位置但切换数据库时也需确认，以防磁盘恢复后直接按默认零预算管理。确认仅属于本次保存请求，不形成永久配置字段；保存与新建均不启动引擎或淘汰旧视频。「不保留视频」不禁用位置编辑。两个位置均在重启后生效，不自动搬文件。

存储、网络等运行配置统一在设置页校验保存，并由现有重启流程应用。视频和 VRCX 导入独立在曲库执行，使用当前生效目录。视频导入恢复固定清单和已保存回执，未完成任务重启后等待手动继续；不自动导入或删除源文件，规则见[视频导入与恢复](video-import.md)。VRCX 导入不跨重启恢复。

「停止加速或退出时恢复游戏直连」（`restoreHostsOnStopOrExit`）默认开启，缺失或 null 采用默认值，明确关闭则保留。它是保存即生效的停止／退出行为配置：草稿不改变策略；由关闭改为开启时，保存先准备当前托管接入的恢复权限（复用助手，缺少时才请求 UAC），再原子写入全部配置。网页在开启此选项的保存请求中沿用授权操作的 120 秒等待期限，并提示可能出现的管理员授权；超时只提示结果未确认，保留草稿供核对，不自动重试。权限准备或写入失败保留旧配置和旧退出策略；权限准备不修改 hosts。保存成功后同时更新 saved/active 中的退出选项，单独更改它不要求重启；同次提交的其他运行配置仍待重启。退出请求携带已提交策略交由已有助手执行，不在退出时申请 UAC。默认恢复后，重启按自动加速设置重新接入；关闭自动加速时可手动一键开启。权限助手和失败边界统一见[hosts 契约](console.md#hosts)。

常规设置中的「启动程序时自动打开 WebUI」（`autoOpenWebUI`）默认 true，在新进程启动桌面托盘时决定是否自动打开浏览器；保存不即时开关页面。尚未同意当前条款或同意记录失效时，即使该设置为 false，也自动打开条款确认弹窗，避免程序等待确认却没有可见入口；不改写已保存的偏好，确认有效后恢复按设置决定。显式 `-no-open` 优先，网页发起的重启继续传入该参数，防止重复打开页面。托盘主动打开和再次启动已有实例属于显式激活，仍可打开 WebUI。

「主题」（`theme`）是程序级配置，接受 system/light/dark，缺失、null 或空值默认 system。选择后通过 `/api/settings/theme` 单独自动保存，沿用配置原子写入与生命周期锁；成功后同时更新 saved/active，立即应用网页、Logo、标签页图标和托盘，无需点击保存或重启。失败保留原配置与外观并报告错误。不提交其他设置草稿，不应用或清除已有待重启配置；普通设置表单不携带主题，省略时保留最新保存值。条款弹窗沿用已保存主题，旧浏览器 localStorage 不再作为依据或自动迁移，避免不同浏览器覆盖程序配置。


页面初始主题由 bootstrap 提供，已打开页面通过现有状态轮询同步其他入口的更改，每次新快照均校准本地外观，避免交错保存的延迟响应使页面停留在旧主题；托盘复用一秒状态刷新。选择浅色／深色时所有入口使用同一显式偏好；选择跟随系统时网页遵循浏览器的 `prefers-color-scheme`，托盘遵循 Windows 的 `SystemUsesLightTheme`，两者可因系统应用／任务栏模式不同而配色不同。系统主题通知与 Explorer 托盘重建均保留显式选择。
