# 数据库 v9 开发验证（2026-11-01）

本轮以已发布的 v8 `9cc27069` 为对照，实施 v9 数据库、媒体地址、清单、请求统计和界面适配。现行规则以[存储契约](../storage.md)、[歌曲与媒体设计](../song-catalog-design.md)和[下载设计](../download-resource-design.md)为准；本文记录实际证据和限制，不另设规则。

检查环境为 Windows amd64、Go 1.27.3、Node.js 24.22.1、pnpm 11.25.0 和 Microsoft Edge。数据库、配置和视频使用隔离夹具或新建测试目录，没有操作用户真实库、启动 VRChat 或修改系统 hosts。

## 业务和迁移覆盖

| 范围 | 已验证行为 |
| --- | --- |
| v8 升级 | [迁移测试](../../internal/cacheproxy/storage_migration_test.go)比对保留的歌曲资料、偏好、需求、成员、资源访问和请求事件；保留事件 ID，旧的零大小转为 NULL，清单键转为 `songs_list`。共享资源、不同节点、重复地址、确定性选择和旧失败地址均有覆盖。 |
| 失败保护 | 通过测试专用 SQLite 驱动在真实迁移的各阶段注入故障，核对事务回滚、v8 数据及版本、外键恢复和修复后重试。旧表及保留表的 CHECK 和外键异常在删除旧表前拒绝；非法 URL 错误不泄露地址。[打开边界测试](../../internal/cacheproxy/storage_v9_open_test.go)覆盖三个 WAL 恢复阶段，不代表真实断电或磁盘耗尽。 |
| 打开与桌面配置 | 只读选择检查不改 v8 字节，真正可写打开时一次性迁移，重开不再迁移；旧程序拒绝 v9。桌面测试覆盖默认库启动升级、选择另一 v8 后重启升级、空视频目录及既有视频策略确认。其他旧版本、错误身份及未来版本仍拒绝。 |
| 媒体地址 | [地址](../../internal/cacheproxy/media_urls_test.go)与[观察事务](../../internal/cacheproxy/song_url_metadata_test.go)测试覆盖共享资源、节点隔离、提交顺序、映射更新、失败回滚和重启复用。播放、队列、预览与补齐固定已选 MD5；查询得到新版本可更新后续映射，不能切换当前请求。 |
| 补齐与取消 | [固定资源补齐测试](../../internal/cacheproxy/prefetch_resource_test.go)覆盖已有地址的后台更新、已完成查询结果重试、固定资源失败回退，以及与预览共享新查询的两种启动顺序。独占查询随任务取消；被其他调用复用时，取消只结束批量等待。 |
| 候选与故障 | 全量补齐只使用本轮选中的当前清单歌曲，不被 20 个非成员旧关联拖住；九个有效共享候选、明确选择的历史目标、屏蔽歌曲仅作地址线索及预览八首上限均有回归。地址入库失败立即返回存储故障，不继续查询别名或误报上游错误；已完成存储故障不被并发取消掩盖。 |
| 清单反馈 | 全部来源失败时保留已接受的本地清单并显示当前错误；任一来源成功同步后静默完成并清除当前同步错误。本地存储故障不能被其他来源成功掩盖；独立的本地扫描故障不会被后台同步成功清除。取消或未取得响应不冒充成功。 |
| 新库与统计 | 新库建表、内置资料和版本在同一事务提交，已有库不重新预置。受控 CLI 新库含 10,446 个资源、10,471 首占位歌曲和映射，清单水位、成员、地址及请求表为空，外键检查通过。响应来源按保留请求明细汇总，清理后贡献同步减少；首正文分位数仍按最近 72 小时的保留样本计算。 |
| 冻结样本 | v2～v8 DDL 和样本未改写；v9 样本用合成数据填充 10 张表。原 v8 二进制夹具中的 URL 缺少 `e/s`，用于验证拒绝且原文件不变；成功迁移仅修改隔离副本的 URL。 |

另编译已发布 v8 代码的隔离打开入口：迁移前可打开 v8 副本，迁移后旧入口拒绝 v9，主文件哈希不变。10 万条合成请求记录样本的三次完整迁移约 275～285 ms；100,001 条保留请求的来源汇总单次约 16 ms。这些是本机、指定样本的结果，不外推其他数据规模、磁盘或并发性能。

## 已发现的失败及边界

- 初版迁移测试仅由测试代码执行部分 SQL 并手动回滚，不能证明生产迁移失败处理；后来改为在生产路径逐阶段注入。之后又补充旧库 CHECK 和被删除表外键的异常用例，确认原实现会错误提交，修复后均通过。
- 受控回归曾复现播放/队列重试从资源 A 切到 B、复用已有地址后漏检查更新、映射变化后漏用已完成查询、批量取消后独占查询继续，以及无已有地址时重复查询。现行测试分别覆盖固定身份、重试、共享与取消责任。
- 曾复现已有曲库不显示同步错误、后台恢复后残留旧错误、非法清单音量未拒绝，以及全量补齐受非成员旧歌曲阻塞。清单反馈的早期实现曾展示备用成功时的失败来源；随后确认备用成功静默完成，早期反馈检查只代表当时实现，不作为现行要求。
- 最初的浏览器通知断言同时匹配可见 Toast 与屏幕阅读器节点，限定可见内容后通过；真实历史页夹具首次未触发等块，改为先发送响应头后复测通过。Windows 临时目录搬迁曾报“拒绝访问”，单项连续 10 次及后续整包通过；本次整理的定向测试再次失败。增加关闭错误检查后，当前代码 15 次中通过 14 次，v8 基线 20 次中通过 18 次，Console 与配置锁均未报告关闭错误。原因仍未确认，不把重跑通过当作问题解决。
- 默认全历史制品扫描曾因读取超过 256 MiB 而失败；分批读取后又发现 8 个已发布历史 WebUI 未登记。均已核对引入提交的构建清单并精确登记；本轮保留已发布历史登记和最终产物登记。

原始失败与通过日志、隔离探针、数据库及截图在本地忽略目录 `artifacts/v9-implementation/`、`artifacts/v9-review/`、`artifacts/v9-feedback-review/`、`artifacts/v9-fallback-silent/`、`artifacts/v9-prefetch-refresh/`、`artifacts/review-two-issues/`、`artifacts/review-three-issues/`、`artifacts/review-three-followup/` 和 `artifacts/v9-history-cleanup/`。这些资料未随仓库发布；历史失败日志保留在各目录，不将重跑通过等同于查明偶发原因。
