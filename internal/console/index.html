    请求分组与传输口径
    仅显示已结束并写入数据库的 HTTP 视频请求，不是实时下载任务。歌名为资源关联曲目，不能据此确定实际播放歌曲。 同资源相邻 GET Range 请求记录时间相隔不超过 30 秒时合并；完整请求、HEAD 分开显示。分组仅覆盖已加载窗口，边界可能截断。 时间为请求记录时间，GET 在播放地址解析后记录；传输量为向客户端实际写入的字节（MB = 1,000,000 字节），不是视频大小或回源下载量。 单次耗时包含地址解析、等待和校验。多请求组跨度按最早记录时间至最晚「记录时间 + 单次耗时」估算，包含间隔、不叠加并行耗时；组平均速度为组字节数除以估算跨度。 GET 记录时间与耗时起点不同，因此组跨度及平均速度均为估算值，不代表精确起止时间。 完成表示服务器处理结束，不证明客户端播放完成；200 / 206 本身不证明传输完整。旧记录中的写入失败可能是客户端提前断开。 每次最多查看最近 500 条 HTTP 请求，预缓存不占用窗口，受明细保留天数限制。

    统计口径与计算方式
    仅统计成功完成的 GET 视频请求（200 / 206），每次 Range 请求单独计数；HEAD、失败、中断、预下载不计入命中率。节省流量按命中实际返回字节累计（1 GiB = 1,073,741,824 字节），表示缓存替代的上游流量，非扣除预下载后的净节省。延迟指响应头耗时：上游为实际视频回源请求（含预下载，不含选路探测），本地包含缓存校验。降幅 = 1 − 本地平均延迟 / 上游平均延迟；两组样本未按视频配对，负值表示本地更慢，不代表完整视频加载或起播速度。无样本时显示 —；统计保存到本地数据库，重启后保留。升级时从仍保留的请求明细补入次数和流量，历史响应头耗时无记录，不补算延迟样本。

    覆盖率说明
    覆盖率 = 已缓存清单当前版本的曲目数 ÷ 清单全部曲目数（含隐藏曲目）。共用视频的曲目分别计数，旧版本不计入覆盖。刷新时一次获取清单并检查本地文件存在及大小，不逐首请求、不读取视频正文；完整性由播放或完整校验检查。显示上次成功刷新结果，下载或淘汰后可手动刷新。

        扫描、校验与下载说明
        「仅扫描检查」获取最新曲目列表与同版本校验和清单，匹配本地已知版本后跳过逐首地址查询，并复用未变化文件的校验记录；记录在重启后仍有效。「完整校验」重新读取视频检查完整性，共用视频只读取一次。两者不下载、不删除视频，可与队列预缓存同时运行；地址请求和本地校验并发可在设置中调整。「下载补齐」优先复用最近一次完整扫描的曲目和地址，未变化的已校验文件跳过重复校验；扫描结果仅供下一次补齐使用，重新扫描、保存设置或重启会清除用于补齐的逐首结果，同一存储目录的上次成功统计仍会保留。无可用结果时检查最新曲目，旧地址失败后重新解析，固定 CF 时单独检查 CF。队列运行时会先临时停止预缓存，下载补齐停止、完成或失败后自动恢复；CDN 已关闭时保持停止。两种下载模式均最多同时下载 2 首，共用后台额度，为游戏播放保留 1 个下载名额。下载补齐优先准备高热度歌曲：有本地真实需求时使用本地热度，否则使用内置初始优先级；同分时大 ID 优先。统计卡片显示上次成功任务的结果，当前进度在下方显示；下载补齐在剩余预算不足以容纳下一首完整视频时自动停止，可前往设置调大预算后继续。两项操作均无需启动 CDN 或修改 hosts。
