# 视频导入、暂停与恢复

本文维护视频导入的现行规则。2026-10-30 起替代此前“视频导入进度与回执只存内存”的约定；普通批量下载、VRCX 导入和旧引导状态不因此获得恢复能力。

## 一批任务与固定清单

曲库中的「扫描并导入」先递归枚举来源目录，排除当前视频目录、符号链接和非普通文件，保存完整清单后才逐文件校验与导入。清单保存路径、文件身份、大小和修改时间，不提前读取所有文件内容或计算全部 MD5。

清单一旦保存，本批次不再遍历源目录。后来新增的文件留到下一批；原条目被移动、删除、替换或属性变化时直接跳过并记录原因，不追踪新位置或接纳替代文件。权限和其他 I/O 错误按失败记录，继续时可重试；不能将无法读取误判为文件变化。扫描未完成便中断时尚无完整清单，也没有导入文件，继续时重新枚举。

导入只使用当前本地已知资源，无需在线更新或歌曲映射。同卷优先硬链接，跨卷复制；源文件和暂存内容校验、禁止覆盖已有目标、屏蔽检查及视频保留策略继续沿用现有实现。硬链接共享内容，导入后不得修改源视频。

## 暂停与逐文件恢复

- 运行时可「暂停」；中断当前校验或复制，未完成文件下次从头处理，不保存字节级进度。已进入发布且返回成功的项目先保存回执再停。
- 关闭或刷新 WebUI 不停止后台任务。正常退出保存已完成项，崩溃后使用最后可靠保存的记录。重启只展示状态，未完成导入显示“已暂停，等待继续”，不启动引擎、重新扫描或自动处理文件。
- 「继续导入」只处理清单中待处理及失败的项目。成功和跳过的项目不重做；已导入目标被保留策略淘汰后，也不因继续任务重新补回。
- 每个文件的结果原子保存成功后才处理下一项。保存失败立即停止，保留最后可靠记录，界面明确提示。失败的写入不发布新的清理资格。
- 视频已经发布、成功回执尚未保存便崩溃时，继续处理会将仍存在的目标按已有文件跳过，不补发清理回执。该源文件保留；这是第一版有意接受的恢复范围。

## 源文件清理

只有本批次新发布且已保存成功回执的文件可以清理。原本就存在、未知、屏蔽或变化而跳过的项目没有清理资格。删除前再次验证源文件身份、大小、修改时间、源和目标的完整内容，并在操作期间保护目标引用。目标不存在或校验失败时保留源文件及可重试回执；源文件已经改变时撤去旧回执的清理资格。

回执可跨重启保留，删除确认不可恢复。每次清理都需要勾选和明确确认，也可以暂停。中断后只处理尚有回执的项目；已经不存在的源文件记为“无需清理”，不冒称本程序删除成功。程序启动不会接着删除。

本功能不改变视频保留预算。导入成功并非永久保留承诺，旧回执也不能绕过完整目标校验。

## 存储与任务生命周期

实例的 `data/state/video-import.json` 使用独立 `version=1`，保存一批任务及必要回执，不建立任务历史或核心数据库表。完整清单和逐项结果是进度依据，显示计数从记录汇总。复用配置实例锁与 `workfiles.Write` 的固定原子工作槽；启动只清理该工作槽，不删除正式记录。

任务绑定创建时生效的数据库与视频目录，记录实际绝对路径。位置不匹配时保留记录并禁止继续／清理，可恢复原位置后重启或放弃该批次；不自动重绑定搬迁后的路径。损坏、未知版本或不完整记录原地保留并显示错误，不启动任务或静默覆盖。

只保留一批任务。新建前先「结束本次」或「放弃本次」，明确确认清除任务记录及剩余清理回执；完整视频和源文件均不删除。丢失此状态不损害数据库或视频，可新建任务，但旧清理回执不能重建。没有使用导入功能时不创建状态文件。

## 验证

文件与重启规则通过真实 Go 实现、隔离子进程强杀和浏览器连接隔离 Console 验证。纯浏览器夹具只覆盖按钮、确认和展示；进程强杀不等同于真实断电或磁盘耗尽。记录见[本轮验证](validation/video-import-recovery-20261030.md)，没有需要 VRC 判断的新增场景。
