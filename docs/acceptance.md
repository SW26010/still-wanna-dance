## 修复与边界

初版坚持完整校验后才开始响应，真实播放器的短探测连接在约 20 秒断开，造成重复解析和约 55 秒加载。修复改为共享渐进下载：客户端可独立读取已收到的区间，探测端断开不取消下载；完整大小/MD5 校验和缓存发布成功后才释放整文件最后一字节。校验失败中止正在等待的响应，半文件不发布。已发送的局部 Range 无法撤回，不能声称这些字节发送前已完成整文件校验。

1345 的负例保留：该次 CF 长连接下载速度约几十 KB/s，低于视频需求；同机独立 CF 请求约 332 KB/s、HKG 约 785 KB/s，说明不同连接有明显速度差异。本地小块流式 8 MiB 对照约 0.1 秒，未复现本地磁盘吞吐瓶颈。该曲未被发布为完整缓存，结束时无半文件残留。不能保证任意上游连接持续播放；MVP 没有自动测速、自动换源或分段加速。同一文件尚在下载时，后续跨域请求仍共享最初选定的下载任务，切 CDN 不会自动重启该任务。

修复版单元/HTTP 故障回归、vet、Windows 构建及 Linux 交叉编译通过；核心包覆盖率 82.6%。渐进首包、独立 Range、客户端中断、超时和校验失败断流用例重复 10 次通过。Windows 本机没有 race 检测所需的 C 工具链，Linux race 仍仅配置于 CI，未宣称执行通过。

## 复现工具

先构建 `bin/stepstash.exe`，在仓库根目录运行（需要 Node.js）：

```powershell
node scripts/acceptance.mjs '<已有歌曲库>' '<原版目录>/wanna-cdn.exe'
```

工具读取既有库的 1343/1344，下载约 74 MB，启动的子进程结束时清理；结果、视频和完整日志留在已忽略的 `test-runs/acceptance-*`。它不会修改 hosts。原版需已有的 LICENSE.txt 及用户已接受的 I_AGREE_TO_THE_LICENSE.txt。

游戏接入辅助工具 `scripts/game-hosts.ps1` 要求已在 127.0.0.1:80 启动且 1343 热缓存探测通过，再执行 Enable。Disable 仅移除本工具添加的精确标记行，保留其他 hosts 变更并记录前后哈希；两者均需管理员权限。Lab 必须位于仓库 test-runs 目录。
