# 基于下载结果的共享 IP 选路

本页记录尚未实施的设计。现行选路见[上游通道](upstream-channels.md#直连测量和推荐)，任务生命周期与尝试预算见[下载需求与资源管理设计](download-resource-design.md#单次尝试超时与下载延续截止)。

## 现状与目标

当前下载执行按 Console 提供的候选顺序重试。候选优先使用 Monitor 的推荐，随后补入 DNS 候选。失败只推进当前块的游标，同一 IP 仍可能被后续块优先尝试。业务下载期间自动资源探测可能暂停，因此需要让真实下载结果直接影响后续选路。

## 共享状态与选路

每个生效的直连上游持有一份线路状态，按实际请求的资源主机与候选 IP 索引。播放、预取、批量下载等执行实例共用该状态，观测可跨块、跨视频复用。

- **尝试前选择**。下载执行层在每次发起尝试前读取共享状态，结合目标主机的有效 DNS 候选、本块已尝试的候选和剩余预算，决定下一条线路。首次尝试和块内重试都使用这套规则。状态更新从下一次选路生效，已发出的请求沿用自己的生命周期。
- **尝试后记录**。执行层按实际请求的主机与 IP 写回每次尝试的结果。完整读完且通过网络响应校验的 Range 提供成功证据。可归因到线路的连接失败、正文重置或超时可降低该线路的优先级。任务取消、来源 need-by 到期、本地写盘失败和仅由资源自身造成的错误对线路可用性保持中性。共享状态保存选路所需的近期信息，逐次明细由日志记录。

固定 IP 候选为空时沿用普通直连回退。该尝试只有在确认实际使用的目标 IP 后才更新对应线路，无法归因的结果只保留在日志中。

第一版将可供重启复用的成功观测持久化到 `data/state`。保留原始观测时间，重启后允许仍在有效期内的样本参与选路，并按当前 DNS 候选约束 IP 的使用。临时降级和在途计数由当前进程建立。

## 选路倾向

- **DNS 基线**。从同一资源主机的多次 DNS 结果中，记录反复出现的一批 IP 作为基线。每次选择只考虑当前仍有效的候选。基线尚未形成时，使用当前有效的 DNS 候选作为起点。
- **急需的块**。每次尝试前按最新 need-by 判断还有多少余量。余量较小时优先选择近期实际下载较快的线路。缺少可用的近期测量时，优先使用 DNS 基线。
- **余量充足或无期限的块**。优先给过去表现尚可、观测已变旧的线路一次更新机会，也用部分尝试探索新出现或尚无下载观测的 IP。随重试时间增加，有限期限的块按最新余量调整选路倾向。
- **并发分散**。候选均适合当前块时，倾向选择在途尝试较少的 IP，让并发负载更均匀，同时积累不同线路的实际下载观测。线路被选中后计入该 IP 的在途尝试，尝试收尾后释放。急需块优先考虑能否及时交付，分散只在适合它的候选中起作用。

## 单次尝试时限

第一版直连业务下载在还有未尝试的有效备用 IP 时，对当前 IP 的单次尝试设 30 秒上限。从发起尝试开始计时，到完整读取并校验本次 Range 为止，计时覆盖连接、等待响应头和接收正文。现有响应头预算和父级截止可更早结束尝试。最后一个候选沿用现有单次尝试时限，给慢速线路保留完成机会。

30 秒到期时结束当前尝试、关闭已有响应，并按当前 IP 记录一次块下载超时。下载需求和剩余预算仍允许时，尝试下一条线路。任务取消或来源截止先到时，线路可用性观测保持中性。

## 自动测速

独立采样器接替 Monitor 的定时单字节资源检查和自动吞吐测速。每次采样针对某个资源的某一块，默认串行执行（并发为 1）。Monitor 的手动资源检测保留为按需诊断，通用连通性检测、歌曲列表和播放地址检测沿用现有流程。

采样有独立的短时限，向上游请求 Range，校验响应并边读边丢弃正文。即使本地已有该块，采样也实际读取上游。响应关闭并完成清理后，才可开始下一次采样。

- **直连**。第一版允许采样与业务下载并行，采样器自身仍串行执行。可较频繁地采样，补充近期下载观测。触发方只提供资源和块号，由采样执行侧结合有效 DNS 候选和近期观测选择 IP。采样和业务下载按实际请求的资源主机与 IP 更新同一份下载观测，业务执行读取这份记录并独立决定后续选路。
- **代理**。请求使用当前配置的唯一代理上游，DNS 由代理处理。仅在业务下载不活跃时偶尔采样，用于更新该代理上游的实测速度。

采样器独立管理任务的触发、取消和清理。块资源使用管理、块下载调度器和 WebUI 块需求视图继续服务业务下载。采样因取消或让位而结束时，线路可用性观测保持中性。

## WebUI 线路观测

网络页「当前连接」的资源观测可按资源主机展示直连 IP 的近期表现排名，统一使用自动采样和业务下载的共享观测。首批可展示最近一次观测时间，以及最近一次成功下载完整 1 MiB 块的耗时。拟从向该 IP 发起单次网络尝试开始计时，到读取并校验完整块为止，涵盖连接、响应头等待和正文读取。

排名用于比较近期线路表现。具体任务的选路仍由执行层结合当时的有效 DNS 候选、need-by 和在途尝试决定。

## 职责与范围

调度器按块需求管理启停和并发，并提供动态 need-by。下载执行层管理选路、重试、预算和结果记录。基于 IP 的自动选路仅适用于直连，沿用[现有资源下载协议](upstream-channels.md#业务请求的协议策略)。Monitor 可作为诊断手段，业务选路以共享下载观测为依据。

## 待定规则

- DNS 基线的入选条件、need-by 余量与观测新鲜度的判定、更新旧观测与探索未知 IP 的相对优先级，以及并发分散如何参与排序。
- 线路降级条件和恢复时机。
- 并发尝试结束时的共享状态更新顺序。
- 持久化观测的字段、有效期和旧样本兼容方式。
- 直连自动测速的触发频率，以及代理空闲时的采样间隔。
- WebUI 线路排名的计算依据和汇总时间范围。

## 验证场景

实现后用受控上游验证以下行为。

- 一个视频在首选 IP 上发生正文重置后，另一个视频的新尝试优先使用其他有效候选。
- 当前 IP 持续返回正文但无法在 30 秒内完成块下载时，有效备用 IP 可接续尝试。最后一个候选可在现有尝试时限内完成慢速下载。
- 普通直连回退可继续下载。确认实际目标 IP 时观测归入该线路，无法归因时各 IP 的观测保持原状。
- 仅取消单个任务时，共享状态保留该 IP 原有的线路观测。
- 急需块有近期快线时优先使用快线，缺少近期观测时回到 DNS 基线。IP 失去有效 DNS 资格后退出候选。
- 余量充足或无期限的块能更新旧观测和探索未知 IP。并发且有多条合适候选时，尝试分布到不同 IP。
- 已有本地块仍会发起上游采样。默认设置下重复触发时最多一个采样在途，取消后等响应清理完成再开始下一次，采样正文不落盘。
- 独立采样启用后，Monitor 的自动轮次继续检查歌曲列表和播放地址，资源采样由独立采样器执行。手动资源诊断和通用连通性检测仍可运行。
- 直连可在业务下载进行时并行采样，采样结果可供后续业务选路使用。代理在业务空闲时使用配置的唯一上游采样，结果用于记录该上游的实测速度。
- 重启后可复用仍有效的成功观测。候选资格按当前 DNS 结果判断，样本有效期按原始观测时间计算。
- WebUI 的直连线路观测可反映自动采样和业务下载的结果，完整块耗时对应同一 IP 上的一次成功尝试。
