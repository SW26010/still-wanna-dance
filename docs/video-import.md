# 视频导入、暂停与恢复

本文维护视频导入的现行规则。2026-10-30 起替代此前“视频导入进度与回执只存内存”的约定；2026-11-12 起改为独立 SQLite 按条目保存，替代逐文件重写整批 JSON。普通批量下载、VRCX 导入和旧引导状态不因此获得恢复能力。

## 一批任务与固定清单

曲库中的「扫描并导入」先递归枚举来源目录，排除当前视频目录、符号链接和非普通文件，保存完整清单后才逐文件校验与导入。清单保存路径、文件身份、大小和修改时间，不提前读取所有文件内容或计算全部 MD5。

清单一旦保存，本批次不再遍历源目录。后来新增的文件留到下一批；原条目被移动、删除、替换或属性变化时直接跳过并记录原因，不追踪新位置或接纳替代文件。权限和其他 I/O 错误按失败记录，继续时可重试；不能将无法读取误判为文件变化。扫描未完成便中断时尚无完整清单，也没有导入文件，继续时重新枚举。

导入只使用当前本地已知资源，无需在线更新或歌曲映射。同卷优先硬链接，跨卷复制；源文件和暂存内容校验、禁止覆盖已有目标、屏蔽检查及视频保留策略继续沿用现有实现。硬链接共享内容，导入后不得修改源视频。

同一导入阶段内，暂存文件的已打开句柄与已校验源文件的身份、模式、大小和修改时间一致时，复用本阶段的 MD5，不重复读取共享内容；独立副本仍完整校验。文件身份与属性检查继续覆盖校验和发布过程，不按盘符或硬链接调用成功直接省略校验。

选择来源目录后，界面按来源与本次目标目录的实际存储卷预估空间：同卷显示“预计不额外占用视频空间”，跨卷显示“预计需要额外空间”，无法读取目录或确认存储卷时显示“空间占用待确认”。新任务使用当前生效的完整视频目录，已有批次使用其绑定目标，不使用尚未生效的设置。检测只读目录信息，不枚举视频、不计算容量、不启动引擎或创建导入任务；子目录的卷边界及最终硬链接／复制结果仍逐文件确认，硬链接的其他错误不会自动回退复制。

## 暂停与逐文件恢复

- 运行时可「暂停」；中断当前校验或复制，未完成文件下次从头处理，不保存字节级进度。已进入发布且返回成功的项目先保存回执再停。
- 暂停请求发出后，界面等待后台状态同步；后台确认正在暂停期间不可重复提交，停止后按实际结果显示已暂停、完成或清理结果。状态接口以 `pausing` 表示暂停进行中，`running` 保持到工作结束，`paused` 表示停下后仍有未完成项目；中间状态不写入恢复记录。清理操作同样遵循暂停状态。
- 关闭或刷新 WebUI 不停止后台任务。正常退出保存已完成项，崩溃后使用最后可靠保存的记录。重启只展示状态，未完成导入显示“已暂停，等待继续”，不启动引擎、重新扫描或自动处理文件。
- 「继续导入」只处理可靠保存的清单中待处理及失败的项目。已保存的成功和跳过项目不重做；已导入目标被保留策略淘汰后，也不因继续任务重新补回。异常退出时最多重新检查最后 64 个未提交的跳过或失败项目，不重新枚举来源目录。
- 成功发布的视频逐项提交成功回执后才处理下一项，即使此时收到暂停请求也先保存回执。跳过和普通失败结果最多积攒 64 项提交；遇到成功回执时一并提交，在暂停、正常退出和任务结束前补齐剩余结果。提交使用独立于工作取消信号的事务；保存失败立即停止，不重试该批写入或处理下一项，保留最后可靠记录并明确提示，不发布新的清理资格。
- 运行中只发布已提交的条目和计数，因此跳过或失败结果的显示最多暂缓一小批；逐项更新内存计数，不在每项完成时克隆、遍历完整清单。加载和任务结束时再从完整记录汇总。
- 视频已经发布、成功回执尚未保存便崩溃时，继续处理会将仍存在的目标按已有文件跳过，不补发清理回执。该源文件保留；这是第一版有意接受的恢复范围。

## 源文件清理

只有本批次新发布且已保存成功回执的文件可以清理。原本就存在、未知、屏蔽或变化而跳过的项目没有清理资格。删除前再次验证源文件身份、大小、修改时间、源和目标的完整内容，并在操作期间保护目标引用。目标不存在或校验失败时保留源文件及可重试回执；源文件已经改变时撤去旧回执的清理资格。

清理重新读取目标内容计算 MD5，不沿用导入或上次清理的校验结果。本次清理中，源文件的已打开句柄与刚校验目标的身份、模式、大小和修改时间一致时，合并共享内容的哈希读取；独立文件分别校验，删除前仍检查源文件快照及路径身份。

回执可跨重启保留，删除确认不可恢复。每次清理都需要勾选和明确确认，也可以暂停。每个清理结果单独提交，仅更新对应条目；保存失败立即停止。中断后只处理尚有回执的项目；已经不存在的源文件记为“无需清理”，不冒称本程序删除成功。程序启动不会接着删除。

本功能不改变视频保留预算。导入成功并非永久保留承诺，旧回执也不能绕过完整目标校验。

## 存储与任务生命周期

实例的 `data/state/video-import.sqlite` 使用独立 SQLite 身份 `SWDI` 和 `user_version=1`，保存一批任务及必要回执，不建立任务历史或核心数据库表。`task` 保存元信息和清单数量，`items` 按固定序号保存单项记录；恢复时验证条目数量、顺序及原有文件／回执约束。完整记录是进度依据，运行计数仅为内存派生值。

创建任务、枚举完成及旧记录迁移时才写完整快照：在固定 `.video-import.sqlite.swd-tmp` 工作槽构造数据库，使用内存回滚日志，关闭后 Sync 并原子替换正式文件；未发布的工作槽不参与恢复。后续按项或小批次在 SQLite `WAL`、`synchronous=FULL` 下提交，不重写全部清单。配置实例锁保护本状态，工作线程持有连接，停止后关闭；SQLite 自身管理正式数据库的 WAL／SHM 等伴随文件，启动垃圾清理不删除它们。尚未使用导入功能时不创建数据库。

兼容原 `data/state/video-import.json` 的 `version=1`：没有新数据库时启动只读旧记录，首次明确继续或清理时保存新数据库；新快照可靠发布后才移除旧 JSON。迁移失败保留原记录，不处理后续文件或开始源文件删除；若新快照已发布但旧文件未能移除，以新数据库为准，不双写或回退旧状态。损坏的新数据库不能用旧 JSON 静默替代。

任务绑定创建时生效的数据库与视频目录，记录实际绝对路径。位置不匹配时保留记录并禁止继续／清理，可恢复原位置后重启或放弃该批次；不自动重绑定搬迁后的路径。损坏、未知版本或不完整记录原地保留并显示错误，不启动任务或静默覆盖。

只保留一批任务。新建前先「结束本次」或「放弃本次」，明确确认清除任务记录及剩余清理回执；停止工作线程并关闭连接后，仅移除该任务已知的状态文件及其 SQLite 伴随文件，完整视频和源文件均不删除。丢失此状态不损害核心数据库或视频，可新建任务，但旧清理回执不能重建。

## 验证

文件与重启规则通过真实 Go 实现、隔离子进程强杀和浏览器连接隔离 Console 验证。纯浏览器夹具只覆盖按钮、确认和展示；进程强杀不等同于真实断电或磁盘耗尽。原 JSON 版本的验证见[恢复验证](validation/video-import-recovery-20261030.md)，按项持久化、旧状态迁移及写入规模见[增量保存验证](validation/video-import-progress-20261112.md)，没有需要 VRC 判断的新增场景。
