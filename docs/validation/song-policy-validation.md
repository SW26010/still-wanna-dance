# 歌曲屏蔽与收藏开发验证

业务规则见[下载需求与资源管理设计第 8 项](../download-resource-design.md#8-歌曲屏蔽与收藏)。本记录维护存储、来源准入、本地资源与控制台的开发验证；游戏播放器行为另列边界。2026-11-04 起，收藏统一受视频存储预算约束，仅在预算内优先保留；此前零预算或超预算收藏保留的结果只适用于当时规则，现行语义与增量验证见文末。

## 存储与本地资源管理（2026-10-21）

数据库 v3 新增互斥的歌曲偏好记录，保留冻结的 v2 DDL 和二进制夹具；v2 打开失败且文件字节不变。测试覆盖事务失败回滚、恢复普通时删除记录、目录重开保留偏好、曲库更新不改偏好和摘要。收藏操作本身不创建需求、块使用或下载。

受控 HTTP 与资源夹具覆盖：

- 被屏蔽歌曲的 GET/HEAD、队列准备和手动预取在需求创建前拒绝，不回源；已有共享文件不让歌曲绕过判断，普通关联仍能保留该文件。
- 完整队列保留未知条目、屏蔽队首及中间条目的时长，后续开始时间、位置和块需求集合不受筛选干扰。
- 全部关联屏蔽的完整视频在预算未满及不限容量时均回收，已有资源引用和使用保护继续延迟删除；临时块复用同一回收机制，不扩大收藏保护。
- 收藏完整视频在零预算和单视频超预算时发布，原评分不变；占用仍计入同一预算，普通视频使用剩余空间，取消最后一个收藏后恢复普通淘汰。
- 发布前重新核对屏蔽和收藏状态；普通批量预算停止后，收藏资源预留仍可准入，同一 MD5 只计量一次。

执行与结果：

## 边界审计

## 审查修复：离线收藏先于启动回收（2026-10-21）

审查发现一个已复现的 P1：已有普通视频、当前零预算且引擎未启动时，收藏 API 先调用 `ensureEngine`，初始化按旧偏好淘汰视频并清理临时文件，然后才写入收藏。接口成功不能证明文件受到收藏保护。此前浏览器夹具预先启动了引擎，没有覆盖这个入口条件。

现改为离线直接写入偏好，不启动引擎或执行回收。复用从 VRCX 离线导入提取的独占目录锁、布局/版本检查和数据库打开流程；在线与离线共用原偏好事务。在线标记仍与发布和回收串行，已有使用证据的失联库仍拒绝新建。正常引擎启动读取已提交的收藏后再按预算清理。

- 新增回归修复前稳定失败，明确观测到收藏目标被删除；修复后文件字节及临时残留保持，标记不创建引擎，后续零预算启动仍保留收藏。原失败保存在 `artifacts/song-policy-offline-before.log`。
- 偏好、离线库、历史导入及 VRCX/引导定向回归通过：缓存 0.945 秒、控制台 3.948 秒。覆盖独占锁拒绝、v2 库字节不变、失联库拒绝、首次标记建库与在线路径。结果见 `artifacts/song-policy-offline-verified.log`。
- 真实浏览器夹具改为从未启动引擎、已有普通视频开始，收藏后明确核对引擎仍未启动，再启动/重开零预算引擎并核对文件存在；同时继续覆盖筛选、标记、403 和无下载。截图及结果位于 `artifacts/song-policy-offline-browser/`，窄屏截图已目视检查。
- 定向 Windows race 通过（缓存 2.492 秒、控制台 3.792 秒），两包 `go vet` 通过；原始输出见 `artifacts/song-policy-offline-{race,vet}.log`。复用前轮不受影响的全量回归结果，不重新执行游戏验证。

本修复未修改需求集合、块资源使用管理或块下载调度器，没有新增后台任务、配置或数据库版本。

## 审查修复：容量等待后的歌曲准入复查（2026-10-21）

审查指出，后台候选通过入口检查后可能在 `addPreparation` 等待使用容量；等待期间屏蔽歌曲，原循环醒来后直接登记需求。此前入口测试没有覆盖偏好在容量等待期间变化的情况。

现在由共用的来源层 `addPreparation` 在每次尝试登记前检查当前歌曲偏好，覆盖首次接入和容量唤醒后的重试。入口的早期检查继续避免不必要的解析或预算准备；已登记来源不再经过这个循环，保持原来的使用、交接和退出规则。

- `TestPreparationRechecksBlockedSongAfterCapacityWait` 用 `synctest` 精确停在容量等待，覆盖手动补齐、冷队列及本地命中队列。修复前三项均失败：前两项实际请求视频，后者错误登记使用需求。失败证据保存在 `artifacts/song-policy-capacity-before.log`。
- 修复后三项均返回 `ErrSongBlocked`，不发送准入成功通知，不新增需求、块使用或资源会话，不请求视频；手动补齐释放本轮预算预留。真实 SQLite、文件和受控 HTTP transport 参与验证，无公网依赖。
- `TestBlockingDoesNotCancelAdmittedPreparation` 覆盖已登记的手动及队列来源：屏蔽后需求和使用仍然有效，按原释放及队首交接期限结束；既有已接纳 GET 完整交付回归继续通过。

## 收藏改为预算内优先保留（2026-11-04）

本节替代前述所有收藏可突破预算的规则与验证结论，历史执行结果保留。用户确认：收藏总量超预算时允许自动淘汰其中的完整视频，保留标记；不开设独立收藏预算或额外开关。原设置字段、默认值、保存后重启生效及“不保留”时禁用的语义继续使用。

发布准入与已有文件回收共用收藏优先、每类内部按现有评分及全部同分规则取舍；收藏超预算也会被淘汰，零预算或单视频超预算不进入合并与校验。回收先处理单个文件大于总预算的资源，避免清空原本能装下的普通文件。使用保护与必要引用继续延迟回收，释放后按预算收敛。已有超预算收藏也适用新规则，升级后首次引擎初始化可能清理部分完整视频。

手动补齐先处理收藏，仍受原单轮预算约束：初始库存及已消耗额度保持计费，不主动为补齐淘汰旧文件腾空间，也不因回收循环复用额度。共享资源按全部当前关联判断收藏优先，未解析资源按歌曲标记判断；扫描保持原顺序。移除预算停止后收藏继续绕过容量检查的分支和对应提示。

验证范围与结果：
