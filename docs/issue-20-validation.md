# Issue #20 单视频 Range 并发开发验证

基线 `a159768`。本轮仅实现和开发验证，真实游戏、hosts、托盘及实网播放体验留至集中验收；不 push。

## 第一步：共享视频请求额度

`request_budget.go` 为每个缓存引擎限制最多 6 个在途视频 HTTP 请求，其中后台最多 4 个，预留 2 个给真实读取等待。与 `MaxDownloads` 的资源任务名额分开；API、清单、测速及空闲 TCP 连接不计入这个视频请求额度，底层连接池和代理节点准入仍分别管理自身连接。

首请求（含顺序 200 回退）、后续 Range、重定向和通道重试均经过额度。排队中的后台请求出现播放需求后可提升优先级；同级 FIFO。响应正文关闭完成后才归还，取消或收到响应头不提前释放。排队取消不调用 transport，也不向 Monitor 注入线路失败。

自动检查（2026-10-14）：Go 1.27.1 / Windows amd64，`go test -tags=no_easytier ./internal/cacheproxy -count=1 -timeout=180s` 通过。新增回归覆盖读请求预留、优先级提升、排队取消、失败归还及阻塞 Close 时额度仍被持有。初次沙箱执行在已有缓存发布路径遇到 `Access is denied`，基线同样失败；正常用户权限、测试专用临时目录复测通过。自动化不改变 LA-037 实机状态。

## 第二步：并行缺块领取与读取优先

单视频采用 3 个后台 worker 和 1 个读取等待 worker，仍为 1 MiB 块。后台 worker 先帮助已有读者，再准备读取位置之后最多 2 个块，最后补齐其余缺块；读取等待按到达顺序处理，不按文件偏移偏袒头部。预读提示随读位置移动，关闭/取消后失效；提示不是实际播放器缓冲时长。全局 6/4 请求预算约束所有视频，不随歌曲数量乘大。

正在进行或排队的块保持唯一领取；排队后台块被读者需要时原地提升。专为读者发起的块在最后一个等待者离开后取消，等请求关闭才重新领取；普通后台块继续完成。已完成的块保留在当前 flight 的 spool，调度不取消整文件、不重新下载已完成块。跨任务抢占及其原有重新下载语义仍由 #22 管理。

自动检查（2026-10-14）：新增单视频并行且无重复块、两首预缓存占满 4 个后台额度时另一路冷播放与尾部 Seek 同时取得预留额度、需求 FIFO、近端预读移动/失效等回归。核心新场景及原 Seek 取消/共享尾部场景连续 10 次通过。旧尾部测试的“最多两个请求”断言按新单视频上限调整，保留每块只下载一次、洞未填不发布及最终字节校验；取消测试固定占满所有后台 worker，避免把已开始的普通后台块误当作读取专属请求。

本批 Windows 全缓存包 `go test -race -tags=no_easytier ./internal/cacheproxy -count=1 -timeout=180s` 通过，使用 Go 1.25.0 与已有 w64devkit GCC 16.2.0，覆盖取消、完整性、顺序回退、重定向/通道回退、存储和任务调度；未发现 DATA RACE。首次普通回归只因旧“两请求”断言失败，调整预期后上述定向与 race 通过。

## 第三步：由对照结果修正首块及 Seek 竞争（当前行为）

同一 `range_benchmark_test.go` 分别在基线 `a159768` 的隔离源码副本和当前代码执行；Go 1.25.0 / Windows amd64 / CGO=0，无其他并行性能任务。每个场景 3 组，每组 3 次正式计时（另有 Go benchmark 预热），每次新建隔离缓存、完整校验约 12 MiB 相同内容。两种回环上游：每请求 20 ms 响应头等待 + 每 2 ms 64 KiB；共享总带宽每 2 ms 64 KiB、无额外响应头等待。播放场景读取首字节后跳到第 10 MiB，再等待整文件完成。

初版仅增加 worker 时，单请求受限的预缓存约快 2.6 倍，但共享总带宽下首正文从约 30 ms 增至 86 ms、Seek 从约 66 ms 增至 128 ms。这个退化未作为最终结果接受，保留[初版原始对照](evidence/issue20-development/benchmark-initial-parallel.txt)。

当前增加以下保护：

- 前台新下载先取得首块，再展开后台补齐；尾部读取仍可绕过首块。播放器加入已有预缓存且首块缺失时，也会让其他后台块让位。
- 首块等待或真正跳转才取消本资源不被读者需要的在途分块。普通后续顺序读取不反复取消预取；多个读者仍需要的块保持。
- 让位 worker 保留独占块和已接收的部分缓冲，待该需求完成后从剩余字节继续请求。已完成块始终保留。临时响应必须关闭完成才归还请求额度。
- 恢复仍校验精确 Content-Range、长度、内容编码及强 ETag，最后整文件 MD5 后发布；弱/无 ETag 沿用最终 MD5 边界。真实错误丢弃当前块的部分内容并使用原有有限回退；本地让位不消耗失败尝试，也不重新尝试此前失败的通道。重定向后从已验证终点恢复。
- 只保留当前进程、当前 flight 中每 worker 的至多 1 MiB 缓冲；未新增落盘断点格式、用户设置或选路机制。应用退出和整任务取消仍丢弃未完成缓存。

下表为 3 组各自均值的中位数；仅证明受控模型，不代表公网或游戏体验：

| 场景 / 指标 | 基线 | 修正后 |
| --- | ---: | ---: |
| 每请求受限 / 纯预缓存完成 | 685.40 ms | 265.18 ms（约 2.58 倍吞吐） |
| 每请求受限 / 播放加 Seek 后完整下载 | 636.19 ms | 346.94 ms |
| 每请求受限 / 首正文 | 53.33 ms | 53.55 ms |
| 每请求受限 / Seek | 54.69 ms | 54.81 ms |
| 共享总带宽 / 纯预缓存完成 | 412.61 ms | 411.50 ms（无明显收益） |
| 共享总带宽 / 首正文 | 30.06 ms | 29.90 ms |
| 共享总带宽 / Seek | 65.57 ms | 33.66 ms |

修正后所有测量的正文传输/内容大小比为 `1.000`（工具显示精度），纯预缓存每文件仍 13 个请求；播放/Seek 场景为 13.67–14 个请求，包含本地让位后的剩余区间请求。它不是所有真实网络上的流量上限，网络中已发送但取消前尚未读取的数据可能重复传输。完整[基线输出](evidence/issue20-development/benchmark-baseline.txt)、[播放保护首次修正输出](evidence/issue20-development/benchmark-playback-priority.txt)和[收尾修正后最终输出](evidence/issue20-development/benchmark-final.txt)均保留；上表采用最终输出。

新增自动回归：弱/缺失 ETag 的有效内容、强 ETag 变弱/消失/变化拒绝、弱 ETag 下错误内容 MD5 拒绝、失败后等待所有 Body.Close 完成并回收临时文件；让位后从精确 64 KiB 位置恢复、已有失败通道不重试、重定向终点保留、恢复后的 Range/ETag 错误拒绝、播放器加入已有预缓存。上述核心并发场景及原多读者/取消场景通过十轮 Windows race；最终新增的首块加入及重定向恢复也单独通过十轮 race。共享 Seek 允许有依据的取消/续取，因此原“任何 Seek 块都只请求一次”断言调整为完整性和有界调度检查；无跳转时每块恰好一次仍由独立并发测试验证。

未执行公网视频 A/B、真实播放器卡顿或长时间游戏验收；这些仍属于 LA-037。

## 收尾审查与最终检查

审查发现请求从读取优先降为后台时，另一个较早等待者可能仍在等它，而降级者又开始遵守 FIFO；若此时没有其他事件，会留下空闲额度。`request_budget.go` 在自身优先级改变时通知共同队列。新增回归在 `aa32e33` 隔离副本稳定等待超时失败，修正后 20 轮 Windows race 通过。台账 LA-037 增加对应需求消失/额度释放的实机步骤。

最终使用 Go 1.25.0 / Windows amd64，race 编译器为已有 w64devkit GCC 16.2.0：

| 检查 | 实际结果 |
| --- | --- |
| `go test -race -tags=no_easytier ./cmd/... ./internal/... ./data/... -count=1 -timeout=240s -json` | `aa32e33` 全部正式包通过：14 个测试包，1,209 个测试/子测试通过，15 项跳过，无 DATA RACE；另 3 个包无测试 |
| 收尾唤醒修正后，相同参数复测 `./internal/cacheproxy ./internal/console ./cmd/still-wanna-dance-console` | 3 包、943 个测试/子测试通过，12 项跳过，无 DATA RACE；包括新增唤醒回归。其余包未改动 |

产品改动均限于 `internal/cacheproxy`，未改配置/存储版本、Monitor、代理后端、界面或跨歌曲准备数量，无新依赖。旧并发文档已加当前实现并保留历史评估。原始测试日志保留在忽略的 `artifacts/issue20/`，仓库只保存脱敏检查摘要和回环对照。未启动游戏、修改 hosts、重新打包发布或 push；开发完成与 LA-037 待实机验收分开。
