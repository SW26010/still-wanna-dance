# 配置与运行生命周期

本页描述当前实现。配置、核心数据库与辅助状态的目标职责见[持久化数据职责与边界](persistence-design.md)，实施顺序见[迁移计划](persistence-migration-plan.md)；数据库和完整视频位置独立，桌面应用持有数据库。

配置缺失与资源故障分别表达：普通偏好缺失按默认值加载；数据库或视频位置缺失时，启动存储准备流程只补齐缺失项，通过最终路径组合与资料保护检查后自动初始化，并显式保存位置，不额外提示。隐式默认位置存在旧资料，或补齐数据库会改变已有视频的管理依据时，以黄色「待确认存储」说明确认步骤；实际配置／资源故障显示红色并保留原因，二者共存时总体状态优先显示故障。状态接口以派生的 `storageConfirmation` 传递待确认说明，与 `storageError` 分开，不持久化新标记。已知存储诊断另以 `storageIssues` 绑定字段、级别与当前生效路径，设置页复用字段校验组件显示黄色警告或红色错误；更换草稿位置后不把旧实例的故障标到新位置，放弃草稿则恢复原提示。运行故障的字段归属复用设置校验元数据，但保留真实故障原因，不改成预期拒绝。

配置模块在 `internal/console/settings.go` 统一字段定义、默认值、字段校验、路径转换与设置请求解码；`config_file.go` 统一文件加载及更新，内部处理格式版本、未知字段和受保护凭据，复用现有凭据保护与 `workfiles.Write`。普通设置和 VRCX 忽略选择共用文件更新入口；加载只返回规范化结果，不准备数据库、视频目录或网络，也不改写文件。启动日志通过轻量入口读取 `logLevel`，启动另读取规范化设置以确定块工作区，不提前执行完整初始化。

WebUI 草稿从后端完整的已保存快照初始化，只转换输入文本与显示单位，不另行补配置默认值；“同时下载数量”“并发增长间隔”“提前准备时间”“延续保护时间”的空输入是明确的恢复默认操作：页面启动数据从后端现行默认值提供灰色 placeholder，前端提交对应数值，显式 0 仍保留原含义。清空默认值本身也可保存或放弃，缓存估算中的提前准备时间与延续保护时间均按各自默认值处理空输入，展示与换算见[内容约定](webui-content.md)。保存时只提交相对该快照实际改变的字段，避免旧页面覆盖其他页面已经保存的无关设置。字段范围提示和交互校验仍由表单负责，后端保留最终校验。字段级拒绝以 `code=settings_validation`、`fields`（配置字段名到原因的映射）返回；Mihomo 配置导入内容使用 `proxyImportText`。前端将原因附于对应字段图标，不新增可见错误文字行，不刷新或离开设置页。此类拒绝不新增 `actionErrors.settings` 或桌面故障通知，也不清除已有操作故障；实际配置写入失败仍沿用原故障反馈，只有成功保存才清除该操作的旧故障与故障中心事件。

Mihomo 文件／Base64／URL 输入属于前端草稿，不作为设置字段提交。点击保存时，如果网络表单中仍有待导入内容，先复用显式「导入」的检查请求，成功后以返回的草稿 ID 进入普通设置保存；检查失败不发起保存。保存失败保留已检查草稿供重试。文件名／导入时间随该草稿更新并在配置原子保存时写入普通元数据；这两项展示信息不影响核心的待重启判断。

`settingsEditor` 独立持有已保存配置、当前生效的校验基线、Mihomo 导入草稿、路径选择与 hosts 授权操作。正常应用和恢复窗口分别组合该模块；恢复窗口不构造 Console 或业务服务。`settings_save.go` 中的 `POST /api/settings` 在事务锁下把本次字段合并到最新已保存设置，沿用主题、凭据和 Mihomo 配置草稿处理，完整校验合并结果，再检查及准备变更的资源位置与所需权限；原子写入成功后才更新内存快照。正常应用向编辑器提供同一个 `lifecycleMu`，主题、VRCX 选择和 hosts 操作继续按原顺序串行；原子替换不代替整个读改写过程的串行。发布保存结果时同时更新 Console 的立即生效字段，状态读取不会看到已保存配置与立即生效配置的中间状态。其他业务继续接收当前生效参数。

设置请求中缺失或 null 的字段保留已保存值，显式 false、0、空串按字段语义校验；例如清空 `vrchatLogDir` 才恢复自动识别，省略它不改变路径。不同字段的并发修改相互保留，同一字段以最后成功保存的请求为准，不增加版本冲突协议。配置文件加载仍采用启动默认值，下文各字段的“缺失或 null 使用默认值”均指文件加载。配置格式仍为 v8，保存与重启的生效边界不变。

当前配置版本为 8，统一使用 `vrchatLogDir`、`videoBudgetBytes`、`downloadConcurrencySoftLimit` 和 `restoreHostsOnStopOrExit`。此次发布前整理不迁移旧配置、不读取旧名称别名；旧版本拒绝打开且保留原文件。当前 v8 配置中已停用的 `upstreamMode=auto` 是一个明确例外：读取时转换为 `proxy`，启动校验通过后原子写回该字段并清除已停用的回收策略字段，保留代理凭据、节点及其他字段，不增加格式版本。设置请求只接受 direct/proxy。迁移当次运行首次进入首页时弹出简短通知，同一浏览器标签刷新不重复；迁移已落盘，后续启动不再通知。写回失败则启动报错，不宣称迁移成功。数据库及其他状态格式不因字段调整改变，版本边界见[存储契约](storage.md#持久化格式与语义)。

`vrchatLogDir` 表示用户指定的 VRChat 日志输入目录，缺失、null、空串或仅空白表示自动识别；非空路径相对配置文件解析，实例内路径落盘为相对路径。`settings` / `activeSettings` 在自动模式下始终保留空串，读取日志时才解析当前用户的默认目录；`defaultLogDir` 仅向界面提供默认路径展示，不回写配置。指定和恢复默认均保存后重启生效，不再单独保存手动模式布尔值。

配置可以在服务或任务运行时保存。保存校验、写入配置文件并更新已保存快照；除下述主题与停止／退出策略外，当前 Console 的配置、网络连接、共享本地资源引擎、监测策略、扫描与任务保持不变。

「主题」自动保存后立即生效，「停止加速或退出时恢复游戏直连」保存即用于停止加速和本次退出；其余运行设置在应用重新启动后生效，包括没有任务运行时保存的设置。单独停止、启动播放网关或任务不会应用待生效配置。

「程序日志级别」（`logLevel`）默认 `info`，支持 `off/error/warn/info/debug`，缺失、null 或空串采用默认值，未知值拒绝。保存后重启整个程序生效，参与 `settings` / `activeSettings` / `restartRequired`；关闭不删除已有日志，也不影响游戏日志输入、请求历史或运行统计。初始化先复用配置格式校验读取该字段，以覆盖 Console 构造期日志；完整设置继续走原加载流程。行为与字段口径见[日志](logging.md)。

播放地址入口固定为 CF，已移除 `downloadUpstream` 设置。直连自动吞吐探测采用内部固定周期，已移除 `throughputIntervalMinutes` 设置，具体规则见[上游检测与测速](upstream-channels.md#上游检测与测速)。旧配置中的这两个字段不生效，再次保存设置时移除；其他未知字段仍按原规则保留，不增加配置版本或迁移流程。

歌曲屏蔽与收藏属于本地曲库偏好，不属于本页的启动配置。其保存后对后续决策的生效边界见[歌曲偏好设计](download-resource-design.md#8-歌曲屏蔽与收藏)；不纳入 `activeSettings` / `restartRequired`，也不因标记变更启动下载任务。

「忽略 VRCX 导入建议」是当前配置实例的界面选择，主配置以 `vrcxImportDismissed` 保存；不进入可编辑的 `settings` / `activeSettings`，不应用待重启设置，普通设置保存保留该字段。默认与完整生命周期统一见[历史初始化契约](song-catalog-design.md#vrcx-历史初始化)。

块回收固定采用原默认策略，规则见[本地资源管理](download-resource-design.md#6-本地资源管理的存储与外部契约)。已移除 `aggressiveBlockReclamation` 配置，旧值（包括 on/off）读取时忽略，不进入设置 API 或运行快照；单纯读取不改写文件，在下一次成功写入配置时清除该字段及其大小写别名，保留其他未知字段，不增加配置版本或单独迁移流程。

「高级下载设置」中的下载并发软上限与增长间隔也遵循此规则。配置字段 `downloadConcurrencySoftLimit` 与 `downloadGrowIntervalMS` 缺失或 null 时分别使用 16 和 250，明确保存的 0 ms 表示关闭缓增；范围与执行语义见[下载并发](download-concurrency.md)。

「优先保留收藏视频」（`retainFavorites`）默认开启，保存后重启应用生效；仅在视频保留方式为「限制为／不限制」时生效。「不保留」时保留原设置值，控件禁用并置灰，切回保留模式后恢复；生效时收藏在同一预算内优先保留，空间不足仍可能被淘汰；关闭或不生效时收藏只做标记，按普通预算取舍。切换选项不启动下载、补齐或恢复文件。规则见[歌曲屏蔽与收藏](download-resource-design.md#8-歌曲屏蔽与收藏)。

「历史请求明细」使用显式三选项，默认永久保留，保存后重启应用生效；不保留会停止新增并清理已有明细。来源总览按[现场汇总保留明细](storage.md#请求统计的计算方式)，随明细清理而变化，歌曲需求计分仍独立保留。限定天数及配置规则统一见[请求明细保留期](cache-retention.md#请求明细保留期)。

「下载与缓存」中的延续保护时间也在应用重新启动后生效。`localProtectionGraceSeconds` 缺失或 null 时默认 300，接受 0～10000 的整数；显式 0 表示不延续保护。保护资格、起算点和回收边界见[本地保护](download-resource-design.md#本地保护)。

状态接口中的 `settings` 是已保存配置，`activeSettings` 是当前运行配置，`restartRequired` 是两者规范化后的差异。两份配置均不返回代理密码；密码差异仍参与待重启判断。保存请求省略密码时保留最近保存的密码，显式空串清除密码。

设置表单展示已保存配置；运行信息、本地视频列表与监测展示当前配置。连通性检测与下载测速始终使用当前生效客户端，设置草稿和待重启配置不能成为测试对象。保存失败不会更新已保存快照；把配置改回当前值会清除待重启提示。

默认由播放网关带动队列预加载：`queueWithGateway` 为 true 时，启动网关会开启队列；停止、运行故障及加速失败撤销网关时，等待队列停止并撤销队列来源需求。为 false 时，网关不启动队列。队列启停仅由网关生命周期管理。共享引擎由 Console 持有，懒创建后保留到应用退出。队列的 `desired` 表示实际启用意图，`running` 表示读取任务是否运行；日志读取失败单独报告，不改变 hosts 与网关共同决定的加速结果。手动下载不暂停或恢复队列。

引擎记录的首个本地存储故障通过状态接口 `storageError` 展示；无故障时省略该字段。WebUI 公共错误栏持续显示原因、停止新下载的影响及修复后退出并重新打开应用的步骤，本地视频能否读取取决于故障位置，不把数据库或视频盘不可用描述为仍可正常读取。修复目录、成功读取本地视频、启停播放网关或队列都不会清除此错误；新应用实例创建新引擎后重新判断。此字段直接读取应用打开数据库的结果、业务存储错误及已有引擎错误；没有视频引擎时仍显示数据库故障，不额外持久化，也不改变表示配置差异的 `restartRequired`。

首页与托盘的「开始加速」共用同一完整流程：先检查已知缓存工作区故障并完成安全的延迟清理，再检查及配置 hosts 接入、启动网关、复核就绪后开始游戏请求检测；前置检查失败不申请 UAC、不修改 hosts。后续失败撤销本次变更，保留原有接入及已运行网关。已有正确 SWD 映射时，缺少退出恢复权限不阻止加速、不申请 UAC，恢复权限由游戏连接状态中的「修复」单独准备，具体见 [hosts 契约](console.md#hosts)。缺少映射仍按原流程授权写入，冲突仍拒绝覆盖。首页和托盘运行时显示「停止加速」，停止后显示「开始加速」。停止共用 `/api/activation/disable` 对应的生命周期流程：HTTP 播放和 HTTPS 透传均停止，队列随网关停止；恢复直连选项开启时复用已有助手移除本程序托管映射，关闭时保留接入。停止不创建助手、不请求 UAC，助手继续驻留供下次开始加速复用；恢复失败仍停止网关与队列，并明确报告原因和实际接入状态。共享引擎及独立手动下载保持运行。外部控制提供开始／停止加速、恢复权限准备、退出与重启入口，不另开 hosts 写入／恢复或队列控制接口。

加速状态的 `activation.error` 保留完整操作错误，`activation.connectionError` 单独报告接入检查、授权、复核、回滚及停止时恢复直连的错误；不存在时省略，不持久化。新一次启停操作开始时清除旧接入错误，失败后保存本次原因，成功后保持为空。主动修复取得恢复权限后，仅清除此前停止时因缺少该权限产生的接入错误，依据内部错误来源判断；保留检测窗口、历史操作错误及其他故障，取消或失败不清除。视频服务继续由 `cdnError` 和当前端口检查报告，队列继续由 `actionErrors.queue`、`queue.logError/error` 报告故障。目录可读取且监控已启动即视为正常，`queue.file` 仅用于说明当前日志或等待日志出现；空目录、旧日志及日志暂未更新不构成读取错误，过期队列仍按[日志队列规则](queue-prefetch.md#日志检测与频率)撤销。端口启动与接入回滚同时失败时，各自状态保留自己的原因，完整操作错误仍包含两者；前端不解析错误文案猜测归属，也不把历史请求失败视为当前组件故障。

状态接口的端口可用性与网关运行状态取自同一次快照。端口空闲或已由当前网关持有时视为可用；引擎仍在初始化时保持「启动中」，不把自身监听报告为冲突，也不提前报告「运行中」。绑定、释放与端口探测共用状态锁，引擎初始化与连接排空仍在锁外；其他监听者即使属于同一进程也照常报告冲突。启动失败和停止时释放监听并清除归属。

常规设置提供「启动程序时自动开启视频加速」（`autoAccelerate`，默认 false）；下载与缓存设置提供「随视频服务启用队列预加载」（`queueWithGateway`，默认 true）。保存后重启生效，不是即时操作开关。自动加速每进程执行一次，与首页和托盘手动加速共用接入、网关和回滚流程，可能请求 UAC。刷新网页、激活已有实例或重复调用启动入口不会重试。

常规设置的「停止与退出」提供「随 VRChat 退出」（`exitWithVRChat`，默认 false；缺失或 null 同样关闭），保存后重启生效，配置格式仍为 v8。开启后独立观察当前 Windows 会话中的 `VRChat.exe`，不依赖加速、队列、日志目录或条款后的网络启动。先开 SWD、尚未开游戏时继续等待；本次运行须先成功监测到游戏，才会随其退出。

发现游戏使用 Windows 会话进程枚举；取得进程句柄后，通过原生等待接收该进程结束或 SWD 取消的信号，游戏运行期间没有定时枚举。句柄只申请 `SYNCHRONIZE` 权限，不请求提权或读取游戏内存；打开后再次核对 PID 仍属于当前会话的目标进程，避免枚举与打开之间 PID 复用导致等待无关程序。只需等待一个已知实例：它结束后立即重新发现其他或重启的实例，仍有实例就继续等待；没有实例时等待 2 秒并复查，仍为空才请求正常退出。尚未发现游戏或监测失败时，每 2 秒重试发现。失败记日志、撤销缺席确认，不把未知当作退出；SWD 退出或重启会唤醒原生等待，并在释放句柄后结束监测。

正常退出、崩溃和强制结束共用上述系统进程结束信号；切世界、日志停更、旧日志退出消息及启动器结束不触发。确认窗口内重新发现游戏会取消退出判定；游戏重新启动超过该窗口时，SWD 可能已开始退出。此机制只适用于 Windows；进程存在不代表游戏正常响应或已经进入房间，也不进行程序路径或签名认证。

随游戏退出复用 `RequestExit` 及应用的统一退出流程：网页收到现有生命周期通知，网关、队列、下载、导入与后台任务正常停止，数据库及临时资源按既有规则收尾，hosts 按最近成功保存的 `restoreHostsOnStopOrExit` 处理，不重新请求 UAC。不会等所有下载完成，也不终止任何游戏进程。监测在 SWD 退出／重启或清理开始时停止，后到的游戏退出不改变已经接受的重启决定。

自动加速根据有效条款记录与已保存的 `autoAccelerate` 执行。程序启动时已有有效记录则执行一次；尚未同意则保留本进程的待启动意图，明确同意、成功保存并完成条款后的网络启动后再消费。关闭自动加速时不启动；重复确认、刷新网页或再次调用启动入口不重复执行。自动加速失败不自动重试，用户处理原因后可手动一键加速。旧引导进度、回执及待续接导入不再参与启动。

首次确认条款后，如果内嵌代理或网络监测启动失败，已保存的同意仍有效；界面说明启动失败并提示修复后重启，不误报同意记录保存失败。该进程暂不消费自动加速意图，避免在代理不可用时自动开启；内嵌代理的启动错误也保留在当前设置状态中。Mihomo 的选择缓存打不开只提示本次选择不会保存，不视为代理启动失败，不阻止 Console 或自动加速；缓存生命周期见 [Mihomo 选择缓存](mihomo-dashboard.md#配置和运行)。

配置版本 8 使用上述字段，缺失或 null 时 `autoAccelerate` 默认 false、`queueWithGateway` 默认 true，明确保存的布尔值保留；不读取或迁移旧自动启动字段。版本 7 及更旧配置拒绝打开并保留原文件。

待应用配置会显示「立即重启并应用」。有尚未保存的表单更改时按钮禁用。重启请求使用现有 Host、Origin 和会话令牌校验；先返回响应，再由程序入口停止服务与任务。`run()` 返回并完成全部延迟清理（包括配置锁、桌面单实例锁及日志文件）后，`main()` 才启动替代进程。

重启保留绝对配置路径及托盘模式，避免重复打开浏览器。默认启动在重启时直接传递并优先复用本次网页服务端口，即使端口记录未能保存也一样；端口不可用时由系统分配，旧页面无法跟随新地址时可从托盘重新打开。`-no-tray` 模式下，若保留了标准输出，可从中查找新地址；日志级别为 `info` 或 `debug` 时，也可查看最新 `console_ready` 记录的 `url` 字段。显式 `-listen` 启动的重启继续使用本次实际地址，无法监听时报告错误。页面等待原地址的新实例会话令牌出现后刷新；响应丢失不会重复发送重启请求。60 秒内未确认新实例时显示手动恢复提示。批量任务不自动续跑；按已保存的自动加速和队列随动配置启动，仍受使用条款限制。退出和重启同时到达时，首次被接受的操作决定结果。

托盘退出、外部 Windows 窗口关闭请求（`WM_CLOSE`）、WebUI 退出／重启、已确认的 Windows 会话结束及条款页超时共用同一退出决定；后到的请求回执返回实际生效的 `action`，不会将已接受的退出改为重启。内部取消通过独立托盘消息执行清理，保留已有退出决定，不将故障收尾误报为主动退出。`/api/lifecycle` 是只读 WebSocket，每个 WebUI 文档一条连接，先发送当前状态，决定退出／重启后推送 `action: exit/restart`；`running` 仅表示尚无退出决定，不作为后台健康检查。订阅不依赖当前页面、可见性或条款接受，不启动业务任务；校验 Host、同源 Origin 和 Fetch Metadata，不在 URL 携带会话令牌，也不接收业务指令。

通知表达“退出／重启已被接受”，不证明清理成功。收到通知与收到操作回执共用一个前端处理入口，停止业务刷新和事件订阅，迟到结果不覆盖已接受的决定；重启等待只启动一次，确认框等待期间收到退出决定后不再提交旧操作。通知连接意外断开不改变后台健康判定，下一次成功读取状态时尝试恢复订阅；离开文档释放连接，页面恢复时重新连接。未收到通知时继续按状态请求的实际结果显示读取／更新失败，不能据此认定程序崩溃或正常退出。WebSocket 不占用现有 SSE 的普通 HTTP 长连接槽位；复用锁定的 `coder/websocket`，不引入通用消息总线或持久队列。升级连接由应用显式收尾，通知写入有期限，写完直接关闭连接，不等待网页回应关闭帧；最终清理仍有宽限，慢网页不阻塞退出。订阅在握手成功响应发出前登记，关停开始后拒绝新的升级；已获准但握手尚未返回的订阅也纳入通知与清理，宽限耗尽后取消。未经过已接受退出请求的清理只关闭连接，不补造正常退出通知。

数据库文件（databasePath）与完整视频目录（videoDir）独立配置。首次打开时，应用自动准备实例下的 data/database/storage.sqlite 与 videos，并将相对路径写入配置，立即供曲库、收藏、历史、后台资料同步及下载等入口共用；无需进入设置、手动建库或重启。两项仍为空的未配置实例同样适用；其他已有设置保留。数据库初始化不启动视频引擎、请求采集或网络访问，其他辅助文件仍按功能需要生成。

临时视频缓存父目录以 `blockCacheDir` 独立保存，缺失、null 或空串使用 EXE 旁 `work/`。设置的「下载与缓存」页可选择已有可写目录或恢复默认，保存后重启生效；目录切换不移动视频或临时块。新选择时检查类型、权限和工作区与数据库、视频及程序数据的隔离；权限预检覆盖所选父目录、已存在的工作区或需要创建工作区的目录，之后权限仍可能变化。其他数据盘无法解析时仍可选择缓存目录，已能解析的路径继续检查别名和重叠。配置读取成功时，默认和自选工作区都遵循同一规则：启动时无法核验的数据路径不记为缓存故障，工作区持锁但暂不清理，待所有相关路径可核验后、启动视频引擎前复查隔离并清理。配置读取或校验失败时不能信任自选路径，沿用原有启动规则仅尝试清理默认实例工作区，无法核验配置中的数据路径。未变化位置不因失联阻止无关设置保存。工作区自身不可用时状态接口的 `workError` 提示路径及原因，界面仍可更改位置；修复原目录后需退出并重新打开应用。不启动依赖工作区的视频引擎，不静默换盘。运行中发生的块读写故障继续通过现有 `storageError` 报告。

改变位置时，配置原子保存 `pendingBlockCacheCleanup` 以记录当前实例旧位置；启动在资源边界检查及独占锁保护下只清理记录位置中本实例的已知块。旧位置不可用或其他数据路径尚无法核验时保留记录供下次启动重试；成功清理或确认工作区不存在后移除记录。不会递归扫描所选父目录、删除未知文件或自动搬迁；详细布局和备份边界见[存储约定](storage.md#配置实例与路径解析)，验证范围见[临时缓存位置验证](validation/block-cache-location-20261104.md)。

启动存储准备统一负责补齐一个或两个未指定的位置；配置读取不创建资源，业务读取和状态展示不自行推断缺失项的处置。补齐后复用路径组合校验及设置保存的视频策略检查：隐式默认数据库存在数据库文件或 SQLite 伴随文件时不接管；默认视频位置已有完整视频，或新数据库将管理明确指定目录中的已有视频时，等待确认，不启动视频管理。明确指定的数据库仍严格打开；丢失、为空、损坏或版本不支持时只报告故障，绝不改建空库。明确指定的视频目录不可用时不回退默认位置、不创建替代目录；已打开数据库的歌曲资料功能仍独立可用。所有检查通过后只创建缺失项需要的新资源，成功后用现有配置保存流程记录实际位置。待确认是预期拒绝，不产生桌面故障通知；真实初始化故障保留独立原因。不探测历史布局或旧安装标记，不解析迁移旧配置，不扫描任意外置资源；未知文件原样保留。自定义位置继续保存后重启生效：设置中的新建操作只创建数据库，不保存或启用配置，也不创建视频目录；打开已有文件不补表。新选择的数据库先只读验证 v8/v9 格式资格，新选择的视频目录在保存时可以创建；未变化的位置不做可写性探测，失联视频盘不会阻止无关设置保存或被重新建为空目录。

程序目录内仅允许当前实例的默认数据库、完整视频和临时缓存位置；自选位置应在程序目录外，选择已有资料与新建共用路径规则。缓存按用户所选的父目录检查（默认使用 EXE 旁 `work/`），不能与完整视频目录相同或互相包含；数据库文件不能位于这两个目录内。允许三个位置共享上级目录，路径包含判断使用操作系统路径语义，并检查可解析的符号链接和目录联接；配置文件内的相对路径仍以配置父目录为基准，不按字符串形式决定是否合法。VRChat 日志和导入来源属于输入，不套用这组存储选择限制。

选择或恢复默认时，所选位置进入草稿，并与其他字段当前草稿一起检查；存在冲突时在相关字段显示错误图标及高亮，保存拒绝此草稿；调整任一位置后复查整组草稿，合法后清除标记。选择器等待或检查期间的路径变化，以及轮询收到其他页面已保存的位置变化，都以最新合并草稿复查；复查完成前禁用保存，过期响应不能覆盖新结果。选择的新数据库尚不能合法创建时只保留路径，草稿合法后在保存时准备数据库；放弃草稿不会创建尚未准备的数据库，恢复默认也不建库。数据库在新建前还检查当前生效及已保存的位置，避免新文件进入仍可能使用的目录。保存时在生命周期锁下对本次修改合并最新已保存值，再由后端复核，避免其他页面或路径别名变化绕过约束。之前已保存的组合不因新增选择规则自动失效，也不阻止无关设置保存；重新选中未变化的已保存位置不按新增选择规则报错，其他变更位置仍须检查，原有的数据库文件检查、工作区隔离和安全清理检查继续生效。现有数据库在实际打开时迁移 v8 或验证 v9，视频目录继续验证类型与可用性。

数据库为 v9：已有配置打开受支持的 v8 库时，在可写打开入口[静默一次性迁移](storage.md#v8-到-v9-的静默迁移)；选择其他 v8 库时先只读检查格式资格，不读取旧库业务数据或提前修改，保存后仍按原有重启边界打开并迁移。成功不新增迁移确认或通知，失败沿用存储错误反馈；原有视频保留策略确认继续生效。更早数据库格式仍拒绝，配置格式仍为 v8。

WebUI 所有本地路径共用 Windows 原生选择器。点击只读路径框直接选择，旁边仅有“恢复默认”；系统窗口内可导航、输入路径或创建目录。数据库、视频和缓存选择／恢复默认共用后端位置规则，`/api/storage/validate-location` 只检查当前草稿并返回警告，不创建或保存资源。SWD 数据库通过同一个文件对话框选择已有文件或新文件名，确认按钮为“选择”，不提供覆盖提示；草稿路径合法后 `/api/storage/prepare-database` 再次检查组合并只读验证现存数据库，仅对不存在的新文件调用已有建库机制，损坏、版本不符或不可读文件保持原状并报错。位置检查和数据库准备沿用普通 API 的 15 秒超时；超时保留草稿并允许调整或放弃。数据库准备超时只报告结果未确认，不自动重试，重新选择时检查已有文件。已保存或当前生效的数据库文件丢失时，选择原路径仍报错，必须恢复原文件或另选新文件名。数据库选择不保存或启用配置，也不创建视频目录。VRCX 使用文件打开对话框，完整视频、临时缓存、视频导入和 VRChat 日志使用目录对话框；视频导入和 VRCX 读取均需另行触发。

恢复默认只更新本处草稿，不启动选择器、建库、搬迁或导入。数据库和视频回到实例默认位置，仍需保存／重启；日志恢复自动识别（`vrchatLogDir=""`），选择目录则将路径保存为 `vrchatLogDir`。VRCX 清除自选路径并释放旧预览，重新使用检测得到的默认路径；视频导入清空来源。统一选择接口 `/api/path/select` 校验会话、来源和条款，整个程序同时只允许一个选择窗口。前端使用可取消等待，后端保留 5 分钟上限，避免普通 API 的 15 秒超时中断查找；关闭选择器保留草稿，关闭页面或退出程序取消对应请求和窗口。原生窗口继承所属窗口的 SWD 图标，复用内嵌 ICO，经标准输入传给助手，不落临时图标文件。

变更数据库或视频位置且目标已有完整视频时，保存前必须确认当前保留策略和所选数据库中的收藏依据。复用失联视频位置但切换数据库时也需确认，以防磁盘恢复后直接按默认零预算管理。`/api/storage/check` 返回是否需要确认；保存请求的 `confirmVideoPolicy` 则携带确认框中对应的 `databasePath`、`videoDir`、`videoStorageMode`、`videoBudgetBytes` 和 `retainFavorites`，无确认时省略。后端在同一生命周期锁内对照合并并规范化后的实际保存值；不匹配则拒绝保存，刷新状态后由用户重新确认。无关字段仍按部分更新合并，不能用布尔值代替具体确认内容。

存储待确认提示中的「确认并保存」只补齐草稿中缺失的数据库和视频位置，不替换已有选择，复用位置校验、数据库准备、视频策略确认与普通设置保存；不调用路径选择器。已有视频仍需在原策略确认框中确认，取消不保存配置，数据库准备失败定位到数据库字段。保存后移除一键确认入口，提示重启后应用；运行实例的待确认或故障状态仍保留到重启。确认仅属于本次保存请求，不形成永久配置字段；保存与新建均不启动引擎或淘汰旧视频。「不保留视频」不禁用位置编辑。两个位置均在重启后生效，不自动搬文件。

存储、网络等运行配置统一在设置页校验保存，并由现有重启流程应用。视频和 VRCX 导入独立在曲库执行，使用当前生效目录。视频导入恢复固定清单和已保存回执，未完成任务重启后等待手动继续；不自动导入或删除源文件，规则见[视频导入与恢复](video-import.md)。VRCX 导入不跨重启恢复。

「停止加速或退出时恢复游戏直连」（`restoreHostsOnStopOrExit`）默认开启，缺失或 null 采用默认值，明确关闭则保留。它是保存即生效的停止／退出行为配置：草稿不改变策略；由关闭改为开启时，保存先准备当前托管接入的恢复权限（复用助手，缺少时才请求 UAC），再原子写入全部配置。网页在开启此选项的保存请求中沿用授权操作的 120 秒等待期限，并提示可能出现的管理员授权；超时只提示结果未确认，保留草稿供核对，不自动重试。权限准备或写入失败保留旧配置和旧退出策略；权限准备不修改 hosts。保存成功后同时更新 saved/active 中的退出选项，单独更改它不要求重启；同次提交的其他运行配置仍待重启。退出请求携带已提交策略交由已有助手执行，不在退出时申请 UAC。默认恢复后，重启按自动加速设置重新接入；关闭自动加速时可手动一键开启。权限助手和失败边界统一见[hosts 契约](console.md#hosts)。

常规设置中的「启动程序时自动打开 WebUI」（`autoOpenWebUI`）默认 true，决定普通桌面启动是否打开浏览器；保存不即时开关页面。尚未同意当前条款或同意记录失效时，即使该设置为 false，也自动打开条款确认弹窗；不改写已保存的偏好。正常启动时显式 `-no-open` 优先，网页发起的重启继续传入该参数复用原页面；托盘主动打开和再次启动已有实例属于显式激活。

桌面程序遇到最终失败或需要处理的运行故障时，通过统一故障中心打开 WebUI，不受 `autoOpenWebUI` 或启动时的 `-no-open` 限制。已有 WebUI 文档保持 `/api/lifecycle` 连接时，消费本次自动打开请求并沿用页面的错误反馈，保留当前位置及未保存草稿，不再打开首页；后台标签页、条款及说明页面同样计入。不新增在线状态或轮询；关闭最后一个页面后，后续新故障仍可自动打开，已消费的故障不会因关页而补开。普通启动的自动打开也沿用此判断；托盘主动打开和再次启动已有实例的显式激活不受影响。

故障通知按业务错误语义判断，不从 HTTP 状态码、响应文案或日志级别推断。管理读取或独立处理函数显式保留需要上报的原始错误；共用操作入口记录业务操作返回的运行故障。无效输入、字段校验、忙碌、过期页面／草稿及缺少确认等预期拒绝由共用 `requestRejection` 错误标记表达，只保留当前请求的原有反馈；主动取消授权及生命周期取消同样不新增故障，也不清除旧故障。混合错误中仍有真实运行故障时继续上报，保留错误链和脱敏响应文案。批量任务因视频存储预算耗尽停止只保留任务结果，不触发故障、不证明旧故障恢复；同时发生的歌曲执行失败或任务记录写入失败仍报告。

中心合并同一来源持续故障和不同来源传播的同一原因，只有对应业务来源明确恢复后，再次失败才算新故障。操作来源在分发处按业务职责明确指定，不再按 URL 第一段合并不同业务；网络测速、连通性检测、SOCKS5 检查及取消操作分别记录，成功取消不代表启动失败已恢复。设置保存和主题保存共用配置写入来源，加速启停、视频导入控制继续共用各自现有业务来源和错误展示；异步任务故障仍由任务最终结果负责，不能由请求受理成功代替恢复。

运行故障来源包括配置和启动失败、工作区及数据库故障、自动／托盘加速与管理操作失败、任务最终失败和日志写入失败。后台仍在重试的单次失败不作为故障；房间队列日志连续三次读取失败后触发，读取恢复或停止队列清除该故障。连通性检测按项目判断，同一项目至少一个实际来源可用即不报告故障；手动检测所有已尝试来源失败时触发，自动检测须连续三轮失败，历史保留或跳过的结果不计入。程序日志写入恢复后再次失败也可重新触发。上述通知分类不改变原有重试周期、配置修复能力、响应状态码和用户文案。

已确认的不同程序或配置实例冲突不进入恢复服务：使用 Windows TaskDialog 说明冲突，关闭提示后结束本次进程，保留已有实例。冲突详情保留已有实例的程序位置与 PID；配置位于该程序旁的默认 `config.json` 时省略配置路径，仅自定义配置显示该行。正文为「本次启动已取消。请先退出正在运行的 SWD，再重新启动。」；冲突弹窗通过 TaskDialogIndirect 的 cxWidth 设置为 220 对话框单位，由 Windows 按字体与 DPI 排版，其他错误保持系统默认宽度。其他启动故障导致正常 Console 无法构造时，独立回环服务使用同一套嵌入式 WebUI，显示「启动失败」与具体原因，不轮询不可用的业务状态接口，不加载业务资源。公开文档与退出仍可用，未核验条款时不宣称已经同意。

恢复模式直接使用正常的 `SettingsAndNetwork`／`SettingsPage` 设置页，常规、存储、下载与缓存、网络的布局、字段及操作没有独立副本。仅通过 `GET /api/recovery/settings` 获取配置和目录元数据，操作复用正常的设置、路径选择、存储准备、代理导入等接口与处理函数，不伪造正常运行状态。

两个启动入口共用 `settings_editor.go` 中的配置编辑初始化和 `settingsHandler` 操作入口；恢复路由只接纳该入口明确提供的配置操作，不再转发通用业务动作路由。配置编辑需要的身份、生命周期、已保存配置及权限助手在此集中初始化，业务存储和运行服务仍由正常启动另行构造。前端 `SettingsEditor` 统一提供快照、草稿、可用性和编辑策略，表单不根据数据来自正常／恢复接口推断行为；正常页面各自创建草稿，恢复页提供共享草稿，不额外创建闲置的本地草稿。

设置能力以整页为单位开放：当前版本、完整且类型正确的配置，且恢复服务持有独占配置租约时，所有设置操作均可尝试；格式损坏、类型不符、版本不兼容、无法读取或被其他实例占用时，整页不可编辑并说明原因，不以默认表单替代无法解码的配置。语义无效的原值与字段错误继续显示。只读打开和校验不改写原文件。恢复页采用一份跨分类草稿，避免多处无效配置相互阻止保存；任何分类的保存／放弃作用于本页全部设置草稿，校验会转到首个错误字段。主题也先进入这份草稿，保存成功后应用；正常模式的分分类保存与主题自动保存行为保持不变。

服务端拒绝设置时，先显示所属分类及字段错误，等保存请求和后续配置刷新完成、控件恢复可用后再聚焦。恢复托盘读取已提交主题并复用正常托盘刷新机制；草稿或保存失败不改变托盘外观。恢复页面初始主题使用同一已提交值，配置不可读或主题无效时显示系统主题，仍保留设置中的无效原值供修正。

恢复设置读取失败的文案与页面已有启动原因完全相同时，只展示一次；另外发生的接口、权限或配置租约错误仍单独显示。曲库在数据库尚待确认且没有真实存储故障时，沿用黄色提示与设置入口，暂停依赖该数据库的曲库／清单读取及刷新，不显示通用读取失败或持续加载。只有视频目录待确认、数据库可用时仍允许读取曲库；真实故障继续保留错误反馈。清单接口也将尚未接管数据库视为待确认，不制造另一个清单读取故障或伪造已统计的覆盖率。

修复保存与正常设置共用字段／跨字段校验、资源路径冲突与变更位置校验、凭据保护、未知字段保留和原子写入机制。恢复服务在租约内串行重新读取、合并提交字段、校验及写入；部分更新不会覆盖其他页面已保存的无关字段，手工编辑成无法解析的文件也不会被旧快照覆盖。限定保留期必须大于 0、限定视频预算必须大于 0、代理模式所需连接参数等始终成立的约束共用 `normalizeSettings`。旧位置与新选择的兼容边界仍按原有存储契约，仅更换位置时执行选择约束，不因修复无关设置追溯拒绝旧路径。

新建数据库、选择已有库、导入 Mihomo 配置、修改停止与退出策略均复用正常设置流程。选择及准备存储位置仅校验相关路径，不被尚未修好的无关标量阻塞；完整保存仍要求合并后的配置通过全部校验。数据库创建不覆盖原文件；目录切换仍需视频保留策略确认；Mihomo 使用现有独立校验进程和加密草稿提交机制，校验可能访问网络和缓存目录，但不启动代理服务。退出策略开启时按现有条件准备权限，取消或失败不保存；恢复服务关闭时按成功保存的策略结束权限助手，清理失败继续报告。正常业务的条款门禁不因此解除。

缓存位置变更沿用待清理记录，实际清理仍由正常启动的安全检查处理。保存失败不发布成功快照；保存成功只表示设置操作完成，不表示下一次启动一定成功。点击「重启并应用」前重新读取并校验配置，关闭恢复服务、释放配置及实例租约后启动替代进程；原页面等待新会话并自动刷新。资源故障仍可能使下一次启动失败。恢复入口不开放加速、下载、曲库等业务操作。

恢复模式的托盘与网页退出请求不等待配置事务锁；先按既有生命周期协议通知应用关闭，再由 `BeginShutdown` 取消请求、路径选择和权限准备，`Close` 等事务结束后清理权限助手并释放租约。因此进行 URL 导入或等待权限准备时仍可退出。重启仍须等待当前配置事务完成并重新校验，不能跳过未完成的保存直接重启。

恢复服务优先复用重启端口，否则选择可用的回环端口。恢复网页要求成功取得并登记桌面实例、创建托盘，托盘就绪后才打开浏览器；实例身份／管理、托盘、本地服务或打开浏览器失败时，先清理恢复资源，再由桌面入口显示 TaskDialog，不保留无托盘的恢复网页。托盘意外结束时同样关闭恢复服务。所有启动失败恢复页统一在最后一个网页断开 60 秒后退出并移除托盘、释放租约；期间任一页面重新连接就取消倒计时。托盘就绪后浏览器始终未连接也按 60 秒退出。正常运行期间的故障提示页不采用此规则，已同意条款的正常后台仍可驻留。仅 TaskDialog 创建失败时保留 MessageBox 作为最后的错误显示方式。程序清单默认声明 Per-Monitor V2；TaskDialog 与托盘复用线程级 DPI 作用域，在创建窗口前设置 PMv2，结束或失败后恢复调用线程原状态。路径选择器独立进程继续使用自身的 PMv2 作用域。系统接受打开请求不证明窗口实际可见。显式 `-no-tray` 继续用于无桌面的开发／自动化运行，错误写入 stderr，不弹浏览器或系统对话框。

正常设置中的「主题」（`theme`）是程序级配置，接受 system/light/dark，缺失、null 或空值默认 system。选择后通过 `/api/settings/theme` 单独自动保存，沿用配置原子写入与生命周期锁；成功后同时更新 saved/active，立即应用网页、Logo、标签页图标和托盘，无需点击保存或重启。失败保留原配置与外观并报告错误。不提交其他设置草稿，不应用或清除已有待重启配置；普通设置表单不携带主题，省略时保留最新保存值。条款弹窗沿用已保存主题，旧浏览器 localStorage 不再作为依据或自动迁移，避免不同浏览器覆盖程序配置。


页面初始主题由 bootstrap 提供，已打开页面通过现有状态轮询同步其他入口的更改，每次新快照均校准本地外观，避免交错保存的延迟响应使页面停留在旧主题；托盘复用一秒状态刷新。选择浅色／深色时所有入口使用同一显式偏好；选择跟随系统时网页遵循浏览器的 `prefers-color-scheme`，托盘遵循 Windows 的 `SystemUsesLightTheme`，两者可因系统应用／任务栏模式不同而配色不同。系统主题通知与 Explorer 托盘重建均保留显式选择。

托盘右键菜单在每次展开时读取当前主题，与托盘图标使用同一深浅选择；已展开的菜单不承诺即时换色，下次展开生效。保持 Win32 原生绘制，底色、文字、悬停和禁用项由 Windows 配套呈现，高对比度优先遵循系统。深浅适配使用 Windows 10 1903 起的未公开 uxtheme 接口，仅在菜单生命周期内设置进程偏好并在关闭后恢复；旧系统或接口不可用时保留默认系统菜单，不影响操作。

## 代理面板的运行选择

内嵌 Mihomo 的完整配置导入与保存仍遵守上述重启契约。zashboard 仅操作当前核心的选择、健康检查与连接；选择不修改 SWD 设置，影响新连接，由核心 cache.db 按原生规则保存名称。首次确认条款前不启动核心健康检查。详情见 [Mihomo 与 zashboard](mihomo-dashboard.md)。

SOCKS5 地址格式由 `internal/upstreamnet` 共用检查，设置保存、配置加载和代理拨号使用同一规则：支持 IPv4、带方括号的 IPv6（可带作用域）、ASCII 主机名／域名（含 localhost）；端口须为 1～65535 的纯数字。首尾空白在设置规范化时移除，不接受协议前缀、路径、非法 IP、域名标签或带正负号的端口。格式检查不发起 DNS 或代理连接；可用性继续由当前运行配置的网络检测判断。
