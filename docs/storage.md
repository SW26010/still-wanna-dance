# 数据与工作文件存储

本页维护当前落盘与存储契约。本地资源管理的规则、接口及验证边界见 canonical 文档[下载需求与资源管理设计](download-resource-design.md)。

持久化整理的目标原则见[职责与边界](persistence-design.md)，实施步骤见[迁移计划](persistence-migration-plan.md)。数据库与完整视频目录已独立配置，块使用 EXE 旁固定工作区。桌面应用启动时准备默认业务存储，已有配置则严格打开所选数据库，元数据与个人资料操作不依赖视频引擎。桌面格式 7 的 databasePath、videoDir 首次自动采用默认位置，无需手动建库；自定义位置才需要在设置页选择，保存后重启应用，不自动搬运。初始化与已有资料保护的边界见[配置生命周期](settings-lifecycle.md)。CLI 使用 `-database`、`-video-dir`，明确建库另用 `-create-database`，详见[服务手册](service.md)。核心引擎也只接收已打开的数据库、已有视频目录和应用持有的工作区；不再保留混合根或隐式建库入口。

> 当前采用[曲库、资源关联与歌曲需求统计](song-catalog-design.md)模型。建议主库名为 `storage.sqlite`，两个入口均可选择文件名；SQLite `application_id=0x53574443`（SWDC）、`user_version=8`。版本 4 引入请求身份、响应范围、首正文分类与采集覆盖水位；版本 5 删除重复内容版本键；版本 6 收紧数据约束并清理持久化职责：所有表采用 STRICT，删除 media.source_path、请求来源及需求标记，明确可空请求身份，并停止保存预下载明细。歌曲资料列和清单摘要保持不变。版本 7 新增按块折算的三类响应来源字节（逐请求及累计），不保存可随块大小重新解释的块数。版本 8 将 songs 字段对齐 Udon、删除备选独有字段，并改用共同元数据摘要 v2。保留冻结的版本 2～7 DDL 与夹具，不实现开发期旧格式兼容或迁移。

[歌曲屏蔽与收藏](download-resource-design.md#8-歌曲屏蔽与收藏)通过独立偏好表保存；表结构及版本边界见[歌曲偏好存储](#歌曲偏好存储)。

MD5 文件身份以本页和[曲库设计](song-catalog-design.md)为准，演进背景见[早期 MD5 设计](history/md5-resource-design.md)；下载与本地保护遵循[下载需求与资源管理设计](download-resource-design.md)。无版本旧配置及旧数据库请保留备份，使用独立的新配置和存储目录；不要通过更名或修改版本号复用。

```text
EXE/work/<实例>/
  download-block-*.part
  .lock
所选数据库文件
  SQLite 必要伴随文件（若有）
所选完整视频目录/
  {md5}.mp4
  .swd-tmp/download-publish-*.part
  .swd-tmp/import-*/video
  .swd.lock
```

曲库和文件管理接口接收明确的数据库文件与视频目录；列表／删除凭据绑定两者，歌曲偏好绑定数据库位置。视频目录不可用时，歌曲资料仍可读取，本地视频状态及占用显示未知，不能按“已保存／缺失”筛选；缺失的数据库报错，不伪装为空曲库。每个数据库持有文件旁 `<数据库文件名>.lock`，每个完整视频目录持有其内 `.swd.lock`，块工作区保留自己的锁；锁范围不随数据库或视频目录名称变化。不再兼容开发期旧程序的父目录锁，旧测试程序应退出后再使用这些资源。数据库不得落在视频发布暂存范围、视频锁或受管 MP4 文件名位置，块工作区不能覆盖数据库或完整视频。

块存储不保留半块前缀、重试游标或重定向进度，不再有 32 个/512 MiB 的暂停检查点上限。读取按需打开块文件并持有短期引用，合并取得完整快照，旧清理不会删除后来替换的新文件；新会话使用调用方当前地址。块写入使用普通系统缓存，不对每块强制 Sync。「激进的缓存回收策略」开启时，完成写入、保护变化及保护到期触发逐块回收；保护判断与可用性移除在同一锁下完成，必要块 I/O 引用释放后删除，整份会话/reader 引用不扩大保护。策略显式保存 auto/on/off；auto 在「不保留」时开启，在「限制为」（即使已满）及「不限制」时关闭，on/off 不随预算变化。块收齐后先按视频存储预算、现有库存和共用资源评分取得预留，再合并校验；普通资源预算为零、单视频超预算或未进入保留集合时不合并、不校验，也不发布；开启「优先保留收藏视频」时，收藏可突破预算，全部关联屏蔽的资源不能发布。未取得资格不改变块的回收策略；合并快照前正常回收造成的缺块按未保留处理，不记为存储故障。

若保留块绑定旧地址的强 ETag，换地址时退出旧块注册并重新下载，防止旧实体条件阻塞新地址或混用未经确认的实体；旧读者引用继续有效。实体条件的适用边界以 canonical 文档第 7 项为准。

本地视频唯一身份是小写 MD5。歌曲 ID、URL 中的资源编号、版本、目录、线路和大小均不参与文件键。同 MD5 只保存一份文件，共享下载、容量记账和淘汰；多个歌曲 ID 可以指向同一个 MD5。不另建文件名映射表。

Range 与顺序 200 共用完整块文件存储；仅完整块写入并关闭后可读，未完成块不落盘保存。取得持久化预留后顺序合并，复制时计算一次 MD5，核对长度和 MD5 后同步、关闭并原子发布正式文件。后续假设文件不被外部修改，普通播放和扫描不再计算 MD5，也不依据属性变化重新校验。活动响应共用已打开的文件句柄、各自独立读取位置，最后一个使用者结束后关闭句柄。

歌曲资料以 Udon 为 canonical；备选清单只补缺失的歌曲—MD5 关联。新取得且时序有效的播放 API 观察可覆盖已有映射，不依赖视频下载或持久化成功；纯 URL 请求不猜测歌曲 ID。歌曲清单缺席不删除积累资料，当前成员独立存于 catalog_members。

ID 播放先检查屏蔽状态并在命中时返回 403；准入后的播放命中本地时立即返回，同时后台对照上游 URL 的 MD5；后台检查不替换文件、不打断播放。缺少映射或文件时解析 URL 并冷加载。URL 播放直接取查询参数 e 的 MD5 查本地，缺失时用该 URL 冷加载。

独立的 CheckReferencedFiles 函数把映射中的 MD5 去重，一次枚举目录后返回存在集合和缺失 MD5 及其歌曲 ID。忽略孤儿资源，不检查视频大小或内容。ReadLocalCatalog 只读取当前成员，缺映射歌曲单列待识别；单项目标读取不受成员限制。入口同时获取清单状态、歌曲与引用快照，在任务期间保护已知资源，任务结束释放；每次新任务重新检查，不缓存跨任务结果。外部文件删除仍可能导致实际播放打开失败。

| 表 | 内容 |

播放地址解析成功并通过 URL 校验后，`ObserveSongURL` 在同一事务中保存 `song_urls`，按 URL 的 `e`（MD5）把 `s`（字节数）写入 `media.byte_size`，并补齐占位歌曲、更新 `song_media` 当前关联。写入复用映射锁，与清单同步及映射快照串行；歌曲和资源外键延迟至事务提交时检查，使过期观察仍可在不修改资料的情况下退出。清单创建资源时未知大小仍为 NULL；只解析地址即可补齐，不需要请求视频正文或创建本地视频文件，持久化准入可直接使用这份关联计算歌曲分数。同 MD5 的多首歌曲共用一条资源记录。沿用已有资源写入规则，有效值可更新已知属性，缺失属性不抹掉已知值。

运行期上游监测也复用该入口：每次自动或手动探测播放 API 成功后，直接保存本轮所选歌曲的 URL 和大小，并按同一规则更新当前关联，无需再次查询 API。单候选和多候选通道均覆盖，API 键统一为无查询参数的地址，节点保存实际请求值 cf，已有历史 nya 记录保留但不用于当前下载；排序使用探测请求自身的起止时间，不以回调落库时间刷新旧响应。资源采样失败不撤销已取得的 API 证据和补缺关联；写库失败保留本地存储故障，不改变 API 健康判断。只刷新当轮实际探测到的歌曲，不追加整库批量请求，签名地址不进入状态接口。

探测样本从所有歌曲的缺项候选中选择，不要求已有 MD5：缺映射、`media.byte_size` 为 NULL/非正数，或同 API 的 cf 节点缺少当前 MD5 的非空、未标失败 URL。不同内容的旧地址不算补齐；地址只是超过 24 小时仍算已有元数据，不将全库重新变为缺项，实际播放继续执行原有时效/校验规则。按歌曲自身有效分数及同分歌曲编号从高到低补，不累加共享资源的其他歌曲分数。每批复用原请求探测一首，未补齐的失败项本遍先跳过、下一遍重试；齐备后恢复普通抽样。仅更新 URL/大小和当前关联，不推断其他歌曲字段、不下载完整视频、不产生需求分数，也不新增数据库字段。

仅接受查询发起时间严格更新的 URL 观察；较旧或同刻的观察不修改 URL、资源元数据或歌曲关联。事务内任一写入失败则全部回滚，并沿用本地存储错误处理。查询排序跨同一歌曲的全部 API/节点；新的有效观察可覆盖已有 `song_media`，无论来自清单还是较早 API。读取缓存不重新进入观察写入。URL 观察不产生播放统计；关联和资源属性已知不代表文件已下载或完成校验。

请求取消或超时可能令事务先自动回滚、随后 `Commit` 才返回 `sql.ErrTxDone`。仅在该错误与 `ctx.Err()!=nil` 同时出现时，将错误还原为上下文错误，避免误记持续存储故障而阻断后续冷加载。上下文有效时的事务结束错误，以及取消时并发发生的其他存储错误，仍按存储故障处理。

清单通过 Udon 和两个同级备选进入共同同步入口。较新完整候选更新歌曲资料、当前成员和水位；同版本优先 Udon，同级或同源冲突保留现状。较旧备选仍可补资源和映射空缺，不降低歌曲水位。歌曲摘要 v2 不包含 MD5，完整规范以[曲库设计](song-catalog-design.md#清单同步与增改不删)为准。获取失败保留已接受资料。

全量补齐每次获取清单并补充资料，只处理当前成员；已知相同 MD5 共用任务，无映射歌曲分别按 ID 解析。映射没变但文件已被淘汰仍会补齐。指定目标不受成员限制；已固定 MD5 与解析结果不一致时报告失败，不把其他内容当作完成。

资源分数是当前关联歌曲分数之和，孤儿资源为零分。映射改变不立即删除旧文件；容量超限时按分数淘汰，活动请求、下载的必要引用及统一块保护保持有效。有限需求进入本地保护提前窗口后保护数据，最后一份块需求结束后按配置延续（默认 300 秒，0 表示不延续）；任一块受保护则完整文件不可删除，不另设队列专属文件保护。淘汰只删除文件，保留关联和统计。文件发布与数据库提交不是跨资源原子事务，已发布的 MD5 文件即使没有元数据也可命中。

数据库、视频目录和块工作区分别持有 OS 排他锁。普通打开严格验证已有 v8，只有明确新建使用排他创建初始化结构；引擎借用应用业务存储，取得视频锁后清理发布／导入暂存并执行原有保留策略。固定块工作区先于文件日志和数据库准备并清理。离线删除复用应用业务存储并取得视频锁，不另开第二写连接。备份请正常退出后优先保存数据库及恢复所需伴随文件；完整视频按需保留，临时文件和锁不需备份。

本地视频列表展示当前歌曲关联；请求记录另存请求处理时的明确歌曲 ID 和资源身份，查询时不由当前映射推断或改写历史。列表最近访问保持原语义：长期保存的最后 GET 时间与保留期内 HTTP 请求明细取较新值；清理明细不丢失最后 GET 时间或歌曲需求累计值。

## 数据库打开约定

各类文件的备份、重建、损坏处理和安全回收条件见[运行文件生命周期](runtime-lifecycle.md)。

数据库与受管视频文件的路径冲突按当前操作系统的路径语义判断。Windows 上 MD5 或 `.mp4` 扩展名的大小写变化仍属于同一保留文件名，不能作为数据库位置；正式视频命名规则仍为小写 MD5 加 `.mp4`。该检查不改变数据库或配置格式。

数据库打开／新建、引擎启动和离线删除只按当前资源契约校验，不检查旧数据库标记、旧视频文件名或历史父目录布局。不符合当前受管命名规则的文件不参与视频列表、容量淘汰或清理，原样保留；符合 `<32 位小写十六进制 MD5>.mp4` 命名的普通文件即使没有数据库记录，仍纳入本地视频管理。数据库仍校验版本和结构，明确新建仍拒绝已有主文件及 WAL、SHM、journal，视频目录仍验证类型与资源锁；运行中的存储目录不应由其他程序改写。

所有数据库连接通过同一入口建立，路径在一个位置定义。本地视频列表、曲库、最近请求及流量统计使用只读连接，统一验证应用身份与格式版本；缺库时不创建文件，读取页面不补表或补索引。

只有明确新建操作才初始化不存在的数据库；该操作与视频目录是否存在无关，已有空文件也拒绝。共同创建入口取得数据库写锁后、创建主文件和连接 SQLite 前，检查同名 `-wal`、`-shm`、`-journal`；任何目录项存在或无法可靠检查时都拒绝创建，原样保留恢复资料，失败释放锁。当前身份、当前版本的库仅验证完整表、列、索引和约束，不补建结构。不识别的身份和不支持的历史版本报错；遇到未来版本，明确提示更新程序。失败不会改写格式标记或清理临时下载。当前没有迁移链；今后的真实升级需要在这个受控入口中明确实现，不能散落在业务读取函数中。

不再生成或依赖 `verification.sqlite`。下载大小和 MD5 校验、显式完整检查、活动文件句柄和并发保护保持有效，检查结果仅在进程内用于本次操作。盘上碰巧存在的旧校验库被忽略，不自动删除。

## 歌曲偏好存储

本节描述当前 v8 中的歌曲偏好结构（最初于 v3 引入）。需求准入、共享资源、收藏不触发下载及预算规则统一见[canonical 设计第 8 项](download-resource-design.md#8-歌曲屏蔽与收藏)，此处只维护存储契约。

在同一 `storage.sqlite` 中使用一张歌曲偏好表，已有 `songs`、`media`、`song_media` 及统计表不改列：

```sql
CREATE TABLE song_preferences (
 song_id INTEGER PRIMARY KEY REFERENCES songs(id),
 policy TEXT NOT NULL CHECK(policy IN ('blocked','favorite'))
) STRICT;
```

无记录表示普通；`blocked` 表示屏蔽，`favorite` 表示收藏，恢复普通时删除该行。主键保证同一歌曲的偏好互斥；写入时验证正整数 ID，缺少歌曲资料时在同一事务补建 `songs` 占位行。复用现有外键检查，不级联删除，不为未定义用途增加更新时间、历史记录或额外索引。

偏好是用户维护的曲库数据，随存储库备份和切换，不进入 `config.json`。曲库刷新、歌曲—MD5 关联更新、VRCX 统计初始化及视频清理均不覆盖偏好；它也不进入清单 `sha256-v2` 摘要。资源的收藏资格通过当前关联及 retainFavorites 配置推导，全部屏蔽状态通过当前关联推导，不新增资源名单表、资源分数副本或下载/完整性状态列；标记不等于文件已保存。

数据库格式已升为 v8，使用 `schema/storage-v8.sql` 和对应二进制样本，冻结的 v2～v7 DDL 与样本保留。继续不兼容、不迁移旧格式：旧库拒绝打开且不改写，请使用独立新存储目录。不能由业务读写自动补表或改版本号。请求字段允许未知值为 NULL；这不授权读取不支持的旧格式。当前配置格式为 v7；清单摘要为 v2。

偏好写入与 VRCX 历史初始化共用应用业务存储的数据库锁、严格打开和事务入口，不启动引擎或资源回收。明确新建只创建标准数据库；视频盘不参与建库判断。在线标记仍与发布、淘汰串行，数据库锁在应用停止消费者及引擎、排空已接受写入并关闭数据库后释放。

## Portable 文件契约与生命周期

本节是应用落盘位置和备份范围的统一清单。路径由 `internal/apppaths` 解析；软件版本变化不改变文件名。当前配置格式为 `schemaVersion=7`，媒体 SQLite 为上述版本 8。旧测试配置版本 1～6 不兼容、不迁移，不应手工改版本号继续使用。

### 配置实例与路径解析

应用只打开已有合法数据库，不根据库存、任务结果或空目录判断能否初始化。Monitor、收藏、历史和 VRCX 复用应用数据库，不启动视频引擎。缺失库明确报错；建立新库必须使用明确的创建操作。库存与任务快照仅供查看过去结果，不授权建库、恢复运行、选中项或删除。

令 `C` 为主配置的绝对路径，`B` 为其父目录，`R` 为实例数据根，`D` 为所选数据库文件，`V` 为所选完整视频目录：

- 默认 `C=<EXE目录>/config.json`，`R=B`，数据库和视频首次自动准备为 `data/database/storage.sqlite` 与 `videos`。
- 自定义 `-config <目录>/config.json` 同样以该目录为 R；其他文件名采用 `R=C.d`。例如 `profiles/a.json` 的条款与状态放在 `profiles/a.json.d/data/state/`，日志放在 `profiles/a.json.d/logs/`；默认数据库和视频位置分别为 `a.json.d/data/database/storage.sqlite`、`a.json.d/videos`。
- 同目录 `config.json`、`a.json`、`b.json` 的锁、日志、密钥、确认记录和状态独立。不要把另一个配置嵌套在已有实例的数据根内；共享同一实例根就是共享其附属状态。
- `-config` 参数本身的相对路径基于启动工作目录；配置内数据库、视频及手动 VRChat 日志的相对路径始终基于 B。保存时位于 B 内的路径转为相对路径，外部路径保留绝对路径。默认 VRChat 日志目录随当前用户环境解析。
- 工作区始终位于 EXE 旁 `work/`，桌面按规范配置路径、CLI 按数据库／视频路径组合区分实例；EXE 内的相对身份使整包移动后仍定位到同一实例区。不同入口分命名空间，不建立永久身份文件或新增用户设置。用户数据位置不能与 work 树相互包含。
- 主配置不能命名为保留的 `terms.json`、`channel.key`、`config.lock`、`data`、`state`、`logs`、`storage`、`videos`、`work`、`licenses`，也不能使用 `.swd-tmp` 后缀，避免覆盖规范配置和原子写入工作槽。
- 多个配置选择同一数据库或视频目录时，分别受对应 OS 锁保护；配置隔离不允许绕过资源排他所有权。

配置版本独立于软件发行版本。读取拒绝缺失、不支持或未来版本；保存前再次检查磁盘版本，并保留当前版本中的未知字段。设置 API 不能指定磁盘格式版本。配置、条款、库存/任务/吞吐快照使用每目标固定的 `.<文件名>.swd-tmp` 工作槽，排他创建、同步并原子替换；持有配置实例锁的启动流程只清理本实例已知工作槽。旧引导状态、未知名称和其他配置保留，异常类型拒绝且不递归清理，失败不覆盖已提交文件。通道密钥仅缺失时排他创建，损坏原文保留并降级为临时通道身份；不承诺所有文件构成跨文件事务。

默认启动只使用当前配置和资源路径，不探测或迁移历史安装目录与文件。明确传入的配置仍按版本校验，当前默认位置已有资料时不自动建库，未知文件原样保留。

## 清单内容摘要 v2

应用启动另行加载[预置资源快照](../data/media-seed/README.md)：事务内只补缺失资源、大小和歌曲映射，已有映射不回退。`catalog_state` 的 `media_seed` 行使用独立快照版本和 `sha256-seed-v1` 摘要，不推进 `songs` 水位，不生成成员或 URL。导入外部视频以 `media` 中已知 MD5 为准，无需歌曲映射或在线清单；超预算淘汰仍通过现有歌曲映射计算分数和偏好，无关联资源按零分处理。

`catalog_state.digest` 保存 `sha256-v2:<小写十六进制摘要>`。摘要输入固定为 UTF-8 前缀 `still-wanna-dance/catalog/v2\n`（末尾一个换行），后接规范化歌曲列表的紧凑 JSON。字段由独立的 `catalogDigestSongV2` 明确投影，不直接序列化业务类型 CatalogSong。

歌曲按 ID 升序。v2 投影只包含当前共同歌曲资料，排除 MD5、来源、上游时间和未知字段。可空标量区分未知与零值；volume 统一为 float32 可表示值；两个逐歌数组规范化重编码，保留元素顺序和数组内 JSON 数字文本，对象键稳定排序。显式 null 的 tag 与 Udon 空字符串 shader_motion 统一为空数组；未给出的字段保持未知。

字段顺序、名称及 Go encoding/json 编码由固定摘要回归约束。生产使用 catalogDigestV2；冻结 v1 投影移入历史契约测试。若新增参与摘要的语义，必须显式定义新投影并决定数据库格式，不能修改已有摘要含义。

## 持久化格式与语义

版本号不随软件版本递增，也不为了称作“v1”而重用试验期编号。开发期最早冻结基线是 SQLite **2**、配置 **3**；当前首发候选基线采用 SQLite **8**、配置 **7**、库存/批量/尝试快照 **3**、吞吐快照 **2**，不迁移旧格式。当前 SQLite 的完整 DDL 固定在 `internal/cacheproxy/schema/storage-v8.sql`，有效二进制样本在 `internal/cacheproxy/testdata/storage-v8.sqlite`；旧 v2～v7 DDL 与样本保留用于拒绝及不改写回归；JSON 样本在 console、upstreamstate 的 testdata 中。今后改变契约必须保留旧样本、明确新版本和升级决策，不能重新生成旧样本来消除回归失败。

### SQLite 字段清单

以下为完整表清单；类型、NULL、CHECK、外键和索引以冻结 DDL 为准。无显式默认值的必填列必须由写入方提供，未声明为 NOT NULL 的资料列允许 NULL。所有业务表采用 STRICT，INTEGER 为有符号 64 位，REAL 为双精度；业务端仅写有限分数和合法正整数歌曲 ID。数据库不承诺任意手工写入均有效。

| 表 / 身份 | 字段与来源、空值和单位 | 价值与关系 |
| --- | --- | --- |
| `songs` / `id` 正整数主键 | 可空 TEXT：name、artist、dancer、major、groupName；可空 INTEGER：playerCount、rpe；可空 REAL：volume、start、end；flip、double_width、skip_random、disable_public 为可空 0/1；tag、shader_motion 为可空合法 JSON 数组文本 | Udon 共同歌曲资料及父级分组信息，不含 MD5 或备选独有字段；清单缺席不删除记录 |
| `media` / `md5` | 小写 32 位十六进制非空键；byte_size 可空非负字节数 | 资源索引，不是文件存在/完整性的证明；与 MD5 文件相互独立 |
| `song_media` / `song_id` | 歌曲外键 → 非空 media.md5 外键；md5 索引 | 每首歌一条当前关联，多首歌可共享同一媒体；备选只补空缺，新的有效 API 观察可更新，显式 ID 下载完成仅补缺 |
| `song_urls` / `(song_id,api,node)` | 歌曲正整数、API/节点/完整 URL 文本、小写 MD5、正字节数；歌曲和资源分别外键关联 songs、media，均为 DEFERRABLE INITIALLY DEFERRED；query_started_at、observed_at、failed_at 为 Unix **纳秒**，failed_at 默认 0=未失败 | API 证据缓存，写入时在同一事务更新当前歌曲关联，仅新取得且时序有效的观察可覆盖已有映射；node 为实际 API 参数（当前固定 cf，保留历史 nya），URL 可带签名参数；不属于代理密码。24 小时内未失败且不在未来的记录才可使用 |
| `song_preferences` / song_id | policy 仅允许 blocked / favorite，外键关联 songs | 无记录为普通；用户标记不写需求统计，不触发下载 |
| `song_usage` / `song_id` 外键 | demand_count 非负累计次数；demand_score 非负 REAL；last_demand_at 为 Unix 毫秒 | 按歌曲跨域 GET 或用户显式 VRCX 历史初始化，30 秒去重、60 天半衰期指数累计；历史按原时间计算。明细清理后不能无损重算 |
| `song_playback` / `song_id` 外键 | transfer_count 非负累计次数、last_transfer_at Unix 毫秒 | HTTP GET、200/206、completed、正字节完成证据，按完成时刻 30 秒去重；不是游戏首帧或完整播放确认 |
| `catalog_state` / `catalog_key` | 非空主键，当前键 songs；revision 原始民用水位；digest 为 sha256-v2；source 溯源文本；accepted_at Unix 毫秒 | 接受清单的事务水位，身份/摘要不可随展示更名修改 |
| `catalog_checks` / `catalog_key` | 非空主键；checked_at Unix 毫秒，默认 0=从未成功验证；message/error 默认空串=无诊断 | 成功验证时间和最近错误；失败不把旧成功时间改成失败时间 |
| `catalog_members` / `song_id` 外键 | 当前已接受完整清单的成员 ID | 与 song_media 一起推导覆盖，不复制另一份成员资料 |
| `media_access` / `md5` | 小写 32 位十六进制非空键；last_requested_at Unix 毫秒，按 max 更新 | 最近 GET 事实；独立于歌曲归属、明细保留期，允许未被 media 收录的资源 |
| `request_events` / `event_id` INTEGER 主键 | resource_md5 为请求处理时的资源 MD5，未知为 NULL；MD5 同时表示内容身份和内容版本，不另存 version_key。host/method/range_header/cache_result/outcome 为请求证据文本；requested_at 为请求到达的 Unix 毫秒；file_bytes/transferred_bytes 非负字节，后者仅计实际写出的视频正文；elapsed_ms 非负持续毫秒；status HTTP 数值。可空字段：song_id 为请求处理时的明确正整数歌曲 ID，completed_at 为结束 Unix 毫秒，response_bytes 为本次有效响应长度（字节），first_body_ns 为单次首正文耗时（纳秒），first_body_blocking 为首正文前实际等块的 0/1；download_bytes/cache_bytes/local_bytes 为三类固化折算字节，三列同时已知或同时 NULL | 有界原始请求日志，歌曲及资源身份在处理时冻结，可空事实未知为 NULL，不靠当前关联回填；首正文样本仅在已实际写出视频正文时有效，不要求最终成功。按 resource_md5+requested_at、时间复合索引（requested_at DESC,event_id DESC）查询；同毫秒按 event_id 排序，清理后不承诺 ID 全局永不复用 |
| `request_observation` / `id=1` | started_at 为新口径开始采集的 Unix 毫秒；retained_since 为清理水位的 Unix 毫秒，初始 0=尚未清理，按 max 更新 | 与明细清理同事务推进水位，跨重启保留；与 72 小时窗口共同决定可用范围及不完整窗口提示，不表示持续在线时长 |
| `traffic_totals` / `id=1` | saved_bytes 非负累计命中字节；hits/misses 非负累计次数；download_bytes/cache_bytes/local_bytes 为非负累计折算字节，均初始化为零 | HIT/MISS 沿用 HTTP GET 成功完成 200/206 的事实；三类来源按已写出块计入，取消／失败不抹掉已计块。requests、命中率由二者推导。首正文统计直接来自 request_events 的单次有效样本，按到达时间最近 72 小时、实际等块／无需等块分组计算 P50/P95，不再保存 playback_latency 累计表 |

`request_events` 只保存 HTTP 视频请求，method 是 HTTP 方法，cache_result 是 HIT/MISS 等响应分类，outcome 为 completed/failed/canceled/incomplete/aborted 等结果；预下载只保留已有诊断日志，不写业务历史。这些诊断文本不是可扩展行为开关，未知值不得当成成功。累计计数不因删除视频或清理明细而重置。评分固定 `oldScore * 2^(-elapsed/(60 days)) + 1`；回拨或 30 秒内重复需求不计分、不降低 last_demand_at。未来改评分必须保持旧含义或随数据库版本明确重置/重算策略，不假设请求历史完整。

用户显式导入 VRCX 时可按[历史初始化契约](song-catalog-design.md#vrcx-历史初始化)整体替换 `song_usage`，非空统计需二次确认；提交点复查并与需求写入串行，失败回滚。只补必要占位歌曲，不修改媒体、映射、请求明细或配置；不增加表、格式版本、原始历史文件或持续同步状态。源 SQLite 只读并使用正常 WAL 快照，预览聚合及完成回执只在内存保留至过期。

请求身份独立于当前曲库，不加歌曲或资源外键；解析失败也可保存明确歌曲 ID。对外 JSON 继续使用字符串 ID／MD5 和空串表示未知，不丢失大整数精度。`counts_as_demand` 已删除：请求符合条件不代表通过 30 秒去重，不能据此还原累计次数。

### 时间与排序

- SQLite 真实时间点统一解释为 UTC Unix 毫秒，只有 song_urls 的三个字段明确使用纳秒，以区分同毫秒并发查询；纳秒范围必须可由 int64 无损表示。其新结果必须有严格更大的 query_started_at；同刻第一条获胜，较旧/回拨结果不覆盖新值。失败只能标记实际尝试的同一条查询。时钟回拨后未来观测不可复用，等待重新获取或时钟恢复。
- JSON 持久化真实时刻用 RFC 3339、UTC `Z`，允许 0–9 位可变小数秒，不按文本字典序比较。Go 零时间 `0001-01-01T00:00:00Z` 表示尚未发生；SQL 明确指定的 0 哨兵表示未知/未失败，不能展示为 1970 年。一般 SQL 时间不以 0 自动表示 NULL。
- `revision` 只接受 14 位 `YYYYMMDDhhmmss`，校验日历日期；不接受时区后缀/小数秒。用共同比较轴排序但不声称其真实 UTC 偏移；同水位同摘要等价，不同摘要冲突。该逻辑水位与机器时钟无关。
- 持续时间不编码为日期：吞吐 `durationNs` 是纳秒整数，请求 first_body_ns 是单次首正文耗时纳秒，请求 elapsed_ms 是毫秒。UI 用毫秒/秒/Bps 展示；song_urls 的纪元纳秒不作为 JSON Number 暴露给 JS，时间对象编码为字符串。不要把 SQL int64 原样新增到 JS 数值接口。
- 文件 ModTime 是 OS 文件属性，用于句柄/删除身份核对，非数据库事件时间、不保证跨文件系统精度。运行中计时优先 Go 单调时钟，持久化后不保留单调部分。快照读入偏移可解析，但再次保存规范成 UTC。吞吐冷却遇到未来 lastAttempt 时失效重采样，避免长期卡住。

条款凭据按保存顺序从旧到新排列，启动时反向逐条检查，找到当前用户能解密且用途、条款版本、正文摘要及时间有效的第一条即停止。单槽格式错误、损坏、无法解密或条款过时只跳过该槽，不影响其他槽；没有匹配项才要求重新确认。整个封套格式错误、空列表、超过 8 条或超过 64 KiB 均不授予同意；读取不改写文件。允许系统时钟回拨，确认时间不决定槽位顺序，也不证明身份。

只有用户点击“同意完整条款”才保存：重新读取现有列表，已有匹配凭据时复用原记录及时间，不重复占槽或改写文件；否则独立加密并追加，满 8 条只淘汰最早保存的一条，其余密文保留，包括其他环境无法解密和旧条款记录。原封套整体失效或格式不支持时，本次明确确认以新格式的一条记录替换，不导入旧格式。保护、读取、大小检查或原子写入失败时保留原文件，不授予新的同意；成功保存后才更新内存。单个已知原子工作槽及配置锁沿用现有机制，不增加凭据目录、用户身份索引或管理界面。

通道身份的 HMAC 输入为：

- 外部 SOCKS5：JSON 数组 `["socks5-channel-v1",address,username,password]`，输出 `stable-v1-` 加十六进制摘要。
- Mihomo 节点：`swd-mihomo-node-v2` 加 NUL 字节，再加原生连接参数的 JSON，输出同样的 `stable-v1-` 摘要。展示名、导入顺序和活跃上限 K 不参与身份；连接参数或凭据变化会改变身份。不强求跨格式/省略默认值等价合并；v1 身份域保留为历史，不迁移、不重置 channel.key。

DPAPI CurrentUser 不使用路径作为额外熵，不请求 UAC。同用户覆盖/移动可用；另一用户或普通独立机器可能不可用，但域用户漫游可能保留能力，**不是绝对设备绑定**。非 Windows 无明文替代方案：保存密码或节点快照明确失败，已有封套显示不可用。强制代理的不可用凭据使代理拨号失败；Auto 保留允许直连/代理回退的策略，不篡改保存的偏好。节点连接参数及凭据已由整份快照保护；未来增加令牌、私钥、带认证订阅 URL 同样必须保护，不落盘原始导入副本。

配置中的 `logLevel` 保存为 `off/error/warn/info/debug`，缺失、null 或空串默认 info；保存后重启生效，配置格式仍为 7。关闭日志不删除已有文件，不改变请求明细保留规则。

诊断日志也使用 RFC 3339 UTC 时刻，但不是恢复业务状态的格式；错误文本和事件属性可以随实现变化，不为日志增加用户数据迁移版本。

### 打开、失败与未来升级

普通打开只验证已有数据库的身份、版本和冻结结构；零字节、缺失或损坏文件报错，不补表／索引、降版本或隐式建库。缺库时可选择原数据库或恢复数据库及必要伴随文件，不要求一律恢复完整视频备份。明确新建与普通打开分开：仅在满足创建条件的位置初始化，已有视频不授权重建数据库，也不妨碍用户明确另建新库；接入已有视频仍须确认保留策略。全新初始化使用一个 SQLite 事务写 DDL、初始累计行和版本；中途失败回滚，不在失败路径清理下载文件。数据库锁覆盖初始化和整个可写连接寿命；只读入口不建库。未知对象或结构改变同样诊断，而不是当作可随意重建的数据。

数据库入口要求普通文件、可确认的单一硬链接名称和实际完整路径；写入及只读入口共用检查，多硬链接文件和短文件名等非规范别名明确拒绝，文件保持原样。普通大小写和词法路径处理沿用原规则，不静默改变已选数据库的作用域，不新增身份登记库；视频导入仍可使用硬链接。程序使用中的数据库和伴随文件不得由外部移动、替换或改名。

本次没有伪造 v1→v2 或配置 v2→v3 迁移。将来正式发布的旧格式若需要升级，应在该唯一打开入口持锁检查身份后、启动业务前实现针对性事务步骤，保留旧样本并测试成功/失败回滚和降级拒绝；迁移结果必须与目标版本新建库通过同一冻结结构校验。当前 v8 已有仅用于测试的后继格式重建演练，覆盖失败回滚及重试、全表剩余数据保持、版本提交和降级拒绝，不代表已提供产品迁移链；配置升级应原子替换，失败保留原文件。不能以删库重建、改版本号或清空陌生目录代替升级。

### 按块折算的响应来源（v7）

`request_events.download_bytes/cache_bytes/local_bytes` 为可空非负 INTEGER，三列必须同时已知或同时 NULL；引擎处理的 GET 保存三个整数（未写出正文为零），HEAD 不适用，缺失事实不根据 HIT/MISS 回填。`traffic_totals` 的同名三列为非空非负 INTEGER、初值零。请求结束时随现有 usage 批处理在同一事务保存明细并汇总累计，每批最多更新一次累计；失败整体回滚。清理明细只影响明细和既有保留水位。`GET /api/response-sources` 只读累计，不扫描历史；逐请求 JSON 使用 `sources` 对象（未知为 null）。分类、整块计入与字节固化规则统一见[响应来源观测](download-resource-design.md#响应来源观测)。
