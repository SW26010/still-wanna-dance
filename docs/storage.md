# 数据与工作文件存储

本页维护当前落盘与存储契约。本地资源管理的规则、接口及验证边界见 canonical 文档[下载需求与资源管理设计](download-resource-design.md)。

> 当前数据库为 v9，配置仍为 v8。媒体地址、清单状态与请求统计按本文及[媒体地址模型](song-catalog-design.md#媒体地址模型)运行；已有 v8 在可写打开入口静默一次性迁移，普通业务只读写 v9。代码与隔离验证见[v9 开发验证](validation/storage-v9-20261101.md)；旧 v8 DDL、二进制样本及历史失败证据保留。

持久化整理的目标原则见[职责与边界](persistence-design.md)，实施步骤见[迁移计划](persistence-migration-plan.md)。数据库、完整视频目录和临时块位置可独立配置，块默认使用 EXE 旁工作区。桌面应用启动时准备默认业务存储，已有配置则严格打开所选数据库，元数据与个人资料操作不依赖视频引擎。桌面配置中的 databasePath、videoDir 首次自动采用默认位置，无需手动建库；自定义位置才需要在设置页选择，保存后重启应用，不自动搬运。初始化与已有资料保护的边界见[配置生命周期](settings-lifecycle.md)。核心引擎只接收已打开的数据库、已有视频目录和应用持有的工作区；不再保留混合根或隐式建库入口。

> 当前采用[曲库、资源关联与歌曲需求统计](song-catalog-design.md)模型。SQLite `application_id=0x53574443`（SWDC）、`user_version=9`。v9 将地址改为资源归属，精简清单与请求状态，保留歌曲全部资料及个人需求。v2～v8 冻结 DDL 和样本保留；仅支持本文规定的 v8→v9 转换。

[歌曲屏蔽与收藏](download-resource-design.md#8-歌曲屏蔽与收藏)通过独立偏好表保存；表结构及版本边界见[歌曲偏好存储](#歌曲偏好存储)。

MD5 文件身份以本页和[曲库设计](song-catalog-design.md)为准，演进背景见[早期 MD5 设计](history/md5-resource-design.md)；下载与本地保护遵循[下载需求与资源管理设计](download-resource-design.md)。无版本旧配置及旧数据库请保留备份，使用独立的新配置和存储目录；不要通过更名或修改版本号复用。

```text
EXE/work/<实例>/ 或 所选缓存目录/<实例>/
  download-block-*.part
  .lock
所选数据库文件
  SQLite 必要伴随文件（若有）
所选完整视频目录/
  {md5}.mp4
  .swd-tmp/download-publish-*.part
  .swd-tmp/import-*/video
  .swd.lock
```

曲库和文件管理接口接收明确的数据库文件与视频目录；列表／删除凭据绑定两者，歌曲偏好绑定数据库位置。视频目录不可用时，歌曲资料仍可读取，本地视频状态及占用显示未知，不能按“已保存／缺失”筛选；缺失的数据库报错，不伪装为空曲库。每个数据库持有文件旁 `<数据库文件名>.lock`，每个完整视频目录持有其内 `.swd.lock`，块工作区保留自己的锁；锁范围不随数据库或视频目录名称变化。不再兼容开发期旧程序的父目录锁，旧测试程序应退出后再使用这些资源。数据库不得落在视频发布暂存范围、视频锁或受管 MP4 文件名位置，块工作区不能覆盖数据库或完整视频。

块存储不保留半块前缀、重试游标或重定向进度，不再有 32 个/512 MiB 的暂停检查点上限。读取按需打开块文件并持有短期引用，合并取得完整快照，旧清理不会删除后来替换的新文件；新会话使用调用方当前地址。块写入使用普通系统缓存，不对每块强制 Sync。选择「不保留」时，完成写入、保护变化及保护到期触发逐块回收；保护判断与可用性移除在同一锁下完成，必要块 I/O 引用释放后删除，整份会话/reader 引用不扩大保护。「限制为」（即使已满）及「不限制」时保留运行期块，规则以[本地资源管理](download-resource-design.md#6-本地资源管理的存储与外部契约)为准。块收齐后先按视频存储预算、现有库存和共用资源评分取得预留，再合并校验；资源（含收藏）预算为零、单视频超预算或未进入保留集合时不合并、不校验，也不发布；允许保留视频且开启「优先保留收藏视频」时，收藏在预算内优先取舍；「不保留」对收藏同样不执行合并、校验或发布，全部关联屏蔽的资源不能发布。未取得资格不改变块的回收策略；合并快照前正常回收造成的缺块按未保留处理，不记为存储故障。

若保留块绑定旧地址的强 ETag，换地址时退出旧块注册并重新下载，防止旧实体条件阻塞新地址或混用未经确认的实体；旧读者引用继续有效。实体条件的适用边界以 canonical 文档第 7 项为准。

本地视频唯一身份是小写 MD5。歌曲 ID、URL 中的资源编号、版本、目录、线路和大小均不参与文件键。同 MD5 只保存一份文件，共享下载、容量记账和淘汰；多个歌曲 ID 可以指向同一个 MD5。不另建文件名映射表。

Range 与顺序 200 共用完整块文件存储；仅完整块写入并关闭后可读，未完成块不落盘保存。取得持久化预留后顺序合并，复制时计算一次 MD5，核对长度和 MD5 后同步、关闭并原子发布正式文件。后续假设文件不被外部修改，普通播放和扫描不再计算 MD5，也不依据属性变化重新校验。活动响应共用已打开的文件句柄、各自独立读取位置，最后一个使用者结束后关闭句柄。

歌曲资料以 Udon 为 canonical；备选清单只补缺失的歌曲—MD5 关联。新取得的合法播放 API 观察可覆盖已有映射，不依赖视频下载或持久化成功；纯 URL 请求不猜测歌曲 ID。歌曲清单缺席不删除积累资料，当前成员独立存于 catalog_members。

ID 播放先检查屏蔽状态并在命中时返回 403；准入后的播放命中本地时立即返回，同时后台对照上游 URL 的 MD5；后台检查不替换文件、不打断播放。缺少映射或文件时解析 URL 并冷加载。URL 播放直接取查询参数 e 的 MD5 查本地，缺失时用该 URL 冷加载。

独立的 CheckReferencedFiles 函数把映射中的 MD5 去重，一次枚举目录后返回存在集合和缺失 MD5 及其歌曲 ID。忽略孤儿资源，不检查视频大小或内容。ReadLocalCatalog 只读取当前成员，缺映射歌曲单列待识别；单项目标读取不受成员限制。下载入口同时获取清单状态、歌曲与引用快照，在任务期间保护已知资源，任务结束释放。Store.InspectLocalCatalog 复用同一资料快照和文件检查，仅返回当时的覆盖情况，不启动引擎、不取得文件使用租约；职责与故障边界见[曲库快照规则](song-catalog-design.md#本地快照与当前成员)。每次新任务重新检查，不缓存跨任务结果。外部文件删除仍可能导致实际播放打开失败。

| 表 | 内容 |
| --- | --- |
| songs | 正整数歌曲 ID、对齐 Udon 的可空标量资料及两个 JSON 数组列 |
| song_media | 歌曲 ID → 唯一当前 MD5，外键关联歌曲和资源 |
| media | MD5、可空字节数，不作为本地文件存在性依据 |
| song_preferences | 本地屏蔽或收藏标记；无行表示普通，不表示文件存在 |
| song_usage | 明确歌曲 ID GET 或显式 VRCX 历史初始化的累计有效需求、指数分数及最后计分时间 |
| catalog_state | 已接受完整歌曲清单的来源与版本，键为 songs_list |
| request_events | 到达／结束时间、请求当时歌曲及资源身份、结果、实际视频交付字节与有效响应长度、可空首正文耗时及等块分类、按块折算的三类来源字节 |
| media_access | 最近 GET 时间，独立于歌曲热度和请求明细保留期 |
| media_urls | 按 MD5/节点保存最后提交的完整播放地址 |
| catalog_members | 当前完整清单成员 |

Udon 播放 API 固定使用 HTTP；持久化地址不再带 API 身份。完整视频 URL 原样保存，实际资源协议由播放来源规则决定，节点过滤和格式校验由共用地址存储层执行。

`ObserveSongURL` 校验播放 API 响应后，在同一事务更新 `media` 的大小、`media_urls` 地址、占位歌曲和本次查询歌曲的当前映射，按实际提交顺序覆盖。复用映射锁，与清单同步及快照串行；即时外键始终启用，失败整体回滚。未知大小不抹掉已知值，资源大小与文件是否存在各自独立。

运行期检测、Monitor 与测速将已取得的 API 响应交给同一写入入口，不再重复解析请求或用查询时间拒绝迟到结果。资源下载失败不删除或标记地址；写库失败单独反馈，不改变 API 网络健康判断。只更新本次实际查询的歌曲，签名 URL 不进入状态接口。

后台候选按 `song → song_media → media → media_urls` 检查完整性：缺映射、未知大小或缺当前允许节点的合法地址时按原分数和公平遍历顺序补齐。同一 media 的完整地址由所有当前关联歌曲共享；不按年龄或下载失败重复创建缺项。正常检测仍可使用普通样本自然刷新资料。

新的合法 API 观察可覆盖已有 `song_media`，无论映射来自清单还是较早 API；不再比较查询发起时间。读取缓存不重新进入观察写入。URL 观察不产生播放统计；关联和资源属性已知不代表文件已下载或完成校验。

请求取消或超时可能令事务先自动回滚、随后 `Commit` 才返回 `sql.ErrTxDone`。仅在该错误与 `ctx.Err()!=nil` 同时出现时，将错误还原为上下文错误，避免误记持续存储故障而阻断后续冷加载。上下文有效时的事务结束错误，以及取消时并发发生的其他存储错误，仍按存储故障处理。

清单通过 Udon 和两个同级备选进入共同同步入口。较新完整候选更新歌曲资料、当前成员和水位；同版本优先 Udon，同优先级视为已处理，保留现状。较旧备选仍可补资源和映射空缺，不降低歌曲水位。不计算或比较清单摘要，完整规范以[曲库设计](song-catalog-design.md#清单同步与增改不删)为准。获取失败保留已接受资料。

全量补齐每次获取清单并补充资料，只处理当前成员；已知相同 MD5 共用任务，无映射歌曲分别按 ID 解析。映射没变但文件已被淘汰仍会补齐。指定目标不受成员限制；已固定 MD5 与解析结果不一致时报告失败，不把其他内容当作完成。

资源分数是当前关联歌曲分数之和，孤儿资源为零分。映射改变不立即删除旧文件；容量超限时按分数淘汰，活动请求、下载的必要引用及统一块保护保持有效。有限需求进入本地保护提前窗口后保护数据，最后一份块需求结束后按配置延续（默认 300 秒，0 表示不延续）；任一块受保护则完整文件不可删除，不另设队列专属文件保护。淘汰只删除文件，保留关联和统计。文件发布与数据库提交不是跨资源原子事务，已发布的 MD5 文件即使没有元数据也可命中。

数据库、视频目录和块工作区分别持有 OS 排他锁。可写打开严格验证 v9 或一次性迁移受支持的 v8，只有明确新建使用排他创建初始化结构；引擎借用应用业务存储，取得视频锁后清理发布／导入暂存并执行原有保留策略。块工作区先于文件日志和数据库准备；配置读取成功时，数据库或视频路径不可解析、无法确认别名，默认和自选工作区均暂缓块清理，在引擎启动前复核所有路径、通过后再清理。配置读取失败的旧有默认工作区清理边界见[配置生命周期](settings-lifecycle.md)。工作区自身不可用时保留设置页面并报告故障，不启动视频引擎。离线删除复用应用业务存储并取得视频锁，不另开第二写连接。备份请正常退出后优先保存数据库及恢复所需伴随文件；完整视频按需保留，临时文件和锁不需备份。

本地视频列表展示当前歌曲关联；请求记录另存请求处理时的明确歌曲 ID 和资源身份，查询时不由当前映射推断或改写历史。列表最近访问保持原语义：长期保存的最后 GET 时间与保留期内 HTTP 请求明细取较新值；清理明细不丢失最后 GET 时间或歌曲需求累计值。

请求结果沿用 `request_events.outcome` 文本列；`expired` 表示 SWD 下载截止到期，`blocked` 表示请求时命中歌曲屏蔽，`playback_info_failed` 表示最终无法取得有效播放地址或必要信息（包括播放信息查询超时，不包括本地存储错误）。仅在重试结束后的最终失败出口记录；普通上游传输超时不等于下载截止到期，重试恢复或本地交付成功后的后台查询失败不改变 `completed`。已捕获的服务端最终失败不被随后发送响应引起的连接取消覆盖，其他失败继续保留 `failed`／`aborted`／`incomplete` 等原有证据。HTTP 状态始终是 SWD 实际返回客户端的状态，不用于推断失败类别。此变更不修改 v9 表结构、配置版本或历史行，不执行迁移与回填；旧 `timeout` 不再新增且无法进一步确定原因，展示兼容集中在共用结果映射。旧版程序可读取新增值，无法识别时显示未知。界面分类及原因提示以[请求列表](webui-design.md#请求列表)为准。

## 媒体地址存储目标

**当前数据库格式 v9（`user_version=9`）。** 行为规则与取舍统一见[媒体地址模型](song-catalog-design.md#媒体地址模型)，本节只维护字段和格式边界。

以 `media_urls` 替换 `song_urls`，继续使用核心 SQLite、STRICT 表及真实启用的外键，不另建存储。主键为 `(md5, node)`，字段仅为：

| 字段 | 类型与约束 | 含义 |
| --- | --- | --- |
| `md5` | TEXT NOT NULL，沿用小写 32 位十六进制约束，外键关联 `media.md5` | 固定资源身份 |
| `node` | TEXT NOT NULL，非空 | 实际请求的 API 节点参数；来源许可在业务层统一判断 |
| `url` | TEXT NOT NULL，非空 | 通过现有协议及资源元数据校验的完整视频地址 |

`media` 和 `song_media` 的字段保持原职责，大小只存于 `media.byte_size`。地址表不保存 API 入口、查询歌曲、查询/观察/失败时间或同义状态；相关字段也不转移到歌曲映射表或辅助文件。业务写入需校验 URL 的 MD5 与行键一致，并与资源属性、本次歌曲关联在同一事务提交。

v9 同时将 `media.byte_size` 收紧为可空的 `INTEGER CHECK(byte_size>0)`：NULL 表示未知，已知大小必须为正整数，不再允许落库为 0。沿用现有写入的未知值归一化及缺失大小不覆盖已知大小的规则；URL 解析和预置资料中声明的大小仍必须为正数。该约束不改变资源身份或文件存在性判断。

v9 保留 `songs` 的全部现有资料字段、类型和约束，尽可能保留已接收的上游清单信息；不因为个别列目前没有业务读取、或取消清单摘要而删除它们。字段清单和解析规则见[歌曲资料](song-catalog-design.md#songs歌曲资料)。

v9 同时确认删除以下字段及表，不新增替代字段或历史 URL 存储：

| 删除范围 | 旧 v8 的值从哪里来 | 删除理由 |
| --- | --- | --- |
| `catalog_state.accepted_at` | 本地接纳这版歌曲清单或预置资源快照的时间 | 只有写入，没有业务读取或界面用途；v9 清单判断只使用 revision、source |
| `catalog_state.digest` | songs 的共同歌曲资料摘要、media_seed 的内置快照正文摘要 | 取消同版本内容差异检测；同版本同优先级视为已处理，保留已有资料；内置包只在建库时导入，不比较旧库中保存的版本和摘要 |
| `catalog_state` 的 `media_seed` 记录 | v8 保存上次应用到数据库的内置资源资料包版本、摘要及 bundled 来源 | v9 的内置资源资料只在新建数据库时初始化一次，不因软件更新向已有库写入，也不需要记录预置包导入版本 |
| `catalog_checks` 整表 | 旧版只维护 songs 一行，保存最近成功检查的 checked_at/message 及最近 error | 不再保存或投影这三个字段；当前错误由操作或检测状态反馈 |
| `request_events.host` | 请求处理所用 `video.host`，即解析后的视频地址主机；歌曲本地命中时为空 | 未用于请求历史查询或展示；它不是客户端请求的 Host，也不证明实际使用了哪个回源连接，放弃这份附加诊断信息 |
| `request_events.file_bytes` | 请求处理所用 `video.size`；使用资源地址时取上游视频 URL 的 s 参数（可复用已保存地址），本地命中时取文件长度 | 没有业务读取或界面用途；资源大小已有 `media.byte_size`，无需在每条请求中保留当时的总大小快照 |
| `request_events.cache_result` | X-SWD-Cache 响应头的 HIT/MISS 等粗略分类 | 历史接口虽返回 cache，产品没有使用这项明细；历史页使用按块折算的三类来源，累计命中统计也不读取该列 |
| `song_playback` 整表 | 按歌曲累计成功完成的正字节传输；transfer_count 为计数，last_transfer_at 为 30 秒去重所用的上次计数时间 | 唯一读取是求和后返回未被当前页面使用的 playbackTransfers，没有参与歌曲评分、预加载或保留决策；v9 停止维护这项旧累计 |
| `traffic_totals` 整表 | 单行保存旧 HIT/MISS、命中字节及三类按块折算来源的跨请求累计 | 停止维护无人使用的旧命中指标；三类来源总览改为查询时汇总当前保留的请求明细，接受清理明细后统计随之变化 |
| `request_observation` 整表 | 单行保存 started_at 采集起点和 retained_since 明细清理水位 | 2026-11-01 确认取消首正文“数据不足 72 小时”的覆盖提示；最近 72 小时的分组、分位数和样本数直接由保留明细计算，不需要该状态 |

删除 `song_playback`、`traffic_totals` 时一并移除其专属计数、去重、累计更新、初始化和读取逻辑，以及整个 `/api/status.traffic` 投影和对应无用类型；不从请求明细重建旧 HIT/MISS、节省字节或播放传输次数。`song_usage` 的需求计数、历史导入和优先级机制继续保留。

删除 `catalog_checks` 时一并清理其写入、读取及接口/快照中的专属字段，不搬到 `catalog_state`、辅助文件或替代表。清单资料、当前成员和已接受版本仍在原事务内提交；移除检查状态写入不能遗漏原提交点。当前失败仍须进入操作或检测反馈，重启不再恢复数据库中的上次检查错误；完整边界见[清单检查反馈](song-catalog-design.md#清单检查反馈)。

删除范围不包含 `response_bytes` 和 `transferred_bytes`：两者分别记录这次客户端响应应交付及实际写出的有效视频字节，用于交付比例和请求结果展示。歌曲需求、请求时间及单次请求的来源分类、按块折算规则保持不变；来源总览的统计范围改为当前保留明细。

本轮保留字段沿用现有名称，不采用统一更名方案；计量规则、时间单位及空值含义继续按原契约解释。

数据库格式为 v9，完整结构校验使用冻结的 `storage-v9.sql`；应用身份不变，v8 冻结结构仅在打开边界用于一次性转换。普通业务没有旧表别名、兼容视图或双写；更早及未知格式拒绝并保留。配置格式仍为 v8。

删除 `cache_result` 时一并清理历史接口的 `cache` 投影及对应无用类型字段。运行期 X-SWD-Cache 响应头保持原含义，不根据三类来源重新推导旧的 HIT/MISS 分类。

其余字段已找到当前用途：记录 ID 与到达时间支撑分页和清理；GET/HEAD 及 Range 用于筛选和请求详情；歌曲与资源身份用于历史展示、定位和相邻请求判断；HTTP 状态与 outcome 分别描述响应状态和传输结束情况；结束时刻、单调计时耗时及首正文等待用于展示与分组统计。`download_bytes/cache_bytes/local_bytes` 仍用于逐请求来源占比，含义是[按块折算的响应来源](download-resource-design.md#响应来源观测)，不能解释为上游网络流量，也不要求三列之和等于 `transferred_bytes`。实现与验证范围见[v9 开发验证](validation/storage-v9-20261101.md)。

### v8 到 v9 的静默迁移

**当前行为（2026-11-01）。** v9 程序可写打开已有库时，在取得现有数据库排他锁后检查应用身份与冻结结构：完整合法的 v8 在业务启动前原地迁移一次；v9 按现有规则验证后直接使用。成功不弹确认或迁移通知，也不增加配置项；失败通过现有存储错误反馈，不以空库或部分迁移库继续运行。v2～v7、未知、损坏及未来版本仍拒绝，原有文件与恢复材料保留。迁移之外的业务读取和只读查询只接受 v9，不提供 v8 兼容读取。

整个结构转换、数据复制、清理及 `user_version=9` 在同一个 SQLite 事务内完成；先检查 v8 身份和冻结结构，在事务内用 SQLite `quick_check` 和外键检查验证旧库完整性、数据约束及关联，再转换并校验目标结构和外键关系，最后更新版本并提交。旧库中将被移除的表也参与检查；异常或检查失败时拒绝迁移。任一步失败回滚，保留原 v8 结构和已提交业务数据；下次打开可重试。若重建表需要临时调整外键检查，只能在迁移连接及独占期间进行，提交前必须验证全部外键，恢复业务连接的外键约束。继续遵循 SQLite 的 WAL/journal 恢复机制，不手工删除伴随文件或仅复制主文件。迁移成功后旧 v8 程序不再接受此数据库；本次不新增自动备份文件或兼容副本。

| v8 内容 | v9 迁移处理 |
| --- | --- |
| `songs`、`song_media`、`song_preferences`、`song_usage`、`catalog_members`、`media_access` | 原值和关联完整保留；不以预置包重新生成或覆盖现有资料 |
| `media` | MD5 和正数大小保留，0 归一为 NULL，原 NULL 保持未知；关联不因归一化变化 |
| `request_events` | 保留事件 ID、歌曲/资源身份、时间、结果、字节、首正文及三类来源等目标字段；只删除已确认的 host、file_bytes、cache_result |
| `catalog_state` | 将歌曲清单键 `songs` 转为 `songs_list`，保留来源和版本；去除 digest、accepted_at 和 media_seed 行 |
| `song_urls` | 按下述规则转换为 `media_urls`；不由地址重建或覆盖 `song_media` |
| `song_playback`、`traffic_totals`、`catalog_checks`、`request_observation` | 按已确认的 v9 设计删除；来源总览之后从保留明细计算，已清理明细的历史累计不再保留 |

旧地址按 `(md5, node)` 合并：节点非空、URL 须通过现有协议/资源参数校验，且 URL 内 MD5 与旧行一致。同一键有多条时，比较 v8 保存的 `observed_at`，保留获取时间较晚的地址；时间相同时按 v8 主键确定性选择。`observed_at` 只用于本次选择，不进入 v9，不作为有效期或有效性的证据；v8 的 `failed_at` 和地址年龄不用于排除候选。旧地址无法安全归属到 MD5/节点、数据无法满足 v9 保留字段约束或外键时，中止并回滚，报告不包含完整 URL 的错误；不把无法迁移当作上游资源失效，也不静默丢弃异常数据。

已有配置直接打开原位置时自动触发迁移。设置页选择另一个 v8 库时，选择/保存前只读检查应用身份和冻结结构，不读取或展示 v8 业务数据、不提前改库；这只能初步判断格式资格，不能保证实际迁移成功。保存配置后按原有重启边界，在真正可写打开时再次检查并执行迁移。原有视频保留策略确认照常进行，不新增迁移确认。迁移是已有库转换，不执行新库的内置资源预置，也不改变视频文件或配置。读取公开数据、曲库和历史的普通只读入口只接受已经迁移完成的 v9。

验证范围以开发记录为准，要求覆盖冻结 v8 样本和含真实形态数据的隔离库：所有保留字段、用户偏好和需求、清单水位、请求事件 ID 和来源字节；0 大小、空清单状态、共享资源/重复地址、旧失败地址和异常地址；逐步注入失败后回滚、WAL 恢复和重试；迁移后的结构与全新 v9 一致、外键完整、重开不再迁移、旧程序拒绝 v9；默认配置及选择另一数据库的路径不要求额外迁移确认，原有视频策略确认继续生效。只验证副本，不操作用户真实库。旧后继格式演练保留为历史参考，本轮结果见[v9 开发验证](validation/storage-v9-20261101.md)。

### 请求统计的计算方式

**来源汇总按当前保留明细计算。** `/api/response-sources` 在查询时对当前数据库保留的 `request_events.download_bytes/cache_bytes/local_bytes` 分别求和，只返回汇总值；不再保存跨明细清理的累计，不新增替代表或辅助状态文件。范围为全部保留明细，继续独立于列表的时间筛选和分页。逐请求的来源占比仍使用本行三列。

先汇总各类已固化的字节，再计算占比，不平均逐请求百分比，也不按当前块大小重算历史。失败或取消请求中已计入的来源字节仍参与求和；未知事实不补造，空明细或没有已计入字节时沿用无来源统计的展示。明细清理后汇总同步失去对应贡献；不保留明细并清理完成后，没有来源统计数据。跨重启仍可从剩余明细重新计算。

页面标题为“响应来源”，提示说明统计范围为全部已保留请求、清理明细后贡献同步减少；刷新周期、手动刷新、查询失败反馈及切换数据库行为沿用现有机制。验证覆盖保留期清理、空明细、失败/取消已有贡献、重启重算、占比计算及实际数据规模下的查询耗时。既有 v7/v8 验证中的单行累计只属于旧实现。

首正文等待时间已经按查询现场计算，v9 保持其样本筛选和算法：`/api/latency` 按请求到达时间读取最近 72 小时内、已写出视频正文的 GET 样本，用 `first_body_ns` 和 `first_body_blocking` 分组计算 P50、P95 与样本数；后续取消或失败不抹掉首正文事实。不保存累计耗时或预先计算的分位数，不随来源汇总改为全部保留期。

v9 已删除 `request_observation` 整表，停止初始化采集起点和随明细清理更新水位，移除 `/api/latency` 的 availableFrom、partial 及前端对应类型和“数据不足 72 小时”提示。查询不再以这张表是否有记录作为返回样本的前提；from/to 仍表示最近 72 小时的查询窗口，不承诺连续采集满整个窗口。不把时间移到别表或文件，也不由最早请求近似推断覆盖范围。保留样本数、无样本时分位数为 NULL 和暂无数据的反馈；保留期清理、重启和历史列表筛选规则不变。实现时验证新库空样本、短保留期/不保留明细、重启重算及接口和页面移除覆盖状态。

### 单行状态与清单水位

v9 不保留 `traffic_totals`、`request_observation`、`catalog_checks`，没有结构上限制为单行的业务表，也没有替代通用键值表。

`catalog_state` 仅保留 `catalog_key TEXT PRIMARY KEY NOT NULL`、`revision TEXT NOT NULL`、`source TEXT NOT NULL`，使用 STRICT。业务只写 `songs_list`；尚未接受完整清单时无该行。没有预置导入状态。冻结 v8 仍保留旧键与字段。

`songs_list` 是行键；它的 source 和 revision 分别记录已接受完整歌曲清单的来源入口和上游 time。歌曲内容仍按每首一行存于 `songs` 表，当前完整清单的成员存于 `catalog_members`。前台“更新曲库”、后台/手动上游检测及全量检查/补齐共用清单同步入口；接受新清单时，资料、成员和这条版本记录在同一事务提交。已有歌曲可能只是预置或播放 API 创建的占位，不能据此认为完整清单已经初始化。来源和版本不能从歌曲字段及成员列表反推。实现时同步修改清单状态读取、写入、初始化判断及相关测试，不为旧键增加兼容查询。

程序嵌入的[资源资料包](../data/media-seed/README.md)含 MD5、可选字节数和歌曲 ID → MD5 关联。v9 在明确新建数据库时初始化一次，将资源、占位歌曲和映射写入新库；表结构、预置资料与格式版本在同一创建事务中成功或回滚，失败不能留下可误认为初始化成功的当前格式库，失败文件及恢复材料按现有保护规则保留。普通打开、只读检查、切换已有库及软件更新均不重新导入或检查预置是否齐备，不以任何替代字段、表或文件记录导入状态。

预置不建立 `catalog_members` 或 `songs_list` 清单版本，也不代表视频已下载。已有库不因新软件内置包变化而获得新预置映射；正常播放 API 和备用清单仍按各自已确认的业务规则获取资料并更新或补缺。初始分数是内置的查询时默认值，不写 `song_usage`，有本地真实或导入的需求后由本地分数取代；软件更新影响的范围见[歌曲优先级](cache-retention.md#排序规则)。

歌曲清单继续跨来源比较版本，v9 只取消摘要差异检查；2026-11-07 起同版本仅 HTTPS Udon 优先，其余三个入口同级；同版本处理和备用触发统一见[清单版本记录](song-catalog-design.md#清单版本记录)。删除 digest 时清理专属计算、比对、冲突类型及诊断逻辑，不改为现场重算或转存摘要；资料格式校验、外键和事务回滚继续保留。其余保留表按歌曲、资源、地址节点或请求记录增长。

## 数据库打开约定

各类文件的备份、重建、损坏处理和安全回收条件见[运行文件生命周期](runtime-lifecycle.md)。

数据库与受管视频文件的路径冲突按当前操作系统的路径语义判断。Windows 上 MD5 或 `.mp4` 扩展名的大小写变化仍属于同一保留文件名，不能作为数据库位置；正式视频命名规则仍为小写 MD5 加 `.mp4`。该检查不改变数据库或配置格式。

数据库打开／新建、引擎启动和离线删除只按当前资源契约校验，不检查旧数据库标记、旧视频文件名或历史父目录布局。不符合当前受管命名规则的文件不参与视频列表、容量淘汰或清理，原样保留；符合 `<32 位小写十六进制 MD5>.mp4` 命名的普通文件即使没有数据库记录，仍纳入本地视频管理。数据库仍校验版本和结构，明确新建仍拒绝已有主文件及 WAL、SHM、journal，视频目录仍验证类型与资源锁；运行中的存储目录不应由其他程序改写。

所有数据库连接通过同一入口建立，路径在一个位置定义。本地视频列表、曲库、最近请求及流量统计使用只读连接，统一验证应用身份与格式版本；缺库时不创建文件，读取页面不补表或补索引。

只有明确新建操作才初始化不存在的数据库；该操作与视频目录是否存在无关，已有空文件也拒绝。共同创建入口取得数据库写锁后、创建主文件和连接 SQLite 前，检查同名 `-wal`、`-shm`、`-journal`；任何目录项存在或无法可靠检查时都拒绝创建，原样保留恢复资料，失败释放锁。当前身份、当前版本的库仅验证完整表、列、索引和约束，不补建结构。不识别的身份和不支持的历史版本报错；遇到未来版本，明确提示更新程序。失败不会改写格式标记或清理临时下载。仅 v8 在这个受控入口一次性迁移为 v9，不能在业务读取中迁移或补表。

不再生成或依赖 `verification.sqlite`。下载大小和 MD5 校验、显式完整检查、活动文件句柄和并发保护保持有效，检查结果仅在进程内用于本次操作。盘上碰巧存在的旧校验库被忽略，不自动删除。

## 歌曲偏好存储

本节描述当前 v9 中的歌曲偏好结构（最初于 v3 引入）。需求准入、共享资源、收藏不触发下载及预算规则统一见[canonical 设计第 8 项](download-resource-design.md#8-歌曲屏蔽与收藏)，此处只维护存储契约。

在同一 `storage.sqlite` 中使用一张歌曲偏好表，已有 `songs`、`media`、`song_media` 及统计表不改列：

```sql
CREATE TABLE song_preferences (
 song_id INTEGER PRIMARY KEY REFERENCES songs(id),
 policy TEXT NOT NULL CHECK(policy IN ('blocked','favorite'))
) STRICT;
```

无记录表示普通；`blocked` 表示屏蔽，`favorite` 表示收藏，恢复普通时删除该行。主键保证同一歌曲的偏好互斥；写入时验证正整数 ID，缺少歌曲资料时在同一事务补建 `songs` 占位行。复用现有外键检查，不级联删除，不为未定义用途增加更新时间、历史记录或额外索引。

偏好是用户维护的曲库数据，随存储库备份和切换，不进入 `config.json`。曲库刷新、歌曲—MD5 关联更新、VRCX 统计初始化及视频清理均不覆盖偏好。资源的收藏资格通过当前关联、videoStorageMode 与 retainFavorites 配置推导，全部屏蔽状态通过当前关联推导，不新增资源名单表、资源分数副本或下载/完整性状态列；标记不等于文件已保存。

当前数据库格式为 v9，使用 `schema/storage-v9.sql` 和对应二进制样本；v2～v8 DDL 与样本冻结保留。可写打开静默迁移 v8，偏好及个人需求原值保留；其他旧格式拒绝。配置仍为 v8，普通业务不读取旧库。

偏好写入与 VRCX 历史初始化共用应用业务存储的数据库锁、严格打开和事务入口，不启动引擎或资源回收。明确新建只创建标准数据库；视频盘不参与建库判断。在线标记仍与发布、淘汰串行，数据库锁在应用停止消费者及引擎、排空已接受写入并关闭数据库后释放。

## Portable 文件契约与生命周期

本节是应用落盘位置和备份范围的统一清单。路径由 `internal/apppaths` 解析；软件版本变化不改变文件名。当前配置格式为 `schemaVersion=8`，媒体 SQLite 为上述版本 9。旧测试配置版本 1～7 不兼容、不迁移，不应手工改版本号继续使用。

### 交付与按需生成

```text
SWD/                              # ZIP 内固定目录，不含版本号
  SWD.exe
  licenses/                       # 仅此目录与 EXE 随 ZIP 交付
  config.json                     # 首次启动生成，默认配置
  config.lock                     # 配置实例锁，退出释放，文件可保留
  data/
    database/
      storage.sqlite              # 核心数据库，可独立外置
      …                           # SQLite 必要伴随文件及数据库锁
    state/                        # 按需生成，通常无需备份
      terms.json                  # 明确同意后才写入
      channel.key                 # 网络通道身份材料
      webui-port.json             # 上次成功启动的本地控制端口
      throughput.json
      inventory.json
      batch-last-success.json
      batch-last-attempt.json
      mihomo/                     # 现有组件 Home，按需生成
  videos/                         # 完整视频，可独立外置
    {md5}.mp4
    .swd-tmp/                     # 同卷发布、导入暂存
    .swd.lock
  logs/<UTC秒级时间>[-序号].log    # 每片 1 MiB，总预算 20 MiB
  work/<实例>/                    # 默认随 EXE，可单独选择父目录
    .lock
    download-block-*.part
```

首次打开未确认条款的应用生成配置、配置锁、日志和默认块工作区，并在未配置且无已有资料时自动准备默认数据库及视频目录。路径解析本身不创建文件，`data/state/` 按功能需要产生。明确建库可创建文件父目录，保存新视频位置可创建缺失目录；保存其他设置不创建或探测未变化的视频位置。只读页面不建媒体库；需要媒体管理时，引擎借用应用已打开的数据库。视频目录缺失或无法读取时，保留旧库存并报错，不将缺失目录当成零库存。系统运行身份和安全清理分别按 #24、#25 已收口，交付文件进一步精简仍由 #26 负责。

### 配置实例与路径解析

应用只打开已有合法数据库，不根据库存、任务结果或空目录判断能否初始化。曲库更新、Monitor、收藏、历史和 VRCX 复用应用数据库，不启动视频引擎。缺失库明确报错；建立新库必须使用明确的创建操作。库存与任务快照仅供查看过去结果，不授权建库、恢复运行、选中项或删除。

令 `C` 为主配置的绝对路径，`B` 为其父目录，`R` 为实例数据根，`D` 为所选数据库文件，`V` 为所选完整视频目录：

- 默认 `C=<EXE目录>/config.json`，`R=B`，数据库和视频首次自动准备为 `data/database/storage.sqlite` 与 `videos`。
- 自定义 `-config <目录>/config.json` 同样以该目录为 R；其他文件名采用 `R=C.d`。例如 `profiles/a.json` 的条款与状态放在 `profiles/a.json.d/data/state/`，日志放在 `profiles/a.json.d/logs/`；默认数据库和视频位置分别为 `a.json.d/data/database/storage.sqlite`、`a.json.d/videos`。
- 同目录 `config.json`、`a.json`、`b.json` 的锁、日志、密钥、确认记录和状态独立。不要把另一个配置嵌套在已有实例的数据根内；共享同一实例根就是共享其附属状态。
- `-config` 参数本身的相对路径基于启动工作目录；配置内数据库、视频、临时缓存及手动 VRChat 日志的相对路径始终基于 B。保存时位于 B 内的路径转为相对路径，外部路径保留绝对路径。默认 VRChat 日志目录随当前用户环境解析。
- `blockCacheDir` 缺失、null 或空串使用 EXE 旁 `work/<实例>`；自选父目录直接使用其下 `console-<配置身份摘要>`。默认工作区使用 EXE 内相对身份以支持整包移动；自选工作区使用规范配置绝对路径区分不同安装，同一父目录不混用实例。移动配置后自选工作区身份会变化，不迁移临时块。工作区不能与数据库、完整视频、配置、状态或日志重叠，也不建立永久身份文件。自选缓存父目录和完整视频目录的包含关系、数据库文件位置及旧配置兼容规则统一见[配置生命周期](settings-lifecycle.md)。
- 主配置不能命名为保留的 `terms.json`、`channel.key`、`config.lock`、`data`、`state`、`logs`、`storage`、`videos`、`work`、`licenses`，也不能使用 `.swd-tmp` 后缀，避免覆盖规范配置和原子写入工作槽。
- 多个配置选择同一数据库或视频目录时，分别受对应 OS 锁保护；配置隔离不允许绕过资源排他所有权。

配置版本独立于软件发行版本。读取拒绝缺失、不支持或未来版本；保存前再次检查磁盘版本，并保留当前版本中的未知字段。设置 API 不能指定磁盘格式版本。配置、条款、库存/任务/吞吐快照及控制端口记录使用每目标固定的 `.<文件名>.swd-tmp` 工作槽，排他创建、同步并原子替换；持有配置实例锁的启动流程只清理本实例已知工作槽。旧引导状态、未知名称和其他配置保留，异常类型拒绝且不递归清理，失败不覆盖已提交文件；控制端口记录是可丢弃的提示，其工作槽无法安全清理或记录无法保存只记录警告，不阻止启动。通道密钥仅缺失时排他创建，损坏原文保留并降级为临时通道身份；不承诺所有文件构成跨文件事务。

默认启动只使用当前配置和资源路径，不探测或迁移历史安装目录与文件。明确传入的配置仍按版本校验，当前默认位置已有资料时不自动建库，未知文件原样保留。

## 持久化格式与语义

版本号独立于软件发行。当前 SQLite **9**、配置 **8**、库存/批量/尝试快照 **3**、吞吐快照 **2**。SQLite 仅迁移 v8；其余格式遵循各自既有边界。当前 DDL 与二进制样本为 `internal/cacheproxy/schema/storage-v9.sql` 和 `internal/cacheproxy/testdata/storage-v9.sqlite`，v2～v8 样本冻结保留。旧 v8 结构夹具含无 e/s 的占位 URL，原样保留并用于失败保护回归；成功迁移使用仅修正该 URL 的隔离副本，不重生成旧样本。

### SQLite 字段清单

以下为完整表清单；类型、NULL、CHECK、外键和索引以冻结 DDL 为准。无显式默认值的必填列必须由写入方提供，未声明为 NOT NULL 的资料列允许 NULL。所有业务表采用 STRICT，INTEGER 为有符号 64 位，REAL 为双精度；业务端仅写有限分数和合法正整数歌曲 ID。数据库不承诺任意手工写入均有效。

| 表 / 身份 | 字段与来源、空值和单位 | 价值与关系 |
| --- | --- | --- |
| `songs` / `id` 正整数主键 | 可空 TEXT：name、artist、dancer、major、groupName；可空 INTEGER：playerCount、rpe；可空 REAL：volume、start、end；flip、double_width、skip_random、disable_public 为可空 0/1；tag、shader_motion 为可空合法 JSON 数组文本 | Udon 共同歌曲资料及父级分组信息，不含 MD5 或备选独有字段；清单缺席不删除记录 |
| `media` / `md5` | 小写 32 位十六进制非空键；byte_size 可空正整数字节数 | 资源索引，不是文件存在/完整性的证明；与 MD5 文件相互独立 |
| `song_media` / `song_id` | 歌曲外键 → 非空 media.md5 外键；md5 索引 | 每首歌一条当前关联，多首歌可共享同一媒体；备选只补空缺，新的有效 API 观察可更新，显式 ID 下载完成仅补缺 |
| `media_urls` / `(md5,node)` | MD5 外键关联 media；节点与完整 URL 均非空 | 保存最后提交的资源地址；不存查询歌曲、API、时间或失效状态 |
| `song_preferences` / song_id | policy 仅允许 blocked / favorite，外键关联 songs | 无记录为普通；用户标记不写需求统计，不触发下载 |
| `song_usage` / `song_id` 外键 | demand_count 非负累计次数；demand_score 非负 REAL；last_demand_at 为 Unix 毫秒 | 按歌曲跨域 GET 或用户显式 VRCX 历史初始化，30 秒去重、60 天半衰期指数累计；历史按原时间计算。明细清理后不能无损重算 |
| `catalog_state` / `catalog_key` | 非空主键 songs_list；revision 为上游 time，source 为来源入口 | 与歌曲资料和当前成员在同一事务更新，不存摘要或接受时间 |
| `catalog_members` / `song_id` 外键 | 当前已接受完整清单的成员 ID | 与 song_media 一起推导覆盖，不复制另一份成员资料 |
| `media_access` / `md5` | 小写 32 位十六进制非空键；last_requested_at Unix 毫秒，按 max 更新 | 最近 GET 事实；独立于歌曲归属、明细保留期，允许未被 media 收录的资源 |
| `request_events` / `event_id` INTEGER 主键 | resource_md5 为请求处理时的资源 MD5，未知为 NULL；MD5 同时表示内容身份和内容版本，不另存 version_key。method/range_header/outcome 为请求证据文本；requested_at 为请求到达的 Unix 毫秒；transferred_bytes 非负字节，仅计实际写出的视频正文；elapsed_ms 非负持续毫秒；status HTTP 数值。可空字段：song_id 为请求处理时的明确正整数歌曲 ID，completed_at 为结束 Unix 毫秒，response_bytes 为本次有效响应长度（字节），first_body_ns 为单次首正文耗时（纳秒），first_body_blocking 为首正文前实际等块的 0/1；download_bytes/cache_bytes/local_bytes 为三类固化折算字节，三列同时已知或同时 NULL | 有界原始请求日志，歌曲及资源身份在处理时冻结，可空事实未知为 NULL，不靠当前关联回填；首正文样本仅在已实际写出视频正文时有效，不要求最终成功。按 resource_md5+requested_at、时间复合索引（requested_at DESC,event_id DESC）查询；同毫秒按 event_id 排序，清理后不承诺 ID 全局永不复用 |

`request_events` 以客户端 → SWD 的入站 GET/HEAD 请求为记录单位，保存 SWD 处理及向客户端交付响应的结果。正常歌曲播放 API 请求由代理在内部解析资源并返回视频正文；已有直接资源入口也按其入站请求记录。SWD 内部查询上游 API、回源 Range 或下载多个块不会分别产生这些明细。method 与 range_header 来自客户端请求，status 是 SWD 返回的 HTTP 状态，outcome 为该次处理的 completed/failed/canceled/incomplete/aborted 等结果。预下载和曲库预览不写业务请求历史。这些诊断文本不是可扩展行为开关，未知值不得当成成功。歌曲需求累计不因删除视频或清理明细而重置。评分固定 `oldScore * 2^(-elapsed/(60 days)) + 1`；回拨或 30 秒内重复需求不计分、不降低 last_demand_at。未来改评分必须保持旧含义或随数据库版本明确重置/重算策略，不假设请求历史完整。

用户显式导入 VRCX 时可按[历史初始化契约](song-catalog-design.md#vrcx-历史初始化)整体替换 `song_usage`，非空统计需二次确认；提交点复查并与需求写入串行，失败回滚。只补必要占位歌曲，不修改媒体、映射、请求明细或配置；不增加表、格式版本、原始历史文件或持续同步状态。源 SQLite 只读并使用正常 WAL 快照，预览聚合及完成回执只在内存保留至过期。

请求身份独立于当前曲库，不加歌曲或资源外键；解析失败也可保存明确歌曲 ID。对外 JSON 继续使用字符串 ID／MD5 和空串表示未知，不丢失大整数精度。`counts_as_demand` 已删除：请求符合条件不代表通过 30 秒去重，不能据此还原累计次数。

### 时间与排序

- SQLite 真实时间点统一为 UTC Unix 毫秒。媒体地址没有时间字段，合法 API 观察按实际提交顺序覆盖。
- JSON 持久化真实时刻用 RFC 3339、UTC `Z`，允许 0–9 位可变小数秒，不按文本字典序比较。Go 零时间 `0001-01-01T00:00:00Z` 表示尚未发生；SQL 明确指定的 0 哨兵表示未知/未失败，不能展示为 1970 年。一般 SQL 时间不以 0 自动表示 NULL。
- `revision` 只接受 14 位 `YYYYMMDDhhmmss`，校验日历日期；不接受时区后缀/小数秒。用共同比较轴排序但不声称其真实 UTC 偏移；同版本同优先级视为已处理，不比较正文摘要，见[清单版本记录](song-catalog-design.md#清单版本记录)。该逻辑水位与机器时钟无关。
- 持续时间不编码为日期：吞吐 `durationNs` 是纳秒整数，请求 first_body_ns 是单次首正文耗时纳秒，请求 elapsed_ms 是毫秒。UI 用毫秒/秒/Bps 展示；时间对象编码为字符串。不要把 SQL int64 原样新增到 JS 数值接口。
- 文件 ModTime 是 OS 文件属性，用于句柄/删除身份核对，非数据库事件时间、不保证跨文件系统精度。运行中计时优先 Go 单调时钟，持久化后不保留单调部分。快照读入偏移可解析，但再次保存规范成 UTC。吞吐冷却遇到未来 lastAttempt 时失效重采样，避免长期卡住。

通道身份的 HMAC 输入为：

- 外部 SOCKS5：JSON 数组 `["socks5-channel-v1",address,username,password]`，输出 `stable-v1-` 加十六进制摘要。

Mihomo 不再生成 SWD 节点身份或改写显示名，选择持久化由原生名称负责。旧节点身份域只属于历史记录，不迁移、不重置 channel.key。

DPAPI CurrentUser 不使用路径作为额外熵，不请求 UAC。同用户覆盖/移动可用；另一用户或普通独立机器可能不可用，但域用户漫游可能保留能力，**不是绝对设备绑定**。非 Windows 无明文替代方案：保存密码或节点快照明确失败，已有封套显示不可用。代理模式的不可用凭据使代理拨号失败，不隐式改用直连。Mihomo 原始配置中的参数、凭据和 provider URL 随整份原文保护，不落盘原始导入副本；原生缓存不在此加密承诺内。

配置中的 `logLevel` 保存为 `off/error/warn/info/debug`，缺失、null 或空串默认 info；保存后重启生效，配置格式为 8。关闭日志不删除已有文件，不改变请求明细保留规则。

诊断日志也使用 RFC 3339 UTC 时刻，但不是恢复业务状态的格式；错误文本和事件属性可以随实现变化，不为日志增加用户数据迁移版本。

### 打开、失败与未来升级

普通打开只验证已有数据库的身份、版本和冻结结构；零字节、缺失或损坏文件报错，不补表／索引、降版本或隐式建库。缺库时可选择原数据库或恢复数据库及必要伴随文件，不要求一律恢复完整视频备份。明确新建与普通打开分开：仅在满足创建条件的位置初始化，已有视频不授权重建数据库，也不妨碍用户明确另建新库；接入已有视频仍须确认保留策略。全新初始化使用一个 SQLite 事务写 DDL、内置资源资料和版本；中途失败回滚，不在失败路径清理下载文件。数据库锁覆盖初始化和整个可写连接寿命；只读入口不建库。未知对象或结构改变同样诊断，而不是当作可随意重建的数据。

数据库入口要求普通文件、可确认的单一硬链接名称和实际完整路径；写入及只读入口共用检查，多硬链接文件和短文件名等非规范别名明确拒绝，文件保持原样。普通大小写和词法路径处理沿用原规则，不静默改变已选数据库的作用域，不新增身份登记库；视频导入仍可使用硬链接。程序使用中的数据库和伴随文件不得由外部移动、替换或改名。

v8→v9 在唯一可写打开入口持锁执行一个事务，成功和失败保护见上文及开发验证记录。没有 v1→v2 或旧配置的伪迁移；配置更新继续原子替换。不能以删库重建、仅改版本号或清空陌生目录代替升级。

已覆盖固定样本反复读写打开不改字节、旧/未来/未知版本、缺表/索引/新增列、损坏/空/缺失数据库、初始化中途失败回滚、设置替换失败保留密文、DPAPI 篡改与重配、同用户移动、时间精度与并发同刻/回拨、跨库和 Portable 相对路径。2026-10-26 已在可丢弃的 128 MiB NTFS 虚拟磁盘验证真实耗尽：覆盖块写入、视频发布、数据库同步／后台写入及关闭错误，释放空间后验证重开、已提交数据保持和新写入，范围及清理证据见[迁移验证记录](persistence-migration-plan.md#本轮已取得的验证证据)。这不代表任意文件系统、真实断电、另一 Windows 用户／普通跨机器或 VRChat／托盘／UAC 联合场景均已通过。

四步引导移除后，不再读写 `state/setup.json`、`state/setup-apply.json` 或逐 ID 回执；旧文件及旧工作槽保留原样，不迁移、不恢复任务。

### 按块折算的响应来源

`request_events.download_bytes/cache_bytes/local_bytes` 为可空非负 INTEGER，三列必须同时已知或同时 NULL；引擎处理的 GET 保存三个整数（未写出正文为零），HEAD 不适用，缺失事实不根据 HIT/MISS 回填。请求结束时随现有 usage 批处理在同一事务保存明细，失败整体回滚。`GET /api/response-sources` 对全部保留明细求和，清理明细会移除对应贡献；逐请求 JSON 使用 `sources` 对象（未知为 null）。分类、整块计入与字节固化规则统一见[响应来源观测](download-resource-design.md#响应来源观测)。
