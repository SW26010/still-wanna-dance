# 资源域名规则

资源加载、upstream channel、monitor、下载状态和测速记录以有效播放 API 响应中的实际域名区分，不以 CF/HKG 区分资源。

历史上确实观察到 `nya.xin.moe` 和 `play.udon.dance`，其 DNS、地址所属网络和 IP 地理位置也呈现过不同特点。这些只说明当时的网络观测；地理数据库还可能给出不同结果，Anycast 地址也不能代表固定机房。不能据此把两个域名分别定义为 HKG、CF，或保证它们始终存在。旧界面与配置中的 CF/HKG 只保留为播放接口参数的兼容名称：`node=cf` / `node=nya`。

当前资源集合不预置这两个域名，也不限制为两个。monitor 汇总各播放接口、各 API 通道返回的合法地址；同一来源的新结果替换旧结果，候选退休或样本超过有效期（默认 10 分钟）后移除。无有效返回值时资源区为空；出现新域名时动态建立资源通道和界面分组。同一域名每轮每个资源通道只检测一次，不手工改写 Host、路径或签名来补齐另一条“线路”。播放解析确认的域名也有有效期，切换上游配置会清除共享域名集合。

域名语法、协议、视频路径、MD5 和大小仍须校验。客户端任意 Host、DNS 结果、历史 IP 和旧测速文件都不能建立当前资源成员关系。资源重定向须落在已确认集合中，且 MD5 与大小一致；不同接口返回相同域名是正常情况。

旧吞吐记录只有在通道键明确包含域名时才按该域名迁移；只有 cf/hkg 标签而无域名证据的聚合样本丢弃。保留可确认的历史样本和测速冷却时间，但历史样本不会恢复域名成员关系或健康状态。

新 hosts 接管仅添加 `api.udon.dance`，本地 HTTP 播放 API 直接返回缓存或上游视频，不要求预先知道资源域名。恢复功能仍识别旧版托管的两个资源域名，仅用于清理旧配置。CLI 的可重复参数 `-origin DOMAIN=HOST:PORT` 是用户明确指定的可信覆盖，默认空；不再提供隐含域名绑定的 `-cf-origin` / `-hkg-origin`。

历史验收文档、原始日志和测试夹具保留当时的名称、地址和结果，不能作为当前域名清单或固定节点映射。实网验收只使用当次 API 返回的完整 URL；没有返回不同域名的同内容地址时，跨域验证明确跳过，不构造替代地址。

域名聚合与地址来源分别保存。每条有效 API 结果记录实际请求 API、原始 node 参数、歌曲 ID、API 通道身份（monitor 固定通道检查时）、完整返回 URL、域名、路径、观测时间和有效期。同一域名、同一 URL 被多个接口下发时仍保留全部来源；`node=cf` 返回 `nya.xin.moe` 就记录为该组合，绝不反推或改写 node。通道与 monitor 均提供 `ResourceSources(domain)` 内部查询，空域名查询全部，可按 Node、APIChannelID 或完整 ResourceURL 筛选，供后续手动选择或其它业务使用。

monitor 的资源结果通过 `sources` 提供来源列表，界面显示实际 API 与 node。完整 URL 保留原协议和参数，供内部业务追溯；状态 JSON 不输出带签名的资源 URL，也不将其持久化。来源与当前集合一起更新、失效和清理，旧吞吐记录不补造来源。

旧版托管资源映射属于待迁移状态，不因 API 已映射而判定接入完成。启用向导清理后才标为就绪；自动启动显示迁移未完成提示。monitor 与共享 channel 在读取当前集合时都检查来源 API 通道是否仍有效，退休来源立即剔除，不等待整批检查结束，也不会仅因同名候选重新出现而恢复旧来源。跨域验收在缓存 HEAD 触发后台解析后，须等待资源 Host 实际被接受再读取 Range，等待有明确期限。
