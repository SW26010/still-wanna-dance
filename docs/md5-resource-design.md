## 身份与存储

本地视频唯一管理键为小写 MD5，正式文件为 `videos/{md5}.mp4`。歌曲 ID、上游资源编号、版本标识、目录和线路均不参与文件身份。不同歌曲或 URL 的相同 MD5 共用文件和下载任务。文件名本身提供内容索引，不维护额外的文件名映射表。

下载在临时目录完成，校验长度和 MD5 后发布。之后假设正式文件不被修改，普通播放和扫描只检查存在性，不重复计算 MD5。流式冷加载可以读取下载中的临时文件，但只有完整校验成功才发布正式文件。

## 歌曲映射

维护歌曲 ID 到当前 MD5 的关联。批量清单提供权威关联，新增和更新都做，不删除清单中消失的旧 ID。清单优先于播放 URL；后者发现冲突只记日志。缺少关联时可由按 ID 解析的 URL 建立关联。纯 URL 请求不能从资源编号猜测歌曲 ID。

## 快速完整性检查

独立函数读取 ID 到 MD5 的映射、去重引用，一次枚举正式视频目录，用集合差求缺失资源。返回是否齐备、缺失 MD5 及引用它的歌曲 ID，以及检查快照。忽略孤儿 MD5，不读取视频正文、不做 MD5 或大小校验。上层直接使用该结果，不重复逐文件检查。结果不跨任务缓存；补齐任务保护已命中的引用资源，避免内部淘汰使任务快照失效；新任务重新取得快照。外部删除导致的实际文件打开失败仍需正常处理。

## 播放

- ID 请求有映射且本地文件存在：立即返回本地视频，同时后台获取上游 URL 对照 MD5；差异只记录日志，不中断当前流、不后台替换文件、不覆盖清单关联。
- ID 请求没有映射或对应文件缺失：解析上游 URL 并冷加载；缺少的映射由解析结果补充，已有清单关联不被冲突结果覆盖。
- URL 请求：从 `e` 提取 MD5，直接命中本地文件或使用完整请求 URL 冷加载。上游版本标识不参与管理。

## 补齐与淘汰

每次补齐先获取清单、更新映射，再运行快速检查。只处理缺失 MD5；映射改变但文件已存在时不下载，映射不变但文件缺失时仍补齐。同 MD5 只安排一次下载，保留所有歌曲关联。URL 返回的 MD5 与清单不一致时不冒充完成，记录失败供后续重试。

资源分数为当前引用它的所有不同歌曲 ID 的分数之和。无歌曲引用的 MD5 分数为零；共用资源累加歌曲分数。容量淘汰按资源分数从低到高，活动播放、下载和队列保护仍有效。删除文件不删除歌曲关联。映射变化不立即删除旧文件；旧文件成为零分孤儿参与容量淘汰。

队列预留独立于清单映射：同步清单时，仍在待播队列或离队交接期内的歌曲保留已预缓存资源的保护，即使其 MD5 与清单不同。同步不会延长交接期限；交接到期或队列重置后，资源恢复普通容量淘汰规则。

## 存储格式替换

不兼容旧组合键存储，不迁移旧缓存数据。旧存储目录明确报错，要求使用新的存储目录；不删除或改写旧数据。资源表只保存 `media.md5`，不再重复保存版本键和校验和；请求明细中的 `version_key` 继续记录请求对应的 MD5。

## 验证

覆盖 MD5 跨资源版本去重、映射新增/更新/保留旧 ID、缺失检查、立即播放与后台只记差异、未知 ID 冷加载、共用分数累加、活动保护和旧格式拒绝。Windows 本机基准：10,000 条映射、5,000 个唯一 MD5、4,000 个目录文件，快速存在性检查平均约 7 ms（仅函数，不含联网和清单写入；非性能保证）。
