# IPv4 / IPv6 归因补充实验

2026-10-21，在第一批两组实验完成后、采集本批结果前固定以下规则。旧结果保留；新批次不与旧两组实验混为同一实验。

## 要澄清的问题

1. 额外 IP 是否仍优于经过相同真实分块训练筛选的 DNS IPv4 和 IPv6？
2. 当前自动推荐是否落后于现有 DNS 候选的更好选择？
3. 单次或短窗吞吐排序能否泛化到未参与训练的视频？

“最快”只指本批训练选出的候选，不是未知网络下的全局最优；IPv4/IPv6 的对照是具体地址、路由和服务端路径组合，不是对协议本身的纯因果实验。

## 固定四组

- `auto`：产品 Monitor 的当前 DNS 双栈自动推荐，默认 15%/两轮迟滞，在独立实例连续手动测三轮。
- `v4`：DNS IPv4 候选中，训练歌曲 1343 完整分块下载三次均成功、耗时中位数最短的地址。
- `v6`：DNS IPv6 候选中按相同规则选择。
- `extra`：固定额外候选 `103.21.244.1`、`104.16.0.1`、`104.24.0.1`、`162.158.0.1` 中按相同分块训练规则选择。

DNS 和额外候选各先做一轮产品资源测速筛除不可用路径，保存所有结果。可用候选按 IP 排序，三轮训练每轮轮换起点、第二轮反向；训练流量、失败、选择中位数全部保存。选择必须有三个干净成功样本，不因缺测用单次最快值替代。额外候选单独测速仅用于可用性筛选，不用它的短窗速度挑选赢家。完成分块训练后，DNS Monitor 再做两轮，得到 `auto`；它与各族分块训练赢家可能相同，不能因此删掉重复组。

测试歌曲仍为 1344、10552、10553，与训练分离。每个资源每组完整预热一次建立/校验逐块哈希；之后四轮四组顺序固定为 Williams 平衡顺序：

| 轮 | 顺序 |
| --- | --- |
| 1 | auto, v4, extra, v6 |
| 2 | v4, v6, auto, extra |
| 3 | v6, extra, v4, auto |
| 4 | extra, auto, v6, v4 |

每组在每个位置各出现一次，每种相邻有向前序组合恰一次。资源次序仍轮换。共 12 个预热 + 48 个正式完整下载；两组即使 IP 相同仍独立新建连接池、加载器并保留全部结果，作为同路径波动对照。

同 IP 对照若也出现接近或超过 15% 的中位偏移，则同量级的跨 IP 差异不能直接视为稳定收益，需要依靠后续时段和分资源结果判断。正式组不按结果重新排序、换 IP 或延长到得到期望结论为止。

其他加载、校验和限制复用 [原实验](README.md)：产品 DiscardLoader、1 MiB、16 路软上限、250 ms 缓增、Host/SNI/TLS、远端、206/范围/长度/ETag、每块 SHA256、90 秒组期限、两秒组间隔。只比较本批同时段同资源同轮数据。正式内容/远端异常或429/503立即停；训练的一般失败只淘汰该候选，但429/503或内容不一致停止整批。每个块最多一次产品内建重试，所有失败请求保留；区分重试后完成与干净完成。

上限为 40 分钟、正式/预热/分块训练计数 6 GiB；开始前另校验 `20 × 测试资源总大小 + 3 × 可用候选数 × 训练资源大小 + 640 MiB <= 6 GiB`，为最多四轮短窗 Monitor、API 和预检预留空间。训练视频最大 64 MiB。外层 45 分钟。预先规定的总体收益阈值仍为 15%、80% 配对胜率，按每个对照分别计算，且失败率和前 8 MiB 时间不能恶化；未达阈值不能写成稳定可观。
