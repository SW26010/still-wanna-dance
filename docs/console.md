# 本地控制台

## 首次使用与条款确认

首次打开显示[使用条款](../internal/legal/TERMS.txt)，两个确认框默认不勾选，明确确认内容权利边界并同意全文后才能进入。后端同时拦截功能 API；已有配置的自动启动也不会绕过确认。条款版本或全文 SHA-256 改变后须重新确认，确认不会立即触发原有自动启动，需要手动启用功能。同意记录保存在配置旁的 `<配置文件名>.terms.json`（版本、文本摘要、UTC 时间），独立于普通设置。记录损坏时重新确认；保存失败时保持停用。记录是本地操作记录，不证明身份或内容授权，便携目录复制时也会随文件复制。

不同意时仍可停止服务、恢复本程序管理的 hosts 并从托盘退出；关闭网页不退出程序。关于页和页脚可随时打开 `/terms`，`/terms.txt` 提供完整文本。版本变更应同步更新条款中的版本号与 `internal/legal/legal.go` 的版本常量。发布包随附相同的 TERMS.txt；MIT 不变。

## 页面导航

控制台按用途分为五个内容页，桌面使用侧栏导航，窄屏自动换行：

- **首页**（`/#/home`）：启用游戏加速、服务与 hosts 接入状态、本次视频请求检测。
- **监控**（`/#/monitor`）：活动下载、上游总速度与最近 HTTP 请求。
- **缓存**（`/#/cache`）：播放统计、视频版本覆盖率和缓存明细管理。
- **曲库与下载**（`/#/library`）：仅扫描检查、下载补齐，以及任务进度和失败记录。
- **设置**（`/#/settings`）：存储、网络和任务配置，以及单项 CDN 启停、端口状态和 hosts 管理。本地 CDN 下展示房间队列预缓存与准备情况。首页「单项管理」直接进入这里的本地 CDN 区域。

「关于」继续使用独立的 `/about` 页面。五个内容页只显示当前页，支持直接链接、刷新和浏览器前进 / 后退；原来的 `#activation`、`#queue`、`#overview`、`#cache`、`#downloads`、`#recent`、`#batch`、`#preferences`、`#service` 区域链接仍可打开对应页面和区域。未知路由返回首页。

五页切换保留表单草稿、缓存搜索与选择、删除确认及展开状态，不会提交操作或停止后台任务。整页刷新或进入独立的关于页仍是网页加载，未保存的编辑不持久化。所有状态继续共用一套防重叠轮询，浏览器标签页不可见时暂停、恢复可见时刷新；导航本身不创建定时器。缓存明细仍需手动刷新，删除仍需明确确认。键盘导航显示焦点，当前页使用 `aria-current` 标识，切页后焦点进入主要内容；隐藏页不参与键盘和读屏浏览。

验证命令：`node --test scripts/refresh.test.mjs scripts/navigation.test.mjs` 检查前端状态与导航行为；`go test ./...`、`go vet ./...` 和 `go build ./...` 检查 Go 测试、静态分析与构建。

### 上游通道监测

上游检测页展示 upstreamstate.Monitor 的全部操作 × 线路 × 候选通道结果，旧健康检查已移除。direct 模式检查全部有效直连 IP，socks5 模式检查代理通道，auto 模式两者都检查。同意条款后启动后台调度，每轮完成后默认 5 分钟重测；候选变化及观测即将过期时提前重测。关闭浏览器或停止 CDN 不会停止检测，退出应用会取消并等待检测结束。

视频列表、播放地址解析区域分别提供手动检测按钮；视频资源区域提供响应延迟和吞吐速度两个按钮，分别使用带会话令牌的 POST /api/upstream/check/catalog、playback、latency、throughput。手动检测会中止当前自动轮次后执行；列表覆盖三个清单及全部候选，地址解析覆盖两条线路及全部候选，资源吞吐依次测量全部资源候选。地址和资源检测复用有效歌曲样本，必要时查询清单；资源检测先解析合法资源地址，这些依赖请求不覆盖无关区域的结果。手动资源检测不受业务下载暂停规则限制，手动吞吐也不受 配置的吞吐间隔限制；每次仍以 3 秒、16 MiB 或整首完成中先到者停止。手动轮次运行期间按钮禁用，避免重复发起。原有全量立即检测通过带会话令牌的 POST /api/upstream/check 触发；运行中合并请求，距上轮开始不足 10 秒不重复触发。GET /api/status 的 upstreamMonitor 返回纯读取快照，包含全部候选的状态、原因、首字节延迟、样本吞吐、歌曲 ID、观测及有效期。网络配置变化由 Monitor 订阅处理，取消旧检查并重测，仍有效的相同直连通道可保留观测。

业务视频回源（含预缓存）开始时，取消正在进行的自动资源测速，并暂停后续资源测速；全部业务下载结束后自动恢复，被打断的样本不记为通道失败。完整本地缓存读取不会暂停测速。HTTPS 视频透传因无法读取加密请求，保守地在视频连接存续期间暂停；API 透传不触发暂停。界面显示“业务正在加载视频，自动资源测速已暂停”。此规则只作用于自动检测批次，手动检测始终不因业务加载而暂停。

每个清单分别显示响应原始 time：Udon 的顶层 time，Kiva 与 WannaInfo 的 data.time；不将本地观测时间当作清单时间。候选时间不一致时分别保留，缺失时显示未获取。视频列表区分别展示 Udon、Kiva 与 WannaInfo 三个入口及各自的直连 IP / SOCKS5 结果。Kiva 与 WannaInfo 检查 HTTP 与业务状态码、版本、歌曲 ID 和 MD5；无效或冲突的 MD5 会标为响应校验失败。每轮分别校验最多 16 MiB 的歌曲列表，从去重有效 ID 中随机选歌，分别查询 node=cf / node=nya 播放接口。同一路线的所有资源候选共用本轮合法资源样本，自动资源检查分为首字节延迟和吞吐两种：原调度频率仅请求 Range bytes=0-0，读取一个正文 byte 后关闭响应，只更新延迟和可用性，不计算吞吐。吞吐检测独立限制为每个配置周期一轮，按轮次开始尝试的时间写入配置文件旁的 .throughput.json 文件；启动时读取记录，首次或已满配置的吞吐间隔时立即测速，否则等到期。DNS 更新、短 TTL 和失败不绕过此间隔；被业务打断的候选恢复后只做轻量检测，不立即重复完整测速。吞吐轮次仍串行遍历资源候选，对真实资源执行连续 Range 读取并校验响应：正文下载满 3 秒、达到 16 MiB、整首下载完毕，任一条件满足即结束；所有线路与候选的视频资源探测依次执行，避免同时占用本地带宽；不写视频缓存。吞吐按正文下载字节 / 实际正文下载时间计算，排除 DNS、握手和响应头等待；3 秒上限内不足 16 MiB 仍保留已收到数据的测速结果，完全没有正文则记超时。界面同时显示实际下载时长、MiB 样本量和独立的测速时间；轻量检查不会刷新测速时间或覆盖吞吐值，最近一次成功吞吐样本会持久化并在重启后恢复，超过配置的吞吐间隔仍作为历史样本展示，不用于当前测速推荐。样本吞吐是本次窗口的有效速率，不代表持续带宽或全部歌曲的可用性。优先使用本轮 Udon 合法样本，Udon 无有效样本时依次使用 Kiva、WannaInfo；三个列表均失败时可在 10 分钟内复用旧歌曲 ID；没有合法样本时不猜测视频地址，未测候选仍显示待测，旧观测到期显示过期。代理凭据不会进入状态快照。

## 启用游戏加速

首页「启用游戏加速」依次检查 hosts 冲突、启动 HTTP 缓存 / HTTPS 透传、按需调用既有 hosts 提权助手，再等待视频请求。已运行的服务会复用，hosts 已就绪时不请求 UAC。端口或目录错误可按提示处理后重试；UAC 拒绝或 hosts 未完成时，已启动的服务保留，可重试接入或在「单项管理」关闭。不会覆盖其他程序的 hosts 映射。执行期间阻止重复提交；浏览器超时不表示后台操作取消，应等待状态刷新。

服务运行、hosts 接入、收到视频请求分别显示。只有接入步骤完成之后到达且通过本地校验的 HTTP GET / HEAD 视频或播放 API 请求（不要求上游解析成功）才计入本次检测，传输成功与否不影响“收到请求”的事实。历史请求、预缓存、控制台轮询、HTTPS 透传均不计入；无法据此确认游戏客户端、起播或播放成功。等待时请在游戏中请求歌曲，必要时重进世界或重启游戏刷新 DNS。HTTP 视频使用本地缓存；HTTPS 保持加密透传，不使用缓存。

页面显示向导开始、检测起点及首个请求的到达时间（浏览器本地时区）。重新检测或重试清空记录；检测起点之前到达、之后才完成解析的请求也不计入。关闭 CDN、服务故障或操作恢复 hosts 会结束检测；刷新网页保留，多标签页共享，退出程序清空。手动单项启动不自动建立检测窗口。hosts 实时状态可能被其他程序改变，应同时核对三个状态；关闭服务或退出仍不会自动恢复 hosts。

## 缓存明细管理

「缓存」页的「缓存明细」可按歌名、歌曲 ID 或资源指纹查找实际缓存文件，按最近请求、占用或歌名排序，每页最多 50 项。搜索长度前后端统一限制为 300 个 UTF-16 码元，与 HTML maxlength 一致：普通中文占 1 个，补充平面字符（如多数 emoji）占 2 个。点击「查找」或「刷新明细」读取本地目录和数据库；不会联网获取曲库、执行正文 MD5 校验、启动 CDN 或缓存引擎。CDN 关闭、引擎尚未启动时也可查看。翻页、刷新或保存设置会清空选择和删除确认，避免操作旧列表。删除或淘汰使当前页超出范围时，保留搜索和排序条件回退到有效页；连续缩减时最多读取三次并退回首页，避免无限重试。未知文件仅展示，不能通过此页面删除或定位。

主行显示歌名、ID、大小和最近请求。该时间来自资源 GET 汇总及仍保留的 HTTP 请求明细，不代表确认播放；共享文件无法推断实际播放歌曲。资源详情显示指纹和每首歌曲的「本地当前引用 / 历史关联」；本地当前引用不是线上最新版本保证。列表只检查存在、普通文件属性和大小，明确显示「完整性未检查」或「大小不符」，不将版本记录冒充校验证明。每个文件最多展示 20 首关联歌曲和每个标题 300 字符，超出数量有提示；搜索涵盖所有关联。

选择文件后点击「删除选中缓存」，确认区会列出文件、大小及影响歌曲数。共用同一文件的所有关联歌曲都会失去该缓存，需要时重新下载；歌曲资料、版本映射、请求历史和累计统计保留。每次最多删除 50 项，逐项反馈已删除、受保护、已不存在、已变化或失败。确认后文件身份、大小、修改时间、模式或关联变化时跳过，须刷新重选。播放、下载、引擎校验、完整待播队列及离队宽限期保护均在删除前重新检查；独立扫描运行时拒绝整批删除。独立本地校验的同进程资源锁也参与保护。

删除统一经过缓存引擎的资源删除预留，阻止同资源的新引用、发布、淘汰或歌曲关联更新与删除交错。引擎未启动时，以独占存储锁执行同一删除逻辑，不启动服务、自动清理或统计保留期清理；其他进程占用目录时拒绝。成功删除使校验凭据失效并更新运行中容量记账。删除和打开操作仍与存储切换串行化。列表读取不持有生命周期锁或状态锁，慢盘不会因此阻塞服务启停与退出；读取完成后复查设置修订号，期间切换过存储（包括切换后又切回）则丢弃旧结果。

「打开缓存目录」和「定位文件」只接受当前存储标识与缓存条目，不接受任意路径。Windows 使用 Explorer 选择文件，macOS 使用 Finder；其他桌面平台打开其所在目录。目录重定向、符号链接及非普通文件会被拒绝。`GET /api/cache?q=…&sort=recent|size|title&offset=…`、`POST /api/cache/delete` 和 `POST /api/cache/open` 均要求合法 Host、会话 token 和同源 Origin（如提供）；写操作绑定存储标识，删除与定位另绑定条目快照。

分页限制的是返回量。为支持全库搜索和排序，每次读取仍枚举整个视频目录并查询本地元数据，不读视频正文；大库或慢盘可能需要等待，服务端 30 秒超时，界面可重试。列表是手动刷新的快照，不能据此保证文件持续存在或未被外部程序改动。请勿在使用时从资源管理器替换缓存目录结构。

验证：完整 `go test ./...`、`go vet ./...` 和前端 71 项测试通过；新增覆盖共享删除影响、关联变化使确认失效、文件变化、未知文件、路径越界、活动引用/队列/校验保护、离线独占、容量记账、分页、关联展示上限和隐藏关联搜索、接口鉴权、存储切换和扫描保护，以及慢读取期间停止/退出、存储切回时的旧结果丢弃、队列等待期间状态读取与取消、更新/重置顺序和删除末页后回退。Windows 当前环境缺少符号链接创建权限，两项符号链接实测跳过；没有 CGO/C 编译器，未执行 race 检查。资源管理器的实际定位行为仍需桌面人工复核。

Windows 桌面版构建、启动（托盘驻留，无命令行黑窗）：

```powershell
.\scripts\build-desktop.ps1
.\bin\still-wanna-dance-console.exe
```

首次启动由系统分配空闲的本地控制端口（监听 `127.0.0.1:0`），并自动打开实际地址，`-no-open` 可禁止自动打开。关闭网页后仍在托盘运行。原有 `still-wanna-dance.exe` 命令行入口保持可用。

## 托盘与实例避让

托盘菜单包含打开控制台、启动 / 关闭 CDN、停止批量任务、退出 Still Wanna Dance。鼠标或键盘激活图标均可打开控制台；菜单及悬浮提示跟随网页操作更新。Explorer 重建任务栏时重新注册托盘图标。

Windows 桌面入口使用会话级命名互斥锁 `Local\StepStash.Desktop.v1`，控制端口由系统自动分配。主实例在 `%LOCALAPPDATA%\StepStash\console-session-<会话 ID>.json` 记录实际地址和 PID；重复启动读取该会话记录并核对端口所属进程。重复启动不创建第二个服务或托盘，而是最多等待 5 秒，确认 `/api/identity` 匹配保留的 `stepstash-console` 协议身份 后打开已有控制台。若首次启动者在就绪前崩溃，后启动者可重新竞争所有权；进程死亡不会留下永久实例锁。正常退出先删除地址记录再释放实例锁，新主实例启动时清除崩溃遗留记录。不会仅因为端口有人监听就打开未知服务。

配置文件还通过 `<配置路径>.lock` 在整个进程生命周期独占，防止自定义端口实例同时修改同一份设置。锁文件保留是正常现象；OS 在进程退出或崩溃时释放锁，不要运行时删除。缓存引擎对整个存储根目录加独占锁。

退出从统一清理入口停止 HTTP 接口、取消批量任务和下载、移除托盘图标，最后释放配置锁和实例锁。注销 / 关机回调最多等待 4 秒；如果系统取消注销，程序继续运行。退出不会恢复 hosts。hosts 提权助手在实例检查前单独执行，修改完成即退出，主程序不会因此提权。

80、443 或手动指定的控制端口冲突时，Windows 下显示占用进程名和 PID；不结束其他进程，也不自动请求 UAC。旧的无托盘版控制台不会持有新实例锁，需要退出旧版后再启动新版。

默认自动选择端口；也可用 `-listen 127.0.0.1:18082` 手动指定（托盘模式同样支持）。自定义控制端口及无托盘运行示例：

```powershell
go build -o bin/still-wanna-dance-console-cli.exe ./cmd/still-wanna-dance-console
.\bin\still-wanna-dance-console-cli.exe -no-tray -listen 127.0.0.1:18082 -config .\other-settings.json
```

该模式不自动打开浏览器，不创建托盘，使用 Ctrl+C 退出。Linux 默认使用无托盘模式。配置独占及现有缓存独占规则仍然生效。

设计参考 [dancing-log desktop_instance.py](https://github.com/SW26010/dancing-log/blob/c3fa28fa3b68879cb43513bc2cb53f1cc03fa1cc/dancing_log/desktop_instance.py)、[tray_app.py](https://github.com/SW26010/dancing-log/blob/c3fa28fa3b68879cb43513bc2cb53f1cc03fa1cc/dancing_log/tray_app.py) 和 [_win_tray.py](https://github.com/SW26010/dancing-log/blob/c3fa28fa3b68879cb43513bc2cb53f1cc03fa1cc/dancing_log/_win_tray.py) 的所有权、身份探测和统一退出机制。Still Wanna Dance 以 Go / Win32 实现，无新增第三方运行依赖。

## 服务与下载独立

- **启动控制台时自动启用 CDN**：设置中的开关默认关闭（旧配置也保持关闭），停止 CDN 和批量任务后可修改并保存。开启后，下次启动控制台程序时自动触发一次「启动 CDN」，启动检查、结果和错误处理均复用手动启动逻辑；重新打开网页或激活已有实例不会触发。不自动修改 hosts。启动失败会在页面显示原因并写入日志，控制台继续运行，可处理后手动重试。配置字段为 `autoStartCDN`。
- **启动 / 关闭 CDN**：同时控制 `127.0.0.1:80` HTTP 视频缓存和 `127.0.0.1:443` HTTPS 透传。启动检查两个端口和目录权限，任一失败均回滚监听；页面分别显示两个端口状态。端口占用时提示关闭原版 CDN 或其他程序，不自动结束其他进程。hosts 缺失不阻止监听，提供独立修复按钮。停止会关闭已有播放连接，但保留独立下载任务。
- **仅扫描检查**：从 Kiva 清单获取歌曲 ID、名称与 MD5，新增和更新本地映射，保留清单中消失的旧 ID。一次枚举视频目录，检查所有被引用的 MD5 文件是否存在；不读取正文、不计算 MD5、不关心孤儿文件。上层直接使用检查结果。可与队列预缓存和播放并行。
- **下载补齐**：每次重新获取清单并更新映射，使用独立的快速缺失检查，只为缺失 MD5 解析 URL 和下载。同 MD5 多首歌曲只下载一份，已有文件不重复检查。映射不变但文件缺失也会补齐；映射变化但文件已存在无需下载。清单不可用时使用本地已接受的 MD5 映射继续处理；本地没有有效清单时明确报错。URL 的 MD5 与清单不一致时记录失败，清单关联保持不变。
- **停止批量任务**：取消排队和当前等待；已开始的共享下载继续执行，直到完成、失败或程序退出，以免打断游戏。关闭 CDN 同时停止队列预缓存并关闭播放入口，不中断独立批量下载。退出控制台进程会取消全部下载。
- 成功结果与当前任务进度分开显示。完整任务无接口或读取错误时才替换成功结果；扫描中、失败或取消均保留上次成功计数。任务结束或正常停止时另存进度记录。重启恢复记录，但不会自动继续任务；暂不提供下载断点回源。
- 下载补齐按视频缓存容量预算执行：下载前按完整视频大小预留空间，两首并发共享预算，已有视频不重复计费；剩余预算放不下下一首时自动停止，不计为失败，也不保存为全曲库成功结果。已获准的下载正常完成，界面提供前往设置调整「视频缓存上限（GiB）」的入口；停止 CDN 后保存新预算，再次点击下载补齐即可继续。0 表示不限。本轮已使用的预算不会因淘汰而循环释放，避免边下载边淘汰整份曲库。命中和下载计数是过程累计值，当前保留数量与占用空间通过「刷新覆盖率」更新。
- 缓存概览先检查远端并按版本规则更新本地库，再按本地歌曲 ID 对照 MD5 文件存在性，包含隐藏曲目和保留的旧 ID，共用文件按歌曲分别计入覆盖率；文件数按唯一 MD5 计数。远端失败或候选无效时仍重新计算本地覆盖率，并显示检查错误；本地读取失败才保留上次结果。由用户手动刷新，不自动重复扫描。
- 结果写入配置文件旁的 `<配置文件名>.inventory.json`、`.batch.json` 和 `.attempt.json`，写入临时文件后替换；文件随便携目录移动。更换存储目录时不会沿用其他目录的结果。

## 实时下载监控

控制台在最近请求上方显示活动共享任务及上游总下载速度。`GET /api/downloads` 使用控制台 token、Host 和 Origin 检查；读取内存中的线程安全快照，按资源共享任务去重，曲目候选从已有索引补全，不读取日志或启动缓存引擎。多个 Range、播放请求和预缓存加入同一任务不会重复计速。

监控读取不获取控制台生命周期锁，启动、停止、保存设置或引擎关闭期间仍可返回当前快照。歌曲资料查询在锁外进行，受查询期限和引擎取消控制；引擎关闭或被替换时丢弃旧任务快照，不等待关闭操作完成。

字节数为从上游正文实际读取的字节；速度是最近约 5 秒的估算值（按秒分桶，启动不足 5 秒按已用时间计算），不是网卡流量，也不是向客户端传输速度，不包含选路探测、API 查询或 HTTPS 透传。停止读取后速度衰减为零，发布及索引阶段速度为零。总大小来自已解析资源的预期大小；字节百分比不是整个任务完成率，下载时同步计算 MD5，随后仍需验证并发布。任务可能先显示本地缓存检查阶段，命中后不回源。

主行突出歌名、进度和上游速度，资源来源按最终响应域名显示，响应前显示线路待定。完整资源指纹、最多 20 首关联曲目（超出时提示更多）、最终主机名（含已验证的重定向）及空闲时间默认折叠在「下载详情」，统计口径放在「下载统计说明」。详情支持键盘展开，轮询保留展开状态与焦点。不暴露签名 URL 或代理凭据。歌名来自显式任务关联和已有资源映射；共用资源标明关联曲目数量及播放歌曲未确定，不推断实际播放歌曲，未知信息明确标注。

活动任务完成、失败或引擎退出后移除，下次轮询更新；关闭 CDN 或取消等待者不会取消现有共享下载，因此 CDN 关闭时仍可显示继续运行的下载。没有任务时显示空状态；读取失败清空旧列表和速度并自动重试。复用全页面每 5 秒、无重叠的轮询批次，页面隐藏时不再发起新轮询。尚未进入共享下载的容量等待和歌曲地址解析不在此列表中。

## 队列预缓存与刷新频率

队列预缓存的操作和轮询规则见[日志队列预缓存](queue-prefetch.md)。房间队列预缓存展示在本地 CDN 下方，随 CDN 自动启停；设置中可关闭默认开启的「随 CDN 启用房间队列预缓存」，并勾选「手动指定 VRChat 日志目录」以使用自定义路径，默认每次启动按当前用户自动读取。开启后等待新队列同步，不会下载历史日志里的歌曲。队列预缓存与全曲库下载互斥，下载补齐期间暂停，结束后仅在 CDN 仍运行且此功能启用时恢复；视频扫描可与队列预缓存和 CDN 播放同时运行。

网页状态在可见时每 5 秒刷新，隐藏时暂停轮询，恢复可见时立即刷新。操作完成后，页面可见时立即刷新，隐藏时等待恢复可见再刷新；已发出的展示请求正常完成。CDN、下载、日志监听及已启动的扫描任务独立运行，不受网页是否打开或可见影响。

操作请求最多等待 30 秒，hosts 操作因可能等待管理员授权而延长到 120 秒；期限包含响应体读取。超时或响应丢失后解除操作等待，并刷新当前状态供核对，不自动重试。页面提示「结果尚未确认，请勿重复提交」：停止浏览器等待不会取消后台操作，刷新得到的状态也不能证明原请求已经结束。状态查询失败时保留提醒，待连接恢复后继续核对；页面隐藏时延至恢复可见再刷新。

## 上游连接

直连模式使用内置加密 DNS 解析域名，并连接目标 IP，可能影响透明代理的域名分流，使实际连接路径与预期不一致。如需由代理处理域名解析和连接，请选择「SOCKS5 代理」并配置代理地址。

在「缓存与任务设置」中选择「上游连接」：默认「直连（内置 DNS）」沿用内置 DoH 与多 IP 优选连接；选择「SOCKS5 代理」后，填写代理软件的 `主机:端口`，例如 `127.0.0.1:7891`，不加 `socks5://` 前缀。端口以代理软件实际的 SOCKS5／混合端口为准。支持无认证及用户名／密码认证；需要认证时同时填写用户名和密码，各限 1～255 字节。

密码保存到本机配置文件（明文），不通过状态接口回传，不写入任务快照。页面只提示是否已保存；密码框留空保留已有密码，填写新值则替换；清空用户名和密码后保存可移除认证。切换回直连会保留认证配置，便于再次启用。设置 API 省略 `socks5Password` 时保留原值，显式发送空字符串则清除；用户名与密码须配对。变更凭据会重建网络客户端。

API 查询、校验和清单、冷缓存播放、队列预缓存、下载补齐、选路测速和 HTTPS 透传均使用所选出口。代理模式把目标域名和端口直接交给 SOCKS5，不在 Still Wanna Dance 中解析目标域名，不使用内置 DoH 或多 IP 直连，不检查代理端如何实现 DNS；代理不可用或拒绝连接时返回错误，不自动回退直连。原域名 Host、TLS SNI 和证书校验保持不变。代理服务器地址本身若填写域名，由本机网络解析；本地代理推荐填写 `127.0.0.1`。

停止 CDN 和批量任务后保存即可切换，无需重启控制台。保存会重建上游客户端及缓存引擎，清除旧连接和选路测速状态；已开始的库存覆盖率查询允许使用原客户端完成，之后的新请求使用新设置。旧配置默认直连，切回直连会保留代理地址方便再次启用。播放接口选项仅决定 API 查询参数，资源域名由返回值决定，测速经过当前所选出口；完整缓存的本地读取不经过代理。

SOCKS5 使用本地模拟服务验证域名转交、API HTTPS、缓存回源、HTTPS 透传、取消和设置切换；真实代理线路的持续吞吐与 VRChat 联合播放仍需实机验证。

## 独立 DNS

### 网页 HTTPS 播放

hosts 同时影响 HTTP 和 HTTPS。控制台启动 CDN 时提供 TLS SNI 透传，防止网页的视频 HTTPS 请求被映射到本机后遭到连接拒绝。仅接受 `api.udon.dance` 和当前已由有效 API 响应确认的资源域名；新 hosts 接管只写入 API 域名，资源域名不预设，通过所选上游连接方式访问其 443 端口。直连时的独立 DNS 不读取系统 hosts；代理模式将目标域名交给 SOCKS5。不使用额外的 `ud-*` 回源别名，不开放通用代理。网页、封面和统计域名不纳入接管。

直连模式下，转发复用下面的独立加密 DNS、TTL 缓存、多 IP 错峰建连与成功地址优先机制；代理模式下通过 SOCKS5 建连。固定保留域名的原上游，不套用 HTTP 的播放接口参数设置，不跨线路替换路径或签名。TLS 握手及后续密文字节原样传递，浏览器直接验证原站证书；不安装证书、不解密、不改网页、不降级为 HTTP。网页 HTTPS 播放仍消耗上游流量，不命中或填充本地视频缓存，也不计入缓存热度。

只绑定本机 IPv4，最多 128 条连接，ClientHello 限制为 64 KiB / 10 秒，建连最多 15 秒，两分钟双向均无进展的连接关闭。关闭 CDN 会取消解析和建连并清理活动连接。此入口不支持无 SNI 或隐藏目标域名的握手，也不提供 QUIC/UDP 443。

回归覆盖 TLS 1.2 / 1.3、原站证书验证、HTTP/2、Range/HEAD、分片 ClientHello 原样转发、未托管域名拒绝、建连和活动连接取消，以及端口冲突/目录失败的回滚与重启。需要浏览器实网复验时，先释放本机 443，使用当次 API 返回的实际资源域名进行本地连接测试，在 PowerShell 中运行 `$env:STEPSTASH_HTTPS_LIVE='1'; go test ./internal/console -run '^TestHTTPSLiveBrowser$' -v -count=1`。此显式验收辅助服务先通过两个播放接口发现歌曲 1343 的资源域名并打印集合，仅监听 443，两分钟后自动退出，不改 hosts 或缓存；普通测试和 CI 默认跳过。它仅为手工验收提供连接窗口，测试通过本身不代表视频播放成功，须另行检查浏览器。

历史 Chrome 实测（2026-09-26，切换公开域名前）：通过上述辅助服务从原站点击歌曲 6228，播放器 `readyState=4`、`error=null`，播放时间推进到 13 秒；重新打开当时 node=nya 返回的地址后，重定向到 play.udon.dance，继续播放至 37 秒。当时服务连接的是 `ud-nya.kiva.moe:443` 和 `ud-play.kiva.moe:443`，不代表当前默认目标。没有改写网页、视频 URL、系统证书或 hosts；这是该歌曲当时的连通与播放验证，不代表全曲库或持续吞吐测试。

当前公开域名回源的实网验收见[调查后的实现与验证](playback-domain-observation-20260926.md#调查后的实现与验证)。`STEPSTASH_LIVE_UPSTREAM=1` 启用的 `TestLiveHTTPSUpstreams` 会让测试客户端连接临时本地 TLS 透传端口，模拟 hosts 接管，再通过生产 DoH 连接公开域名；验证 API 实际返回地址的视频片段及原站证书，不修改系统 hosts。

### 解析与连接

以下机制适用于直连模式。控制台的歌曲列表、播放地址解析、视频回源均只使用证书验证通过的 HTTPS DNS（RFC 8484 POST），不查询 ISP 或系统 DNS，不读取系统 hosts，也不会在失败时降级到 UDP、HTTP 或自动接受 fake-IP。TLS 使用系统信任库并校验服务域名，拒绝重定向、错误媒体类型、过大或不匹配的 DNS 报文。

内置服务：

| 服务 | HTTPS 入口 | 引导方式 |
| --- | --- | --- |
| 阿里公共 DNS | `https://dns.alidns.com/dns-query` | `223.5.5.5`、`223.6.6.6` 两个独立连接入口，仍验证域名证书 |
| 腾讯 DNSPod | `https://doh.pub/dns-query` | 通过已验证的加密解析获取入口 IP，并按 TTL 缓存 |
| 360 安全 DNS | `https://doh.360.cn/dns-query` | 同上 |
| Cloudflare | `https://cloudflare-dns.com/dns-query` | `1.1.1.1` 引导，验证域名证书 |
| Google | `https://dns.google/dns-query` | `8.8.8.8` 引导，验证域名证书 |

DNSPod 和 360 的入口发现只通过具备固定引导 IP 的 DoH 服务进行，不依赖本地 DNS；同入口并发引导合并，后续读取 TTL 缓存。没有硬编码 DNSPod 已下线的测试 IP。官方依据：[阿里服务资料](https://static-aliyun-doc.oss-cn-hangzhou.aliyuncs.com/download%2Fpdf%2F171662%2FAPI_Reference_intl_en-US.pdf)、[DNSPod 域名接入公告](https://docs.dnspod.cn/notices/mian-fei-ban-dot-dohbu-zai-gong-kai-ipjie-ru-de-gong-gao/)、[DNSPod 旧测试 IP 下线公告](https://docs.dnspod.cn/notices/guan-yu-doh-dotdu-li-ce-shi-ipxia-xian-de-gong-gao/)、[360 官方服务页](https://sdns.360.net/dnsPublic.html)。

有限并发查询这些加密入口，首个有效答复后最多再收集 200ms，合并去重并最多保留 6 个 IPv4 候选；整体最多 6 秒。结果按已收集答复中 A 记录与 CNAME 链的最小 TTL 缓存（最多 300 秒）。连接候选每隔 200ms 错峰启动，单连接最多等待 5 秒；成功地址优先复用，取消其余连接，全部失败时清除缓存。IP 层衡量连接建立速度，视频小段测速在上游线路层进行。视频请求仍保留原始 HTTP Host，历史 UI 中 HKG 对应查询参数 `node=nya`，不代表资源域名。

全部加密通道失败时明确报错。这保护的是客户端到解析服务的 DNS 链路，仍信任所选解析服务及系统证书信任库；DNS 模块本身不改变视频或 API 请求的 HTTP/HTTPS 协议。曲库业务仅使用 Kiva／WannaInfo 的 MD5 清单，Udon `https://api.udon.dance/Api/Songs/list` 只用于 monitor，不参与本地曲库更新或水位计算；游戏请求的 HTTP→HTTPS 跳转与 HTTPS 透传继续保留；播放地址 API、版本确认、视频下载、测速和 Range 回源统一使用 HTTPS，保留原始 Host、TLS SNI 和证书域名校验；连接或证书失败不降级至 HTTP，也不回退系统 DNS/hosts。此前依赖明文 DNS 劫持产生 fake-IP 的代理路径不再由此模块自动使用。

2026-09-25 本机逐入口真实解析 `api.udon.dance`：阿里双入口、DNSPod、360、Cloudflare、Google 六项均通过 HTTPS 证书验证与 DNS 报文解析。这不代表其他网络始终可达。可选复测：`STEPSTASH_LIVE_DOH=1` 后运行 `go test ./internal/console -run '^TestLiveDoHProviders$' -v -count=1`。
控制台与独立命令行服务共用内置 DoH 建连逻辑。两者的上游 API 查询和视频回源均使用 HTTPS，默认视频回源端口为 443；DNS、连接或证书验证失败不回退系统 DNS/hosts 或明文 HTTP。视频重定向仅在目标域名已由有效 API 响应确认且 MD5/大小一致时跟随，最多五次，HTTP Location 升级为 HTTPS 后访问。

- 操作后刷新 DNS 缓存。UAC 取消或修改失败时页面报错。

## 目录与配置

填写一个存储根目录并保存；不读取旧歌曲库或提供迁移。运行 CDN 或批量任务时不能修改目录，保存时检查存储目录可写性。尚未启动引擎的新建空目录可直接扫描，显示零视频、零占用；已初始化目录丢失视频目录或无法读取时仍报错并保留上次结果。VRChat 日志目录不创建或修改。

### 统一回源选路

播放地址接口默认 Auto。业务按操作、入口、节点、资源域名和网络模式约束使用 Monitor 提供的实际 Transport。API／清单请求顺序尝试候选，并按剩余时限为备用保留时间；无有效观测时使用配置通道。固定模式约束 API node，不从 node 推断资源域名。下载核心不查询歌曲 API，不维护路由缓存，也不现场测速或独立排名。

资源 Range 请求单独保留本次候选进度：首块或后续区块的范围校验、实体标识检查、短读和网络失败可推进到备用通道，不从首选重新开始。后续区块发生重定向时，只在该区块内保留已验证的最终地址，失败后继续该地址的备用通道。每个地址最多使用四个 Monitor 候选；只有一个通道时，区块失败最多再试一次。多个候选按任务剩余期限分配时间，预算覆盖响应头及 206 正文读取，成功返回响应头不会立即取消请求。若确认上游忽略 Range 并返回合法 200 全文，则撤销候选预算，由整个任务剩余期限约束顺序下载。已经输出的区块不替换；全文降级不据此承诺任意拖拽。

即时播放和队列先保护并检查本地资源，同时独立刷新 API 地址。本地完整资源立即使用；本地缺失时先尝试持久化 URL，失败再等待已有查询。地址记录保留完整 URL、API/node、MD5、大小及观测顺序，当前复用窗口为 24 小时，不保证签名始终有效。新观测不替换已打开资源或已有清单映射。

下载补齐按清单 MD5 调度，对同资源关联的歌曲依次查询，取得目标内容后停止。播放、队列和补齐共享 MD5 下载任务、区间数据、容量保护及最终校验。旧拖拽最后一个读者离开后，可取消其前台区间；后台继续补齐未完成区块。已输出正文后不能切换内容。

资源以 API 实际返回域名区分，同域名不代表相同 URL 或相同内容。当前下载任务可继续访问受信任原始域名的同域重定向；跨域仍需来源许可，所有重定向仍校验 MD5 和大小。这不扩大任意入站资源请求的域名权限。独立命令行服务不提供控制台的 Monitor 推荐回调，接入限制见[服务手册](service.md#游戏接入)。

## 播放请求统计

控制台通过 /api/status 的 traffic 字段展示当前存储目录的累计请求命中、节省流量和首正文时延。命中率分母为成功完成的 GET 视频请求（200/206），Range 按请求计数；HEAD、失败、中断和预下载不计入。节省流量是成功命中实际返回的正文大小，不是扣除预下载后的净流量收益。

播放传输次数另行保存，仅计有明确歌曲 ID、成功完成且返回正文的即时 GET。同曲按成功完成的记录时间以 30 秒窗口去重，不使用请求开始时间；记录时间与入队顺序在同一锁内确定。历史累计不回算。该指标不改变需求评分，也不代表客户端起播或完整播放。

首正文时延从 HTTP 请求开始到首次写入正文，包含 API、下载等待和本地验证。HIT/MISS 分别展示均值与样本数，历史响应头计时不混入新口径。不把不同阶段的 Monitor 样本相加，不计算未配对样本的加速比例。完整传输耗时、首正文和客户端首帧是不同指标。

## HTTP 播放 API 接管与 HTTPS 回源

点击「修改 hosts」接入 `api.udon.dance`；旧版托管的资源域名映射会清理，不再预设资源域名。只要仍有本程序拥有的旧资源映射，即使 API 已映射也会标为待迁移、接入未完成；「启用游戏加速」会执行清理并重新检查。自动启动仅启动服务并显示迁移提示，不自动提权。其他程序或用户的条目不属于迁移范围，被修改的托管条目需手动检查。资源集合与历史记录的解释见[资源域名规则](resource-domains.md)。游戏以 HTTP 请求 `/Api/Songs/play?id=…` 时，Still Wanna Dance 使用 HTTPS 解析上游地址，校验资源指纹，然后直接以 HTTP 返回视频；命中复用缓存，未命中边下边播，支持 HEAD 和单段 Range。支持默认线路以及 `node=cf`、`node=nya`，其他线路明确拒绝。非播放 API 的 GET/HEAD 重定向至原站 HTTPS；原有 HTTPS 请求通过 443 透传，不读取或填充缓存。

游戏入口必须仍使用 HTTP，并且播放器需接受 API 地址直接返回视频；当前 HTTP 播放 API 接管的实际游戏兼容性需要实机确认。仅接管 API 的前提是解析器和播放器能通过这个直接返回视频的本地入口完成后续读取。历史上正常解析后请求资源 URL 有证据；“新的播放绕过 API、复用旧资源 URL”则尚无发生证据、频率统计或稳定复现步骤。假设、条件性担忧及实机验证要求见[仅接管 API 的假设与待验证边界](resource-domains.md#仅接管-api-的假设与待验证边界)。服务端改用 HTTPS 回源不改变当前统一存储的资源指纹；此说明不表示兼容旧存储格式。下载和测速最多跟随五次视频重定向，仅接受当前 API 确认的视频域名且 MD5/大小一致的地址；HTTP Location 会升级为 HTTPS 后再访问。其他重定向明确拒绝。

HTTP 播放 API 优先使用受保护且校验通过的本地文件，不等待后台 API。缓存 URL 下载失败时，尚未输出正文可等待本次已有查询再尝试；旧下载与刷新都失败时保留两个阶段的错误。正文输出后仍中止响应，不切换内容。HTTPS 透传不适用；加载边界见[歌曲加载设计](song-loading-design.md)。

可选实网验收：设置 `STEPSTASH_LIVE_UPSTREAM=1`，运行 `go test ./internal/console -run '^TestLiveHTTPSUpstreams$' -v -count=1`。仅解析播放 API 并读取每路 1 KiB 视频 Range，不修改 hosts。

## 最近请求监控

导航中的「最近请求」显示按记录时间倒序排列的已结束 HTTP 视频请求。每 5 秒随控制台状态刷新，页面隐藏时暂停；「加载更早记录」每次将近期窗口增加 50 条，上限 500 条。查询先筛选 HTTP 请求，再通过专用部分索引 `request_events_http_time` 按记录时间和事件 ID 倒序读取最多 501 条 HTTP 记录；预缓存不占用窗口，hasMore 也仅统计 HTTP 请求。旧数据库首次读取会补建该索引（只为已有数据库临时打开可写连接，不启动 CDN）；以后轮询仅通过索引读取有限记录，不扫描日志或整个请求表。保留天数与现有请求明细设置一致；没有数据库时显示空列表，不创建数据库或启动 CDN。读取失败单独提示并自动重试，存储切换清空旧窗口。

同一资源连续的 GET Range 请求，记录时间间隔不超过 30 秒时组成请求组；其他资源的交错请求不影响分组，同资源 HEAD / 完整请求会打断分组。组只覆盖当前窗口，边界可能截断，扩展窗口后重新计算。展开状态和仍存在的展开控件焦点在正常刷新时保留；混合缓存、完成、中断和失败结果分别列出次数。×N 是请求次数，不是播放次数。

歌名来自 `song_media` 与 `songs` 的当前资源关联，不保存或展示历史所属歌曲。共用资源显示多首候选歌名，不推断实际播放曲目；无关联时显示未知歌名，展开后显示完整资源标识。主行以歌名为主，缓存与结果使用独立标签，传输量、耗时和速度各自对齐成列；窄屏改为分行网格。多曲目主行最多显示两个标题并提示共享资源，展开后列出完整候选、Range 和资源指纹。每个资源最多返回 20 首、每个标题最多 300 字符，多余关联明确标注。API 不返回签名 URL、主机、源路径或 metadata JSON，非标准 Range 内容被替换。`GET /api/requests?limit=50` 要求当前会话的 `X-StepStash-Token`、合法 Host 与同源 Origin（如提供）；limit 必须为 1～500。

实际传输量是响应向客户端写入的字节数，MB 使用十进制，不是视频大小或后台回源量。单次耗时包含地址解析、等待与校验。GET 的记录时间在播放地址解析后更新，但单次耗时从 HTTP 处理开始计量，两者起点不同。多请求组按最早记录时间至最晚「记录时间 + 单次耗时」计算**估算跨度**，包含请求间隔，不相加并行耗时；**估算平均速度** = 字节和 / 估算跨度。这两个组指标均在界面标为估算，不代表精确起止时间；单条请求的耗时与速度仍使用其原始 elapsedMS，0 毫秒显示「—」。

HTTP 200 / 206 不单独决定完成状态；保留记录的 canceled / aborted / failed 语义，旧版写入失败且无错误 HTTP 状态显示「写入失败 / 连接中断」，不能据此断定后台下载失败。读取时会将已知长度下的短传输标为不完整，不修改原始明细或累计统计。处理完成也不证明客户端播放完成。尚在进行、尚未写入、队列溢出丢弃，以及资源识别之前被拒绝的请求不在此列表中。

验证：`go test ./...`、`go vet ./...`、Go 构建及 `node --test scripts/refresh.test.mjs`（63 项）通过。请求监控新增覆盖 1 条 HTTP 请求被 500 条预缓存包围时仍可见、旧库关闭 CDN 时索引迁移、查询计划使用部分索引且无排序临时表、时间排序与窗口、未知和多曲目关联、标题与关联数量上限、短传输和中断解释、API 鉴权、无数据库和损坏数据库、30 秒分组边界、混合结果、并行跨度、展开及焦点保留、存储切换、读取失败恢复和不重叠刷新。在隔离的本地 Console 浏览器预览中确认 CDN 关闭时历史记录可见、×3 请求组可展开、混合命中与中断分别显示，桌面五列对齐、320 像素窄屏无横向溢出且刷新保留展开，浏览器无脚本错误；未实测辅助技术与 Windows 高对比度。

自动吞吐检测间隔可在 WebUI 设置中调整，默认 20 分钟，允许 1～1440 分钟整数，对应 throughputIntervalMinutes。旧配置未设置时采用默认值。保存后按最近测速尝试时间重新计算到期时间，不重置计时；缩短后已到期则唤醒调度。此设置同时决定吞吐样本参与推荐的有效期，首字节检测频率不变。保存沿用设置页要求：先停止 CDN 和批量任务。

## 本地清单与检查状态（2026-10-06）

覆盖率、扫描和下载补齐始终先尝试检查远端、按规则同步本地，再读取本地快照开展业务。远端不可用时使用已有本地清单重新计算，不沿用旧的文件计数；没有有效本地 MD5 清单则提示无法处理。正常联网时也使用同一流程。Udon 清单仍仅用于 monitor。

界面分别显示最后检查时间和本地数据水位。最后检查时间只在完整校验并完成版本比较或事务更新后推进，包括同版同内容及合法旧版本；网络、解析、版本冲突或写入失败不推进。水位是已接受的 Kiva／WannaInfo 共享 songs 版本，旧候选不会降低它。错误独立展示，重启保留；已有数据库没有历史检查记录时显示未检查，不用其他时间代替。覆盖率结果记录计算所用水位；本地水位变化后提示重新刷新。

检查状态独立从当前存储目录的数据库读取；离线重启或保存设置关闭引擎后仍可恢复，不使用旧覆盖率快照中的检查状态，也不会为读取状态启动引擎或创建数据库。monitor 的 MD5 候选校验／同步失败会记录错误；同轮旧镜像检查成功不掩盖其它候选的冲突，后续成功轮次清除错误。
