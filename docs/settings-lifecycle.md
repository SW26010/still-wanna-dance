# 配置与运行生命周期

配置可以在服务或任务运行时保存。保存校验、写入配置文件并更新已保存快照；除下述退出策略外，当前 Console 的配置、网络连接、共享本地资源引擎、监测策略、扫描与任务保持不变。

除「退出时恢复游戏直连」保存即用于本次退出外，其余运行设置在应用重新启动后生效，包括没有任务运行时保存的设置。单独停止、启动播放网关或任务不会应用待生效配置。

歌曲屏蔽与收藏属于本地曲库偏好，不属于本页的启动配置。其保存后对后续决策的生效边界见[歌曲偏好设计](download-resource-design.md#8-歌曲屏蔽与收藏)；不纳入 `activeSettings` / `restartRequired`，也不因标记变更启动下载任务。

「激进的缓存回收策略」保存为显式枚举 aggressiveCacheReclamation=auto/on/off，初始为 auto。自动只在视频保留选项为「不保留」时开启，「限制为」及「不限制」时关闭；使用有效预算判断，不受界面记住的预算输入值或当前剩余额度影响。手动开启/关闭不随预算变化，选回自动后恢复跟随。该选项仅在设置的存储标签编辑，使用引导沿用已保存策略，恢复本页默认也不改动它；状态快照保留策略本身，实际行为由当前运行配置计算。仅切换策略也参与待重启，引导核对仅展示此前已保存、尚未生效的策略差异。配置格式为 6，不迁移旧格式。

「高级下载设置」中的下载并发软上限与增长间隔也遵循此规则。配置字段 `downloadSoftLimit` 与 `downloadGrowIntervalMS` 缺失或 null 时分别使用 16 和 250，明确保存的 0 ms 表示关闭缓增；范围与执行语义见[下载并发](download-concurrency.md)。

「优先保留收藏视频」（`retainFavorites`）默认开启，保存后重启应用生效；关闭时收藏只做标记，按普通预算取舍。切换选项不启动下载、补齐或恢复文件；引导保留此设置。规则见[歌曲屏蔽与收藏](download-resource-design.md#8-歌曲屏蔽与收藏)。

「本地存储」中的本地延续保护时长也在应用重新启动后生效。`localProtectionGraceSeconds` 缺失或 null 时默认 300，接受 0～10000 的整数；显式 0 表示不延续保护。引导保留该设置，并在最终核对中显示此前保存但尚未生效的更改；保护资格、起算点和回收边界见[本地保护](download-resource-design.md#本地保护)。

状态接口中的 `settings` 是已保存配置，`activeSettings` 是当前运行配置，`restartRequired` 是两者规范化后的差异。两份配置均不返回代理密码；密码差异仍参与待重启判断。保存请求省略密码时保留最近保存的密码，显式空串清除密码。

设置表单展示已保存配置；运行信息、本地视频列表与监测展示当前配置。保存失败不会更新已保存快照；把配置改回当前值会清除待重启提示。

默认由播放网关带动队列预加载：`queueWithGateway` 为 true 时，启动网关会开启队列；停止、运行故障及加速失败撤销网关时，等待队列停止并撤销队列来源需求。为 false 时，网关不启动队列。后台保留独立启停能力。共享引擎由 Console 持有，懒创建后保留到应用退出。队列的 `desired` 表示实际启用意图，`running` 表示读取任务是否运行；日志读取失败单独报告，不改变 hosts 与网关共同决定的加速结果。手动下载不暂停或恢复队列。

引擎记录的首个本地存储故障通过状态接口 `storageError` 展示；无故障时省略该字段。控制台公共错误栏持续显示原因、停止新下载的影响及修复后退出并重新打开应用的步骤，已保存的本地视频仍可读取。修复目录、成功读取本地视频、启停播放网关或队列都不会清除此错误；新应用实例创建新引擎后重新判断。此字段直接读取引擎，不额外持久化，也不改变表示配置差异的 `restartRequired`。

常规设置提供「启用控制台后自动一键加速」（`autoAccelerate`，默认 true）；预加载与下载设置提供「随视频网关启用队列预加载」（`queueWithGateway`，默认 true）。保存后重启生效，不是即时操作开关。自动加速每进程执行一次，与手动加速共用接入、网关和回滚流程，可能请求 UAC。刷新网页、激活已有实例或重复调用启动入口不会重试。

有效条款记录及首次引导最终应用成功后才允许自动加速。仅同意条款、浏览或校验引导不会启动；即使此时退出并重新打开程序，也继续等待最终应用。需要重启的应用先由新进程完成回执续接，再执行自动加速；配置、导入启动或完成回执失败均不提前执行。自动加速失败不自动重试，处理原因后可手动一键加速；重复提交或重进引导不重新执行已消费的启动意图。

配置版本 6 使用上述新字段，各自缺失或 null 时默认 true，明确 false 保留；不读取或迁移旧自动启动字段。版本 5 及更旧配置拒绝打开并保留原文件。

待应用配置会显示「立即重启并应用」。有尚未保存的表单更改时按钮禁用。重启请求使用现有 Host、Origin 和会话令牌校验；先返回响应，再由程序入口停止服务与任务。`run()` 返回并完成全部延迟清理（包括配置锁、桌面单实例锁及日志文件）后，`main()` 才启动替代进程。

重启保留绝对配置路径、实际控制台端口及托盘模式，避免重复打开浏览器。页面等待新实例的会话令牌出现后刷新；响应丢失不会重复发送重启请求。60 秒内未确认新实例时显示手动恢复提示。批量任务不自动续跑；按已保存的自动加速和队列随动配置启动，仍受使用条款限制。退出和重启同时到达时，首次被接受的操作决定结果。

引导最终核对复用后端完整配置校验，用规范化配置（含不向浏览器公开的凭据）比较是否需要重启，并核对首次同意后的待执行启动意图。校验只返回重启／执行启动设置两个事实，不保存设置或启动服务。摘要据此展示本地服务、队列和游戏连接的具体影响；无法核对时不允许确认。正式应用仍重新校验。无需重启的重新引导保留已手动关闭的服务；需要重启时按启动设置执行。完成反馈读取实际状态，不能将配置应用成功等同于服务启动或播放成功。

「退出时恢复游戏直连」（`restoreHostsOnExit`）默认开启，缺失或 null 采用默认值，明确关闭则保留。它是保存即生效的退出行为配置：草稿不改变策略；由关闭改为开启时，保存先准备当前托管接入的恢复权限（复用助手，缺少时才请求 UAC），再原子写入全部配置。网页在开启此选项的保存请求中沿用授权操作的 120 秒等待期限，并提示可能出现的管理员授权；超时只提示结果未确认，保留草稿供核对，不自动重试。权限准备或写入失败保留旧配置和旧退出策略；权限准备不修改 hosts。保存成功后同时更新 saved/active 中的退出选项，单独更改它不要求重启；同次提交的其他运行配置仍待重启。退出请求携带已提交策略交由已有助手执行，不在退出时申请 UAC。默认恢复后，重启按自动加速设置重新接入；关闭自动加速时可手动一键开启。权限助手和失败边界统一见[hosts 契约](console.md#hosts)。

常规设置中的 `autoOpenWebUI` 默认 true，在新进程启动桌面托盘时决定是否自动打开浏览器；保存不即时开关页面。显式 `-no-open` 优先，网页发起的重启继续传入该参数，防止重复打开页面。托盘主动打开和再次启动已有实例属于显式激活，仍可打开控制台。浏览器的跟随系统／浅色／深色选择仅存在 localStorage，立即生效，不进入 Settings、重启判定或首次引导草稿。
